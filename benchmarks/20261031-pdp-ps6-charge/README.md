# PS-6: the pairs-and-solve kernels charged in the counted unit

Visual copies of the study's results report and its two run reports (counted sessions 2026-10-18, timed sessions and calibration 2026-10-31), with every graph as SVG and a 150 dpi PNG rendered from the same plotting source (`research/pdp_oracle_speedup_20261011/tools/plot_ps6.py`).  The study directory, [`research/pdp_oracle_speedup_20261011/ps6_charge/`](../../research/pdp_oracle_speedup_20261011/ps6_charge/), holds the raw sessions, sources and interpretation and is the source of truth; `copies.json` lists each copy's source, SHA-256 and size.

Measured (counted unit `S`, the ledger's five char2 rungs `n = 15 ... 27`, random binary curves, `l = n/3`, `m = 3`, one target per run, every arm on the same workloads): S4 pairs-and-solve baseline `S = 1,270 ... 114,574`; PS-2 group-law kernel, recorded (its pairs unpriced, a lower bound) `33.8 ... 22.4`, `139.7 ... 9,915` at 1 GAE per pair; the library's MITM table `57.9 ... 197.0`; matched `rho.negation` `2.1 ... 1.1`.  The kernel against the table is unresolved inside the AGENTS.md section 5a band at every rung.  Stage diagnostics only; no end-to-end speedup, no ECC2K-130 claim.

**Gate standing.**  `VALIDATION.json` names a replay certificate, a validator report and a matched-rho descriptor with the section 5a band; `python3 scripts/validation_gate.py evidence benchmarks/20261031-pdp-ps6-charge` reports `valid`.  The artifacts were produced by the study's author on the machine that measured: the scalar re-verification and the totals recomputation are separate code, but no second party and no second host class replayed the sessions, which the study README states (section 6, D6).
