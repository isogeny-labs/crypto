\textbf{Scope.} This is a validation and CI repair for the crypto repository's pinned
SEA proof project and proof gate. It does not certify every historical experiment
in crypto, cryptanalysis, or crypto-autoresearcher. No scientific trial or
performance measurement was run.

\section*{Observed failures and correction}
\href{https://github.com/aburan28/crypto/actions/runs/39459394168}{CI run 39459394168}
at \mono{892ef408e98f190ef19c0ab5fee8030cb5d91c6d} had 37 successful jobs,
two failed jobs, and one cancelled job. These are job outcomes, not counts of
verified theorems or experiments.

The SEA project built \mono{SeaProofs.lean}, including its theorem axiom
printouts, but Lean 4.19 rejected the gate's \mono{--trusted} program argument
before the separate axiom audit. This was a gate implementation failure, not a
counterexample. The DenseCapacity target failed in that CI run while downloading
Lean 4.34.1 because of a TLS connection error; that run produced no theorem
verdict. A later local run of the repository gate passed its five theorems.
The cancelled tree-split job failed during Git checkout (connection reset and
\mono{index-pack} failure), before Lean ran. The later local tree-split gate
passed 24 declarations; one registered \mono{native\_decide} proof uses
compiler trust and is counted separately.

The repaired gate passes the unchanged trust manifest through
\mono{LEAN\_AUDIT\_TRUSTED\_FILE}; the auditor receives only module names as
program arguments. Whitespace normalization now uses Lean APIs available in
both Lean 4.19 and 4.34.1. CI installs each pinned toolchain before the proof
step and retries only failed downloads, at most twice. Build and axiom failures
still fail normally.

The SEA declarations include \mono{SeaProofs.bsgs\_complete}, a search
completeness theorem for an explicitly supplied additive group, and
\mono{SeaProofs.direct\_equals\_full\_intersection}, a predicate identity.
The local audit found only standard Lean foundations, \mono{propext} and
\mono{Quot.sound}, for SEA. It does not prove that the Rust point-counting
implementation conforms to the abstract predicates or establish a new speed
or ECDLP claim. The older successful CI jobs are not a fresh build of current
main; the PR's full proof matrix remains a separate gate.
The complete Rust test used the minimal sparse profile with the SEA fixture
and local \mono{isogeny\_algos} dependency included. Two earlier sparse
checkout attempts lacked tracked inputs and failed during compilation; their
logs are retained. The successful raw test log SHA-256 is
\mono{de7281263c07499c30f671e7e0821010f60a16f918095b18c2ff6a37ebf95271}.
