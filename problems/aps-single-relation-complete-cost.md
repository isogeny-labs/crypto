# APS single-relation complete-cost validation

**Status:** open accounting/export, parameter-ladder and access gaps;
bounded independent replay added 2026-10-29.

The [bounded native study](../research/aps_extensions_20261026/README.md)
checks the paper's relation path and several extension mechanisms on tiny
public fixtures. Its F4 counter does not include complete factor-base/label
construction, symbolic polynomial construction, root decoding, sign search,
deduplication or final verification. `prime_fast` and the new expression layer
do not yet supply a complete common operation tally for this route. The JSON
fixture runner is not an ecbench/unified experiment export. The
[2026-10-29 replay continuation](../research/aps_replay_20261029/README.md)
now supplies independent EC/sampling/relation replay for its emitted fixed
public-fixture transcripts; cost and execution-history attestation remain open.

Consequently the current receipts establish bounded correctness only. They
cannot decide whether a partition, unordered-divisor presentation, sparse
orbit, covering family or hybrid solver reduces complete expected cost.
This is not a mathematical obstruction to an improvement.

The [blocked backlog card](../backlog/XP-20261026-aps-complete-cost-panel/README.md)
preserves the requested controlled comparison. To unblock it:

1. Instrument all phases and retries, extend bounded independent replay to
   the chosen panel/parameter ladder, and integrate native ecbench/export
   output. Include pre-transcript abort outcomes and independent metric
   validation. Verify that an intentionally
   expensive setup changes total cost, and that invalid relations fail closed.
2. Choose the exact curve/target/base populations, controls, effect threshold,
   sample size, seeds, runtime envelope and external solver comparison. Freeze
   a valid `experiment.protocol/v1` and its analysis on a merged code revision.
3. Retain the toy instrument's caps until a separately reviewed backend/cap
   extension supports the intended ladder. The current implementation does
   not cover m=5 or the full 11–22-bit paper ladder.
4. Resolve the automatic approval rejection of the source/worktree checkpoint
   upload (source-code egress to S3 needs explicit user approval), supply the
   configured upload credential, complete the resume record, push and pass
   the checkpoint gate before launch. Do not retry or bypass the rejected
   upload without that approval.
5. Collect every planned outcome, compare complete cost with the frozen IC
   baseline and strongest matched rho, independently replay and recompute
   headline numbers, and retain null/negative outcomes.

## Independent bounded replay (2026-10-29)

The [independent native replayer](../research/aps_independent_replay_20261029/README.md)
checks the existing fixture JSON using separate ordinary-residue affine
arithmetic, without the producer's curve, solver or recovery code. Fourteen
native transcripts cover twelve arms and three fixed public curves. The same
nine replay/corruption tests pass as a standalone package and repository example.
It binds model/ICV1 identity, validates every labelled point and reported
coordinate set, recomputes signed A/B coefficients and checks nonzero B and dG=Q.
Pruned orbit inputs require independently checked label propagation.

This supplies a bounded witness replayer, not a complete experiment exporter.
It does not certify root enumeration completeness, sampling/draw history,
deadlines, primitive costs or unsupported parameter ladders. A producer
orbit-overlap refusal before JSON emission is retained in the new study's
failure record; the future panel must also export such pre-transcript failures.
All remaining accounting, protocol, checkpoint, reference and environment
requirements above remain open. No performance run or cost reduction is claimed.

## Independent arithmetic replay (2026-10-29)

The [BigUint replayer](../research/aps_replay_20261029/README.md) uses separate
existing point arithmetic, independently
regenerates seeds/draws/labels, verifies all emitted signed relations and useful
recoveries, and checks complete coordinate sets by finite point enumeration.
The CLI cross-checks all twelve arms in both enumeration modes. Corrupt labels,
omitted complete-set roots, invalid signs/status/retry counts and B=0 witnesses
with the correct public answer are rejection controls.

This closes the mathematical replay component for emitted transcripts on the
three current fixtures. It does not price producer work or attest solver
diagnostics: its receipts explicitly set `costs_attested=false` and
`execution_history_attested=false`. A future timed driver needs a frozen,
common verification interval and separately reported post-run completeness
auditing. Full operation accounting, native export, supported parameter ladder,
metric validation, protocol and source-checkpoint approval are still owed.

## Native timing support (2026-10-30)

The [measurement-instrument study](../research/aps_measurement_20261029/README.md)
adds `ic.aps_v1` with explicit bounded parameters, retained attempts and
pre-transcript failures, actual polynomial exports, and separate affine witness
checks. One clock closes setup and five exclusive online phases, beginning the
online window before live-target conversion. All failed search work remains
inside it; post-run report aggregation/serialization is explicitly separate.
Late verified witnesses are retained without becoming in-budget successes.

This implements the timing/collection part of item 1, not its complete operation
accounting or independent metric/full-set validation. Missing algebra reports
leave diagnostic counts unknown. Native audit classification reflects the
cooperative deadline; a static APS audit and deterministic rho replay do not
attest APS count replay. The existing fixed-fixture replayer keeps its scope.
The [checks and source-boundary receipts](../research/aps_measurement_20261029/CHECKS.md)
distinguish completed checks, failures, cancelled builds and pending validation.

The native unified export, held-out four-size ladder, frozen protocol/analysis,
full accounting, independent replay/metric validation, source-checkpoint approval
and EKS admission remain open. Development control specs are not that freeze.
No performance experiment, expected-cost reduction or scaling result is claimed;
the original panel and exit criteria above remain unresolved.
