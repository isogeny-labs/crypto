# RunPod jobs that survive pod loss

RunPod can remove or stop a pod without warning: on-demand pods too ("Exited by Runpod" on
2026-11-07 and 2026-11-09; pod `y8fnixt44o3ziv` gone mid-run on 2026-11-15, taking ten hours of
EXP-PKM-DENSE-DEC-001 rows with it). Anything that lives only on the pod is at risk. This
directory makes a long job lose at most the work unit in flight.

| Layer | Where | What it does |
|---|---|---|
| Durable state | RunPod network volume, mounted at `/workspace` | rows, progress, `autorun.json`, boots, heartbeat; outlives any pod |
| Self-restart | `supervisor.py` on the pod | on boot, restarts the job recorded by the last `POST /run` unless a `COMPLETE` file exists under `runs/` |
| Resumable job | the job itself | skips finished units (e.g. `pkm_algebraic_oracle --out F --resume 1`, a `.done` marker per cell) |
| Self-stop | `supervisor.py` on the pod | terminates the pod (REST v2, with the `RUNPOD_API_KEY` RunPod injects) once no job has run for `SELF_STOP_GRACE` s (default 3600; `controller.py --self-stop-grace`; −1 disables) |
| Off-pod copy and replacement | `controller.py` on the client | mirrors changed files every 5 min; replaces a pod that is gone, exited or silent for 15 min; deletes the pod when `--done` matches |

## Use

```bash
# 1. a volume in a data center with CPU pods (10 GB ≈ $0.70/month), once
curl -s -X POST https://rest.runpod.io/v1/networkvolumes -H "Authorization: Bearer dummy" \
  -H "Content-Type: application/json" -d '{"name":"my-run","size":10,"dataCenterId":"EU-RO-1"}'
# 2. start the controller; it creates the first pod and writes the pod token to --token-file
python3 tools/runpod_resilient/controller.py --volume VOL --name my-run --mirror research/x/runs \
  --token-file "$SCRATCH/pod_token" --progress runs/large/progress.txt --done 'done last-cell'
# 3. once the pod answers /health: upload the binary and job script, then POST /run once
curl -X PUT --data-binary @bin "https://POD-8888.proxy.runpod.net/upload?name=bin" -H "Authorization: Bearer $(cat "$SCRATCH/pod_token")"
curl -X POST -d '{"argv":["bash","job.sh"]}' https://POD-8888.proxy.runpod.net/run -H "Authorization: Bearer …"
```

Uploads land on the volume, so a replacement pod needs no upload: its supervisor restarts the
job by itself. The controller keeps its pod id, mirrored file sizes and replacement count in
`<mirror>/controller.state.json` and every action in `<mirror>/controller.events.jsonl`; restart
it with the same arguments to adopt the running pod.

## Limits

- A unit in flight when the pod dies is computed again from scratch. Units should be short;
  a 24-hour unit is still exposed for 24 hours. Record each attempt (wall time, pod) so a lost
  attempt is visible, and fix in the protocol how many attempts a unit gets.
- The volume pins the pod to the volume's data center. If that data center has no CPU stock,
  replacement fails until it has (`create_failed` events); the volume and rows stay safe.
- If the client dies, nothing deletes a finished pod except the self-stop. On 2026-11-15 a finished pod
  idled 17.7 h (≈ $18) because the controller died with its host container. Since then the pod
  terminates itself `SELF_STOP_GRACE` seconds after its last job exits, or after boot if no job runs;
  the rows are on the volume. Tested live 2026-11-18: an idle pod on the volume terminated itself
  2 min after boot with a 120 s grace. The key RunPod injects into a pod works with
  `api.runpod.io/v2` (self-read, pod list, `POST /pods/{id}/action` → 204); `rest.runpod.io` did not
  resolve from inside the pod.
- The client-side mirror lives as long as the client. The volume is the durable copy; commit the
  mirror to Git at milestones.
- Pod tokens are generated by the controller and stay in `--token-file` (mode 600). Never commit them.
