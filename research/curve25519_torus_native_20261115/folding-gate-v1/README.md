# Folded-certificate support audit

The standard linear-algebraic folded-RS dimension/root-count certificate is
incompatible with a six-agreement budget at original length at least42, under
the explicit premises in PROTOCOL.md. Core Lean checks five named integer
endpoints. This is a restriction on that certificate, not a decoding lower
bound. [pcc:PCC-20261123-243ecb]

The Rust control constructs all44 signed geometric positions of the original
p101/A95/q3/K8 toy base, with zero geometric duplicates. A frozen supplied
section has exactly six matches; original indexed/group, raw-R and numeric
section replay agree. All21 parameter pairs fail the standard guards, even
with optimistic full-block packing. Three release unit tests, fmt and strict
all-target Clippy pass locally. No decoder or unknown-root backend was called.
[pcc:PCC-20261123-1b51f3]

Read report.md/report.pdf, PROOF_MAP.md, ROUTE_STATUS.md and NEXT.md. Source
identity is SOURCES.sha256/SOURCE_QUALIFICATION.json; full captured native
evidence is native-v1/native-run-v1.tar.xz. Formal source/gate/declaration
bindings are retained separately. Local Lean pass and unsigned native records
do not establish independently signed standing. Actual-curve support,
polynomial-message/Artin applicability and useful search cost remain open.

The exponent-facing successor is a finite exact rank test for low-degree
interpolation on the original large-q coset, with original membership/index
rows retained. It is not implemented by this component. [pcc:unverified]
