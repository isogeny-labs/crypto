## Relation events and budgets

For each exact base and each target, build one full-point membership index, preserving the point-to-column, Frobenius phase, sign and coefficient mapping. Import and index time and peak memory are measured separately. An m=2 arm exhaustively checks each of the 2,760,082 distinct labeled point rows as the first summand, computes the unique group complement, and asks whether it is in the same base. Canonicalize unordered duplicate pairs, reject infinity or a mismatched group equation, and insert every checked row into a rank tracker over the exact subgroup order. A completed exhaustive arm may report an exact per-target count for this base; a cap or error is censored with the last completed index.

An m=3 arm draws exactly `2^20` deterministic pairs of point-row indices per target and base using BLAKE3 XOF keyed by ASCII `N83-M3-PAIRS-v1`, seed `20261019`, target index and pair ordinal. Map each 64-bit draw modulo 2,760,082; reject and redraw a repeated index within a pair using the next XOF word. Check the third-point complement in the full base, verify every returned group equation and coefficient row, and insert checked rows into the same exact rank tracker. Record duplicate sampled triples, attempts, successes and rank; repeated pair draws are charged, not hidden. This is a sampled bounded relation event, never an exhaustive m=3 yield claim. A cap records completed draws and remains censored.

Run one target at a time, base order U,D,D,U for target 0 and alternating U,D for targets 1–7. Use a fresh output for each arm, one CPU, hard 4 GiB memory, zero swap, 1,790-second internal deadline and 1,800-second independent outer cap. Write fsynced progress every 10 seconds (completed first-point or pair attempts, lookups, checked relations, rank, process CPU, peak memory) and a separate final/cap receipt. Preserve failures, interrupted arms and all output hashes. Constructed two- and three-summand group sums from first distinct base points are positive controls; altered target and row receipts must fail independent native replay before natural results are accepted. A/A repeats share an exact base/target and code path; their wall spread describes L0 noise only unless the host earns the repository's isolation level.

Record setup as cold work and price reuse counts `q ∈ {1,8,64}` as `setup + q × measured per-query stage cost`; retain the individual measured parts and label any arithmetic projection as derived. Never infer a total pipeline runtime from this stage projection.

## Decisions

- Exact native replay and matching point-set/label digests qualify a factor-base stage for comparison; any mismatch blocks the comparison.
- A checked m=2 or m=3 relation increases the recorded rank only if the exact row is independent. Zero returned rows under a completed finite arm is that arm's observation, not a general absence claim.
- A cap, missing progress or failed positive control is censored/invalid as appropriate and does not rank U against D.
- The next protocol version may widen budgets or targets only as a new experiment with prior outcomes retained.
