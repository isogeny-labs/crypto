# Clean native-worker source after the first spot preflight

The first spot P arm exited 1 before a run directory existed. Its complete [raw files](spot-arms/p-preflight-v1/), bound by [the 12-file manifest](p1-raw-files.sha256), show `ENOENT` from the Linux worker. The original `primary_adapter.rs` read `/sys/fs/cgroup/memory.max` at the cgroup mount root. On this host the systemd scope has its memory files in the path named by `/proc/self/cgroup`; the mount-root files do not exist. This is an infrastructure adapter defect, not an oracle disposition. No A1 or B arm ran with the first binary.

The corrected `primary_adapter.rs` resolves the process's cgroup v2 membership and uses that path for the limit, swap, current and peak reads. Its test covers both a container root and a native nested scope, and rejects missing or traversing memberships. The remote source copy with this exact file passed [all 21 release example tests](remote-cgroup-fix-example-tests.log).
