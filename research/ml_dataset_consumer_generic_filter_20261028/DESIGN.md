## Finding and acceptance scope

The current consumer does not independently replay generic-v1 large-prime
filtering. It hashes all artifacts, binds plan/config/public/provenance, and may
check positive scalar/PDP equations; its only solver-specific native arithmetic
hook beyond those is root certificates. Generic v2 therefore needs a new checker,
not merely an accepted schema string. Unknown generic artifacts are currently
integrity evidence, not independently verified source combinations or rank.

Implement independent finite **supplied-domain, source-equation, filter-prefix,
completed-matrix and positive-recovery** checks for recognized v2. The standalone
crate must not link crypto, invoke its filter/checker/rank routines, include its
source files, or count optional producer replay as independent arithmetic.
Preserve the exact current generic-v1 and Koblitz-v1 acceptance paths and their
unverified filter status. Do not retrofit new native-trace claims onto v1.

This increment does not reconstruct the residual pool's exhaustive lift/search
or cyclic-membership construction. Public source equations can be verified
without private subgroup logarithms. Supplied construction metadata remains
hash-bound provenance; saved membership Booleans are not proofs. Checking rP=0
is an r-torsion test, not proof that P lies in the cyclic group generated by G
when r-rank can exceed one. Do not call this complete factor-base/residual-pool
construction verification. Existing optional producer replay continues to cover
its own stricter construction and implementation replay as separately labeled
producer evidence. No new logarithm search is needed or proposed.

Preserve prime/binary/Koblitz families, both twists, n=3..61 in the existing
public-arithmetic envelope, including requested binary sizes23..31 and47..61.
The generic relation collector's m=2..15 with m-2 chosen small points is not
higher-m Semaev root support. Use the actual saved schema to select this path;
admitted Koblitz signed-Frobenius calls still use their separate v1 route.

## Public domains, queries and source equations

Reuse independent public_curve validation. Separately require the dataset scalar
modulus r to be an odd prime in[3,2^63), using the existing independent primality
method (Field::prime rejects3 and cannot be reused blindly). Verify finite G/Q
and rG=rQ=identity; check finite distinct domain points and rP=identity. This
can establish the selected prime-order generator and torsion equations, not
whole-curve cardinality, cofactor truth, exhaustive construction or membership
of every r-torsion point in <G>.

Reconstruct small signed columns from the ordered actual base points: the
representative is lexicographic min(P,-P), columns appear at first occurrence,
and the signed coefficient is1 or r-1. Reconstruct residual signed columns in
the same way from its saved finite domain; enforce its advertised point/column
caps, disjoint signed small/residual domains, and paired signed closure. Bind
all residual construction/projection fields through the full domain hash, but
report their construction proof status false. Never read private membership
logs to produce an independent filter label.

Rebuild the complete finite pair table from supplied residual points in i then
j>=i order. Retain identity sums in the table but omit them from lookup; equal
nonidentity sums keep the first pair. Check all saved sums/indices and counts.

Derive the collection limits exactly: w=min(requested_work,100000), queries=
min(w,4096), pairs=min(floor(w/4),8192), residual_points=max p with p(p+1)/2<=pairs,
residual_columns32, x_candidates2048, filter_every32, max_small_weight/max_sources4096.

Replay each recorded query's coefficients and m-2 small indices from the pinned
public RNG contract, and separately verify its group arithmetic. Producer lock
is rand0.8.8, rand_chacha0.3.1, rand_core0.6.4; StdRng is not a future-proof
algorithm name. Pin compatible dependency versions and a64-bit sampling path,
with known-stream vectors from the pinned producer fixture. Reusing a standard
PRNG dependency does not import producer arithmetic and should not be called an
independently reimplemented PRNG. If exact stream replay is unavailable, do not

Seed mix is seed XOR rotate_left(generator_index,17) XOR rotate_left(key_index,31)
XOR0x8a01731f94b0d6c3. Draw a in[0,r), b in[1,r), then m-2 indices in[0,small_len)

## Independent native filter replay

The new checker must implement scalar coefficient algebra itself using safe
u128 products/reduction and ordered sparse maps/merges. Reuse no producer filter,
normalization, inverse, schedule, report, source-replay or rank routine. Supplied
inverse/scale values may be checked multiplicatively rather than recomputing the
producer Euclidean inverse. Schema definitions and documented wire order are
shared contracts, not implementation imports.

For each batch, bind index, through_attempts, source_count, ordered cumulative
sources and remaining limits. Sources are all accepted attempts through that
position, not a fresh delta. Require exactly the scheduled batch positions:
after each accepted source count divisible by32, or at the query cap. A final
censor or verified target recovery stops further attempts/batches.

Reconstruct finite transition state with its own arithmetic:

| Transition | Independent requirement |
|---|---|
| Begin / Normalized | Ordered raw input hash/counts/options/limits; mod-r merged zero-free rows and position; normalization reservation |
| DuplicateDropped | Exact normalized small/large/rhs duplicate, first retained representative; distinct source IDs |
| Peel | Chosen column currently degree1; unique live incident row; complete before/after degrees and row removal. Any valid declared singleton choice is acceptable; do not invent a deterministic queue order absent from this wire |
| CoreReady | All singleton peeling exhausted; smooth rows in retained order; core sorted by (large weight,small weight,id); static core degrees/report |
| RowBegin | Exact original normalized source row, singleton source coefficient1, version0 |
| PivotSelected | Prefer existing pivot; then static Markowitz score(degree-1)*(row large weight-1), then column ID; reference/version and score exact |
| Reduction | Current pivot/version; canonical inverse with inverse*pivotcoeff=1; cancellation scale; full small/large/rhs/source AXPY; acceptance by max_small_weight/max_sources; only acknowledged accepted reductions update row/version |
| PivotStored | Exact current row/reference only when no pivot exists for the selected column. Rejected Reduction ends that input without storing or completing the rejected candidate |
| CompleteRow | No large columns; exact current row/source combination; smooth rows included; counters and cycle classification exact |
| Finish | Exact acknowledged completed-row list; only acknowledged Finish establishes final report/completed batch |

Independently recompute every report field, all reservations and prefix totals.
Native WORK_SCOPE and BYTE_SCOPE strings must match the pinned schema, and their
exclusions must remain in consumer output. Source combination validation checks
that complete rows equal the sum of normalized original inputs, with large terms
canceling. It does not prove that the returned rows form every possible relation
or a complete dependency basis.

## Cumulative caps and terminal semantics

Production v2 policy is fixed at input_rows4096,input_terms1000000,row_terms65536,
events100000,bytes16777216,work1000000. Input/state ceilings are per batch.
Remaining event allowance subtracts cumulative attempted events; remaining byte
allowance subtracts acknowledged event bytes; remaining work subtracts computed
work. All sums/subtractions are checked. Do not reset to full caps at refilter.

Native attempted_events=events.len()+presence(unacknowledged). Track cumulative
acknowledged_events, attempted_events, acknowledged_bytes, refused_event_bytes,
acknowledged_work, computed_work, inverse_calls and acknowledged_inverse_calls.
Byte refusal can compute one event whose full compact bytes exceed remaining
allowance; retain/count it separately, do not acknowledge it or mutate committed
row/report state, and stop the whole collection. Zero remainder remains zero.

Stop priority and evidence are exact:

- InputLimit occurs before raw hashing and native events/work; validate its
  zeroed counters/rows, absent hash/reservation/event, initial nonfinal report.
- StateLimit, then EventLimit, then WorkLimit is reservation admission order.
  Require the exact next_reservation, no unacknowledged event, and a justified
  first exceeded condition at that scheduled operation.
- ByteLimit requires the exact computed unacknowledged event, no next_reservation,
  computed/acknowledged separation and byte excess.
- SinkFailure cannot occur in a successfully sealed generic v2 transcript. It
  is worker failure; capture prefixes remain evidence without a filter success.
- Completed requires acknowledged Finish, final report and no pending event or
  reservation. Finish refusal is censored even when prior complete rows exist.

Only the final batch can be censored. It carries no legacy rank snapshot,
recovered scalar or recovered logs, and no later query/batch. Empty declared
domain, query-budget exhaustion, trace censoring and positive recovery remain
distinct. Never translate any cap/failure into UNSAT or absence of relations.

Do not demand an impossible default-policy fixture: derived dataset inputs are
already bounded by4096 attempts and short source rows, and accepted sparse states
have at most4097 small,32 residual and4096 source columns. InputLimit/StateLimit
are meaningful low-level or reduced-policy tests but may be unreachable through
this fixed production adapter. Keep such tests distinct from genuine default-
policy sealed Work/Event/Byte censor interoperability.

## Independent checker admission and leakage

Before typed expansion, cap each v2 transcript/batch file to32MiB and bind its
manifest size/hash. Preserve raw-artifact limits separately from mathematical
caps. Use bounded typed decoding and avoid duplicating the complete event Value
forest for every payload; compare one batch artifact at a time. The standalone
consumer's64MiB general JSON ceiling is unchanged for legacy inputs.

Proposed conservative initial independent envelope (to freeze before coding):
4096 actual small points/4097 rank columns; residual<=127 points and32 signed
columns (actual producer normally stops at64 points); <=8192 pairs,4096 attempts,
129 batches; native policy ceilings above; <=4194304 dense rank coefficient cells
before allocation; <=128million checked term/rank logical units and <=1048576
reserved curve addition/doubling units per cell. All are cumulative across
refilters. Charge scalar multiplication's bounded worst-case bit schedule before
calling existing affine arithmetic. Public validation/hashing/parsing exclusions
must be stated; none of these is a CPU/RSS/total-cost measurement.

If the independent checker cannot admit a producer-valid artifact, return an
explicit consumer_resource_limit error/unverified status according to the
existing audit API, never a producer-censored result, lower-size substitute,
partial rank, or successful check. Do not silently narrow n, m or the input base.
The final memory policy should account for typed decoded storage, raw bytes,
source maps, matrices and one comparison payload; reject before oversized dense
allocation. No claim of whole-process RSS follows from file/vector caps.

New native traces, source coefficients, query seeds/indices, construction logs,
pivots, inverses, RREF, rank, recovery, counters, stop reasons and all binding/
manifest hashes stay in restricted labels/provenance. static_features remains
byte-equivalent for the same public/base/config across generic v1/v2. Do not add
the residual relation-query domain to the consumer's ordinary PDP feature view
or claim producer-training-export equivalence. Existing whole-field splits,
legacy/v2 policy feature schemas and unsupported null-feature behavior stay.
