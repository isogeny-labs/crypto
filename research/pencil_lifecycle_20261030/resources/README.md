# Execution resource prefix and external closure API

T-949. Implementation: `src/cryptanalysis/ecbench/diagnostic_resources.rs`.
This is software infrastructure for diagnostic custody, not a scientific run or cost model. No module registration, build, test execution, solver, cloud or Git changes were performed by this agent. Five fake-clock/failure tests are source fixtures awaiting root integration and execution.

One session monotonic clock supplies all offsets. Begin the execution envelope before context/directory/ChildInput work. Strict marks are child-started, child-reaped, record-durable, diagnostics-durable, session-durable; failures can seal any reached prefix. Missing marks/hashes stay absent. Returned status requires the full sequence. Seal after summary preparation, before its publication. Serialize exact ResourcePrefix bytes; after actual write+sync, create PublicationTail::observed with those bytes and actual interval. Do not invent a tail on IO failure.

Append the tail to a runner journal; publish exact journal bytes externally. The journal never claims its own write is included. Last publication stays pending until supplied ExternalExit binds exact journal bytes, session/runner/clock and an externally observed payload wall interval. Absent closure returns closed_payload_wall_ns=None. total_active_worker_ns remains None even after closure. Nested child/process/record intervals are not summed. The supplied external whole-payload wall interval includes gaps and session overhead once; no per-row amortization or GAE/dollar conversion is made here.

Trust boundary: this module validates shapes, ordering, hash equality and interval consistency. It does not authenticate a caller, attest source compilation, observe process exit or verify external receipt custody. Root must accept ExternalExit only from the existing authorized owner and bind observation_receipt_sha256 to retained actual external bytes. If that owner cannot supply the same clock's payload wall interval, closed_payload_wall_ns stays null. Neither this interval nor controller lifetime establishes cumulative active worker time. total_active_worker_ns is always null here; suspension, queue and recovery accounting require a separate owner observation contract.

All prefix, journal and closure types reject unknown JSON fields. Exact prefix and journal parsing rejects duplicate keys before deserialization, with 64 KiB and 8 MiB input caps respectively. Published-prefix bytes are deserialized and compared with revalidated state before hashing. Journal exact bytes and ordered tails are revalidated at closure. Cross-session/clock/runner/scientific run/attempt/source/protocol/binary substitution, repeated sequence, backwards clocks, overlapping execution intervals, missing durable hashes and premature closure reject. Caller-supplied PublicationTail is an observation claim, not IO proof; retain the referenced prefix artifacts.

Independent stage failures: setup/context/spawn failure can seal with no marks; child failure can seal after reap; record/ingest/session failure preserves preceding marks. If prefix or journal publication itself fails, retain that failure externally; this API cannot publish a receipt of its own failed write. Historical Timing fields and accepted mathematical results are untouched.

Tests included (not run): failure-prefix missing fields; mark/binding/overflow rejection; publication failure/hash mismatch leaves total unknown; external closure exact wall interval without nested double counting and with active time remaining null; duplicate-key and oversized-input rejection. Root should run focused library tests after module wiring. No fresh validation count or all-cost completion is claimed.
