# Independent reap/publication fixture delta review

Read-only 2026-10-30. Reviewed runner-v4-reap-publication-fixtures.patch SHA5889cbd8881ca47436e4f23a8cf95be6d02bc8b9f9835a444f2874a725bbbae0 against private runner-v4 and inspected helper callsites/current source. No builds, tests, solver calls or edits by reviewer.

No concrete source defect identified in this delta. ReapObservation::from_result requires both Ok and reap_observed. Both production resource marking and sidecar access use that same helper; bool::then is lazy, so an unobserved reap cannot invoke the reader. The fixture explicitly constructs Ok(Reaped) with reap_observed=false, proving the important distinction at the software-test source level. Missing later stages correctly force Failed prefixes even in the observed-reap branch.

The process fixture invokes an explicitly generated /bin/sh script whose body only drains stdin with cat and exits0. The supplied input() constructs/serializes a fixed ChildInput but never calls Workload::build, resolves or invokes its named bsgs method. The script ignores ecbench's exec argument. Therefore this is a process-lifecycle software fixture, not a mathematical experiment. The ETXTBSY retry handles failed spawn before callback; it is not a scientific retry. The nonexistent executable branch checks no spawn observation/no reader access. Global signal/process helpers make the requested single-test-thread execution appropriate.

IO collision expectations match publication ordering. When the prefix destination already exists, exclusive hard-link fails before journal append, leaving prior journal bytes and record untouched. When only tail destination exists, the prefix has been successfully published and appended before collision, so retained prefix and changed in-memory journal are expected. Both preserve original destination bytes and leave external closure pending with wall/active totals null. Temporary publication files may remain on collision; the fixture cleans its private directory and does not assert absence of those files or false durability.

These tests cover real fake-process spawn/reap, lazy unobserved-reap gating and prefix/tail destination collisions. They do not cover every sync failure, full runner error integration, final-journal failure, scientific callbacks, checkpoint restore or timing qualification.
