# Explicit diagnostic activation v1 — private unapplied proposal

Patch SHA256: `6a05f2f3129f47475f14372ffd77e6802731527ce3b691c12297256d234cc582`. Exact two-file bases and proposed hashes are in `explicit-diagnostic-activation-proposal/PROPOSAL-RECEIPT.json`. This delta is limited to runner.rs and record.rs; it is not applied to the working tree.

The runner's temporary unconditional rejection is replaced with a pre-plan helper that hashes the actual configured child executable with the existing streaming file hasher, computes the existing ECS1 identity-view spec digest, and invokes strict launch validation with both. The helper runs only for an explicit launch, before plan() can generate a workload. No launch field is inferred or rewritten. The existing execute_session check still compares the launch to the captured parent executable hash and validates the entire resolved plan, arm configuration, role and profile before any child. The child rehash below catches substitution between the initial executable read and exec, before producer installation.

The child's v2 placeholder rejection is replaced with metadata/custody validation followed by hashing the running executable. Linux uses /proc/self/exe, preserving the actual exec'd inode; other platforms use current_exe. A mismatch or inability to read the binary returns an error before workload construction. Existing bounded-input, duplicate-key and mixed-v1/v2 rejection remains. Legacy v1 diagnostics remain explicitly rejected. After ordinary workload reconstruction and expected-workload-ID comparison, the existing full serialized workload digest validation remains mandatory. Method resolution and exact config/seed binding are unchanged. The already-integrated actual with_diagnostic_lifecycle invocation then installs the common lifecycle for every arm, with the candidate-only prefix sink and existing explicit finish/error/panic ownership semantics.

There is no default activation: absent launch/context follows its original branch and performs no added executable hashing. The hashing and diagnostic plumbing are real additional work, covered by the existing enclosing process/session resource intervals; this patch supplies no new performance estimate and does not claim inner solve time includes that work. Existing censorship of late child output, sidecar acceptance, resource journaling and publication-tail handling are unchanged.
