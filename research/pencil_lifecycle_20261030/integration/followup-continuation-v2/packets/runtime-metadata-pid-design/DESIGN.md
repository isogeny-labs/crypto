# Narrow metadata inspection and pre-exec PID evidence proposal

This additive design preserves supervisor v1/v2 unchanged. No Docker request, container command, helper compilation or scientific execution was performed. The design is prospective and requires source review plus actual engine/API binding.

## Replace broad /opt copy with precise HEAD metadata

Docker's documented HEAD /containers/{id}/archive?path=... exposes a base64 JSON X-Docker-Container-Path-Stat header. The Moby v28.0.0 handler calls ContainerStatPath and writes that header; unlike GET it does not call ContainerArchivePath or stream file content. This supports targeted metadata inspection of stopped-container ancestors without copying unrelated /opt descendants. Primary references: https://docs.docker.com/reference/api/engine/version/v1.51/ and https://raw.githubusercontent.com/moby/moby/v28.0.0/api/server/router/container/copy.go . The reviewed tag is evidence of API design, not identification of the installed daemon.

The PathStat struct contains name,size,mode,mtime,linkTarget; it does NOT provide UID/GID, ACLs or file hashes. Its mode is Go os.FileMode, not a POSIX st_mode: the directory flag is1<<31 and permission bits are the low9bits. Source: https://raw.githubusercontent.com/moby/moby/v28.0.0/api/types/container/container.go . Keep tar-member UID/GID/hash/length checks for exact artifact files. Do not derive ownership from HEAD or treat metadata as a hash check.

Proposed exact HEAD list: /, /opt, /opt/isolab, /opt/isolab/recovery, /opt/isolab/recovery/lib, /usr, /usr/local, /usr/local/bin. Pin a mutually supported API version from the admitted daemon/client record. Call through the same explicit local Unix socket with a pinned curl client under the empty sudo environment; no redirects, proxy, Docker context or remote endpoint. Example template, not executed: curl -q --head --silent --show-error --max-time15 --unix-socket /var/run/docker.sock --noproxy '*' http://localhost/vPINNED/containers/EXACT_ID/archive?path=URL_ENCODED_EXACT_PATH . Preserve status/header receipts, cap each header response64KiB and reject duplicate PathStat headers. Require HTTP200, valid base64/unique-key JSON, bounded schema, directory mode with no special flags, empty linkTarget and all three execute bits. Use identity inspection before/after the sequence; no concurrent container mutation is admitted.

Query every ancestor separately to avoid passing a symlink ancestor unnoticed. Reject linkTarget and non-directory flags. The pure head_contract.py decoder specifies these checks without issuing requests. It is source preparation only. These are mode-bit observations; HEAD does not establish ACL absence or ownership. Exact artifact reads remain: ecbench, owner, build-info, smoke JSON and the runtime directory with its explicit manifest allowlist. Thus the broad /opt archive is removed while ownership/hashes for consumed files remain checked. No claim to enumerate all other image contents is introduced.

This adds8 small HEAD requests and replaces one broad copy with three narrow copies. The300-second shared budget remains unchanged; actual request latency is unmeasured and exhausting the budget stops qualification. No automatic retries or expanded time allowance are implied. Installed HEAD behavior, API version and pinned curl identity remain unresolved execution bindings.

## Resolve the PID observation requirement explicitly

The current wording requires effective pids.max=1 before container start. Docker create alone does not expose a running init process or necessarily instantiate its cgroup. Configured HostConfig and daemon support are not a kernel observation. OCI distinguishes creation of the runtime environment from execution of the user program, but adopting direct OCI control would change the current Docker-owned lifecycle and is not the smallest amendment. Primary reference: https://raw.githubusercontent.com/opencontainers/runtime-spec/main/runtime.md .

Proposed minimal prospective amendment: require effective pids.max=1 to be observed BEFORE THE TESTED PROGRAM'S EXEC, rather than before Docker container start. This changes the observation boundary explicitly. Use one independently reviewed, static, single-process exec gate as container entrypoint; bind its source/binary/hash and mount it read-only at /qualification/exec-gate. The gate does not fork, start threads, call a shell, or run a scientific payload. It checks actual UID/GID1000, PID1, private cgroup-v2 mapping and the actual pids.max file in its own cgroup; requires value1 and pids.current1; emits a separate bounded gate receipt; then execve replaces the same PID with the fixed ecbench or owner executable and exact frozen arguments. Gate failure exits before the tested executable. Docker limits, UID, network/rootfs restrictions and one-container ownership remain in force.

Kernel cgroup-v2 documentation says fork/clone cannot exceed pids policy and that counts are tasks/TIDs; administrative migrations can exceed limits. Therefore the gate must bind its actual cgroup and observation instant, and this proposal assumes no concurrent administrative migration or limit mutation. The observation is kernel readback before payload exec, not proof of continuous immutable enforcement. Primary reference: https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html . No fork test or new worker process is proposed.

The gate receipt must be distinguishable from payload output, bound to image/container/case by the supervisor and preserved separately. Positive JSON validation strips only the exact gate record, not arbitrary extra lines. The mount is a new explicit read-only executable input and requires a prospective update to the exact mount inventory. Budget includes gate startup and receipt handling within each existing20-second active case. Q0 byte checks also bind the gate binary. The actual final ecbench/owner bytes and arguments stay unchanged; the entrypoint path changes explicitly. Existing exact-CLI checks remain separately retained.

No gate implementation or compilation is included here. Before execution: approve/review the amended observation boundary, implement and independently review the small no-fork gate, bind runtime cgroup namespace/mount availability and gate bytes, then amend the supervisor. If the original literal pre-container-start observation is mandatory, this option is insufficient and qualification remains pending; a runtime-level prestart hook or lower-level lifecycle would require a separate larger design. Neither configured limits nor after-start opportunistic sampling closes that original requirement.
