# Next construction: retained native session exporter

The existing runner already produces the required native files. `runner::run_session` starts its clock before parsing, validates the diagnostic launch before planning, publishes exact host/plan/preparation, and calls `prepare_lifecycle_child` for each actual execution. Reuse those producers.

`diagnostic_resources::FreshOwnerPins` and `SessionResourceJournal::close_fresh_enclosing_evidence` already validate the fresh observer configuration, real Pod/Job/image/request pins, preparation/journal hashes and enclosing interval. `diagnostic_binding_core::OwnerObservation` is explicitly a comparison value, not authentication. `diagnostic_file_adapter::Request::Actual` consumes host/session/preparation/launch/context and owner-observation file pins; `check_actual_session` recomputes typed context joins.

The next source-only packet should implement a retained-evidence exporter that invokes those existing APIs, derives the comparison owner fields only from checked native evidence, emits exact FilePins and a structural actual-session report, and separately retains the external controller custody receipt and its independently supplied expected identity pins. It must never promote JSON assertions to authenticated provenance. Caller custody admission remains explicit and distinct. No new observer, launch identity, key infrastructure or duplicate adapter is needed.

Prelaunch and postrun are different boundaries. The fresh observer's `observe` launches `ecbench run` and publishes its receipt after reap; consequently the complete actual-session bundle cannot be required before spawning that same session. Before launch, the reviewed protocol and real controller enforce sources, plan, resources, deadline and retry/start boundary. After the native session, the exporter checks the retained files and custody before accepting rows. The observer leaves allocated worker time, exact kernel exit, and accepted external closure null; preserve those unknowns and charge the separate conservative allocation ledger.

Proposed next files under a NEW reserved packet: `PLAN.md`, `retained_export.rs.txt` (Rust adapter draft using current crate APIs), `controls.rs.txt`, exact dependency/source bindings and bounded runner, report and evidence. Prefer an isolated temporary test crate reusing exact native source modules or a narrowly scoped existing-crate test target if dependencies cannot be isolated without semantic copies. Freeze the choice before compilation. Controls: exact fixture success; changed Pod/Job/config/request/image/binary/preparation/session/clock/PID/starttime/context; replay phase rejected; incomplete observer rejected; externally unauthenticated input remains unauthenticated; no invented active-worker or exact-exit fields. An ordinary source fixture is not a native cohort result.
