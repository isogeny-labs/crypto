# Component acceptance boundary

A zero process exit alone is insufficient. For Lean, require the exact published nonempty source hashes, required module inventory in dependency order, native exit zero for every required module, unchanged input bindings, and the exact named axiom readback inventory with only permitted axioms. The new helper fixes process failure propagation and fresh receipt directories; it does not replace this acceptance predicate. The independent gate review tests an empty Readback module to show the distinction.

For saved accounting, the native program is a reporter. Require the separate independent accept.jq predicate: exact seven arm names, exactly1,260 standardized rows and1,260 candidate/rho conservation passes per arm, no issues or unresolved counts, and input hashes matching the published originals. Exit zero with an issue report is not acceptance. Eight malformed-input controls are retained.

For the written divisor argument, require the separate source-fidelity review of smoothness, characteristic, finite local multiplicities, infinity orders and the two principal divisors. Polynomial Lean declarations do not mechanize the geometric carrier.

None of these predicates establishes scientific timing, physical instrumentation completeness, full-cohort execution of a changed algorithm, or campaign authorization.
