# Signed word composition: source derivation and next proof interfaces

The machine-level bridge can be reduced to a finite sign invariant plus existing canonical scalar arithmetic. No new exponentiation proof is necessary for the +/-2 branch: for odd r, inverse(+2)=r/2+1 and inverse(-2)=r/2 in canonical words. This is a written derivation bound to source, not a newly checked Lean theorem or measurement.

1. Exact state predicate. Let GoodWords mean every stored Potential.s is either i8 +1 or -1, every potential a,b is less than r, and every present fixed pair is canonical. Require incoming su,sv in +/-1, incoming a,b<r, prime r>2 and r<=2^63. Forest/index validity and available counter/size headroom are independent state predicates. The desired abstract interpretation maps s through its signed integer value and each u64 coefficient to ZMod r.

2. Base and node insertion. three_leads.rs1543–1545 defines ID=(1,0,0);1559–1570 initializes node0 with this potential and fixed(0,0);1572–1579 inserts another ID and no anchor. Both preserve GoodWords for r>0. Root find returns ID rather than reading an arbitrary stored root potential.

3. Find induction. At1582–1597 recursive find obtains q at the root, then reads the current p. If both signs lie in +/-1, their product lies in +/-1 and is exactly representable by i8. Canonical q.a,q.b remain canonical after signed(p.s,word); add(p.a,signed(...)) and its b analogue are canonical under r<=2^63. The two actual writes preserve GoodWords. This induction follows recursive state, not an assumption that the original pre-recursion p remains unchanged. The reviewed Run theorem's post-recursion read supplies the right composition interface.

4. Union induction. At1658–1671, cu=su*pu.s and cv=sv*pv.s are +/-1. Thus cu+cv is exactly one of -2,0,2; no i8 overflow occurs. At1682, s=-cu*cv is +/-1; -cu and -s are representable, and both orientation branches retain that sign. Signed offsets aa,bb and their reversal remain canonical. At1702–1711, subtracting potential offsets from a canonical child anchor and multiplying by the sign remains canonical; a newly stored parent anchor is canonical. If parent already has an anchor, anchor either constrains two canonical differences or leaves it unchanged. Public edge does not dynamically enforce incoming sign/canonical predicates; the collector supplies them.

5. Same-root scalar bridge. The zero sign-sum branch passes canonical neg(a),neg(b) to constraint. Field zero tests reflect literal zero because canonical words inject into ZMod r. A nonzero coefficient b gives exactly the nonzero/primality premises of WideModPow.generator_decode. For equal signs, cu=cv=+1 or cu=cv=-1; native denominator is respectively2 or r-2. Both denominators are nonzero and canonical for prime r>2. Existing widened modular exponentiation provides canonical inverses. Subsequent Ring.mul calls are widened u128 operations, not the narrow base-field multiplier.

6. Closed inverse expressions. Write odd r=2h+1. Then2(h+1)=r+1, hence h+1 is inverse2 modulo r. Also(-2)h=1-r, hence h is inverse(-2). Both h and h+1 are positive and below r for r>=3; the expressions r/2 and r/2+1 fit u64 without computing potentially overflowing r+1. Existing generator_decode plus uniqueness of field inverse identifies the native generated words with these representatives by canonical_equality. This specializes the already-proved inverse algorithm; it does not propose changing measured runtime or its counters.

Concrete invalid-sign counterexample. Take r=101, one newly allocated root x whose intended value is1, and call edge(x,0,x,1,1,0). The intended equation0*x+1*x=1 is true. Both find potentials are ID, so cu=0,cv=1. Native cu+cv is nonzero and cu!=1, hence it selects denominator99=-2 and inverse50 (99*50=4950=49*101+1). It stores fixed[x]=(50,0), violating intended root value1. The source does not reject sign0. Valid collector sites never produce this sign; the example precisely shows why the sign invariant cannot be dropped. Similarly signed(101,0,5)=96, not the field product0*5.

Other invalid-premise boundaries. For any r>2^63 and canonical a=b=r-1, the exact sum2r-2 exceeds u64; wrapping arithmetic gives2r-2-2^64, differing modulo r from r-2. A checked Rust build can instead trap. This symbolic example does not assert that a particular unverified modulus passed the primality constructor. Noncanonical inputs also defeat the neg bridge: Ring.neg computes(r-a)%r without first reducing a, and signed(+1,a) returns a unchanged.
