# Target-score semantics and a useful zero-score edge

Source commit: 5cd0a45205e0896a5987364ccde900ec0813f477. Native definitions: src/cryptanalysis/three_leads.rs:1619-1717; policy call: src/cryptanalysis/three_leads_followup.rs:347-356. Full unchanged source and its local modules are copied into this packet. This is a source derivation plus five fixed software controls over F7, not a cohort or policy evaluation.

After two finds, an edge has form cu*R + cv*S = a+b*k, with signs cu,cv in {+1,-1}. Each anchored root has form x+y*k. Substituting anchors and combining equal roots gives a residual equation. If every nuisance coefficient vanishes, a nonzero coefficient of k gives a unique target value. If a free root remains with nonzero coefficient, that root can absorb any target value. This conclusion assumes a field of odd characteristic, consistent prior equations, valid signs and an as-yet undetermined target.

For equal roots with opposite signs, the residual target coefficient is b; the score is 3 exactly when b is nonzero. For equal roots with equal signs and an anchor coefficient y, the residual is b-2*cu*y; the score is 3 exactly when this is nonzero. If the root is free, the nonzero nuisance coefficient 2*cu gives an anchor, not an immediate target value (score2 when b is nonzero, otherwise0). For distinct roots, substitute each fixed root; if both are fixed, the nonzero residual target coefficient produces score3. With one or two free roots, the same coefficient instead produces score2 or1. This is a case-by-case paper derivation, not a new Lean theorem or independent fidelity verdict.

Counterexample to discarding score-zero edges: over F7 let u be a fresh graph node. Edge0 is 0+u=0+0*k. Its score is0 and insertion returns None, but it fixes u=0. Edge1 is 0+u=1+k; now its score is3 and insertion returns6. Without edge0, edge1 has score2 and insertion returns None. Both equations are consistent at k=6. Thus immediate target coefficient and future usefulness are different properties. The actual policy inserts every unseen split edge and uses the score for subsequent walk priority; this is not a bug report against a nonexistent score-zero filter.
