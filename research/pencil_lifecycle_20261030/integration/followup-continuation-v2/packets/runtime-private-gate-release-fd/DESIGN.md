# Proposed descriptor-based gate release

Status: design only; T1475. No implementation, proc write, runtime, mount or test execution. Frozen PLAN precedes this design. The v4 Docker archive copy failed with `container rootfs is marked read-only` after Q0 and Q1 host-ancestry checks. This replaces that transport only. Preserve read-only root, pids1, all capability/network/cgroup controls, existing 16MiB /work tmpfs, strict diff, active20s/case and total300s including30s reserve. Root's budget ownership must be refreshed separately before any runtime.

## Interface and exact sequence

Propose `publish_release_fd(endpoint, container_inspect, gate_receipt, expected_ancestry, nonce, deadline, revalidate) -> transport_receipt`. Fixed names only, no caller-chosen path. Revalidation invokes existing pinned-socket live_endpoint and check_host_ancestry; it compares complete container ID, nonce, host PID, start ticks, cgroup path/device/inode. No fallback to Docker cp or a shared endpoint.

1. Require exact held-gate readiness receipt and existing container/source/image joins. The reviewed gate opens /work, checks TMPFS_MAGIC and checks absence of gate-release BEFORE emitting its receipt. Therefore no additional readiness protocol or gate binary change is needed.
2. Open trusted /proc with O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC and require PROC_SUPER_MAGIC on its FD. Open literal decimal expected PID relative to it with the same directory flags. Obtain os.pidfd_open(PID,0); unsupported or denied access fails closed. Through the held proc directory, bounded-read stat and cgroup with NOFOLLOW/NONBLOCK; verify live state, PID/start ticks, exact unified cgroup, then re-read stat. Reject any pidfd poll event before publication. Bracket opening both anchors with identity checks; a held proc FD never retargets to a reused PID, but neither FD keeps the process alive.
3. Open literal `root` relative to held proc PID FD as a directory with CLOEXEC. This is the single intentional magic-link traversal; applying NOFOLLOW to this component would reject the required kernel interface. Open literal `work` relative to that root FD with O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC. Never reconstruct a full path for writes. Verify root FD ST_RDONLY. Verify actual work FD directory, UID/GID0, mode1777, fstatfs TMPFS_MAGIC, writable and nosuid/nodev/noexec flags, total filesystem capacity at most16MiB. Reopen work from the held root FD during final validation and compare device/inode. Missing access is a failure, never permission expansion.
4. Create a nonce-derived single-component staging name `.gate-release-<nonce>.partial` relative to work FD with O_RDWR|O_CREAT|O_EXCL|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC, mode0600. Verify root-owned regular file, nlink1, initially empty. Write exactly37 bytes (canonical36-byte UUID plus newline), bounded short-write loop, fsync, explicit fchmod0444 regardless of UMask0077, fstat and descriptor readback including EOF. Require size37, root UID/GID, mode0444, nlink1 and matching bytes/hash. No special file is opened as a token; exclusive creation rejects every preexisting staging type.
5. Revalidate pinned endpoint, identical container inspection, complete host ancestry, held-proc identity, pidfd non-readiness, root readonly/work tmpfs/custody, gate/case and UTC/monotonic deadlines immediately before publication. Record prepublication receipt to owned host receipt directory. Set publication_attempted before the commit syscall. Publish once with renameat2(workfd, staging, workfd, `gate-release`, RENAME_NOREPLACE). Require supported Linux ABI; errors including EEXIST fail closed. Plain os.rename/os.replace are forbidden because they overwrite. A tiny explicitly typed libc binding for renameat2 and fstatfs is proposed, limited to Linux x86-64 with checked sizes; no compiled helper or new container process is required. Unknown ABI/symbols fail closed.
6. Atomic rename preserves one link and completed metadata. On successful return, record publication_possible=true and the verified prepublication token inode/hash; final token may already have been consumed by gate execution. PID exit after rename is not independently a transport failure: Q1 intentionally exits quickly. Existing case/log/exit/cgroup/diff checks determine case result. No success claim follows solely from publication.

## Failure, race, and cleanup semantics

All prepublication failures close held FDs and may remove only our staging name after matching its device/inode against the held token FD. A final name is never overwritten or deleted as rollback. Mark any interruption or uncertain return after publication_attempted as release_possible/uncertain; retain evidence, do not retry the syscall, mint a new nonce, or repeat the case. Existing exact-container teardown remains responsible for any possibly released process. There is one publication attempt per case.

PID and cgroup observations are not an atomic guarantee that a process remains alive until rename. The held proc/root/work FDs prevent numeric PID reuse from redirecting publication; the trusted source-pinned gate, no extra process (pids1), dropped capabilities and fixed mount tree supply the remaining race boundary. No claim of protection against an unrelated privileged host actor modifying the mount tree is made. The gate receipt binds cgroup identity but not work inode; same-work reasoning uses the verified process view, unchanged trusted gate path and immutable mount controls. This assumption must be explicit in review.

Permission to dereference proc/PID/root is subject to ptrace access rules. The current service's effective ability to do so is untested. No CAP_SYS_PTRACE addition, proc remount, setns, rootfs change, mount or new service capability is part of this design. Failure remains a retained qualification failure.

## Primary documentation read

- [Linux proc filesystem](https://docs.kernel.org/filesystems/proc.html): held proc descriptors do not retarget reused PIDs; they do not prevent process death or reuse.
- [proc_pid_root(5)](https://man7.org/linux/man-pages/man5/proc_pid_root.5.html): kernel root link supplies the process mount view and enforces ptrace access checks.
- [pidfd_open(2)](https://man7.org/linux/man-pages/man2/pidfd_open.2.html): stable task descriptor and exit polling, not a liveness lock.
- [open(2)](https://man7.org/linux/man-pages/man2/open.2.html) and [Python3.9 os APIs](https://docs.python.org/3.9/library/os.html): descriptor-relative opens and explicit close-on-exec/nofollow flags. Python's rename interface does not provide RENAME_NOREPLACE.
- [renameat2(2)](https://man7.org/linux/man-pages/man2/renameat2.2.html): no-replace publication supported by tmpfs since Linux3.17; fail on unsupported flags, never emulate with check-then-rename.
- [statfs(2)](https://man7.org/linux/man-pages/man2/statfs.2.html): check filesystem type on the held FD; statvfs flags alone do not identify tmpfs.

This is a proposed source construction, not an implemented or validated transport. Send to root and independent reviewer before implementation.
