# Independent source review: computation cutoff V2

Reviewed private patch `18ca5367f942bf70441828cba3c7ba0e7f5decdaa8cdc642a5e36a5e0af68719`. Source hashes independently checked: cloud `4af22f9d539a6a3636821f1649278ea13dd02dc1f594471d0d3c1ba66d09baae`, supervisor `ffb089d6f58f16a5e2528d6d2917d758cb552991ac3b814b7b32ab4feefd9645`, deadline `e1a4032fc15a5091f6581672d21f9034ba4d207e1887a06b2e26a63cbec4a560`.

Disposition: do not integrate this version unchanged. Two concrete defects and one namespace-custody gap follow. This is source review, not runtime qualification. No watchdog, build, cloud action or scientific workload was run by the reviewer.

1. **Blocking: wall-clock rollback extends the reserved duration.** `deadline.rs:20` checks only SystemTime. The watchdog repeats that same check, as does subprocess supervision. Rejecting startup before admission does not prevent a later backwards adjustment. Capture one monotonic deadline at admission, share it unchanged across watchdog/actions/children, and retain UTC checks for forward changes. Add fake-time coverage that rolls UTC backwards after admission. Rust explicitly documents SystemTime as non-monotonic: [Rust SystemTime](https://doc.rust-lang.org/std/time/struct.SystemTime.html).

2. **Blocking: ordinary API defaulting rejects the intended computation Pod.** `cloud.rs:586` omits downward `fieldRef.apiVersion`; `computation_owner_matches` compares the whole env array exactly. Kubernetes defaults this selector field to `v1`, so a server-normalized Pod fails comparison against the submitted value. Pin or normalize only this known default; preserve selector paths, binding values, duplicate checks and all other keys. Add an API-shaped fixture with the explicit default. This same defect is present in the earlier fresh-owner Job env and downward-volume comparison and needs a separate correction. The computation manifest disables service-account-token automount, so ordinary service-account volume injection is not the explanation. [Kubernetes defaulting source](https://raw.githubusercontent.com/kubernetes/kubernetes/v1.35.0/pkg/apis/core/v1/defaults.go).

3. **Namespace custody gap:** the matcher rejects host/shared PID namespaces and extra regular containers but ignores initContainers and ephemeralContainers. Ephemeral containers can target a regular container PID namespace. Reject pre-existing extra container classes; separately retain the assumption that another authorized actor cannot inject them later. This is not evidence of a host-wide kill: PID namespace boundaries still apply. The blast radius is the asserted private namespace, which needs explicit custody. [Kubernetes ephemeral container API](https://kubernetes.io/docs/reference/generated/kubernetes-api/v1.35/#ephemeralcontainer-v1-core), [Linux PID namespace semantics](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html).

The subprocess design redirects stdout/stderr to exclusive no-follow files instead of inheritable pipes, uses process-group termination and bounded reap polling, and keeps unknown reap/worker accounting explicit. The PID-1 watchdog performs no evidence I/O before namespace termination, covering synchronous blocking paths in the supervisor subject to scheduler/kernel progress. It is intentionally unexecuted in host fixtures. Ordinary output files can grow beyond the read cap while a child runs; the cap bounds ingestion, not disk allocation. Observed test receipts do not establish actual EKS teardown, measured billing, complete journal closure or scientific execution.

Budget and deadline were not changed. All failures remain recorded; V3 should supersede this review with separately hashed artifacts, preserving V2.
