# N83 runner accounting probe, 2026-10-24

This is a **diagnostic host probe**, not a factor-base measurement or an admission decision. The previous frozen five-base run `40114927017` remains `HOST_STRATA_GATE` with no selected base. The probe tested one temporary `m7i.2xlarge` Spot instance (`i-06a108ace1073fc57`, `us-west-2c`, Ubuntu AMI `ami-08cf17e3856f70154`, four cores/eight hardware threads). Its SSM runner used the same style of transient systemd service as the frozen run. The instance was requested at `2026-10-24T22:13:10Z`; the successful 60-second load ended at `22:28:14.826Z`. It was explicitly terminated after the result was fetched, and [host_final.json](host_final.json) reports `terminated`. Instance-initiated shutdown behavior was separately read as `terminate`; a 45-minute shutdown was also scheduled by user data. The root EBS volume was configured `DeleteOnTermination=true` while the instance ran.

The provider's exact SSM invocation responses are [accounting_probe.json](accounting_probe.json) (command `86f5eaf6-6aa6-43d8-ad52-a299488a8311`) and [load_probe.json](load_probe.json) (command `79f10033-9e8c-4fe1-a90f-1231fadd4139`). The corresponding [accounting SSM parameters](n83-telemetry-probe-ssm-params-v2-20261024.json), [load SSM parameters](n83-telemetry-probe-ssm-params-v3-20261024.json), decoded service payloads ([accounting_probe.sh](accounting_probe.sh) and [load_probe.sh](load_probe.sh)), and [instance user data](n83-telemetry-probe-userdata-20261024.sh) are retained. The SSM wrapper for the first payload ran it twice with `systemd-run --wait --pipe --collect`, always setting `CPUAccounting=yes` and `MemoryAccounting=yes`, and setting `CPUQuota=1600%` only on the second service. The load payload ran with the same accounting settings and `CPUQuota=1600%`. The quota is 16 CPU-equivalents on an eight-vCPU instance; that choice exposes cgroup throttle counters without intentionally restricting this two-process workload. It must still be tested on the exact future runner and representative load.

The first transient service had `cpu.stat` usage fields but no `nr_throttled` field. The quota-enabled service had `cpu.max = 1600000 100000` and `nr_throttled 0`; both had readable `memory.events`. Under two processes for 60 seconds, the quota-enabled service had `nr_periods 601`, `nr_throttled 0`, `throttled_usec 0`, `oom 0`, and `oom_kill 0`; the observed delta of the host `/proc/stat` steal field was zero jiffies. Its SSM result exited successfully. This single window demonstrates counter observability and one clean sampled interval, not a guarantee of zero steal for a future experiment or equivalence of a new quota contract to the frozen one.

Reproduction on a new host should preflight **the actual measured service cgroup**, including counter presence before and after representative sustained work, OOM counters, host steal, cgroup version, CPU topology, and independent same-target controls. Pin a new protocol and run identity before changing runner properties. Do not edit the frozen receipts or impute zero when a metric is absent. The discarded first attempt (`3b76c1ee-6c90-4230-9d49-a3af4e61ffba`) inspected the root cgroup because of nested shell quoting and is excluded from this conclusion.
