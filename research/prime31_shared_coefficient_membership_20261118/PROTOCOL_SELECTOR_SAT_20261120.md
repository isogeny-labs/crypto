# Prime31 selector-SAT and RR9 remainder-tower discriminator

Status: prospective, frozen before candidate solver execution on 2026-11-20.
The only information used to choose this design was prior repository evidence;
no result from the cases below was observed while writing this protocol.

## Question

Can an exact Boolean circuit recover eight unknown signed factor-base choices
from a public Prime31 target with less growth than the generic four-plus-four
meet-in-the-middle frontier?  The candidate is selector SAT: eight public,
slot-specific point tables feed a bit-level elliptic-curve sum circuit.  This
is the best still-untested prime-field lead after the repository's direct
Semaev-SAT and coefficient-bit-blasting results failed to beat enumeration.

A second, separate arm recovers the missing PR #4692 RR9 shared-remainder
tower source and checks its algebraic construction.  That arm encodes
`M_(A,V,R)(X) | H_B(X)^8`.  It is not an equivalent encoding of a weighted
slot relation unless all eight slots have the same x support.

## Exact semantic object

The canonical relation IR contains:

- a short-Weierstrass curve `y^2 = x^3 + a*x + b` over a prime field;
- one public target `Q`;
- eight ordered slots, each an explicit ordered list of affine public points;
- one unknown index and one unknown sign per slot; and
- the assertion that the eight selected signed points sum exactly to `Q`.

The IR has no secret scalar, witness, pair table, half table, precomputed sum,
or target-specific advice.  The candidate backend may precompute only the
listed public points and constants needed by its circuit.

There are two typed lowerings:

1. `selector_cnf`: exact index/sign selection followed by exact field and EC
   arithmetic.  This accepts slot-specific point tables.
2. `shared_rr9`: the frozen cubic remainder tower for one common monic support
   polynomial `H_B`.  This lowering must reject the IR unless every slot has
   the same x-coordinate support.  Rejection is a type check, not an
   experimental failure.

The weighted controls use slot weights `[1,3,5,7,11,13,17,19]`.  Their slot
supports differ, so they are valid selector-CNF inputs and invalid
shared-RR9 inputs.  A future weighted RR9 comparison needs slot-specific
resultants/incidence constraints and is outside this freeze.

## Frozen curve and controls

Prime31 curve:

```
p = 2147483647
a = 847514846
b = 2087444724
n = 2147446831
cofactor = 1
G = (625037715, 2100627251)
```

For base size `B`, take the first `B` liftable nonzero-y x coordinates in
increasing order, choosing the smaller y root.  Slot `j` contains
`+[w_j]P_i` and `-[w_j]P_i` for every base point.  B4 and B8 use the frozen
panel generator from PR #4728: SplitMix64 state
`0x7738423442383231 xor B`, unbiased nonzero scalars, 64 natural public
targets and eight deterministic planted targets.  Frozen expected natural
labels are B4 `0 positive / 64 negative` and B8
`46 positive / 18 negative`; B8 total multiplicity is 115.  The grader's
four-plus-four tables may label and independently replay cases but must never
enter the candidate process or candidate files.

B6 is a preregistered interpolation rung generated by the same rule and seed;
its labels are computed by the isolated grader after this freeze.  It is not
part of the historical 46/18 claim.

Correctness is first checked exhaustively on Mersenne toy fields using the
same IR and circuit family.  At minimum, all selector assignments for one
valid eight-slot `p=31` instance are evaluated against independent affine EC
arithmetic.  Arithmetic unit tests exhaust all canonical input pairs for
`p=31` and sample `p=127`.

## Candidate encoding

Selector bits use `ceil(log2(B))` bits per slot plus one sign bit.  Out-of-range
indices are explicitly forbidden.  Point selection is a deterministic mux
tree over public constants.

Field elements are canonical q-bit words for `p = 2^q-1`; the all-ones word is
forbidden.  Addition uses end-around carry and canonicalizes all ones to zero.
Negation maps zero to zero and otherwise complements the word.  Multiplication
uses AND partial products, a carry-save reduction tree, and Mersenne folding;
the final word is canonicalized.  Every gate has a functional Tseitin
definition.

The EC circuit starts from infinity and performs eight complete selected-point
additions.  Exceptional equality, inverse, doubling, zero-y, and infinity
branches are explicit.  Final projective equality to `Q` is checked without
inversion.  Every SAT model is decoded and replayed with independent affine
arithmetic before it is accepted.

Export both ordinary DIMACS and, where available, a CNF-XOR rendering of the
same functional circuit.  Hash the IR, encoding metadata, DIMACS, binary,
solver, and command line.

## Arms and matrix

Candidate arms, single-threaded and fresh-process:

- CryptoMiniSat on CNF-XOR when the exporter has actual XOR rows;
- CryptoMiniSat on ordinary CNF;
- CaDiCaL on ordinary CNF;
- the repository native CDCL solver on the same ordinary clauses with the
  semantic selector/sign variables given branch priority; and
- the same source-linked native solver on the exact CNF-XOR rendering.

Plain native branching is retained only as an explicitly named diagnostic
control.  It is not an alternative selected after looking at outcomes and is
not used by itself to advance the lead.  This native-XOR arm and the committed
resource/hash runners were added in the pre-execution amendment recorded in
`protocol-selector-sat-v1.json`; zero registered rows had run at amendment.

The RR9/F4 arm is run only on common-support instances and reported in a
separate table.  It must never be shown as a backend for the weighted panel.

Run order:

1. arithmetic and exhaustive toy equivalence tests;
2. one planted positive and one labelled negative at B4, B6, and B8 for each
   installed solver;
3. all 64 B8 natural controls plus eight planted controls only for arms that
   pass step 2 without wrong answers;
4. held-out B12 and B16 cases only if all B8 controls complete and the work
   growth gate below passes;
5. B31 and complete rank-31/1,024-target integration only if B12/B16 also pass.

No B12/B16/B31 case may be used to revise the encoding or solver choice.

## Measurements and accounting

For every attempt record status, exit code, timeout/OOM, wall and CPU time,
peak RSS, Boolean variables, ordinary clauses, XOR rows, AND/XOR/mux/arithmetic
gate counts, solver decisions, conflicts, propagations, restarts, witness
decode time, replay result, and all forbidden counters.  Missing solver
counters are null, not zero.

The generic comparison frontier is `(2B)^4` four-slot words per half:
B4 4,096; B6 20,736; B8 65,536.  Report it as a group-enumeration control,
not as SAT work.  Compare slopes and ratios under multiple transparent SAT
work measures; do not convert clauses or conflicts into group additions.

Forbidden counters, all required to be zero in the candidate:

- secret scalars consumed;
- supplied witness indices or signs consumed;
- pair-table entries consumed;
- half-table entries consumed;
- enumerated complete selector assignments;
- grader records consumed after public target extraction.

## Decisions, stopping, and interpretation

A wrong decoded answer, missed planted positive after a solver reports UNSAT,
IR/lowering mismatch on an admitted input, arithmetic disagreement, or failed
independent replay is a candidate implementation failure.  It does not refute
the mathematical existence of a better SAT encoding.

A timeout, OOM, solver `UNKNOWN`, unchecked UNSAT, unavailable solver, or
incomplete panel is inconclusive for satisfiability and is retained in the
cost record.  No failed row is silently excluded or retried except one clearly
identified infrastructure failure before the solver reads the instance.

The selector-SAT lead advances beyond B8 only if:

- every frozen B8 label agrees and every accepted witness replays;
- all forbidden counters are zero;
- every planned B8 row completes inside the frozen cap; and
- the upper observed growth in a solver-native work measure is below the
  generic `B^4` half-table frontier, outside same-binary A/A noise where wall
  time is discussed.

If completed B4/B6/B8 work grows at least as fast as `B^4`, or already exceeds
the generic half-table work by a decisive margin at B8, mark this encoding
`not advanced`.  This is a scoped engineering rejection, not an asymptotic
lower bound on SAT or index calculus.

Initial caps are 900 seconds and 16 GiB per solver/case.  Smoke rows may use a
shorter explicitly recorded cap.  Stop an arm after two consecutive rung
timeouts or one OOM.  Do not start B31 unless every prior gate passes.

The committed launchers enforce the checkpoint gate first, reject any relation
that differs from the deterministic B4/B6/B8 panel, refuse artifact overwrite,
apply the wall and virtual-memory caps, bind release-binary and command hashes,
and independently replay every SAT witness.  They intentionally reject B12,
B16, and B31 until a later committed gate decision enables those holdouts.
