# Complete generalized GHS profile screen at N=15

For the binary curve `icv1-f2m15-t131-ed7256f0`, a complete search of the
32,767 nonzero Hess parameters over `GF(2^15)/GF(2^5)` finds **1,922
descendable genus-6 profiles and 30,721 descendable genus-7 profiles**. It
also finds 62 descendable genus-4 profiles. All 62 genus-5 arithmetic
profiles fail the generalized descent predicate. This adds concrete
genus-6 and genus-7 structural candidates to the [genus 2–8 criteria
audit](../weak_curve_criteria_20261114/REPORT.md); its transfer table did
not yet enumerate those genera.

The curve has binary polynomial modulus `0x8003` and coefficients `a=0x1`,
`b=0x524b`. Its registry-selected subgroup has recorded order `16319`.
This screen does not construct the smooth cover or a selected-subgroup map.
These are parameter profiles, not a vulnerability verdict.

| Genus | Descent predicate | Hyperelliptic sufficient flag | Parameters | First `c` |
| ---: | --- | --- | ---: | --- |
| 4 | true | true | 62 | `0x1` |
| 5 | false | false | 62 | `0x5f4` |
| 6 | true | false | 1,922 | `0x2` |
| 7 | true | false | 30,721 | `0x3` |

The last flag is only the native screener's sufficient test (`c` or `d`
fixed by relative Frobenius). A false value does not prove that a resulting
curve is nonhyperelliptic. The genus-5 count describes arithmetic profiles;
the missing descent condition prevents these parameters from entering the
descendable candidate set.

There is a structural reason for that genus-5 exclusion in the degree-3
tower. Within `1 <= s1,s2 <= t <= 3`, the genus formula equals 5 only for
`(t,s1,s2)=(3,2,2)`. Every one of the 62 genus-5 profiles has
`f1=f2=T²+T+1` (`0x7`), so the order-polynomial relation is the
degree-3 relative-trace sum. Both traces vanish, which makes the descent
predicate false. The replay asserts the `0x7` condition for all 62 rows;
the Lean module proves the degree pattern and the order-polynomial-to-trace
implication.

## Criterion and exact replay

For each nonzero `c` in the declared field, put `beta = sqrt(b)` and
`d = beta/c`. Let `f1` and `f2` be the first linear-dependence polynomials of
`c` and `d` under relative Frobenius `x -> x^(2^5)`. With `s_i = deg(f_i)`
and `t = deg(lcm(f1,f2,T+1))` for this curve's nonzero absolute trace of
`a`, the generalized Hess arithmetic genus is

`g = 2^t + 1 - 2^(t-s1) - 2^(t-s2)`.

The descent predicate is `Tr_(15/5)(c) != 0` or
`Tr_(15/5)(d) != 0`. The independent [Python replay](replay.py) implements
field multiplication, polynomial inversion, relative Frobenius, first
linear dependence, polynomial LCM, trace and genus separately from the
native Rust [generalized screener](../../src/cryptanalysis/ghs_generalized.rs).
It first checks the degree-15 modulus with Rabin's irreducibility test,
then enumerates every `c=1,...,0x7fff` and compares every returned native
candidate field by field. It also checks that the native list is complete,
untruncated, and has no other under-bound base-degree branch.

The first genus-6 witness has `c=0x2`, `d=0x49f6`,
`(f1,f2)=(0x7,0x9)` and `(s1,s2,t)=(2,3,3)`. The first genus-7
witness has `c=0x3`, `d=0xea5`, `(f1,f2)=(0x9,0x9)` and
`(s1,s2,t)=(3,3,3)`. The first genus-5 profile has `c=0x5f4`,
`(f1,f2)=(0x7,0x7)` and `(s1,s2,t)=(2,2,3)`, but its trace
predicate is false. All counts and first witnesses are frozen in
[`summary.json`](summary.json). The complete native JSON stream has SHA-256
`823309aabfce18ccbf23e323628ceb587a9c48cc9a7cb728f5bc1a325714132c`;
it is regenerated by the command below rather than stored in Git.

From the repository root, using the pinned Rust toolchain accepted by this
checkout:

```sh
cargo run --release --bin ghs_generalized -- \
  --degree 15 --modulus 0x8003 --a 0x1 --b 0x524b \
  --c-limit 32767 --genus-limit 8 --max-candidates 32767 \
  > /tmp/ghs-n15-native.json
python3 research/ghs_genus6_7_profile_20261114/replay.py \
  --check --native-json /tmp/ghs-n15-native.json
cd research/ghs_genus6_7_profile_20261114
lean GenusArithmetic.lean
```

The measured native run used rustc 1.99.1 on macOS; Cargo release
compilation completed with an optional `rust-objcopy` strip warning about a
missing `libLLVM.dylib`, and the binary executed successfully. The
independent Python replay matched all native candidate fields. The exact
`--check` output is `GHS_N15_PROFILE_REPLAY_PASS 32767`.

## Lean proof map and next construction

The pinned Lean 4 module [GenusArithmetic.lean](GenusArithmetic.lean) proves
the four specific genus-formula evaluations, including the genus-6 and
genus-7 witness degree triples. It also proves that genus five forces the
degree pattern above in a relative-degree-three tower, and that two
`1+T+T²` order relations make the descent predicate false for the two
elements. `lean GenusArithmetic.lean` succeeded under Lean 4.34.1.
`#print axioms` reported no axioms for the arithmetic theorems and only
Lean's `propext` and `Quot.sound` for the trace theorems. Field operations,
the assertion that the enumerated elements satisfy their reported
Frobenius-order relations, finite enumeration, smooth-cover construction,
and subgroup transport remain outside this Lean module. The full geometric
theorem remains open.

The next experiment should construct and independently check the smooth
genus-6 cover for `c=0x2` and the genus-7 cover for `c=0x3`, then exhibit
and verify the maps carrying the selected generator and target. Only after
those maps are available can a destination relation method be measured
against a same-target reference. The genus-4 route remains the smaller
candidate for this curve, so the higher-genus rows expand classification
coverage rather than superseding its cost case.

The structural formulas follow the existing [generalized GHS implementation](../../src/cryptanalysis/ghs_generalized.rs)
and the [Maurer–Menezes–Teske analysis](https://www.cambridge.org/core/services/aop-cambridge-core/content/view/D4B264D082FF67354EE9968D9803102A/S1461157000000723a.pdf/analysis_of_the_ghs_weil_descent_attack_on_the_ecdlp_over_characteristic_two_finite_fields_of_composite_degree.pdf).
