## 6. False-positive verification cost

baseline Bloom K3596: 8589934592 bits; k=3; FPR inserting all roots (n=entries): 0.0305; one key per state (n=states): 0.0050
- Bloom k=3 (n=entries)    FPR 0.03055 -> 1471 false positives per target; upper bound if each costs a full probe (0.555 us): 0.816 ms = 3.14% of 25.95 ms online
- Bloom k=3 (n=states)     FPR 0.00499 -> 240 false positives per target; upper bound if each costs a full probe (0.555 us): 0.133 ms = 0.51% of 25.95 ms online
- xor8 (2^-8)              FPR 0.00391 -> 188 false positives per target; upper bound if each costs a full probe (0.555 us): 0.104 ms = 0.40% of 25.95 ms online
- fp r=8 in ribbon (2^-8)  FPR 0.00391 -> 188 false positives per target; upper bound if each costs a full probe (0.555 us): 0.104 ms = 0.40% of 25.95 ms online
- fp r=12                  FPR 0.00024 -> 12 false positives per target; upper bound if each costs a full probe (0.555 us): 0.007 ms = 0.03% of 25.95 ms online
- with NO prefilter and no fingerprint (retrieval value only): every probe verifies: 48160 state reads/target
  at 0.1 us per DRAM-missing state read (assumed) = 4.82 ms = 18.6% of anchor online; at the anchor probe cost it is the whole online cost

## 8. Which lever is this

Counted S (group operations): a larger K needs 166K usable base points (more group operations to generate),
so this lever does not reduce counted GAE at w=0; it moves only memory and native lookups (w>0). [pcc:unverified]
