## Instance, output and cost

Use ordinary elliptic curves E/F_p, p prime, a prime subgroup of order r and a
fixed or bounded cofactor. Size is b = log2(r); record field bits separately.
Extension degree is one. Specify the family rule, its density, applicable
structure and weakness checks before drawing instances. Do not import an
extension-field descent exponent into this prime-field path.

Freeze the output requirement K(r). For the native one-shot APS path, the
primary endpoint is one valid informative relation (K = 1), including its
nonzero recovery denominator. A classical multi-relation IC arm must instead
declare its required relation count/rank progress. Comparisons use the same
endpoint; a different K is a different experiment.

Define C_rel(r) as cold charged cost from supplied (E,P,Q) to that endpoint.
Charge factor-base generation, labels, partition construction, equations,
supports and joins, quotient reduction, cache training/replay/certification/
rebuild, every failed draw/attempt, witness checks and deduplication. Charge
reusable setup fully to one target. Record memory and retained data per phase.
Report recovery, linear algebra and independent scalar verification separately,
and include them in C_total for any end-to-end claim.

Price every operation family in group-addition equivalents across the owner's
0, 0.1 and 1 band, plus applicable calibration. Retain literal operation counts
and closed wall-clock intervals, including conversion/setup boundaries. An
unpriced total stays unknown. Fewer F4 certification multiplications alone is
not a lower C_rel. Do not normalize away discarded tuples, failed targets,
unproductive relations or construction work.

This contract concerns direct relation collection. Any later transfer arm
needs a separately frozen boundary and the owner's transfer rules; it cannot
silently use a different charging interval.

## Planning model to derive and test

The following is a hypothesis scaffold, not a complexity theorem:

- Factor-base size M(r) grows like r^beta.
- Cold setup grows like r^s and per-attempt cost like r^tau.
- A candidate random-sum approximation is
  pi_informative = coverage * useful_probability * min(1, c_m M(r)^m/r).
- If coverage grows like r^-chi and useful_probability like r^-gamma, and
  attempts regenerate with that success law, then the model predicts
  C_rel = C_setup + T_attempt/pi_informative and
  alpha_rel = max(s, tau + max(0, 1-m beta) + chi + gamma).

These assumptions require explicit derivation and numeric tests. In particular,
conditional coverage and usefulness can be correlated; repeated attempts and
cache reuse need their actual stochastic law, not an independence assertion.
Freeze fixed m for this model. If m grows with b, include m-dependent constants,
partition losses, Semaev degrees and construction costs in the growth analysis.

The first research milestone is to derive the correct model for the implemented
collector and identify which charged exponent a proposed mechanism changes.
A fixed number of equal partitions may change a coverage constant without
changing an exponent. A sparse or auxiliary equation does not make its
construction free. Exact pair support that already enumerates a quadratic join
must stay in the model. A vanishing polynomial on an arbitrary finite set has
degree at least the number of distinct roots; sparsity alone does not remove
that obstacle.

Assess each mechanism by its proposed change to setup exponent, attempt
exponent and informative yield. Keep direct joins/evaluation as baselines when
they already enumerate the desired solutions. Improved sign-safe coverage is
not automatically improved informative relation yield. [pcc:unverified]

## Acceptance contract

This stage-scoped contract borrows the owner's T2 evidence strength without
claiming T2 below rho. Freeze all numerical choices before scaling observations. [pcc:unverified]

1. Register family, parameter laws M(r) and m(r), K(r), all variants/attempts,
   public beacon-derived targets, baseline set, operation prices, memory limits,
   seeds, budgets, target counts, abandonment rules and positive margin delta.
   Compare with the strongest registered applicable collection baseline at
   each price. Include Expanded4/Split4, direct joins/evaluation and relevant
   external solvers where applicable; justify any exclusion.
2. Use at least six sizes spanning at least 24 subgroup bits, with smallest
   b >= 32, all within one bounds tier. Exact curves remain to be registered.
   Use at least 32 targets per size below b = 64 and at least 8 above, with
   advance power analysis. Existing four-size/disjoint-pilot prerequisites
   still apply; this exponent panel extends them and creates no pilot exception.
3. Fit log C_rel = a + alpha log r, with the repository native bound tools,
   for the aggregate and every phase, at every price. Report also the field-size
   fit. Each phase needs enough sizes for an interval (owner minimum four).
   Examine polylog/finite-size alternatives and projected phase crossovers.
   Preregister a paired candidate-baseline exponent contrast; its multiplicity-
   corrected 95% upper limit must be below -delta. Conservatively check the
   largest phase upper limit against the baseline exponent too. Do not accept
   a total slope that hides a steeper growing phase.
4. Freeze a held-out prediction before drawing its instance from a later
   beacon. Choose at least 8 bits above the largest fit size and beyond relevant
   projected phase crossovers, following the owner's below-b128 crossover rule.
   The unwidened prediction interval must distinguish the reduced-exponent
   model from an unchanged-exponent competitor refitted to the same data.
   If no feasible size distinguishes them, the exponent conclusion is unresolved.
5. Retain failures, timeouts, OOMs, restarts and every launched target. Charge
   consumed work and report success probability. A censored run is not a
   completed cost-to-success sample; unresolved upper bounds block success.
   Apply family-wise 0.05 correction over all registered attempts.
6. Require independent replay/recomputation, cross-host audit and signed native
   standing for a validated result. Separate an empirical finite-range slope,
   conditional heuristic complexity and an asymptotic theorem. Finite fits
   cannot prove an asymptotic exponent reduction. [pcc:unverified]

A lower collection exponent can satisfy this goal at relation scope without
establishing a lower full-solve exponent. Claims below matched rho use the full
cold C_total and all T1/T2 requirements in the owner criteria. For general
prime-field sub-1/2 claims, the additional T3 named-heuristic analysis/tests
required by T2 also apply. Subexponential claims require an argument, not a
finite fit. Generic-decomposition lower-bound checks remain applicable.

## Execution dependencies and first action

First action: specify the size-dependent cost/yield law for the native
collector and instrument every missing charged phase. Freeze the mechanism and
baseline before choosing a favorable size range.

Before any performance run, complete canonical accounting, metric/full-set
replay/export, exact registered curves, frozen disjoint pilot/held-out protocol,
native analysis/power/budgets and admission, plus a successful prospective
checkpoint of that exact source/protocol. The old source checkpoint is not a
checkpoint of this future experiment; independent readback remains open.
Canonical protocol/schema bodies were unreadable through available access.
Do not invent a conforming export or bypass the prerequisite.

This /goal pins work; it does not authorize a benchmark launch or spending.
Native-ledger publication/reconciliation and previous private-publication
restrictions remain unchanged. Keep auto-merge off. This scoped definition does
not publish the shared daily log, ledger, raw build logs or private history.
