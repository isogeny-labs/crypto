# R49 construction worklist

1. Finish the two already admitted chart computations under their original
   1200 s /4 GiB limits. Keep every terminal exit and partial file. A failed
   minimal-prime stage supplies no normalization result. Do not replay it
   merely to resume publication.
2. If either producer succeeds, assemble that chart's independent verifier
   from its exact exported files, freeze the assembly and run it under the
   same limit. The compact chart requires b+c=u*c² with c inverted; the plane
   chart uses its actual fourth coordinate u. Never substitute one verifier
   for the other. Prime equality, source identities, corrupted-map rejection,
   full norTest and exact generic dimension32 are separate required checks.
3. If full affine decomposition is incomplete, a genuinely different next
   calculation is minimal-prime decomposition of the zero-dimensional
   generic algebra over F2(u). A unique prime there would identify the source
   function field, but not its affine contraction or normalization. Then
   derive and verify a finite denominator/saturation certificate for the
   contraction. Generic primeness and selected smooth points cannot certify
   the original polynomial ideal as prime. Freeze each affected stage first;
   no increased budget or automatic full-decomposition retry.
4. Actual normalization still leaves exceptional branches and other affine
   charts. Recover all zero/pole divisors of b,c,lambda,nu and the eight
   registered denominators on the proper curve, then construct complete
   prescribed RR spaces. A chosen level77 factor map must satisfy exact
   function-field identities, descent, and nonzero order11 action.
5. Keep the other unresolved lanes explicit: full integral four-map/Hom
   recovery (not fixed-denominator arithmetic alone), node187 simultaneous
   divisors/descent or exact saturation separator, arbitrary reverse principal
   rows with exceptional fibers, full quotient saturation and polarized
   embeddings, theta descent, and genuine larger-n geometric transfers.
   R48's degree13 class remained in the old tested character span; no new
   target rank or IC speed follows from the current chart work.

This is a prospective worklist, not an assertion that an unexecuted stage
passed or that the global geometry is complete.

If presentation identity evaluation reaches a wall cap, the next distinct implementation should log each stage and evaluate source maps inside the exact target quotient ring, avoiding a large ambient substitution followed by a single reduction. This is suggested by normal.lib norTest, which constructs source/target qrings before its map checks. It is a prospective implementation lead, not a measured speedup or a claim about which unlogged step consumed an existing run. Preserve existing capped attempts and do not retroactively change their interpretation.

A further prospective direct-lambda variant can retain v=A/B and n=Nnum/B as rational expressions. It must certify B nonzero in the actual degree32 field, check every forward equation after explicit denominator clearing, and check reverse identities by cross multiplication. This can avoid constructing a large polynomial inverse before the map exists. Installed zeroset.lib/control.lib also use native extgcd for polynomial Bezout identities. Neither variant is executed or claimed faster here; it needs a frozen source, controls, stage markers and original limits before data.
