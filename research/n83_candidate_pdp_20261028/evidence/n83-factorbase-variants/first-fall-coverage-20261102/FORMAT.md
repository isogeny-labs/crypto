# Fixed-base first-fall coverage format

`coverage.json` is an aggregate index of existing frozen V2 first-fall records plus the linked inventory of unlabelled inputs. It does not contain or regenerate case outputs. Each source summary and the `spike29` source-binding audit are identified by repository path, byte length, and SHA-256. The audit binds 48 source hashes to the frozen V2 arms and saved top-form replay, but adds zero first-fall or affine-Dreg labels. The spike35–spike37 raw case archive is referenced by its S3 key, size, digest, and readback flag from the existing custody record. That archive contains report/source and per-case input JSON, but excludes the large source system payloads; the custody record identifies those separately. The six earlier 48-row candidate summaries keep their own evidence directories and persistence indexes.

The `coverage` object compares the protocol's 624 planned systems (13 coordinates × 48 systems) with candidate groups that have saved first-fall summaries. `candidate_groups` keeps per-coordinate counts, replay status, producer status, and FFD outcomes. `coverage.source_availability` gives a metadata-only inventory for the four uncovered candidate groups: it records r29's existing 48 `.sing` systems and replayed top-form source, r38/r39's complete-base top-form preflights and failed terminal states, and the missing r34 base. These are source and attempt states, never substitute first-fall/LFD/affine-Dreg outcomes. `first_fall_outcomes` summarizes saved rows by family. `last_fall_degree.exact_rows` is deliberately separate: a first-fall certificate or a null LFD value does not prove an LFD bound. `last_fall_degree.related_restricted_propagation_panel` links the separate 12-case m3 V4-consequence propagation result; its inherited strict lower bound is retained, while the absence of a unit or exhaustive affine certificate leaves the global upper bound unknown. The `degree_of_regularity` object is separate again; highest-form proxies are not affine PDP regularity labels. `source_files` identifies every input summary, terminal record, and custody file by path, byte length, and SHA-256. For the r29 large system files, the index hashes the small `manifest.sha256` file rather than rereading every system; the existing top-form fresh replay is recorded separately.

Regenerate or validate from the preserved source summaries with:

```sh
python3 research/n83_candidate_pdp_20261028/evidence/n83-factorbase-variants/first-fall-coverage-20261102/build_coverage.py
python3 research/n83_candidate_pdp_20261028/evidence/n83-factorbase-variants/first-fall-coverage-20261102/build_coverage.py --check
```
