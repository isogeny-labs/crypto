# Source-bound terminal functional checker

Development contract, 2026-10-30, before checker controls. The target is the
unchanged42prime m3–9 input/source/base identities from the terminal and
native Lefschetz datasets. The wider three-family m2–9 objective remains open.

Implement a separate Rust instrument. It must check the exact42key set,
input and source hashes, regenerate the complete source using the existing
source donor, and compare the embedded input/source records in the retained
terminal certificate. Pin and verify that certificate's hash. For A0,A1,A2,
check file names, lengths, hashes, canonical polynomial encoding, degrees
and term counts, then recompute H,NF(HX),NF(HX²) and compare all coefficients.
Verify the saved three U-polynomial factors against the exact S3 formula.
Bind the prior conditional top certificate by hash and exact input/source/base
identity, retaining its conditional status. Check the actual executing
binary and all staged source files against the frozen production protocol.

Only after these checks compute the direct complement pairing of H with
C=A2-2tA1+t²H, compare it with (-2)^13*(sumweights-2t), and emit the exact
coefficient polynomial with its hash. This is a source-bound arithmetic
record, not a computation of V16. LFD and regularity fields stay null;
the conditional filtered implication is prose pending independent review.
Zero pairing remains inconclusive, as the direct small-closure controls show.

Native controls use a synthetic natural-target source template, explicitly
not a saved production case. Require rejection of changed input/source/base,
changed certificate or top binding, factor corruption, wrong affine circuit,
missing/duplicate case keys, and changed factor metadata. Preserve the
fixture, certificate and factor identities and all test logs. Use fresh output
directories and native S3 replay. No actual42case arithmetic panel before a
new frozen protocol and backend admission.
