# Joint translation domains and exact frontier enumeration

Supported component: c(z+t*1)=c(z)+kappa*t over the entire finite field, with a separately certified slope, plus arbitrary original predicates. The output is every ordered tuple in D^n satisfying c=0 and those predicates, without duplicates. These are translation-line components, not a proof that every original index-calculus system has this form. Source identities, constraints and domain maps must be proved before integration.

Prime case: D=[0,M], p>2M. If two tuples in D^n differ by a common field translation, each integer coordinate difference lies in[-M,M]. Their congruence modulo p makes them the same integer difference, because their pairwise difference has magnitude<=2M<p. Thus their ordinary minimum-normalized tuple u is identical. Conversely equal normalized tuples differ by a common translation. The unique u has min(u)=0, coordinates in[0,M]; anchor k is its first zero. Coordinates before k lie in[1,M], after k in[0,M], so the disjoint charts contain sum_k M^k(M+1)^(n-1-k)=(M+1)^n-M^n representatives. Every original tuple is uniquely theta=u+b*1 with 0<=b<=M-max(u). If kappa!=0, b=-c(u)/kappa modulo p is the only possible root and is checked against this integer range and all original predicates. If kappa=0, every b is retained exactly when c(u)=0, then tested; this may be output-size expensive and cannot be discarded. Output/candidate admission failures return incomplete with null roots/count. Work is O(n*N) plus correction/predicate costs and unavoidable zero-slope output, where N=(M+1)^n-M^n; live enumeration state is O(n), with O(n*output) stored tuples and sorted output.

Unsafe wrap counterexample: p5,M3,n2,u=(0,3),u'=(2,0). They are distinct first-zero anchors but differ by translation3 modulo5. With c=sum(z)-3,kappa2,b=0 and3 both reconstruct (0,3). The implementation refuses p<=2M rather than claiming a unique chart. This branch needs another quotient scheme; it is not a claim about all scales.

Extension/subspace case: D is an explicitly admitted additive subgroup. The unique gauge x=theta-theta0*1 has x0=0 and remaining coordinates in D; it has |D|^(n-1) representatives. For a nonzero slope the unique b=-c(x)/kappa must lie in D; for zero slope retain every b in D exactly if c(x)=0. Reconstruction and all original predicates prove soundness and completeness. This includes binary and odd extension subspaces. The bounded implementation independently verifies additive closure with O(|D|^2) work and refuses larger admission. Proper prime intervals are not treated as subspaces.

Review: empty output differs from refusal; n1,M0,zero slope,repeated coordinates,full additive groups and coupled nonlinear predicates are explicit controls. The independent oracle enumerates every original tuple. The prior C141 projected product is compared on the same 20 frozen development components; its tuple results must agree before timing. Three alternating repetitions include local domain construction, solving, tuple verification and JSON output serialization. Field/input setup is outside these component intervals, repetitions are not isolated process-cold release repetitions, and this is not a genuine F4/F5/F6 comparison. A geomean<1.25 or any worst slowdown>1.10 refutes this development performance target, not mathematical correctness. Keep all cases, including regressions. Budget:90s,4GiB,CPU0; max8192charts/output. The larger cap replaces the prior unexecuted4096spec to admit n5,M4's6561projected baseline product; frozen version identities differ and no failed execution is retried.

Novelty unestablished: subtraction gauges, translation orbits, first-zero partition and Gaussian quotients are standard constructions. The possible contribution is a proved, costed original-domain frontend coupled to finite-field correction equations; complete hard algorithm novelty and the matching gate remain open. Distinct correction slopes and domain geometries motivate characteristic-specific frontends rather than a universal representation.
