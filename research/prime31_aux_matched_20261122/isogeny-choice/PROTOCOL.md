# Prime31 isogeny choices: bounded comparison protocol

**Status: draft, unadmitted. Planned 230 comparison cells; attempted 0; completed 0.**

This extension belongs to [PR #4923](https://github.com/isogeny-labs/crypto/pull/4923). It does not replace the parent study's historical protocol or execution status. Development builds, fixed correctness contracts, independent replay tests and panel generation are separate from experiments. The canonical experiment schema/freeze, publication and image identity, live access, checkpoint and budget receipts, and an original absolute deadline remain admission requirements. No experiment is authorized by merely creating this file or a panel.

## Questions

1. At degree 1024, do the three rational kernels on `Aminus` produce different relation-finding and full-recovery outcomes on the fixed ordinary target?
2. On exactly the same fiber and target, what changes when ten quadratic membership maps are grouped into five quartic constraints, or expanded into one dense degree-1024 constraint?
3. Does the target's degree-three isogeny change observed costs with a transported factor base, or with a newly lifted native factor base on the destination curve?
4. How do the complete costs compare with a plain factor base of exactly the same number of usable columns and with the three pinned negation-aware rho implementations?

No fastest algorithm is assumed. The registered solver uses the current pinned F4 implementation with `domain_roots = auto` and `sibling_batch = true` in every IC cell. Those are explicit implementation settings, not a claim that their policy is optimal. The source manifest and upstream hashes identify the exact implementation. Any later settings search needs a prospective amendment and its own charged work.

## Fixed public problem

All original-curve cells use:

| Item | Value |
|---|---|
| Field | `p = 2147483647 = 2^31 - 1` |
| Curve E | `y^2 = x^3 + 847514846 x + 2087444724` |
| Prime order n | `2147446831` |
| Generator G | `(625037715, 2100627251)` |
| Public target Q | `(984837385, 1142774582)` |
| Relation arity | `m = 3` |
| Natural-query seed | `4188` |
| Rho seed | `4188` |

The collector receives public curve parameters, `G`, `Q` and `n`. It receives no target scalar. Its natural queries are `[alpha]G + [beta]Q`, with the same deterministic scalar stream in paired cells. Complete recovery is accepted only if the extracted scalar independently reproduces the original public point. Destination-curve recoveries must replay on both curves.

The fixed degree-three map has

```text
alpha = 533591203
t     = 963718081
u     = 1037789400
r(x)  = x + t/(x-alpha) + u/(x-alpha)^2
psi(x,y) = (r(x), y*r'(x))
E1: y^2 = x^3 + 323891735 x + 1985248359
psi(G) = (1767020261,634125456)
```

The map preserves the prime-order scalar. Nonidentity geometric kernel points are not `F_p`-rational; a rationally defined isogeny does not require a pointwise rational kernel. The implementation checks the numerical map and the input/output group conditions; this fact alone is not a solving-cost gain.

## Auxiliary choices and whole-fiber contract

Every choice has geometric degree 1024. The panel uses the single fixed coset scalar **1**. There is no multi-coset census or seed optimization in this panel.

| Choice | Auxiliary curve and source point | Kernel |
|---|---|---|
| `aplus_cyclic` | `y^2=x^3+x`, `S=(3,615668188)` of order `2^31` | `<[2^21]S>` |
| `aminus_h0` | `y^2=x^3-x`, `S=(4,639874715)` of order `2^30` | `<K>`, `K=[2^20]S` |
| `aminus_h1` | Same `Aminus,S` | `<K+U>`, `U=(0,0)` |
| `aminus_h2` | Same `Aminus,S` | `<2K,U>`, of type `C512 x C2` |

The three `Aminus` maps share their first nine degree-two quotients, with kernel `<2K>`. The final order-two line differs. H2 is generated by two independent generators; it is never silently treated as cyclic. The fixed source cosets each have 1024 distinct x coordinates and a non-two-torsion terminal image. The implementation retains the **entire** fiber `V`, including values that do not lift to the target. It does not truncate fibers to manufacture equal sizes.

Cold construction checks the source point's exact order and Hasse interval, kernel inventory, every kernel and coset point, the full-kernel Vélu codomain, and the coefficient identity `N - chi*D = product(x-v)`. It checks that every finite kernel x is a genuine pole (`D=0`, `N!=0`) and that no fiber root is a pole. These checks and their cost are part of setup.

The focused correctness fixtures give the following usable column counts for the one fixed coset. These are arithmetic fixtures, not relation-yield or performance measurements:

| Kernel | Original E | Native E1 | Transported E1 |
|---|---:|---:|---:|
| Aplus cyclic | 518 | 506 | 518 |
| Aminus H0 | 508 | 508 | 508 |
| Aminus H1 | 512 | 519 | 512 |
| Aminus H2 | 515 | 533 | 515 |

Each column has a canonical point and its opposite sign; the two signed points are not separate logarithm unknowns. The three `Aminus` kernel sets and their fixed coset x sets intersect pairwise in 512 elements, so these arms are related inputs, not independent samples.

The sparse H2 doubling-derived quartic factorization is a possible later representation. It is not an additional arm in this panel.

## Target-side arms

| Arm | Membership values and points | Presentations |
|---|---|---|
| `original` | Whole auxiliary `V`, lifted on E | Dense, quadratic tower, quartic blocks |
| `isogenous_native` | Same whole `V`, freshly lifted on E1 | Dense, quadratic tower, quartic blocks |
| `isogenous_transported` | Complete finite image `r(V)`; poles and collisions recorded; point columns transported through psi | Dense only |

The transported arm records the signed permutation between source and destination point columns. Independent replay must verify this permutation and preservation of the paired natural queries and signed relation rows. The transported membership polynomial is reconstructed from the complete finite image; it is not mislabeled as the unchanged auxiliary tower. The native destination factor base can have different cardinality and relations.

## Matched plain controls

For **every kernel and target arm**, build its reference fiber and prepared target base first. Emit `choice_kernel` and `choice_prepared`. Then call the existing production `bases::build_plain_control` on that exact target curve/order with:

```text
columns = reference factor base's actual usable column count
seed = 1
maximum coordinate trials = 1000000
presentation = Dense
```

Emit `choice_plain` with the complete independently certifiable `BaseDefinition`, actual seed, trial cap, reference column count, reference-setup time, plain-setup time and indexing work. The selected collector receives the plain factor base, its `v`, and no tower. It must not begin from the reference base while the plain record is absent.

The overall cold interval includes reference matching, even for a plain control. Reference matching overhead is exposed separately rather than silently removed. A later amortized model may state explicitly which reused setup it excludes; it cannot replace the cold comparison. Some plain configurations repeat when references have the same curve and column count. Such repetitions remain visible and are not independent trials.

## Registered panel and execution order

Per round:

| Cell family | Count |
|---|---:|
| Four kernels x original E x three presentations | 12 |
| Four kernels x native E1 x three presentations | 12 |

Five rounds yield **230 cells: 140 auxiliary IC, 60 plain IC and 30 rho**. All rounds repeat the same target, coset and seeds. They are timing replicates of the same workload, not five independent targets, independent relation searches, or a coset census. No confidence interval for an independently sampled success probability is planned.

The panel generator records a complete ordered, hashed index. It first forms 40 IC cells in kernel/target/presentation order, appending the matched plain control after each target group. It inserts successive rho controls after each six IC cells. In round `r`, it rotates the 46-cell sequence left by `(9*r) mod 46`, then reverses odd rounds. Execute the recorded index order, serially. This interleaves controls and changes order exposure across rounds instead of running five contiguous copies of each candidate.

The index starts with `attempted=0`, `completed=0`, `status=draft_unadmitted`. Update actual execution status only from retained job/process receipts. Do not infer execution from generated cells, successful compilation, unit tests or an opened PR.

## Rho references

The three registered source-pinned implementations are `rho_reference_negation`, `rho_walk_v3` with `RhoV3::v6(true)`, and `prime_fast::rho_parallel` with the existing tuned configuration and one thread. All use the same public target/order, seed and execution envelope. Destination runs include target transfer and validation. No ordinary non-negation A=1 walk is presented as the optimized comparator.

Record capped runs as such. If a backend returns no detailed failed-operation ledger, retain that field as missing and charge its outer process cost. A runtime record must not turn missing counters into zeros. The best independently replayed, admitted complete-solve cost among these specific controls can be a comparator; this finite panel does not prove they are globally optimal.
