Frozen 2026-11-16 before implementation and data. This is a bounded relation-supply screen for the existing Koblitz E0 rootfinding collector, not a new attack or an end-to-end timing panel. It adapts the already proposed sumset-collision idea in `crypto-autoresearcher:ledger/proposals/IDEA-20260928-4e2be7.yaml` and `ideas/catalogue-20260805/A1-index-calculus.md#A1-6` to the exact standard-subspace bases and signed columns used by `pdp3-koblitz`. ## Hypothesis and algebra

The fixed pair table already harvests equal pair sums. A three-point sum can collide with another three-point sum while their pair tails differ. For triples `A=(i,j,k)` and `B=(u,v,w)`, verify the full group equality `S_A=S_B` or `S_A=-S_B` before emitting `row(A)-row(B)=0` or `row(A)+row(B)=0` modulo the prime subgroup order. A triple summing to the group identity supplies its own homogeneous row. Each row uses the existing `col_of` and `coef_of` after cofactor projection. Zero and dependent rows count separately. An equality of x-coordinates alone is never a certificate. [pcc:unverified]

If `C` is the number of folded factor-base columns, homogeneous rank cannot exceed `C-1` when the true column-log vector is nonzero. Rank `C-1` leaves one scalar degree of freedom; a verified known-generator relation and a verified challenge relation are still needed for recovery. The screen measures whether triple collisions can close the observed rank deficit after the existing pair-collision and torsion seeds, and at what exact setup cost. It does not assume those two later relations exist or are cheap. [pcc:unverified]

## Fixed cells and controls

Use registered Koblitz E0 `(n,d)=(13,5),(19,7),(23,8)` with the exact curve IDs and factor-base digests asserted in `tests/rootfind_multihit_relations.rs`. Build the production torsion pair table and replay its verified seed rows first. The source-bound seed ranks are 5, 11, 23, with full matrix column counts 18, 71, 139 (including target column). The triple generator is independent of any target or unknown scalar. Enumerate distinct unordered triples with repetition, including index zero. For K13 exhaust all `C(B+2,3)` triples; for K19 and K23 stop at 32,768 unique triples or exhaustion, whichever comes first, using splitmix64 seed `2026111601 + n` and sorting the three generated indices. Keep all rejected duplicate draws and their costs. [pcc:unverified]

Key each full triple sum by canonical `min(pack(S),pack(-S))`; retain its first witness. For every repeated key, independently re-add both triples, resolve the sign, check the six-point identity, and form the signed modular row. Verify each stored row again with a separate replay implementation before interpreting rank. Include a mutated-witness negative control that must fail. Compare the rank gained by triples against the unchanged pair-seed rank, and report the number of triples needed at every rank increment. Counter fields: unique triples, rejected draws, point additions, hash probes/inserts, finite sum-key collisions, identity sums, zero rows, dependent rows, independent rows, rank trajectory, linear-algebra operations, peak RSS, elapsed wall as L0 diagnostic only. Preserve all rows and witness triples. [pcc:unverified]
