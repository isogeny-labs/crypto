# Before-data amendment: reuse two-point prefixes

Frozen 2026-11-16 before code for this arm and before any scientific execution. The original `PROTOCOL.md` remains in force. This amendment adds a paired generator-cost control to the same K13/K19/K23 triple stream; it changes no curve, base, seed, triple sample, rank criterion, checkpoint gate, or end-to-end claim boundary. [pcc:unverified]

For every sorted sampled triple `(i,j,k)`, the direct arm computes `F_i+F_j+F_k` with two point additions. The candidate retains the full point sum `F_i+F_j` under the ordered pair `(i,j)` after its first use, then adds `F_k`. Both arms must return the identical full point for every unique triple, including infinity. This parity check is validation work outside each arm's modeled generator additions and is counted separately. The collision key, first-witness order, full re-add verification, emitted row, rank trajectory, and tamper control must be byte-for-byte equal between arms. A parity failure invalidates the cell. [pcc:unverified]

Record direct generator additions, candidate new-prefix additions, candidate final additions, prefix-cache hits/inserts, validation additions, collision-verification additions, cache requested backing and process RSS separately. A prefix hit avoids one *group addition* but incurs a hash lookup; the screen makes no wall or complete-call prediction from addition counts alone. Preserve all zero, dependent and independent rows. The `32,768`-triple cap and 512 MiB/600-second run limits stay. [pcc:unverified]

If exact parity and row/rank equality hold, the candidate is eligible for a later frozen same-target complete-call comparison, with cache setup and memory charged. If parity fails, repair the implementation before cost interpretation. If the cache's measured complete cost is worse than direct construction, retain the direct generator. This amendment does not change the L2 F4/F5/F6 panel or authorize execution before the branch-specific S3 checkpoint gate passes. [pcc:unverified]
