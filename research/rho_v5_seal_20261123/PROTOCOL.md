# rho.negation_v5 seal: frozen protocol (written before any new data)

Date 2026-11-23. Lead: rho.negation_v5 (pow2 jump tables, weight-2 cap 64) vs rho.negation, record RES-rho-parity-v5, crypto #4860.

## Steps and pass rules (frozen)
1. Independent replay: `ecbench verify --replay N` of the fp28 (expanded) and fp32 (expanded, large) sessions with a binary built here. PASS = every sampled replay `identical`, digests match, 0 findings. Replay of op counts is host-independent; a different host class is needed for a `vs_rho` claim and is reported separately.
2. Integrity pass on the v5 sessions (python over records.jsonl, plus the `verify` audit): all rows verified with matches_target; total_gae == sum of phase gae; unpriced lists compared per arm; cap/capped-walk behaviour; seeds paired and A/A arm meaning; curve/target overlap with earlier panels. PASS = no accounting asymmetry that favours v5.
3. Sealed bound: `ecbench bound fit` for rho.negation_v5 (and rho.negation) from the sessions, `bound check`. PASS = record checks.
4. fp36 and fp40 multi-curve paired runs, arms rho-neg (reference), cand (rho.negation_v5, cap_multiple 64), rho-neg-aa (A/A control), alternate_measured, curves/targets/seeds disjoint from every earlier panel. 
   Predictions (frozen): S(cand/rho-neg) < 1 at both sizes, point estimate 0.93-0.98, drifting toward 1 with bits because the weight-2 table is capped at 64 jumps while the GAE-optimal k grows (about 450 at fp36, about 1000 at fp40), so the look-ahead and sqrt(k/(k-1)) excess no longer shrink. Wall ratio within 0.93-1.03. The upper 95% CI on S is < 1 only if pairs suffice; with fewer than about 400 pairs I expect the fp40 CI to straddle 1.0. Falsifier: S point estimate > 1.0 at either size.
   Accept rule (as RHO_V5_CAP64): S and wall 95% CI upper bounds <= 1.0.
5. Registry/baseline PR prepared (not merged) only if 1-4 pass.

## Not claimed
Parity or sealing is relative to rho.negation, not the best-seeded rho; bits 20..40 are toy sizes; wall is L0 on this VM, not L2.

## Frozen run design (added before the fp36/fp40 data were taken)
`prime_search` is limited to 8..32 bits, so fp36/fp40 use `prime_explicit` curves generated by PARI `ellcard` (gen_curves.gp, seed 880000+bits, cofactor 1, random a,b, random generator). 16 curves x 8 targets x 12 rounds = 1536 pairs per size, arms rho-neg / cand / rho-neg-aa, `alternate_measured`, `--cpus none` (L0, one thread, shared 4-CPU VM with one other agent; wall is indicative only). Smoke run first (2 curves x 2 targets x 2 rounds, discarded) only to time the cells: 0.07 s/record at fp36, 0.21 s/record at fp40.
