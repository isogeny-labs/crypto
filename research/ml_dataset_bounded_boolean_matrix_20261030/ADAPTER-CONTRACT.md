## Exact increment and dispatch

Add a separate supervised Koblitz-b1,m3 path; preserve existing binary m2 and prime dispatch. Require actual Group::Binary, actual curve.b==1, declared Koblitz family, n23..31 or47..61, affine target, admitted canonical original factor-base points and distinct x codes, and original SolverExecutionContext. Do not accept family string alone as proof of b1. Generalbinary b!=1, m4..15 and identity targets remain explicitly unsupported for this profile. A generalbinary-tagged b1 model is not silently reclassified; a later profile can deliberately admit it. Preserve other existing solver routes and full original corpus objective.

Weil uses the bounded builder alone and returns encoding-complete/solver-not-invoked. F4/F5 must invoke their named native backend before setting native_backend_invoked=true. A builder success never means F4/F5 success. Construction admits K1..64 as existing native design, but K2 is the first mandatory useful engine profile: V=3, at most8 monomials per polynomial. K1 cannot satisfy nontrivial solver acceptance. Larger-selector construction may succeed while solver admission is explicitly refused. These are bounded profile restrictions, not removal of larger-factor-base scope.

## Existing paths and why they cannot simply be widened

src/ml_dataset/solvers.rs::boolean_solve currently rejects m!=2. It creates FieldStructure/SymElement selectors with infallible allocations, builds JSON Macaulay rows before a cumulative byte check, invokes an initial matrix step and then separately recursive solve_boolean_system_filtered, and uses max_solutions=usize::MAX. The recursive callback accepts a root and can stop early on a witness. Its legacy outcome algebra_completed=!stats.exhausted cannot be copied as an exhaustive-enumeration claim for a new profile. lift() builds cloned signed choices before its operation budget, has no deadline/persistence hook and returns at the first witness. Its used>=limit heuristic is not an exact exhausted cursor.

Existing artifacts weil-system.json, macaulay-input.json, macaulay-output.json and boolean-solve.json have legacy roles without a dedicated new semantic verifier. mod.rs::verify_cell already verifies manifest hashes, checked telemetry/capture, original execution context and special root/wide-prime payloads; it does not provide this new S4 replay. Hash checks are necessary but insufficient. Existing set_witness independently checks group sum and central PDP replay should be reused, with stronger new profile binding.

Native src/cryptanalysis/koblitz_groebner.rs::SolveOptions provides node_budget, max_solutions and engine, not memory/deadline/fallible visitor. solve_boolean_system_filtered and recursive solve_with_policy paths have infallible clones/rows/solution buffers and thread-local node trace retention. matrix_f4_f2_counted_impl, build_macaulay_packed, packed rows, unpacked polynomials and rref_f2_counted have allocation paths outside the new builder. Environment-controlled row/column/layout/kernel selection exists. src/cryptanalysis/matrix_f5_f2.rs adds criterion/pruned signature sets, PrefixEchelon buffers, projections and rank-certificate paths. A node cap or n_vars bound by itself is not a resource proof.

## Smallest honest native integration chain

1. Integrate bounded S4 construction plus independently replayed Weil companion. This is useful encoding support, explicitly not F4/F5 invocation.
2. Add an explicitly bounded native *matrix-step* entry for each existing F4/F5 algorithm, initially K2/V3. Reuse those engines, not a substitute enumerator labeled F4/F5. Freeze algorithm selection independent of ambient environment. Pre-admit input copies, multipliers, canonical columns, packed rows, criterion/signature state, pivot copies, parallel live buffers, unpacked outputs and event buffers with checked arithmetic/fallible allocation, and provide sticky fallible boundary callbacks and original deadline checks. Preserve old entry behavior.
3. Run one admitted native degree-bounded step, retain original equations and actual native returned rows/report. Name result scope matrix-step-complete, never complete Groebner basis, complete recursive solver or native enumeration. Independently enumerate the small original signed domain for certificate/negative checking, explicitly labeled extraction/replay and separately charged. This is analogous to the already explicit finite-domain extraction boundary in prime profiles, not a replacement native F4/F5 claim.
4. If full recursive search is required for the first adapter release, add a genuinely bounded recursive entry instead of invoking the existing unbounded function. This expands native scope: each node's algebra/propagation copy, trace, returned root and branch stack needs a gate. Do not pretend step3 implements this. The original recursive comparison remains outstanding after a matrix-step increment.

For K2, C<=8 Boolean monomials, initial n<=61 equations, and at most8 Boolean multipliers per equation give R<=488 pre-criterion rows; each packed row needs at mostone u64. Returned rank<=8. These dimensions bound the matrix payload ONLY. F5 auxiliary lower-degree echelons and signature collections, allocator capacities, repeated copies and RREF options still require line-by-line accounting. No byte/work constant is certified here. Do not approve a guessed2MiB envelope or infer total allocation solely from R,C. Either implement fallible gates or freeze and independently review a conservative complete-kernel bound covering every path. No native solver invocation until that blocker is resolved. Existing global MAX_F4_ROWS20000/MAX_F4_COLS40000 are not this profile's budget and must not be raised.

## Independent extraction and replay contract

For admitted K2, original domain has at most4 finite signed points when canonical/deduplicated: at most64 ordered triples. Validate domain membership and on-curve status from original public/factor-base records before work, not from producer-selected certificates. Enumerate original signed triples lexicographically, including repeated points and identity intermediate sums; do not infer group completeness from S4 vanishing. Independently evaluate original equations on mapped selector assignments; compare all emitted assignments and their coordinates to exact modulo mapping. A positive witness is accepted only after original group arithmetic sum equals target. Preserve the first valid certificate if later extraction/persistence hits a limit.

Freeze addition accounting: charge every actual group.add, including identity starts, and retained replay cost separately. Reserve choice/index/cursor/point storage before cloning or multiplying. On reaching an exact count limit, completion is determined by the next cursor/end marker, not used>=limit alone. A negative conclusion requires full original signed triple coverage with no deadline/work/byte/sink failure. Native step completion alone is never a negative certificate. A positive certificate can remain valid when later work is censored; final status carries both facts.

Historical central replay validates static original limit binding and deterministic counters without reading today's wall clock. Rebuild canonical equations under the frozen bounded profile and require byte/canonical term equality, then replay group rows independently. Returned native rows can be checked at all small-domain assignments for consistency but that is NOT full ideal-membership/basis-derivation proof; label the boundary. Any claim of a refutation must also pass exhaustive original-domain replay. No unlimited re-execution of an interrupted native solver during verification.
