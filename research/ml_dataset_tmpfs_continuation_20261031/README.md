# Prospective tmpfs continuation

This is a fallback design for the untouched suffix of the frozen 64-cell native
prime n23, arity-2, BSGS matrix. The provisional draft selects shards18..63
because the original XFS campaign had sealed custody for0..17 when drafting
began. The original XFS controller has resumed and may advance; the actual
untouched boundary must be reconciled immediately before the draft is filed
and frozen. If XFS completes all64, this fallback must not launch. A changed
boundary requires an updated draft, official checker validation, a new filed
commit, a new frozen protocol, and a newly rebound native plan before any
tmpfs generation. No comparative XFS/tmpfs speed claim is part of this design.

The controller is intentionally not runnable until a committed bindings.json
pins the selected start index, complete frozen protocol file SHA-256 and new
native plan file SHA-256. The native plan retains all64 axes so mixed-radix
indices preserve curve-seed, generator, key and twist identity. The controller
attempts only the selected untouched suffix, holds the original XFS controller
lock for its full run, rejects any original attempt marker in that suffix, and
uses one atomic marker before each new tmpfs solver attempt. It cannot rerun a
marked cell. Independent native verify, report and strict export are recorded
separately; restricted archives and small custody pointers each require a
fresh content-addressed S3 GET and byte comparison before a cell is durable.
Per-cell Git-ready checkpoints retain discovery metadata without witness data.

The output root is a private mode700 directory under /dev/shm. New attempts
require at least8GiB free on that tmpfs mount and16GiB host MemAvailable; the
native worker remains capped at2GiB memory,64MiB trace,30s inner time and90s
outer time. Auxiliary stages are bounded, and the absolute continuation
deadline is12 hours. These gates are admission limits, not runtime or scaling
estimates. Tmpfs files are temporary and cannot be treated as durable before
S3 custody. Linux kernel [tmpfs documentation](https://docs.kernel.org/filesystems/tmpfs.html)
describes the virtual-memory storage and loss on unmount. The current corpus
scope/leakage contract is in docs/ml-dataset/DESIGN.md and
docs/ml-dataset/OPERATIONS.md; the original campaign's per-cell receipts are
under research/ml_dataset_local_campaign_20261031/checkpoints/.

The provisional official experiment.protocol/v1 draft is protocol.draft.json.
It is not frozen, and no tmpfs cryptographic cell has been generated. The
controller may be syntax-checked now; its check and run modes require final
bindings and the final original-campaign boundary. Do not infer full requested
Koblitz/binary/prime, arity2..15 or solver coverage from this 64-cell subset.
