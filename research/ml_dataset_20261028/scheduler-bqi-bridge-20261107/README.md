# Scheduler row arithmetic certificate bridge

This connects the dynamic Boolean matrix scheduler V3 to the existing independent BQI1 checker. It encodes each exact ordered generator (including zero generators), the retained target row, and its generator/multiplier proof. Scheduler polynomials use degree-then-lex ordering; BQI1 requires lex ordering. The adapter sorts borrowed term indices for serialization while preserving generator identities and rejects malformed or duplicate terms rather than silently normalizing them.

Source references: the reviewed `dynamic-boolean-scheduler-proposal-20261107-v3` supplies unchanged scheduler.rs/sparse.rs. The existing `higher-arity-sparse-row-proposal-20261103` supplies unchanged boolean_identity_bqi.rs as bqi.rs and the encoding/prepaid-checker design in matrix_rows.rs. The source-bound binary-matrix-arity-plan-20261107 identifies the full integration obligations. This is reuse of the existing quotient arithmetic contract, not a new algebraic result.

All allocations, serialization, ordering work and checker envelope reservations use the supplied cumulative owner and absolute deadline. The checker maximum envelope is reserved before execution and is not refunded; its internal counters remain in the audit. These are conservative software resource charges, not hardware instructions. A refused owner check after arithmetic verification leaves the audit retained but the overall result failed. Partial raw output survives refusal. Checker limits are explicit caller input; the existing software profile is not enlarged implicitly.

A retained valid row from a capped scheduler attempt can pass this equality check. This never changes that attempt's incomplete status, authenticates the original field system, witnesses native pivot operations, proves closure, or establishes a first/last fall degree. Original execution ownership and CheckedMap binding belong to the private integration layer still being developed.

Validation:22 tests passed (six new bridge controls, nine existing checker tests, seven sparse-donor tests), zero failed/ignored. The actual scheduler test produces a nontrivial two-generator row involving variables128/129, stops at its degree cap, and then verifies that row on the same cumulative owner/deadline. Controls cover exact wire ordering/zero generators, source/target mutations, malformed origins/duplicates/multipliers, every owner refusal including post-check acknowledgement, expired deadline and finite work/wire/checker caps. receipt.json records exact pre/post source hashes and binary hash. This is standalone software validation; no scientific dataset or cloud execution occurred.
