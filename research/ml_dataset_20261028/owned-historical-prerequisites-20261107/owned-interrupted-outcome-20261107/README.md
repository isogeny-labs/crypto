# Narrow supervisor interruption envelope validator

Production helper `owned_search_interrupted_outcome.rs` inspects a borrowed, already-owned serde_json Value and the expected channel disposition supplied by original-config admission. It accepts only timeout, trace_budget_exhausted and worker_failed supervisor forms. Exact supervisor field/type/diagnostic checks, false completion claims, null degree labels, report-marker rejection, matching optional exit code and exact requested-channel disposition prevent generic failures or contradictory reports being promoted.

The helper does not authenticate JSON bytes, manifests, process failure cause, the checkpoint-enabled policy, or original mathematics. Its result grants no export scope. The caller must retain the input and bind it to original manifest/config/context, gate the checkpoint policy, verify capture integrity, select and verify original rows, and revalidate before projection. A worker_failed envelope with no outer exit code and supervisor exit zero is allowed because missing result.json after a successful worker exit yields that actual supervisor fallback. Claimed reason is observed metadata only.

Inspection uses the same caller owner and absolute deadline. Arbitrary requested-channel equality is performed through a metered recursive walk, capped at depth64, with all key/string bytes charged before comparison; no heap clones/allocations. This does not pay for original JSON parse/storage, which are caller obligations. Failed calls do not renew owner allowance. Reservations accepted before a postcheck failure remain charged.

Twelve focused tests pass against the installed production helper, using actual terminal_outcome function extracted from execution.rs and the supervisor field/value shape from mod.rs. Cases include all three actual statuses, missing-result fallback, rejected report markers/generic errors, contradiction and malformed types, exact disposition/absence, large-string budget refusal, depth limits, exit mismatches, deadline/refusal, postcheck retention, and shared-owner exhaustion across invocations. The test channel disposition is explicitly a structural fixture; no real original-config authentication is claimed.

Initial10-test and final12-test logs are retained. Source syntax parsing passes. No full Cargo/CLI build, scientific job, cloud write, commit or Conductor action occurred. This helper is not itself a positive historical export route.
