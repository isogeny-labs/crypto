# Byte-bounded encoding of retained owning-search evidence

`capture_encoding.rs` walks exact retained structures in source order and `capture_wire.rs` streams their encoding through a single pre-admitted byte buffer. It does not clone nested vectors or build a whole snapshot in memory. A huge polynomial, monomial, proof, certificate or diagnostic can cross arbitrarily many chunks. Chunk length, total encoded bytes, acknowledged chunk count, local work, original admission and the original absolute deadline are checked. The returned Attempt retains its unacknowledged buffer, acknowledged counters, encoded byte count, charged work/allocation and failure. A publication failure is terminal in this attempt and retains the exact pending chunk; no retry is performed.

`with_parts` constructs private immutable references from disjoint authentic owner fields and lends the actual original Budget and CaptureEmitter separately. It accepts no replacement map, equations, target, deadline or source identity. The writer implements AdmissionSink using those original objects. Encoder local limits can only restrict this interface; they cannot enlarge original allowance. A successful publish callback must mean receipt-backed publication. The callback must retain its actual receipt before any subsequent fallible check; that responsibility belongs to the publication bridge, not this codec.

## Wire

Magic is the ten bytes `OWNSEARCH\x01`. Each value starts with a tag: 0 null, 1 bool followed by byte 0 or 1, 2 unsigned u64 little-endian, 3 UTF-8 preceded by u64 byte length, 4 raw bytes preceded by u64 byte length, 5 list preceded by u64 item count, 6 map preceded by u64 pair count. Keys are tag-3 strings. All fields and list order are deterministic. Chunk boundaries have no grammar significance and may split length words or UTF-8. Concatenate only receipt-verified consecutive chunks from the same snapshot.

The root has 18 keys, in order: schema, snapshot_index, identity, signed_domain, signed_target, failure, first_stop, diagnostic, normalization_cursor, expansion, normalized, continuation, lift_records, coverage, exclusion_audit, accepted_record, status, encoding_complete. Schema is `owned-search-retained-evidence/v1`. The final sentinel is `encoding_complete=true`. It means the retained snapshot was encoded; it does not mean the algorithm completed or its claims were independently replayed. Snapshot index is a publication sequence supplied by the authentic bridge. Failure/stop/status describe the owner at snapshot start; encoder or publication failures are retained separately in Attempt/publication receipts.

Finite scalar enums/results use their pinned Rust Debug strings, formatted into a fixed 256-byte stack buffer with an explicit 512-work reservation. Larger nested objects are always traversed structurally. Changing those string forms requires a wire-version review. No payload parser or semantic replay is included here; root is independently checking the stream.

Identity includes admitted public/factor/launch/binding hashes, exact retained map bytes, existing map acknowledgment, publication flags and pattern. The map acknowledgment acknowledges the map, not the new snapshot. Signed domain and target retain their exact original order/values. Null distinguishes an absent expansion/search/audit from a present empty structure. Normalization cursors, partial expansion/scratch rows and stage/cursors, zero generators and original generator order remain intact. The new read-only OwnedExpansion accessor mirrors the existing borrowing Expansion accessor.

All continuation partitions and their prefix, equations, children, exclusion ID, statuses and audits are included. Search nodes preserve origin, decisions, queues, candidate, native disposition, basis/proof rows, pending tasks, current row, batches, symbolic reducers, operations, staged commit data and counters. Lift progress, callback outcomes, fresh exclusion replay progress, paired flags, BQI certificate bytes and BQI audits are included. No successful sub-audit is silently promoted. The encoder records existing normalized/source data; it does not independently authenticate equations or replay proofs.

## Existing contracts and integration

Actual CaptureEmitter::payload_borrowed validates identities and handles complete byte payload custody; the codec never substitutes witness publication or a new AttemptBinding. Existing original row capture pays original checking reservations before encoding and retains capture failures. These actual sources, retained proof structures and prior read-only projection informed the implementation; SOURCE_BINDINGS pins them. This adds software encoding, with no new mathematical method or external novelty claim.

Apply expansion-accessor.patch to checked_boolean_equations.rs. Apply registration.patch to the composed owning source and install capture_encoding.rs/capture_wire.rs next to it. The separately implemented publication bridge calls with_parts and encode, derives finite limits from original remaining resources, and calls actual payload_borrowed. Source-level scope permits incomplete attempts, but stopped/deadline-expired original admission may prevent any new snapshot; all previously retained local evidence and acknowledged chunks must still survive.

## Validation and limits

Twenty-four focused Rust tests passed: eight new encoding controls and sixteen donor controls. New tests cover a 10,000-variable nested monomial across hundreds of 127-byte chunks, byte-identical streams across chunk sizes, exact generator/monomial order including zero rows, total byte/chunk caps with exact retained prefixes, publication refusal with no retry, original admission refusal/accounting, expired original deadline, and source-identity/absent-versus-empty distinctions. The fixture is generated by the actual compiled Rust root encoder and nested traversal, not a reconstruction by another language.

The focused harness compiles actual donor retained data types and actual serializer bodies, mechanically extracts scalar owner/projection records, adjusts visibility and omits only with_parts (because it has no authentic production owner fixture). It inherits the historical structural CheckedMap harness but does not use it to assert original authentication. Fixture source hashes/domain and partial native structs are synthetic. `prepare_checks.py` and EXTRACTION_RECEIPT document this. Twenty-four passes do not typecheck the authentic owning borrow split, publication bridge or CLI, and do not constitute a scientific result. The production source parses; authentic assembled compile remains required.

No full Cargo build, SAT rebuild, cloud upload, experiment, Conductor operation or Git operation was performed in this task. Root coordinates independent decoding, integration and durable publication.
