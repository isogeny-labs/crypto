# Original-owner retained snapshot publication

This source adds a real CaptureEmitter bridge for the versioned OWNSEARCH binary snapshot encoder. It uses the original owner, checking reservations, trace allowance, capture limits, shared deadline and immutable map acknowledgement. It does not allocate a new execution grant. Captured chunks have a versioned role, .bin.part paths and owned-search-wire-v1 encoding, distinct pattern/snapshot/chunk indices, and actual durable event positions from CaptureEmitter.

A checkpoint is automatically called after expansion normalization and before Matrix admission. That preserves authenticated equations and retained construction state before subsequent matrix work can exhaust the original allowance. The same checkpoint API can be called again while original allowance remains. Final worker integration calls publish_capture after the owning search returns. The pre-Matrix checkpoint is a real call site; the final caller is supplied by the separate versioned-dispatch packet. Mid-continuation checkpoints are not implemented because its Session owns the exclusive ledger borrow and current continuation has not yet returned to OwnedAttempt. A later capped matrix attempt can therefore retain more evidence in memory than it has durably checkpointed. Stopped or expired budgets cannot fund new snapshots.

Each snapshot starts from the original map event position or the previous complete snapshot's last acknowledged chunk. The bridge prepays exact payload storage quotations, trace, bounded head/path metadata and the full possible replacement allocation of growing chunk/snapshot record vectors before allocation or I/O. All partial records, paths and pre-call event heads are retained. After payload_borrowed succeeds, its actual acknowledgement is installed before integrity/deadline checks. On failure the encoder retains pending bytes and the owning publication keeps earlier acknowledged chunks; no automatic retry occurs.

Snapshot completion requires successful full encoding, zero pending bytes, matching chunk counts, exact consecutive event count/binding/advancing journal positions, and equality of encoded bytes, acknowledged bytes and the checked sum of retained chunk payload lengths. Journal byte_end is an event-stream offset, not a payload byte count. Payload hashes are recorded by the actual CaptureEmitter payload event; this bridge retains its acknowledgement and relies on that existing write/hash/commit contract. Central chain/payload replay remains required to independently establish those bytes. No separate fabricated acknowledgement or payload hash is substituted.

Completed encoding/capture means only that this retained snapshot is durably acknowledged by the local capture store. It is not S3 custody, algorithm completion, a pattern-global negative, or a full solve report. Search status is encoded separately. A publication failure is installed into owner Failure only if the owner did not already have a scientific/native failure; the original first stop remains sticky. Acknowledged partial chunks and failed pending buffers remain accessible through capture_publication even when no successful report is available.

## Install and validation

Apply publication-integration.patch to the exact bound composed adapter and install owned_search_capture_publication.rs in src/ml_dataset. The patch registers the publication module, adds owned state/error storage and inserts the pre-Matrix checkpoint. Separately install/register capture_encoding.rs and capture_wire.rs plus the retained-expansion accessor from the encoder packet. The matching encoder source hashes are observed dependencies, not a claim that that independently produced packet was frozen before this one.

Seven focused tests compile the actual publication bridge with explicitly structural Budget/CaptureEmitter/encoder fixtures. They cover two complete checkpoint chains, second-chunk failure retaining the first acknowledgement and pending data, malformed acknowledgement, deadline failure after a real fixture acknowledgement, stale head/stopped budget refusal, inconsistent byte counters, and claimed completion with pending bytes. They test bridge control flow and retention; they do not execute the authentic CaptureEmitter, original Budget or complete encoder together. Genuine assembled compilation and real capture integration remain required. No full Cargo build, cloud action, scientific experiment, Conductor action or Git mutation occurred.

The initial harness compile failed due to an omitted closing delimiter, preserved in compile-initial.log; the harness was corrected. The first five-control log was superseded before the preservation instruction and has not been fabricated or reconstructed. The six-control intermediate log and final seven-control log are retained. Reviewer-requested corrections changed binary metadata, byte-accounting completion checks and complete replacement-vector prepayment before the final tests.

Source contracts reviewed: original_affine_rows publish_inner and acknowledgement retention, affine_row_central replay policy, actual CaptureEmitter::payload_borrowed and CommittedEventPosition, original owner/Budget source and composed adapter. The format is a separate versioned retained-evidence snapshot, not an affine-row/BQI receipt or a compatible replacement for one. No new mathematical claim is made.
