# Captured equation lineage

`check_lineage(normalized, continuation, variables, *, limits=Limits())` checks captured equations against actual prefix-partition and Boolean-search builders. Input is the bounded reader's decoded `retained.normalized` and `retained.continuation`; variables must be supplied from a trusted dimension or explicitly scoped synthetic fixture. No dimension is silently inferred from highest observed variable.

The checker verifies canonical ascending degree/lex polynomial order and strictly increasing bounded variable IDs; partition equations are exactly captured normalized generators followed by ordered prefix constraints. Child partitions follow the parent's retained witness and first differing bit. Search root equations and Original origins match the partition generators; branch equations, inherited origins and decisions match the actual first-unused-variable builder and true-before-false creation order. Parent/backlinks, unique children and fully branched children are checked. One equation's terms are compared in their actual order, without normalization that could conceal altered evidence.

Building partitions/nodes can retain valid incomplete prefixes. They are marked `inconclusive_partial` and Building nodes appear in `skipped_nodes`; they are never accepted as full equation sources. Missing continuation and work/structural caps are inconclusive. Mismatch means an inconsistent capture lineage, not a mathematically false polynomial identity, satisfiable/unsatisfiable system, or invalid underlying curve.

`verified_nodes` contains `{partition, node}` paths whose complete equations, origins and decisions checked. Any mismatch or cap clears the verified-node list. Consumers must reject a global `lineage_mismatch`, and must not replay a skipped or unlisted node as a verified source. A caller can select `continuation['partitions'][p]['search']['nodes'][n]['equations']` for a listed node, while retaining the original decoded object unchanged. This does not authenticate normalized equations against the original map/descent, replay polynomial identities, prove model coverage, validate point lifts, or establish FFD/LFD. Those flags remain false.

Default caps: 2,000,000 charged work units, 4,096 partitions, 16,384 search nodes, 65,536 variables. Configured limits must be exact nonnegative integers and cannot exceed hard ceilings of 100 million work, 65536 partitions/nodes, and one million variables. Invalid limits raise ValueError. Work is charged before operations; refusal does not increment beyond the cap. Scans, copied expected sequences, canonical comparisons and recursive scalar/list equality are charged. Input decoding is separately bounded by the semantic reader; this API does not decode JSON or arbitrary object graphs. Use only its acyclic decoded primitive wire values.

Fifteen adversarial Python controls cover exact builder order, root substitution, incorrect branch equation/origin/decision, noncanonical terms, incomplete builders, Boolean index substitution, duplicate backlinks, caps, split-prefix divergence missing data, invalid limits and removal of previously verified nodes after a late mismatch. These are independent Python fixtures, not actual owner runs. The preexisting Rust diagnostic encoding fixture is also read through the genuine semantic reader: its normalized list includes a synthetic diagnostic monomial absent from its partition equations, and lineage correctly returns `lineage_mismatch` (partition equations length). This result is retained rather than relabeled a successful source check.

A second, matching fixture is generated by the actual Rust continuation/search kernels and encoder (synthetic n=2, 24509 bytes, SHA256 0698e33d00c8e0c53e31b478da9f7cca0c277306cac085da3777fb2023a3c4d0). Reading that wire with the actual semantic reader verifies one partition and all five search-node equation lineages in 1077 charged work units. The producer retains Err(Audit) from an insufficient nested BQI audit envelope; successful equation lineage does not override that failed audit. The readback receipt preserves the narrow result and all broader verification flags remain false.

Replay controls: `python3 -m unittest -v` in this directory. Independent fixture readbacks use `inspect_selected([open(snapshot,"rb")])` then `check_lineage(retained["normalized"], retained["continuation"], explicit_fixture_n)`. No scientific job, full Cargo build, cloud write, or Git mutation was performed.
