# Historical verified rows from interrupted owned checkpoints

## Existing behavior and distinct scope

The current central route decodes every snapshot and checks source identity, audits only the latest, requires the normal producer report to join that snapshot and terminal capture head, requires first_stop=null, and permits CheckedScope only with an unstopped head. The producer report intentionally cannot be emitted after original-ledger stop or incomplete publication. Preserve this existing v1 route and its claims unchanged.

Add an explicitly opted-in replay scope, suggested name `verified_rows_from_prior_checkpoint`, with a distinct verdict/projection schema. It means the selected committed rows were independently checked at the identified historical checkpoint while the overall producer attempt remains incomplete. It is not successful terminal replay. Gate initially on the explicit checkpoint-enabled original request, recognized stopped/interrupted outer outcomes, and a bounded replay policy. Do not automatically apply it to arbitrary failed cells or broad generic error envelopes. Decode or verifier resource refusal cannot authorize fallback.

## Pure selection contract

Use source-bound per-snapshot classifications produced only after authenticated capture replay. The selector must not accept raw caller booleans such as complete=true as proof. Candidate states are Complete(decoded whole wire, encoding_complete=true, no trailing bytes and original identity bound), StrictTruncated(valid wire prefix ending at exact committed EOF, identity bound), Invalid, and Refused. They carry exact pattern/index/chunk sequence and event receipt ranges.

Require contiguous snapshot indices from0, contiguous chunks from0, and publication adjacency immediately after map or preceding snapshot. All observed events/payloads through terminal head must verify. Complete snapshots may precede the selected one; every complete snapshot must pass wire/source identity checks. Select the final Complete snapshot if no tail. Alternatively permit exactly one final StrictTruncated snapshot immediately after the selected Complete snapshot. Reject multiple partial snapshots, gaps, interleaving, unrelated events, malformed fields, false completion sentinel, trailing bytes, invalid hash/identity, or later complete snapshot whose mathematical verification fails. Never scan backward past a later complete failure to find a positive older row. No complete candidate means Incomplete/no rows.

The strict tail is not just any decoder error. Only genuine EOF truncation after valid prefix parsing qualifies. Work/bytes/deadline/depth/container/string/allocation limits are Refused, not evidence of interruption. Magic/tag/bool/UTF8/duplicate/schema/order errors are Invalid. Declared lengths must remain bounded before allocation. Tail may have arbitrary diagnostic contents only where the schema already permits them.

The current decoder retains raw bytes but discards partial Value on failure; consequently Truncated alone cannot demonstrate the tail identity matches the admitted original. Add a bounded strict prefix check that validates completed root identity/map/receipt fields and every received structural prefix, or conservatively return Incomplete if truncation happens before identity is available. Do not invent a complete identity from chunk filename. A prefix validator cannot certify unseen suffix data and must label the tail semantically unchecked. A failed attempt with zero acknowledged tail chunks has no observable tail: do not infer an attempted snapshot index/count from absent artifacts or producer memory.

## Original and mathematical admission

Retain exact current cell/run/plan/protocol/config/public/factor/launch/capture binding admission, typed original mathematics and factor-base verification, imported CheckedMap authentication and map receipt checks. Existing source capsule construction alone does not prove descent. On the selected complete snapshot, require actual original Boolean descent regeneration plus complete expansion/normalized equality, lineage admission for all selected nodes and committed basis proof verification. Scope is auxiliary Boolean gate equations of the admitted pattern, not signed PDP or all-pattern exhaustion. Never use staged rows, scratch rows or incomplete builders as checked basis. Failure or replay resource exhaustion in these checks means no positive projection.

Use one cumulative parent replay budget and deadline across full capture validation, tail-prefix validation, all original/source checks, selected snapshot mathematics, projection and revalidation. Keep raw tail, all chunks, decoder refusal state and selected audit retained. No renewed budget after failed later verification.

## Report and failure-envelope joins

Do not rewrite or manufacture the normal producer v1 report. A stopped producer often has no such report by design. The new central replay certificate binds the original manifest's exact raw failed outcome, config, attempt binding and terminal head. Validate a narrowly enumerated outer failure envelope and all existing no-success/no-scalar/no-complete-pipeline fields. Preserve claimed producer reason as observed metadata, not independently proven cause. Missing, contradictory or substituted outcome/source bytes reject admission. If a normal v1 report exists, continue enforcing its own exact head/snapshot joins; do not silently reinterpret a contradictory report as an interrupted envelope.

In the no-report route, `producer_report_capture_join_verified` must be false; report separately that the outer manifest/outcome and original capture context were bound. The certificate links selected checkpoint receipt and terminal capture receipt as DIFFERENT positions. The terminal head may contain an allowed capture cap stop; an integrity failure or unverifiable chain never becomes an allowed interruption. A generic stopped flag is insufficient authority.

## Custody and projection

Require unique manifest descriptors for head, complete event stream, map and every committed chunk, including tail. Preserve hashes, lengths and ordering for the whole capture, not only selected bytes. Revalidate manifest, original inputs, context, terminal head, selected chunks and tail before exporting. Any later mutation or projection error invalidates prior scope. Pending uncommitted bytes are optional retained diagnostics with independent descriptors, never treated as committed tail evidence. A truncated tail must not disappear from exported provenance merely because its bytes supplied no rows.

Suggested explicit projection fields: new schema/status; producer_attempt_complete=false; selected_snapshot_index and selected receipt (event count, byte end, hash); terminal_capture receipt; tail disposition/index/chunk count/bytes/hashes; selected_checkpoint_wire_complete=true; selected_rows_verified=true; original_public_factor_map_verified=true; auxiliary_boolean_descent_verified=true; lineage and basis proof scope; outer_manifest_outcome_bound=true; producer_report_capture_join_verified as actually checked; tail_semantics_verified=false when truncated. Keep solver_completed/scalar_recovered/all_patterns_negative=false; all fall-degree/regularity labels null; producer counters/lift classifications unverified; public_features=null and visibility restricted. Do not use the previous generic CheckedScope label for this route.

## Controls before integration

Positive complete-last interrupted envelope; one valid identity-bound truncated tail; zero acknowledged tail distinction; no complete snapshot; malformed magic/tag/duplicate/identity tail; truncation before identity; resource cap masquerading as truncation; multiple partials; gaps/interleaving; valid later complete snapshot with bad descent/lineage/proof; report/outcome mismatch; source/map/head mutation; omitted tail descriptor; shared budget exhausted during tail/revalidation/projection; projection failure invalidates status. Pair actual producer interrupted receipts with fresh readback. Pure selector tests establish selection rules only, not source authentication, custody or original mathematics.

This is a read-only design proposal. No active source edit, build, execution or cloud action was performed. The strict prefix identity check and new central certificate route do not yet exist in the inspected source.
