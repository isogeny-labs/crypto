# Independent successful search-result checker

This adds branch-coverage and exact outcome checking around Search V2 and the existing independently implemented BQI1 arithmetic checker. References are the preserved dynamic-boolean-search-proposal-20261107-v2, scheduler-bqi-bridge-20261107 and search-bqi-integration-20261107. Their scheduler/search/sparse/BQI/bridge source files are copied unchanged; receipt.json binds exact bytes. No new algebraic theorem is claimed.

The checker accepts only successful Witness or UnsatDerived records. It checks root equations/origins against the supplied original list; every child inherits exact parent equations/origins/decisions plus exactly one assignment constraint. Parents precede children, both children split the same variable at opposite values, and no branch repeats an assigned variable. Parent/child links and queue membership must match terminal or pending status. A witness is independently evaluated against originals and its node equations. Every refuted leaf has an independently checked constant-one generator identity. UnsatDerived requires no witness or pending nodes and full linked leaf coverage; Unknown cannot be upgraded.

The checks, certificate storage, and nested arithmetic checks charge the supplied same cumulative owner/deadline. Each nested maximum checker envelope is conservatively prepaid; reservations are not hardware instruction measurements. Checked-node count and arithmetic audit prefixes survive errors, but no resumable checkpoint is claimed. Source authentication stays false: caller-supplied equations are not an authenticated curve map, and these proofs do not attest native execution or its timing. A valid synthetic proof could pass mathematical checking without proving it came from a worker. Integration must bind originals and retained captures independently.

Validation:20 tests passed, zero failed/ignored, including four new groups plus16 unchanged BQI/sparse controls. Tests check actual branching search, conditional and root refutations, nine structural/source/model/proof mutations, and refusal at every checker owner boundary; expired deadline, finite work cap and Unknown are negative controls. This is standalone software validation, not an ECDLP/PDP outcome or dataset generation.

Reproduce with `rustc +1.98 --edition=2021 --test harness.rs -o /tmp/search-result-tests`, then `timeout 60 /tmp/search-result-tests --test-threads=1`.
