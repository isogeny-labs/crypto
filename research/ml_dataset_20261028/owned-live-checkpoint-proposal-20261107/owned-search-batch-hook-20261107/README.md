# Committed-batch checkpoint kernel hook

Implements real first-node native committed-batch callbacks through scheduler::run_with_checkpoint, search::solve_with_checkpoint and continuation::Session::next_with_checkpoint. Original run/solve/next remain hook-free wrappers; deterministic no-due controls match original outputs and exact ledger charges. No public resume/from_attempt method is introduced.

The same caller-held CheckpointControl is borrowed across all nested invocations. Finite nonzero batch cadence and snapshot cap are explicit. Counters and first checkpoint stop remain private; stopped controls refuse at scheduler, search and session boundaries before new preparation work. A due snapshot cap, callback refusal or pre/post check failure propagates Owner rather than ordinary local Cap, so search cannot branch after publication refusal. Pre/post failures preserve their precise cause in the control. Snapshot count measures attempts, not successful durable publications.

Hooks borrow immutable authentic continuation/search/native state, active indices, live parent charge scalars and the same unwrapped mutable owner. Native charge is refreshed at each committed batch; outer live charges are passed explicitly. Callback costs belong to the original owner ledger, not kernel charge counters. Returned native and search attempts are installed before failure propagates. Node remains Running, native.complete remains false, and no candidate or full-search classification is synthesized.

Exact callback signatures are in the source. Session hook arguments are continuation, partition index, search, node index, native, continuation charge, search charge, original owner. This packet does not itself encode or publish these views; the root owns the private borrowed overlay and actual sink integration. No production policy default or published repository source is changed.

Validation: 19 tests pass, comprising nine new kernel controls and ten actual BQI donor tests. The modified scheduler/search/continuation and actual checker/bridge are compiled together; sparse Charge/Owner and polynomial aliases use explicit structural seams matching production. Controls cover first-node callback state, nested retention, same owner charges, postcheck stop, finite snapshot cap, stopped-control reuse, expired deadline, no-due equivalence and due native precheck-cap refusal. A first precheck fixture incorrectly used scheduler-only work threshold under search's additional parent charge; its failed assertion is preserved in tests.precheck-initial.log. The corrected direct scheduler test proves that precheck Cap becomes sticky Owner, and existing search tests prove Owner propagates without branching.

Focused rustc test build uses 1 GiB virtual-memory cap, 40-second CPU limit, 45-second wall timeout and single-thread linker. No full Cargo build, cloud work or scientific data generation occurred.
