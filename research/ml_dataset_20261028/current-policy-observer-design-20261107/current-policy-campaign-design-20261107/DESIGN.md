## Population and separate collection streams

Preserve every requested field size n=23..31 and47..61, m=2..15, binary/Koblitz/prime families, both twists,16 curve seeds,8 generator indices and64 key indices. The prime constructor at n=61 selects2^61-1. These counts preserve the intended large inventory; they are not a cost estimate or commitment to execute all cells.

Four compact templates make the current source choices explicit:

- binary-koblitz-methods: plan/v2 with legacy, projected sampled-x control, literal binary-subspace intersection and Frobenius-union intersection; ten method IDs including enumeration/PDP, BSGS, SAT, Weil, F4/F5/F6, root, PKM and double-large-prime.
- prime-methods: plan/v2 with legacy and projected sampled-x control, and the ten method IDs plus explicit f4-wide-dynamic-v1. The explicit dynamic ID selects the implemented wide prime route; ordinary f4 does not select that route for m4..15. Binary coordinate policies are not silently renamed as prime policies. Prime-specific structural base discovery remains a method-development requirement.
- owned-matrix: plan/v3, exclusive channel/v5, f4, pattern0 and conservative_affine_envelope_checkpoint_v1. It requests one pattern's retained search rows. At m>2 there are2^(m-2) patterns; this template does not cover the entire pattern population. A later bounded, reviewed pattern schedule is required, recorded as separate plans because channels are plan-wide.
- sat-search: plan/v3, exclusive channel/v4, sat,10000 retained events and10000 conflicts as provisional software caps. This requests captured model search, not an UNSAT proof.

All streams retain unsupported cells and construction failures as outcomes. Presence of a solver ID is not implementation coverage or a solution. Existing F6 is geometric four-sum; do not train labels implying general F6 Gröbner semantics. High-arity PKM/root/Weil and prime SAT/F5/F6 remain coverage gaps from the source audit. Additional symmetry/orbit and double-large-prime features must be tied to emitted artifacts, not inferred from the selected family/method name.

The templates use factor-base size8, degree cap3 and work cap100000 from the old inventory as provisional values, not demonstrated sufficient limits. Binary basis[1,2,4,8] is a four-dimensional vector subspace recipe, not a claimed subfield. Candidate limit4096 is explicit. Actual accepted point count, orbit count and Boolean variable count must be measured. No resampling to fill a requested size after seeing solver success. Size, basis dimension, degree cap and work cap become crossed blocks in later bounded plans, each registered before its affected data.

## Comparisons and confounders

Claim classes: exact_computation for independently checked point equations, memberships, recovered scalars and retained row consequences; comparative for finite-population differences in measured solving cost or certified degree; out_of_scope for asymptotic FFD/LFD bounds and universal degree ceilings inferred only from finite samples. These drafts make no comparative finding.

Pair by family,n,curve_seed,generator_index,key_index,twist,m and seed, then cross policy/method/channel. Read actual public instance hashes to verify matching; config equality is not enough. Source generation chooses G and Q independently of policy/solver/channel, but construction can fail, so preserve paired missingness. Twists are paired strata, not identical-group controls. Derived stream rows are not independent new targets. The sampled-base seed excludes generator_index, key_index and m; repeated base constructions within a curve/twist block are correlated, not independent factor-base draws. Use curve/twist blocks as clusters in sampling and uncertainty estimates.

The projected control and literal intersection policies change both domain geometry and projection/membership construction; their raw comparison is a factorial recipe comparison, not an isolated causal effect of subspace structure. Report realized base cardinality and preprocessing cost. A decisive one-factor structure claim additionally needs a matched-cardinality, same-membership construction control not supplied by these templates. Treat cardinality adjustment as predeclared analysis, never post-hoc dropping unmatched results.

Reference: exact enumeration on domains small enough to finish, with independent witness/relation/scalar checks. Solver comparisons require the same equations, order, caps, preprocessing accounting and source/binary. Do not use reference exhaustion as a negative mathematical label. A/A duplicates the same frozen input under the same instrument with only randomized arm-order nuisance. Positive controls use separately tagged planted relations/known tiny algebraic systems through the same checker path; negative controls use independently certified no-relation/UNSAT systems or matched randomized systems with truth explicitly known. An unsolved random instance is not a negative control. Controls cannot be mixed into the unconditioned target training population without tags and separate evaluation.

Randomize arm order within target blocks using a frozen schedule; retain every scheduled and attempted arm. Record commit/binary hash, flags, threads, host, memory, order, seed, stop cause, retries and checkpoint lineage. CPU instructions and algorithm work are separate metrics. Counter availability and multiplexing must be explicit; missing instruction counts remain null. No timing comparison on shared restored work without qualified isolation/A/A evidence.

## Labels and what models can learn

Keep distinct label types: known-answer construction; independently recovered DLP; PDP relation witness; verified partial row; SAT model; independently verified UNSAT; censored timeout/work/memory/trace limit; unsupported; integrity failure. A known scalar used to construct Q is never a recovered-scalar label. A prefix or historical row is never a completed producer or solve.

Candidate learning tasks include factor-base recipe ranking under matched cost, relation likelihood, algebraic-row selection, SAT branching/restarts from causal predecision state, and Frobenius-orbit compression. Each task needs its own feature/label projection and evaluation population. Current historical row exports admit restricted identity/row scope; they do not yet admit causal search-policy training. Do not expose later events as earlier-state features.

Private scalars, factor-base logs, generator multipliers, seeds sufficient to reconstruct labels and provenance are restricted. Training features contain only authorized public state; supervised labels stay separate. All streams, methods, policies, keys, generators, twists and isomorphic models at a field size share its split. The source formula currently assigns validation n26,61 and test n24,52,59; the other requested sizes are training. Thus the2^61-1 target belongs to validation, not training. Preserve that assignment rather than moving a desired target after observing performance. Cross-size transfer links need an explicit component index before stronger leakage claims.

FFD, LFD and degree-of-regularity labels are distinct and default null. Record monomial order, equation system hash, field/Boolean quotient conventions, closure degree, saturation status and certificate scope. Failure to derive1 in a restricted window is inconclusive. A full closure lower bound on an unsatisfiable input needs the independent unsatisfiability/solution-count bridge. Search maximum degree is not a certified regularity or last-fall label. Finite counterexamples need replayable exact certificates; asymptotic claims need a separate theorem.
