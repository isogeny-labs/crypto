# Continuation joined to actual original Budget core

This standalone harness combines unchanged continuation/search/checker donors with the previously mechanically extracted actual Budget core. A thin harness admission forwarder sends incremental continuation reservations to Budget.observe using the original cumulative phase_native counter. The core itself is unchanged and hash-bound; this is not a substitute ledger. It is not the authentic worker ingress or full owning adapter.

Nineteen tests passed: three new joint controls and sixteen donor controls. The positive control enumerates all four assignments of two unconstrained variables using one Session and Budget. Every candidate callback sees the original ownership identity and deadline, remains Matrix, and shares the original addition count. Final native totals equal cumulative continuation reservations plus the original construction reservation. The controls also consume the exact original addition allowance and verify next admission refusal, retained callback error, unchanged cap and forbidden exclusion; and fill the native-phase byte allowance before continuation, verifying sticky refusal without phase reset. Callback reservation consumption is deliberately reflected in the original Budget rather than the wrapper charge counter.

These are synthetic software admission controls. The callback does not perform elliptic-curve arithmetic; its additions are admission calls, not claimed completed group operations. Exclusions are test caller assumptions, not signed-lift proofs. Exact checked-map ingress, actual owning adapter compilation, signed-lift/exclusion replay and full worker capture/CLI remain separate gates. Core extraction excludes later reserve_checking/capture methods and source authentication. No scientific row, cloud job, retry-budget use or production edit occurred.
