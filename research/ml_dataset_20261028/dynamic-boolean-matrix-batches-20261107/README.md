# V3: same-degree Boolean matrix batches

External source implementation based on reviewed immutable V2. No shared source, scientific dataset, cloud or original-limit change. This is the batch matrix component of the planned arbitrary-width route, not F5, signed solution search, CLI admission, large-field performance or fall-degree evidence.

Every minimum-degree task currently pending is frozen into a batch (serial tie order). All candidate polynomials/proofs are materialized before any pivot operation. Symbolic preprocessing reaches a fixed point over all terms in candidates and admitted reducer rows: for each reducible column it retains an exact basis-index/multiplier dictionary entry and the actual scaled polynomial. Boolean multiplication may cancel terms, so a reducer is admitted only if its computed leading column equals the intended column. Reducer rows then candidates are processed through one shared sparse pivot dictionary. Cross-candidate pivots occur inside the same batch. Every XOR has a retained target/source row-index operation and exact updated original-generator derivation.

Batch history owns initial source rows, working matrix rows, reducer dictionary, pivot operations, row ordering, pivots, stage/cursors and original basis length. When a working-copy allocation fails after source admission, initial may contain one more row than matrix; the source row and reducer metadata remain retained. Scratch of an uncommitted arithmetic operation may be dropped while its charges remain. A stopped attempt is retained evidence, not a validated resumable checkpoint.

Novel reduced rows from both candidates AND symbolic reducers are staged. Dropping novel reducer rows could hide unresolved pair work. Only rows whose leading monomial is not divisible by an old basis lead are selected; their exact matrix-to-new-basis index identities are retained. All ordinary and necessary leading-variable field tasks are staged before a bounded, prepaid, allocation-free commit. Before commit the old basis and pending tasks stay coherent and unchanged. Commit removes exactly the frozen degree's tasks and appends staged basis/tasks. New limits batch_rows, batch_ops and batches are explicit additional bounds under the same cumulative Owner/deadline; none renew the caller's resources.

## Validation

Authoritative test.receipt.json reports exact source/binary hashes,60second test bound,exit code and unchanged readback. tests-final.log reports16PASS,0FAIL. Nine scheduler tests and seven unchanged donor tests run. Tests require at least two same-degree candidates, an actual candidate1 XOR candidate0 interaction, later field tasks, and retained matrix/proof operation replay. Independent checks reconstruct every row XOR and generator proof XOR, verify every original-generator identity, and verify dictionary rows equal the indicated basis multiple.

Existing exhaustive256two-variable systems and32three-variable systems compare independently enumerated ideal spans and reduce every enumerated ideal member. These test-only oracles do not become the production algorithm. Other controls cover variable129 nontrivial reduction, V2 empty-generator admission, work/deadline/malformed limits,1499generic owner-refusal points, and a sweep through every admission point in a complete multi-batch run. The latter requires observed Build,Symbolic,Eliminate,PrepareCommit,Committed states, a retained pivot operation at an elimination refusal, staged rows at a commit-preparation refusal, exact old-basis length and retained pending task IDs before commit.

No proof of requested-size practicality follows from these tests. Next integration requires independent review, bounded complete source expansion with actual CheckedMap/original-owner binding, operation replay in the production verifier, then model extraction/signed lift and CLI/export. F5 remains separate signature-aware work.
