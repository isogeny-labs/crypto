# Binary/Koblitz m4..15: complete bounded matrix route

Read-only source design, 2026-11-07. No source edits, builds, experiments, cloud calls or Conductor actions. Evidence hashes identify inspected bytes, not an inferred Git revision. Existing proposals were searched before designing new work.

## Decision

Reuse `checked-map-boolean-equations-proposal-20261102-v2` and `higher-arity-sparse-row-proposal-20261103`; do not write another equation expander or fixed-width elimination kernel. Their missing integration is substantial: private original-owner binding, genuine n23+ validation, arbitrary-width search, F5 selection, all-pattern coverage, central replay and actual CLI delivery. The smallest complete vertical slice is an explicitly named **bounded gate-polynomial F4 search**, supporting every m4..15 by representation and control flow, with real sparse elimination plus bounded splitting, signed group lift and honest partial outcomes. A matrix-row identity alone is a valuable intermediate artifact but does not complete this slice. F5 must subsequently use actual signature-safe selection, not an engine-name alias.

## Source and encoding contract

Current chained source has direct AND gates, XOR rows, units, an impossible flag and finite-domain prefix clauses. Prefer these direct field/gate data, accessible inside the provenance module, over parsing DIMACS. The existing V2 child-module wrapper already has this access. Wire w is variable w-1. Ordered Boolean-quotient generators are g+l*r for each AND; sum(wires)+rhs for each XOR; w+value for units; 1 for impossible; then the exact clause-unsatisfied products for finite-domain clauses. Preserve zero generators and ordering. A positive literal contributes (1+x); a negative literal contributes x. No learned SAT clauses enter the original source set.

Name the presentation `checked-chain-gate-anf-v1`, retaining the field polynomial, basis, curve b, target, original signed domain, code order, identity pattern, map binding and generator hash. It is an auxiliary-wire extension of the field chain. Even direct gate equations are a different polynomial presentation: measured row degrees/closure degrees belong to this named presentation, not the original Semaev or selector-only Weil system. Domain prefix expansion is bounded and may be exponential; preflight/charge each candidate term, retain a partial attempt, and refuse rather than omit a clause. A future factored-domain backend is a separate format/checker.

The independent equivalence obligation is on **all assignments**, not only SAT models: AND polynomial iff its gate, XOR iff parity, unit iff pin, clause product iff clause, and constant 1 iff impossible. Combine that with independently reconstructed CheckedMap field semantics. Include both directions between field chain assignments and gate extensions. This does not prove every x-chain has a signed group lift.

## Exceptional patterns and lift

There are 2^(m-2) intermediate identity masks (8192 at m15), under one original deadline and ledger. For each addition, previous/output identity flags select exactly:

| previous | output | source condition |
|---|---|---|
| affine | affine | n coordinates of S3 via checked gates |
| identity | affine | next summand x equals output x |
| affine | identity | previous x equals next summand x |
| identity | identity | impossible, because every domain summand is affine |

Intermediate identity blocks are explicitly zero-pinned; target identity also has zero coordinates and its identity flag is separate from an affine x=0. Never conflate these. Cover both affine and identity targets. Signed-domain verification must retain actual allowed points, not presume both signs are allowed. Each candidate x-model must be independently evaluated against the complete generator set and original field map, then lifted by choosing allowed signed points and verifying their sum equals the exact target. Capped lift or a spurious x-model is incomplete, not a pattern refutation; continue the same bounded search or report Unknown. Exhaustive refutation requires every model in every pattern to be excluded and search coverage checked. No SAT UNSAT boolean is a substitute.

## Why existing mask engines do not fit

`pq_groebner_f2` uses u64/u128 monomials. The chain all-affine bound is n(2m-1)+4n(m-1)+3n²(m-1): 5198 at n23,m4 and 161467 at n61,m15. These are construction bounds, not observed accepted sizes. Current BQI1 software limits also cap variables and generators at4096. Do not crop original variables/generators or cast high indices into masks.

Direct field coordinates reduce auxiliaries but do not solve the range issue: n(m-2)+m*ceil(log2 K) variables already reaches883 for n61,m15,K64. Substituting gates into selector-only equations risks exponential terms and loses the original bounded representation. Therefore use sorted variable-index monomials with union multiplication and parity cancellation. The existing sparse-row donor does this. Introduce an explicit admitted checker profile sized from actual source counts and remaining original resources; this is a reviewed software profile change, never an implicit allowance increase. Rejection of an oversized cell remains recorded, but supporting only exceptional low-wire patterns cannot establish general arity coverage.

## Native iteration: exact reusable loops and new code

The next native implementation is not just invocation of the saved finite `reduce` function. Existing reference algorithms are `koblitz_groebner.rs::matrix_f4_f2_counted_impl` (degree-bound candidates and packed elimination), `solve_rec` (node specialization, exact original evaluation and two-way splitting), and `pq_groebner_f2.rs::groebner_basis_f2_within` / `queue_field_pairs` (ordinary and Boolean field pairs). These are semantic donors, not callable arbitrary-width backends: their polynomial, output, pair and definition state contains Mask. Keep native operation/count names distinct when reimplementing.

New dynamic scheduler state must retain basis polynomials with generator-combination proofs, ordered pending ordinary pairs, ordered field pairs, next degree window, admitted multiplier cursor, active matrix/candidate dictionary, and completed/queued pair IDs. Use an explicit degree-compatible monomial order; the old sparse-row lex vector order alone is insufficient to claim the donor's degrevlex trajectory. Ordinary pair LCM is variable-set union; quotients are set differences. On inserting each new basis row, queue applicable ordinary pairs and a field pair for every variable in its leading monomial. The existing Boolean reference processes x_i*g (quotient-normalized) for these field pairs, unless it equals g, and reduces it; omitting these pairs can miss Boolean closure even when ordinary pairs are exhausted. Retain each origin and proof through matrix row XORs.

At a fixed degree window, construct symbolic reducer multiples for queued pair polynomials and missing leading reducible monomials, prepay and deduplicate by explicit source/multiplier identity, then perform the real sparse matrix reduction. Insert novel reduced rows and enqueue their pairs. Continue until no admissible pairs/multiples remain, the next degree exceeds the frozen cap, or the owner stops. A window cap returns partial closure; it is not a Gröbner-completeness or LFD label. For the first correct implementation disable optional pair-skipping criteria rather than import unproved mask-specific criteria. Later criteria require explicit certificates/controls.

For solve mode, reuse the solve_rec algorithmic structure with a new dynamic assignment vector and explicit pending branch stack. Both zero/one children inherit the same original equations and current owner. Specialization must retain a checked substitution map back to original variables, or simply retain assignment equations and avoid destructive variable deletion in the first version. Model extraction verifies all original generators and field-map equations before signed lift. A resource stop retains the queue/matrix/branch state and unvisited identity masks; it is not automatic checkpoint resumability until restoration is separately validated. This scheduler plus actual matrix reduction plus exact extraction is the complete native F4-style route. F5 remains a separately implemented selection layer with its own valid Boolean signature rules.
