Written after analysis001 reported all210 counts known, no single cutoff
separating the labels, and two omissions retained by the per-field joint
upper bounds. The original plan, profiler, preparation and outputs stay
unchanged. This is a disclosed post hoc validation stage, not a second
historical sample or a retrospectively preregistered analysis.

Implement a second native extractor using direct line/token scanning instead
of the profiler's regular expressions. Check all210 integer cells against the
original saved packets and catalog. Check complete ordered depths, exact root,
descending integer strings, unique chosen route, strictly increasing catalog
ranks, full CLI completion and every original input/status byte. This stage
expects the observed complete feature matrix; any missing/unknown input stops
validation rather than being converted to zero.

Recompute all40 declared single envelopes and both joint upper envelopes
independently from the checked table. Produce every retained omission with a
published extremum witness. Metadata comparison can check exact JSON equality;
all counts and bound calculations remain native C++.

Also report a post hoc descriptive diagnostic over the same ten features:
list each omitted/published same-field pair for which every omitted count is
at most the corresponding published count. Such a pair is a counterexample
to any coordinatewise nondecreasing cost screen on these ten counts that
accepts that published curve. This adds no new feature or fitted threshold.
The condition does not cover real costs absent from this vector, original
hardware/runtime or a caller with another acceptance rule. Do not claim a
historical cutoff or an attack from this diagnostic.
