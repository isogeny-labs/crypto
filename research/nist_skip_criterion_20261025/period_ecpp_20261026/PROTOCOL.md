PARI2.17.3/OpenSSL. It replaces scientific Python orchestration/validation.
First run50 fixed positive arithmetic pairs spanning limb boundaries up to

against native PARI:250 exact comparisons. Require ABI4/4/4/4 and the complete
ordered row inventory. The first trial uses the host's native32 execution;
an unsupported ABI is an implementation failure, never a curve rejection.

Prover controls: original full-data primes101/65537, composites15/341,
CM-only101, CM-only101 with an explicitly empty catalog, and CM-only101
with a missing catalog. The latter is required to be indeterminate/nonzero,
not a prime/composite scientific verdict. Modified control data never enters
the cohort. Positive certificates run through the legacy checker and an
independent native strict format/binding reader. That reader requires the
requested root, strictly descending/dividing chain, recognized theorem
routes, complete Pratt termination, one final sentinel and no trailing data;
it matches every legacy checker step index/discriminant/success flag and
rejects its failure markers. Exit0 alone is insufficient. Native modern
primality of every requested root is separate from certificate-format admission.

Negative binding controls use a genuine positive101 certificate: wrong root,
missing final sentinel and appended second certificate must be refused even
when paired with an old successful checker transcript. These are integrity
controls, not new mathematical samples. Every control must pass before a
named order runs; preserve any failure and stop instead of relaxing admission.
