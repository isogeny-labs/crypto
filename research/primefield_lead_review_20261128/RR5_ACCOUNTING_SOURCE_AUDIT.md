# RR5 streaming accounting: source audit and patch target

2026-11-25. Read-only inspection of the public `crypto` #5120 branch at `research/prime31_four_summand_20261122/native/{query_pipeline.rs,extractor.rs,relation_adapter.rs}` and current main `src/cryptanalysis/f4_fp.rs`. Source links: [query pipeline](https://github.com/isogeny-labs/crypto/blob/lane/m31-integrated-build-20261123/research/prime31_four_summand_20261122/native/query_pipeline.rs), [extractor](https://github.com/isogeny-labs/crypto/blob/lane/m31-integrated-build-20261123/research/prime31_four_summand_20261122/native/extractor.rs), [adapter](https://github.com/isogeny-labs/crypto/blob/lane/m31-integrated-build-20261123/research/prime31_four_summand_20261122/native/relation_adapter.rs), and [F4 visitor](https://github.com/isogeny-labs/crypto/blob/main/src/cryptanalysis/f4_fp.rs). This is a source-level proposal, not a compiled patch or measured cost claim.

## Existing instrumentation

- `QueryPipeline::submit` forms `[a]G+[b]T`, calls `extract_cofactor_visit`, consumes each signed row through `RelationAdapter::accept`, and records query group-operation counts plus **cumulative** adapter work. `QueryReceipt::phase_accounting_complete` is always `false`. It has no elapsed phases or per-query adapter delta. The early `AlreadyRecovered` return must remain explicitly priced if calls are included in a campaign.
- `extractor::extract_*` times out cooperatively. It counts symbolic additions/multiplications, root multiplications, F4 `VisitReport`, and curve work, but does not divide its elapsed interval into construction, normalisation, visitor, lift, and finalization. An error from `solve_visit_traced` returns early without copying a traversal report; loss of work on that branch must be disclosed, not treated as zero.
- `f4_fp::F4Options` has opt-in `visit_timing`. `VisitReport::timings` then contains `total_ns`, `native_f4_ns`, `root_recovery_ns`, `callback_ns`, and `traversal_other_ns`; its own implementation asserts the four inner parts do not overlap. The extractor currently leaves the option off. A callback includes signed lifting **and** the adapter's row work, so assigning all callback time to algebraic extraction would double count or misclassify it.
- `RelationAdapter::new` validates the curve, target and base and stores setup arithmetic counts; the caller builds the base before that. `RelationAdapter::accept` counts modular row operations and group replay, but no wall time. `QueryPipeline::new` allocates and validates without returning a setup receipt.

## Smallest coherent patch

1. In the RR5 extractor, turn on `opts.visit_timing` only for an opt-in accounting mode (or add an accounting-enabled entry point), retaining the historical serialized/default path. Record an outer `Instant` at entry and nonoverlapping construction, normalisation, visitor, post-visitor lift, and finalization spans. On every return, include elapsed time and a phase-completeness/reason field; do not represent a missing visitor report as zero work.
2. In `QueryPipeline::submit`, record outer elapsed and nonoverlapping query point, extractor call, and receipt/finalization spans. Preserve the visitor's callback total as a **nested** diagnostic, not an additive sibling of the extractor interval. For each query, derive adapter-work and adapter-arithmetic deltas from pre/post cumulative counters with checked subtraction; leave original cumulative fields for compatibility.
3. Time `QueryPipeline::new` separately and require the outer campaign driver to time factor-base construction, query selection, all submits, final scalar verification and serialization according to the declared cold boundary. Do not set `phase_accounting_complete=true` for a query merely because the nested spans sum; the full campaign is the primary gate.
4. For a tiny public target, check outer elapsed bounds each disjoint sum, nested visitor partitions exactly, replay status preservation on `ConsumerStopped`, `Deadline`, `OutputLimit`, `ResourceLimit` and trace errors, and the final `dG=Q` inside the timed interval. Record any unpriced native instruction family explicitly.

This audit avoids a premature claim that visitor timings alone complete cold accounting. It also identifies the first patch as a small opt-in instrument, rather than a change to the RR5 algebra or row acceptance semantics.
