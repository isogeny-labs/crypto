# Fixed trace-fiber engineering preflight, version 1

This is the exact engineering run contract, frozen before its first geometry data. It is not the later canonical full-census protocol and carries no measured result. [pcc:unverified]

## Question and scope

For the one actual public point Q=P=(1,8) on E/F37=(7,19), does the quartic parameter candidate produce exactly the complete trace fiber selected by independent extension-field group enumeration? Both instruments must retain tangents, all signs, all rejected parameter attempts and inverse-twist coordinates. The identity branch is implemented but is NOT exercised by this fixed-point preflight; its full-census acceptance remains separate. [pcc:unverified]

The candidate receives actual Q coordinates through its fixed fixture, not a target logarithm. It attempts all 37² parameter pairs. The auditor constructs the entire E(F37²) population using its own arithmetic before selecting points with R+Frob(R)=Q. Saved candidate answers cannot populate its reference. These are intended algorithms, not checked coverage claims. [pcc:unverified]

The finite fixture is historical development input: A=7,B=19,d=35, monic twist (28,33), supplied subgroup order19 and h=10. Each native implementation checks its own point/order and coordinate-map conditions. No new curve registration, generic map, relation solver or DLP recovery is claimed. [pcc:unverified]

## Binding and order

`ENGINEERING_INPUTS.json` pins the producer, auditor and geometry contract. `ENGINEERING_PINS.json` additionally pins the launcher, Cargo manifest/lockfile and both actual compiled binaries. Neither pin file contains credentials. Their byte hashes and the committed branch head belong to the run record. A later rebuild with different binary bytes needs a new dated pin version before affected execution; do not silently overwrite this freeze. [pcc:unverified]

The order is candidate A, independent audit A, fresh candidate B, independent audit B, exact dataset/receipt A/A comparison, then these controls in order:

1. wrong-d
2. wrong-target
3. missing-tangent
4. duplicate-record
5. wrong-inverse
6. missing-attempt
7. false-root
8. missing-case
9. source-pin
10. spurious-infinity

Every control must actually change payload bytes, recompute the dataset digest, reject with101 and leave no receipt. The launcher retains the entire false payload, digest, command, output and exit. If a required branch is absent and mutation cannot change it, stop and retain the inapplicability failure; do not count it as a successful control or silently remove it. A/A tests determinism only, not timing variance. [pcc:unverified]

## Admission, failures and resources

Success requires two complete independent geometry replays, byte-identical A/A datasets/receipts and all ten changed-payload rejections. A missing positive invalidates the candidate; a timeout is incomplete, not a null advantage. No favorable subset or scalar-label fallback is permitted. The first failure stops this engineering sequence and is retained before a versioned correction. [pcc:unverified]

Use `timeout --signal=TERM --kill-after=10 3600 bash run-fixed.sh`, with two existing local workers maximum and each native stage capped600seconds. This script is sequential. No paid resources, AWS authentication probes or arbitrary result uploads. Shell glue and Python do file/JSON/hash checks only. [pcc:unverified]

The launcher checks the exact approved branch/repository/prefix, clean committed source, current fetched official gate, token presence and frozen pins, then invokes the unchanged official checkpoint gate BEFORE any native scientific command. Token absence or gate failure admits no native command. Existing upload permission persists; credential values must be configured privately, never pasted in chat, PRs or evidence.

Raw outputs remain outside the checkout during engineering. After review, preserve exact sources, successes, failures and altered payloads in the research evidence directory using the established archive policy. Update the truthful RESUME with actual outcomes before the authorized finish/failure checkpoint. No automatic finish checkpoint may upload a stale state description.
