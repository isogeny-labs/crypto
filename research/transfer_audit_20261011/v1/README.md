# v1 of the transfer audit (preserved)

This directory holds the **first run** of the transfer audit exactly as it was committed before
Amendment 3: schema `transfer-audit/certificate/v1`, tool `transfer-audit/1`. It is evidence, not
a working copy. Nothing in it is edited, regenerated or renamed.

The current files one level up (`../certificates/`, `../RESULTS_SUMMARY.md`, `../RESULTS_TABLE.md`,
`../cost_ratio.*`, `../pipeline.svg`) are **v2**, regenerated by the corrected tool (PR #2658). The
v2 regeneration wrote over the v1 paths in place, which removed the v1 set from the tree. It stayed
in git history; this directory restores it so both sets are in the tree side by side. The restoration
changes no v2 file and no tool code.

## What is here

| path | what it is |
|---|---|
| `certificates/` | the 96 v1 files: per-curve certificates, `controls/`, `index.json` (SHA-256 index of 92 of them), `run-log.json` |
| `RESULTS_SUMMARY.md`, `RESULTS_TABLE.md`, `cost_ratio.csv` | the v1 report outputs |
| `cost_ratio.svg`, `cost_ratio_controls.svg`, `cost_ratio_toy.svg`, `pipeline.svg` | the v1 figures |

`certificates/run-log.json` and the F9 records under `certificates/controls/` are the measured part of
the first run. They are the same bytes at the top level, which Amendment 3 kept.

## Provenance

Every file is the git blob at commit `3f31162cd47c544634447601021e20dc48761f88` (merge of PR #2578),
which is the state of `research/transfer_audit_20261011/` on `main` immediately before PR #2658 merged
(`9bb674cc43` has an identical study tree). Extraction was `git archive` of those paths, so the bytes
are the originals.

Checks made when this directory was added:

- all 92 `sha256` entries in `certificates/index.json` match the files here;
- `git diff 9bb674cc43 3f31162cd -- research/transfer_audit_20261011` is empty.

To repeat them from the repository root:

```sh
git diff --stat 9bb674cc43 3f31162cd -- research/transfer_audit_20261011        # no output
cd research/transfer_audit_20261011/v1/certificates
jq -r '.. | objects | select(has("sha256")) | "\(.path // .file // .name)  \(.sha256)"' index.json | sha256sum --check --quiet
```

## What changed from v1 to v2

[`../RESULTS.md`](../RESULTS.md) section 10 lists each correction with the old and new value, and
[`../PROTOCOL.md`](../PROTOCOL.md) Amendment 3 gives the reasons. In short: the baseline rose 0.5 bit
(negation counted once), binary cover images get the baseline's Frobenius class, a weakness verdict
needs an 8-bit margin below the baseline, `refuted` is restricted to carried, priced routes, and
every certificate gained an `evaluation` field. v1 certificates are not readable as v2
(`src/bin/transfer_audit/certificate.rs`).

## What this directory is not

- It is not checked by `transfer-audit check`, which regenerates and compares the v2 set only, and
  `transfer-audit report` reads `../certificates/` only.
- Its verdict labels (for example 15 of 29 sweep curves `class-weak`) are superseded. Cite v2 for
  any current statement and this directory only for what the first run said.
