# L02 deviations from PROTOCOL.md / SPEC.md

PROTOCOL.md and SPEC.md were not edited (`sha256sum -c frozen.sha256` passed before any code was written). No threshold, arm, seed rule, decision rule, instance size or grid cell was changed. No repository hook refused a command (`raw/REFUSALS.txt` not created). No command hit its 900 s timeout (`raw/TIMEOUTS.txt` not created). The largest single command took about 5 minutes.

1. **SPEC 12 test 3 versus SPEC 5 uniqueness rule.** For `p=11, x^5+1` (expected 80) and `p=43, x^7+1` (expected 50624) the SPEC 5 rule ("unique survivor of 32 random divisors") returns `None`: the survivors are `80, 85, ..., 100` (step 5) and `47460, 49042, ..., 56952` (step 1582), because the 32 random point-sum divisors do not generate the whole group. The code implements SPEC 5 as written (such curves would be rejected as `order_ambiguous`; one F7 candidate was, see RESULTS section 8). `selftest.py` test 3 for those two entries asserts that the rule returns `None` and checks the expected value independently from the L-polynomial (genus 2: `N1, N2`; genus 3: `N1, N2, N3`, `N3` counted over `F_{p^3}` inside the test). The brute-force reduced-divisor count for `p=11` (80 and 271) agrees. All other entries of test 3 pass literally.
2. **Test curves outside the admission rule.** Tests 4 and 7 use `p=31, x^5+1` (`#J = 880 = 16 * 5 * 11`, not admitted by `h <= 64`, `r > h`). `build_curve` got an `admit=True` parameter; the selftest helper builds with `admit=False` (everything else identical: order, `lambda`, `nA`, `nB`).
3. **Control polynomial draw order and repeated primes.** SPEC says only that `c_i` come from `Random(seed_of("ctrl:{q}:{p}:{j}"))`. Implemented as `c = [rnd.randrange(p) for _ in range(q)]` giving `c_0..c_{q-1}`. When several CM curves share a prime `p` (F5: 1031, 2081, 4111 have three each, 8221 two; F7: 281 and 547 three each, 1051 two), the "first admitted `j`" would be identical for each; to keep three distinct controls per cell and unique `curve_id`s, each later control at the same `p` continues the `j` counter after the previous one. Rejected `j` values are logged in `raw/instances_C*.jsonl`.
4. **Gate seed label.** G1 "annihilates 32 random divisors" uses a fresh label `gate:G1:{curve_id}` (not in the SPEC 2 table) so the gate divisors differ from the selection divisors; G1 also recomputes `jacobian_order` and compares with the stored `N`. The G2 transport check uses the SPEC label `transport:{curve_id}`.
5. **`N2` computation.** `count_N2` evaluates `f` over `F_{p^2}` using the conjugation symmetry `x1 <-> -x1` (equal norms, weight 2) and list-comprehension Horner; the count is identical to the direct sum (verified by test 2: 123 and 1879, and by test 3 order values). Uncounted, set-up only.
6. **Identity shortcut.** `jac.add` returns the other operand without a counted operation when either operand is the identity, and `smul` starts from `R = D` (SPEC 4 left-to-right). `sqrt_mod` uses `fpow` for `p = 3 mod 4`; it is only called in uncounted set-up.
7. **Safety cap in `run_ic`.** An IC run stops with `status = "trial_cap"` after `50 * target + 20000` trials. Not in SPEC; it was never reached (all 360 IC runs `ok`).
8. **Command wrapper.** `ulimit -v 2000000` and `timeout 900` are applied to each `python3` invocation (each `(k, arm)` pair separately) by `code/runcmd.sh`, with the for-loops of PROTOCOL section 9 in `code/run_all.sh`; the selftest, instance, gate and analysis commands were run one by one through the same wrapper. The selftest command was wrapped as `bash -c 'python3 code/selftest.py > raw/selftest.txt 2>&1'`. The `sha256sum` line of PROTOCOL section 9 was run directly after the analysis (`raw/data.sha256`); per-file hashes are also in `raw/COMMANDS.log`. `raw/.alldone` is a completion marker written by `run_all.sh`.
9. **Analysis details left open by SPEC 11.** Cell statistics use the curves present in all four arms A, B, R_neg, R_aut (all 3 per cell); the arm mean is the mean over curves of the per-curve seed mean; percentile CI uses linear interpolation; pooled D1 and rho_gain are geometric means over the decision cells, bootstrapped in the same replicates as pooled N. Control cells (C5, C7) are analysed with the same code and also get CIs. Resampled curve occurrences are resampled over seeds independently per occurrence.
