# Shared exact point index implementation

2026-11-27. Crypto PR #5282 and cryptanalysis mirror PR #2003. This is a native code integration and correctness record, not a measured speedup. [pcc:unverified]

The optimized two-slot collector now enumerates each factor base once with the same trial RNG and passes both complete point arrays to `PairTable`. Each slot retains one selector-ordered vector and one exact `HashMap<Point, usize>` carrying the original global column number. The hash map answers factor-base membership probes and supplies the matrix column and slot-tagged graph vertex. The optimized collector no longer constructs its separate `BTreeMap` point index. The ordinary reduction and independent certificate verifier retain their own tree indexes as separate control/replay paths.

Column assignment follows the point order returned by `FactorBase::enumerate`, which sorts and rejects duplicate points. Right-slot columns begin after the left slot, even when both slots contain the same physical point. Membership hits still pass factor-base and group-sum replay; graph dependencies and recovered scalars still pass the original v1 verifier. The new map changes neither the `R-P` candidate scan nor the `N+1` row contract.

The test comparing each new column and row to the independent tree index uses a deliberately constant hash. Another test presents the same physical point in both slots and checks that the graph accepts their distinct endpoints. Existing known-answer, cofactor, malformed-input, seeded-certificate, final-RNG, strict-CLI and replay controls also exercise this source. The two common native files and two common docs are byte-identical across the paired worktrees; `native-source.sha256` and the lossless development log archive in `implementation-20261127/` bind the local qualification. These are producer development checks, not signed independent standing. [pcc:unverified]
