## Field setup blocker identified by this audit

fp_backend.rs::Fp64::new at1107 allocates inv_fix and BigUint and calls compute_sqrt_pre at468. That helper has an open-ended search for a nonresidue plus optional HashMap/Vec square-root tables. F4 does not need these tables. Existing m2/m3 adapters also call this constructor; this is a preexisting outer-supervisor setup boundary, not proof of fully admitted native setup.

The first dynamic native module borrows &Fp64 and never creates or clones it. That makes the native accounting boundary honest but does not close end-to-end adapter setup. Before adapter completion, obtain separate ownership for either (A) a fallible bounded constructor covering existing complete Fp64 setup, including bounded nonresidue search/table allocations, or (B) a distinct arithmetic-only context sharing existing Montgomery kernels and exposing no bogus square-root methods. Do not create an ordinary Fp64 with placeholder sqrt state and expose it as fully initialized. No runtime retry to an unbounded constructor. A pre-existing case-local field may be borrowed only when its setup is explicitly charged once and its deadline covered by the original process context.

For native row inversion, use fixed binary exponentiation a^(p-2) via existing f.sqr/f.mul, checking a!=0 and the caller's prime certification. At most61 squarings+61 multiplies; charge128field operations plus fixed loop overhead. This avoids importing a new variable-loop inversion proof obligation. It is not a new field backend. Never call from_biguint/to_biguint in the inner loop; use from_u64/to_u64 conversions with validated canonical integer inputs. Serialized coefficients always leave Montgomery form.

## Ordinary F4 algorithm, exact completion rules

1. Import canonical input to internal monomial/Montgomery term vectors under reservation. Reduce initial generators deterministically, charging arithmetic and allocations; retain stable basis IDs and preserve ideal equality. Input generators above pair degree12 are not dropped. They are allowed up to degree32 and explicitly reflected in maximum row degree.
2. For every newly inserted basis polynomial form all ordinary pairs with older basis IDs. Skip only coprime leading-monomial product criterion. Store complete lcm and stable IDs. Pairs over degree limit remain counted, not silently discarded. No basis deletion or index reuse initially.
3. Pick the minimum pair-degree batch, ties by ascending pair IDs, with deterministic bounded prefix if a batch capacity requires multiple steps. Mark selected pairs in-flight rather than completed before processing. Construct BOTH cancelling monic multiples or their explicit S-polynomial. A one-sided unexplained row is not an S-pair implementation.
4. Symbolic preprocessing uses an ordered frontier of monomials. For each frontier entry scan stored basis leading terms for divisibility; choose lowest basis ID. Admit and include its monomial multiple once, expanding frontier until closure. Never enumerate exponent divisor boxes. Monomial/row dedup uses bounded Vec structures, charging scans and insertion movement. No hidden HashMap growth.
5. Sort columns descending grevlex. Build sparse column-index/coefficient rows. Reduce reducer rows first, then selected pair rows, in deterministic order. One dense canonical-u64 accumulator of C entries per batch is sufficient; explicit f.mul/sub per nonzero pivot entry avoids lazy-capacity and renormalization complexity in this first version. Pivots remain sparse and monic.
6. For each nonzero candidate row, bounded normal-reduce it against the current basis before insertion. Zero remains counted. This conservative postmatrix step ensures no stale leading divisor is promoted and avoids complicated extraction criteria. Newly inserted rows generate ordinary pairs. All rows remain ideal combinations; later S-pair exhaustion proves the resulting basis is a Gröbner basis under the prime/input hypotheses.
7. Complete requires all ordinary pairs exhausted, including none blocked above degree cap, and no in-flight work. UnitDerived requires a nonzero constant actually derived. DegreeLimit means above-cap pairs remain. Any interrupted selection remains pending/in-flight in counters. No full group nonexistence implication follows from affine UnitDerived alone.

Native derivation is producer-computed unless a separately implemented combination certificate checker verifies it. Do not assert independent derivation proof simply because S-pair counts or terminal basis are retained.

## Preallocation and modeled work tariffs

Freeze these definitions as a named reservation model before code. Constants are conservative modeled primitive units, not retired instructions. Every primitive below calls a sticky Gate; all arithmetic uses checked u64 and Layout/usize conversion. Original deadline is clamped once to min(original,entry+5s), never reset between phases or batches. Check before every allocation, row, pivot update, frontier scan, and at most256 coefficient/monomial operations; comparator sorts are finite bounded chunks with before/after checks and external hard supervision.

Let V active variables; M=size_of(Mono28), E=size_of(u64), I=size_of(u32), H current basis count, C columns, R rows, T terms, P pairs. Native memory reservation is cumulative/nonrefunded requested capacity, including transient copies; no peak-RSS claim. Prefer Vec pre-reservation and moves, not implicit clone/collect/resize growth. Each vector allocation charges `128 + capacity*size_of(T)` before try_reserve_exact. Vec-header storage within parent containers is charged by actual size_of. Capacity growth charges the entire newly requested allocation conservatively; moving already admitted ownership does not charge another copy.

- Coordinate predicates/comparison/lcm/quotient/product: `8*(V+1)` each, including checked degree/order loop. Exponent overflow stops before output formation. Unused coordinates remain zero.
- Field multiply/square/add/sub/conversion or nonzero test:16units each; inverse exponentiation reserves4096units including its<=122multiplications and loop/control allowance. No arbitrary implementation-dependent instruction claim.
- Input validation: charge metadata-independent bounded scan or report its separate `validation_work`; to avoid free work, reserve `32*(V+1)*input_terms + 32*(input_polys+1)` before scanning canonical order/degree, after length/V bounds and before callback. Invalid input can report consumed validation reservation without invoking backend.
- Sort T monomials/terms: precharge `32*(V+1)*T*(ceil(log2(max(T,2)))+1)`; in-place sort_unstable only. Equality fold adds `16*(V+1)*(T+1)`. No stable/allocated key copy.
- Polynomial shift/scale: reserve `T*(8*(V+1)+32)` plus full output capacity, before multiplication. Merge/subtract two sorted polynomials: `32*(V+1)*(A+B+1)` and capacityA+B; cancellation may reduce retained support but cannot erase temporary cost.
- Reducer lookup for one frontier monomial: `16*(V+1)*(H+1)`. Frontier duplicate lookup/insertion using Vec: `16*(V+1)*(C+1)` plus moved bytes/accounted storage before growth. Basis/pair scans charge actual bounded length, not exponential divisor count.
- Pair candidates after basis insertion: per candidate `32*(V+1)` for lcm/coprime/degree and queue ordering; if sorted insertion scans P, charge `16*(P+1)` tie/degree comparisons plus moved bytes before insertion. A Vec minimum scan per batch is simpler: charge each visited pair; no heap reallocation assumption.
- Sparse column lookup: binary search, reserve `16*(V+1)*(ceil(log2(max(C,2)))+1)` per term. Initial dense accumulator allocation once per batch:128+8Cbytes; zero/fill charge32C per row. Pivot directory128+I*Cbytes; sparse pivot row capacities separately admitted.
- Pivot update with Zpivot nonzeros: reserve `64*(Zpivot+1)` before f.mul/sub/scatter and counter changes, no output allocation. Dense leading scan/zero tests reserve32C per row or each scanned segment; normalization reserves4096+32Zoutput. Sparse drain reserves128+(I+E)*Zoutput plus row headers before fill. Zero rows retain charged work. Reusing accumulator capacity avoids charging another allocation but still charges clearing and arithmetic.
- Returned basis canonical conversion reserves output vector capacities plus32per coefficient, and every required monomial copy. Reserve a fixed terminal/result allowance at entry or move already owned buffers; failure must not attempt an unadmitted report clone. Event cap checked before callbacks; observer refusal is sticky.

The constants must be line-by-line reconciled with code before source freeze. If implementation changes algorithms (e.g. lazy accumulators, heap queues, hash indexes), amend the tariff first. The useful controls below must succeed under unchanged ceilings; universal immediate refusal is not implementation completion.
