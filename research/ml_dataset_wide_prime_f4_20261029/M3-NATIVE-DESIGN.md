## Proposed useful bounded4-variable algorithm

Introduce private profile selection from admitted n_free and carry it into both State::insert and reducer selection. Legacy admission=None and existing bounded2-variable path retain their original algorithm/tariffs and callbacks. No mutation of f4_fp_tower.rs is needed: keep imported any_between for old paths; add local bounded4 helper in the generic module.

For bounded4 insertion, replace `any_between(lh,l,groups.contains_key)` with `groups.keys().any(|c| c != l && divides(lh,c) && divides(c,l))`. With zero tower masks these predicates exactly characterize the original interval and preserve the boolean chain criterion. Each groups key is already lcm(lh,lm[g]), so the first divides is redundant mathematically but retain it to make equivalence explicit. Number of keys<=h; at mosth² predicate visits. Existing grouping representative, coprime flag, pair-retain logic, kept sort and active invalidation remain unchanged. No extra vector of all divisors or all group-key pairs. Iteration-order differences do not alter the boolean result.

For bounded4 reducer lookup, iterate only current lm_index entries (at mosth), which exactly matches what old divisor enumeration could return. Require divides(lm,m), choose shortest stored polynomial. Preserve old tie semantics by comparing free exponent vectors lexicographically in reversed coordinate order `[e3,e2,e1,e0]`: old odometer advances coordinate0 fastest, masks are zero, so first encountered equal-length divisor has the lowest reversed tuple. Do not use packed Mono's numerical order for tie-breaking: it contains stored degree bits and is not the odometer order. Preserve lm_index's representative if duplicate leading monomials exist; scanning every active polynomial without respecting that map could select a different one. This can be a streaming reduction with no new heap allocation.

## Explicit proposed charges, to be checked during implementation review

Let H=stored basis count<=256, P=stored pair count<=32768, F=frontier length<=admitted columns, T=number of source coefficient slots in a product batch, S=stored polynomial mono/value slots, N=total symbolic nonzeros. Arithmetic below uses checked u64 add/multiply; rejection precedes allocation or loop work. Constants are modeled work units, not retired instructions.

* Four-variable insertion work: `256*(H+1)^2 +64*(P+H+1)`. This reserves two4-coordinate divisibility tests plus comparisons per possible key pair, group construction, packed lcm/coprime/degree helpers, existing-pair filtering and kept sort. Existing insertion byte reservation `256*(S+8*(P+H+1))` remains, including group map/kept/newpair buffers; verify allocation constants against actual container capacities. Reject if slots>262144 or pending-inclusive pair cap fails before insert.
* Four-variable reducer batch work: `128*F*(H+1)`, paying4-coordinate divides, shortest-length lookup and exact tie comparison per map entry. Reserve before parallel map. Keep existing conservative byte reservation `4096*(N+P+1)` only after demonstrating it also bounds F; if that inequality is not established, add explicit `64*(F+1)` for found/todo/live frontier overlap. All workers must share one cumulative preadmission, not independent untracked budgets.
* Products: keep old high `T*(65²*8+256)` tariff initially rather than reduce it in the same change; update precheck to all4 coordinates, charging existing T*8 before visiting pairs of exponents. Four coordinate comparisons and addition fit that documented check tariff. Ordinary zero-tower multiplication cannot expand each source term. This conservative choice still permits the small fixed m3 controls; actual useful execution is a validation requirement, not an assumed outcome.
* Kernel work/bytes retain existing modeled envelope `64*(R+1)*(C+1)*(R+C+130)` and `256*(basis_slots+16*(R+1)*(C+1)+pair_slots+1)`. A separate source review must reconfirm temporary copies, pivot fill-in and concurrent live rows. Four exponents do not enlarge Mono storage (still128bits). Never equate cumulative reserved bytes with RSS.
* Keep fixed4096 diagnostic/report admission before observer, bounded error conversion, final-basis copied storage, sticky refusal and original5second ceiling. Preserve selected_pending restoration on all early exits.

These numeric charges are implementation targets requiring line-by-line review, not a proof of the current unmodified code. If container/work upper bounds cannot be established, gate the affected loop explicitly before work rather than substitute an outer timer or raise ceilings.
