# Run72 preregistration — authentic target-certificate RHS width sweep (Prime31)

Date: 2026-11-22 UTC. Repository: isogeny-labs/crypto, draft PR #4901, existing Rust crate `research/prime31_ic_20261115/native`.

## Research question

Run71 used four signed-three-summand decompositions per public target and produced 96 group-checked target-certificate difference rows. Is **K=4** the best width once the **cost of discovering certificates** is included? Test K=2,3,4 without changing the arithmetic, factor base, relation walk, public target cohort or validation machinery. This is a *downstream, generic-table negative control*, not a claimed non-generic index-calculus solver.

## Frozen design (before implementation/execution)

- Fixed ordinary cofactor-one curve: p=2147483647, a=847514846, b=2087444724, n=2147446831, G=(625037715,2100627251). Never use a specially weak curve.
- Original Rust `Arithmetic`, B677 (509 Dickson + 168 preexisting hybrid), 88 independently group-checked free rows, exact signed-pair authentic-RHS DSU, and full RREF quotient rank. Reuse Run69/Run71 source via `include!`, not a new EC implementation.
- Three separately compiled Rust example arms **K=2, K=3, K=4**. Each must use exactly 32 *public* unknown-index targets generated by one frozen xorshift64 seed; use the same seeds for all widths. Seed A = `0x68B677A1D1` (Run71 replay). Additional seed B = `0x9D3A6F5C127`, seed C = `0x2C6478EB19D`. The secret scalar only produces Q in the test harness and is read solely for post-solve verification.
- Signed-three-point certificate finder: same 916469-entry **generic** pair dictionary, same 1024-shift ceiling per target, same witness-verification logic. Different widths may have different certificate probes. Any failure to produce K valid witnesses is **censored/failure**, not discarded.
- For each target, add exactly K−1 right-hand-side-labelled difference rows by cancelling the target: `(c_r-c_0)·L = j_r-j_0 (mod n)`. Verify every corresponding identity using original elliptic-curve group arithmetic.
- Authentic public relation walk starts at G, tests signed-pair dictionary, increments real independent DSU rank, polls quotient visibility every 32 actual pair hits, stops *difference arm* as soon as **32/32** unknown target logs are determined and group-verified. Continue the SAME stream to a **readout-only K-witness baseline**, with both stops recorded. The difference-arm wall-clock timestamp must be captured **before** baseline RREF, reference BSGS and any unrelated control work.
- Test output: `K,seed,leaf_probes,verified_difference_rows,free_rank_initial,augmented_rank_initial,diff_shifts,diff_hits,diff_independent,baseline_shifts,baseline_hits,baseline_independent,setup_ms,witness_ms,cold_relation_ms,cold_total_ms,BSGS setup/online`. Include denominator/censored outcomes, unknown scalar verification and CI source commit.
- Run original Rust library tests `cargo test --locked --release --lib` and each width via `cargo run --locked --release --example ...` using Rust 1.100.0. A/C seed outcomes are new independent deterministic cohorts, **not** multiple independent hardware samples. Compare wall times only within the same GitHub Actions job/runner; field operation counts and relation-shift counts are exact.

## Acceptance and negative gates

1. K=4, seed A **must reproduce** Run71 exact `1,668,210` difference shifts, `736` hits, 454 independent pair rows, and readout-only baseline `2,528,933` shifts. Fail the gate if these do not match.
2. Each accepted cell proves all 32 logs by native `[k]G=Q`, secret-only post-solve check and matched reference BSGS; verify every group identity. Fail or censor any contradictory RHS or insufficient witness/root.
3. Rank gain means actual quotient-rank increase from new difference rows, not a mere count of rows or apparent 3-sum coverage.
4. Report costs for setup **and** public certificate discovery, not only the relation shifts. No secret indices, planted witnesses, or generic pair table may enter the non-generic RR9/F3 candidate. Current run is explicitly **GENERIC_NEGATIVE_CONTROL** regardless of timings.
5. A **cheaper complete non-generic prime-field ECDLP solver** requires a separately validated unknown-index *algebraic* extractor from PR #4692/#4812/#4822, 46-positive/18-negative blind gate, complete Rust recovery, source-pinned results, same-host optimized shared BSGS/rho and strongest existing index-calculus frontier comparisons for T=1/32/128/1024.
