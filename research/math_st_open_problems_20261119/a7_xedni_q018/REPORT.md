**Outcome.** All 300,000 runs were classified; none was undecided. The
dependent rate at $B=8$ was 0.250% for S1 (250/100,000), 1.859% for S2
(1,859) and 0.068% for S3 (68). The largest rate is 27.3 times the smallest,
and all three pairwise 95% Wilson intervals are disjoint. H7's kill condition
is met: the published 317/100,000 depends on its sampler, and P1.6/Q018
closes as unanswerable as posed. None of the three samplers reproduces
317/100,000 inside its Wilson interval. S1 comes closest, at a ratio of 0.79.
All numbers are unverified assertions in pcc terms [pcc:unverified].

Protocol: `../PROTOCOLS.md` §A7, written before any A7 code. Code: `src/`,
a standalone native Rust crate. `run.sh` regenerates every number here.
Python is used only in `plot.py`, which plots recorded numbers, and in
`crosscheck_upstream.py`, the port check described below, which compares
components and reports nothing else.

## Reading of the paper's Experiment A

Source: Jacobson, Koblitz, Silverman, Stein, Teske, *Analysis of the Xedni
Calculus Attack*, DCC 20 (2000), §5.4, pp. 59–60 (the PDF linked from upstream
`refs/jacobson-et-al2000.md`). I read the text directly; the quotes are
verbatim.

- Points lifted: two. "For Experiments A and B with p = 17, we took r = 2 and
  chose ap = bp = 2 … N = 19 points. We chose P0 = (3, 1) as generator."
  "Experiment A differs from Experiment B only in that M = 1."
- Finite points: "Since we work with only two points … The only conditions
  imposed on Pp,i (i = 1, 2) are that they are not the point at infinity and
  Pp,1 ≠ ±Pp,2", with "µ1 = 1" from Step 1. So $P_{p,1}=P_0$ and
  $P_{p,2}=\mu_2P_0$, $\mu_2\in\{2,\dots,17\}$. The paper does not state the
  distribution of $\mu_2$; all three samplers take it uniform.
- Step 2 (with $M=1$): "choose Pi = (Xi, Yi, Zi) in projective coordinates by
  finding a short vector in the lattice generated by the columns of the
  matrix [[xi, p, 0, 0], [yi, 0, p, 0], [1, 0, 0, p]] subject to the condition
  that Zi is not divisible by … p." Which short vector is taken is not
  stated.
- Step 3: "Solve for small integers ui such that the curve
  (1+pu1)Y²Z + pu2XYZ + pu3YZ² = (1+pu4)X³ + pu5X²Z + (a+pu6)XZ² + (b+pu7)Z³
  passes through Pi … and has minimal discriminant", using Silverman's
  Steps 7, 9 and Appendix B and Havas–Majewski–Matthews HNF. No search region
  or tie-break is given.
- Step 4: "check whether the Pi are dependent. In case of dependency, compute
  the dependency relation with smallest coefficients." The test itself is not
  specified in §5.4. Upstream records it as 2-descent.
- Published: Table 3, row "A p = 17 M = 1": $D_{\min}$ 17 bits, $D_{\max}$
  131, $D_{av}$ 73, 317 dependent; dependent cases 23/91/61 bits. Table 4:
  coefficient magnitudes 1: 311, 2: 304, 3: 16, 4: 2, 7: 1. Text: "301 out of
  the 317 relations for p = 17 were of the form P1 = ±2P2 or 2P1 = ±P2."

## Sampler specification

Fixed on 2026-11-25 before any A7 code ran and before any dependency rate
was seen. The code constants in `src/main.rs` carry the same names.

Common to all samplers (from the paper, §5.4, Steps 1–4 with $M=1$, $r=2$):

- `P = 17`, finite curve $y^2=x^3+2x+2$, $\#E(\mathbb F_{17})=19$,
  $P_0=(3,1)$. $P_{p,1}=P_0$ ($\mu_1=1$). $P_{p,2}=\mu_2P_0$ with $\mu_2$
  uniform on $\{2,\dots,17\}$ (the 16 values with $P_{p,2}\ne O,\pm P_{p,1}$).
- A projective lift of $(x,y)$ is a primitive integer vector $(X,Y,Z)$ with
  $(X,Y,Z)\equiv\lambda(x,y,1)\pmod{17}$ for some $\lambda\not\equiv0$, i.e.
  a vector of the lattice spanned by the columns of the paper's matrix with
  $17\nmid Z$; sign normalised so that $Z>0$.
- Coefficient lattice: the integer solutions $u\in\mathbb Z^7$ of the two
  linear equations that make the paper's curve
  $(1+17u_1)Y^2Z+17u_2XYZ+17u_3YZ^2=(1+17u_4)X^3+17u_5X^2Z+(2+17u_6)XZ^2+(2+17u_7)Z^3$
  pass through both lifts. They form $u_0+L$ with $L$ a rank-5 lattice.
  $L$ gets an LLL basis (`LLL_DELTA = 0.99`, size reduction 0.51).
- $u^\ast$ = the exact closest vector of $u_0+L$ to $0$ in the Euclidean norm
  (enumeration, exact integer comparison; ties: lexicographically smallest).
- Neighbourhood `N(u*)` = $\{u^\ast+\sum_i d_ib_i: d\in\{-1,0,1\}^5\}$, 243
  vectors, $b_i$ the LLL basis (`NEIGH_RADIUS = 1`). Singular curves
  ($\Delta=0$) are dropped from it.
- If the two lifts give no integer solution or a rank-deficient system, the
  lifts are redrawn from the same sampler (counted as `resamples`).
- Box: `R_BOX = 16`: all lifts with $|X|,|Y|,|Z|\le16$ (one per $\pm$ pair).
- Pool: `POOL = 8`: upstream A002's `projective_lift_pool(point, 17, 8)`:
  for $\lambda=1..16$ the balanced residues of $\lambda(x,y,1)$, made
  primitive, sorted by (squared norm, vector), first 8 distinct.

| sampler | lifts of $P_{p,1},P_{p,2}$ | coefficient vector $u$ |
|---|---|---|
| S1 | independent, uniform on the box `R_BOX = 16` | $u^\ast$ (nearest lattice vector) |
| S2 | independent, uniform on the pool `POOL = 8` (A002) | the member of `N(u*)` minimising the height of the discriminant of A002's standard model, $\log\max(\lvert n\rvert,\lvert d\rvert)$ for $\Delta=n/d$; ties by $\max\lvert u_i\rvert$, then lexicographic $u$ (A002's key) |
| S3 | as S1 | uniform on the non-singular members of `N(u*)` |

Seed `SEED = 20261125`. Run $k$ of sampler $s$ uses ChaCha20 seeded with the
32 bytes (`SEED` as u64 LE, $s$ as u64 LE, $k$ as u64 LE, 0u64), so each run
is reproducible on its own.

Dependence test (per run, on the integral model of the lifted curve; a specification, not a result [pcc:unverified]):

- `B = 8`: exhaustive search of $n_1P_1+n_2P_2=O$ with $\max\lvert n_i\rvert\le8$,
  exact rational arithmetic; minimal $\max\lvert n_i\rvert$ reported, then
  minimal $\lvert n_1\rvert+\lvert n_2\rvert$. A found relation is re-verified
  on the general-form integral model [pcc:unverified].
- `B2 = 64`: secondary search, only on runs not dependent at `B`, candidates
  filtered by reduction mod `N_FILTER_PRIMES = 6` good primes, survivors
  verified exactly over $\mathbb Q$. Reported separately; the primary
  classification uses `B = 8`.
- Independence certificate: interval enclosure of the regulator from
  $\hat h(Q)\in[(h(2^nQ)-\varepsilon_-/3)/4^n,(h(2^nQ)+\varepsilon_+/3)/4^n]$
  for $Q\in\{P_1,P_2,P_1+P_2,P_1-P_2\}$, $n$ in `DOUBLINGS = [3,4,5,6]`
  (stop at the first that certifies), with $\varepsilon_\pm$ as in "The independence certificate" below.
  Independent iff the lower end of the regulator interval is $>0$.
- Undecided: neither.

Also fixed before running, as recorded consequences of these definitions: the
pool is A002's de-duplicated list, so it holds 6–8 lifts, not always 8
(for $P_0$ it holds 7). The box holds 52–55 lifts for 16 of the 18 finite
points and 20 for $\pm3P_0$ (`results/run_stderr.txt`). No run needed a lift
resample (`lift_resamples_total` = 0 for all samplers) [pcc:unverified].

## The independence certificate

All of it is computed on the short integral model
$y^2=x^3+Ax+B$, $A=-27c_4$, $B=-54c_6$. This model is isomorphic over
$\mathbb Q$ to the integral model of the paper's equation
($a_1=c_1$, $a_2=c_2\alpha$, $a_3=c_3\alpha\beta$, $a_4=c_4\alpha^2\beta$,
$a_6=c_6\alpha^3\beta^2$, $x=\alpha\beta X/Z$, $y=\alpha^2\beta Y/Z$). Canonical
heights use the normalisation $\hat h=\lim h(x(2^nP))/4^n$, $h(m/d)=\log\max(|m|,|d|)$,
which is LMFDB's. For coprime $(X,Z)$ the duplication is
$x(2P)=F/G$, $F=X^4-2AX^2Z^2-8BXZ^3+A^2Z^4$, $G=4(X^3Z+AXZ^3+BZ^4)$.

- Upper: $\max(|F|,|G|)\le c_{up}H^4$, $H=\max(|X|,|Z|)$, $c_{up}$ the larger
  coefficient 1-norm of $F$ and $G$.
- Lower: there are cubic forms $f_1,g_1,f_2,g_2$ with $f_1F+g_1G=4DZ^7$ and
  $f_2F+g_2G=4DX^7$, $D=4A^3+27B^2$. The code checks both identities
  coefficient by coefficient for every curve. Hence
  $\max(|F|,|G|)\ge4|D|H^4/C$ and $\gcd(F,G)\mid4D$, so
  $h(2P)\ge4h(P)-\log C$.
- Telescoping gives $\hat h(Q)\in[(h(2^nQ)-\log C/3)/4^n,\,(h(2^nQ)+\log c_{up}/3)/4^n]$.
  This is an elementary, self-contained bound. It replaces a cited
  Silverman-type bound, whose constants could not be checked against the
  source here.
- Pairing: $\langle P_1,P_2\rangle=(\hat h(P_1+P_2)-\hat h(P_1-P_2))/4$.
  Regulator interval: $[\,l_1l_2-\max|\langle\rangle|^2,\;u_1u_2-\min|\langle\rangle|^2\,]$.
  Logarithms of big integers come from the top 53 bits, with outward slack.
  $\gcd(F,G)$ is computed as $\gcd(4D,F\bmod4D,G\bmod4D)$, which is exact
  because the gcd divides $4D$.

A lower end above 0 shows that no relation $n_1P_1+n_2P_2=O$ exists at all.
The proof rests on positive-definiteness of the height pairing on
$E(\mathbb Q)/E_{\mathrm{tors}}$; for torsion, $\hat h=0$ and the interval cannot
lie above 0. The rigour rests on IEEE-754 `ln` being accurate to within the
applied slack ($10^{-13}$ relative), an assumption, not a proof
[pcc:unverified].

Interpretation [pcc:unverified]. The sampler moves the rate by more than an
order of magnitude, and the dependence test is not the cause. Every run here
was decided by an exact relation or a certified regulator, so the spread
comes from the lifting and curve-choice distribution, as A002's post-mortem
suspected. Minimising the discriminant inside a neighbourhood (S2) raises
the rate. Drawing uniformly from the same neighbourhood (S3) lowers it.
Uniform box lifts with the nearest coefficient vector (S1) land closest to
the paper. Its discriminant range (17.8–125.9 bits, mean 78.7) and its
relation shapes (mostly $P_1=\pm2P_2$ or $2P_1=\pm P_2$, plus a few with
coefficient 7) resemble Tables 3–4. Its rate is still 21% below the
published one, with disjoint intervals. This resemblance is descriptive; A7
did not test it.

## Deviations from the protocol and from upstream

1. The dependence test is an exact relation search plus a certified height
   regulator, not the paper's 2-descent (the protocol allows this). Because
   no run was undecided, the classification does not depend on 2-descent
   being unavailable.
2. S2 enumerates the full 243-vector neighbourhood. A002 drew 24 random
   members of it, and that random subset is noise the protocol does not ask
   for. The rest of S2 is A002's: pool of 8, $u^\ast$-centred radius-1
   neighbourhood in LLL coordinates, and A002's discriminant-height key.
   A002 centred on rounded least squares; here the centre is the exact
   closest vector.
3. "Nearest coefficient-lattice vector" (S1) is read as the solution $u$
   nearest to 0. Upstream had no S1/S3, so these readings are ours.
4. The neighbourhood is defined in coordinates of this crate's LLL basis
   ($\delta=0.99$), so it depends on the reduction algorithm. Another LLL
   implementation could give a different 243-set.
5. The canonical-height error bound is an elementary resultant bound derived
   here and checked per curve. A cited Silverman bound was not used because
   its constants could not be confirmed against the source offline.
6. `results/controls.csv` was regenerated after the main run. The only code
   change was that commas in control case names became spaces, so the CSV
   parses. The main-run code path is otherwise identical. A rerun of the
   first 2,000 runs per sampler reproduced every `runs.csv` column except
   `seconds` [pcc:unverified].
7. `plot.py` runs under `/tmp/claude-0/report-venv` (matplotlib), because
   the system Python has no matplotlib.

## Limits

- The paper's actual sampler is still unknown. A7 shows only that reasonable
  explicit samplers disagree by up to 27×. It does not show which, if any,
  matches LiDIA/SIMATH. The kill verdict concerns Q018 *as posed*: comparing
  a rate across unspecified samplers.
- $\mu_2$ uniform, the box radius 16, the pool of 8 and the neighbourhood
  radius 1 are single fixed choices. A7 did not scan them. Other constants
  would give other rates, which only reinforces H7.
- The "independent" certificate is rigorous mathematics conditional on
  correct floating-point `ln` within the stated slack, and on this
  implementation being correct. It has not been reviewed independently.
  The controls (LMFDB heights and regulator, planted relations, torsion)
  are evidence, not proof, of correctness.
- Discriminant sizes are for the integral model built from $(\alpha,\beta)$,
  not the minimal model. Comparison with Table 3 is therefore loose.
- Runtime: about 6 minutes for the 300,000 runs on 4 vCPUs (S1 34 s, S2 156 s,
  S3 164 s), plus about 5 minutes for the controls, single-threaded
  [pcc:unverified].
