• Verdict: a verified constant-factor improvement of the classic compact-orbit pair-table pipeline by the double large prime; the single large prime loses; rho is still 30-55 times ahead. At n = 53 the best plain table (320, 440 and 660 columns bracket it at 7.65, 6.38 and 6.83) costs S = 6.38; the two-large-prime collector with a 40-column base and a domain of ten times that (lp2-k40-c10, the same 440-column envelope) costs 3.86, a paired ratio of 0.604 [0.599, 0.610] over 16 workloads. At n = 61 the best plain table is 880 columns (S = 7.62, bracketed by 660 and 1100 columns); lp2-k60-c10 costs 4.26 (paired 0.559 [0.535, 0.578] over 3 workloads).
  • The order survives the pricing band for the best large-prime arms. Native work (hash probes, eliminator row operations, the domain scan) is priced at 0, 0.1 and 1 GAE per operation for every arm, rho included. At n = 53 lp2-k40-c10 against the best plain table: 0.604 / 0.635 / 0.730 (ecbench band: "lp2-k40-c10 < plain-k440" holds across the band). At n = 61: lp2-k60-c10 0.559 / 0.623 / 0.831 and lp2-k40-c20 0.644 / 0.651 / 0.675. Other two-large-prime arms win at weight 0 and lose at weight 1 (lp2-k20-c10 at n = 53: 0.61 / 0.78 / 1.28; lp2-k40-c10 at n = 61: 0.57 / 0.71 / 1.18): their native work is larger than their saved group operations.
  • The single large prime is worse than the plain table at equal envelope (1.73 [1.64, 1.82] and 1.47 [1.42, 1.52] at n = 53), as at n = 41 in 2026-10-12.
  • Distance to the matched strong signed-Frobenius rho (S / Srho at weights 0, 0.1, 1). n = 53: best plain 49 / 49 / 48; best two-large-prime 30 / 31 / 35. n = 61: best plain (880 columns) 85 / 83 / 78; lp2-k60-c10 47 / 52 / 64, lp2-k40-c20 55 / 54 / 52. Rho is ahead of every arm at every weight; the gap is about halved, not closed.
  • It is a constant, not an exponent. The best-arm ratio is 0.60 at n = 53 and 0.56 at n = 61, and the optimal large-prime base stays 40-60 columns while the plain optimum moves from 440 to 880. Two sizes cannot fit a slope; nothing here says the ratio grows.
  • Memory beside time (median peak RSS of the harness's own measurement, wall time exploratory on a shared host): at n = 53 the best large-prime arm and the best plain table use the same memory (317 vs 313 MiB for lp2-k40-c10 and plain-k440) and solve in a median 9.9 s against 13.3 s. At n = 61 lp2-k60-c10 uses 604 MiB and 36.7 s against 1,149 MiB and 59.4 s for the best plain table (880 columns). Memory is not in S.
  • What this is not. The leaderboard's Table A recipe for these curves is a different pipeline (aimed m = 3 collection with an m = 2 descent, in its own unit) at 7.03x (n = 53) and 11.5x (n = 61) of its reference, below the 30-55x here; the large-prime collector was not combined with that recipe, so no Table A row moves. The gain is inside the classic single-target pipeline, whose cost is dominated by the pair-table build.
  • Controls. Every run verified (planted logarithm recovered, independent point check). The duplicate plain arm reproduces the plain arm's S exactly (A/A ratio 1.000 [1.000, 1.000]); the large-prime collector switched off (large_primes=0) reproduces it counter for counter. Replay certificate: ecbench verify --replay-all on every session.
  • Limits. Counted S is deterministic, so the two rounds of a workload repeat each other; the independent units are workloads: 16 at n = 53 (two sessions of eight), 4 and 3 at n = 61 (two sessions). The n = 61 intervals are over three workloads and should be read as such. The 40-60 column optimum was found on the same curves as the confirmation (a grid selected by a pilot of two repeats on separate seeds). n = 61 first session (grid edge at 660 columns) is kept as evidence; the bracket session supplies the best plain table.
