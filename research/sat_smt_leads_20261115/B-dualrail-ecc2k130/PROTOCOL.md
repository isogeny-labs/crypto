# PROTOCOL: does the dual-rail gate encoding transfer to the repository's ECC2K-130 S'4 instance?

Written 2026-11-15 before any measured run (seeds 2026111500 + d). Local pilot, one core, no
isolab host, no replay certificate, no benchmark record: every number is `[pcc:unverified]`.

## Claim under test

The dual-rail AND encoding of `research/sat_smt_leads_20261114/followup-subcube` (rail
r = (not a) & rest and XOR clause t + r + rest = 0 for a gate t = a & rest) reduces CryptoMiniSat
conflicts on the repository's own instance: Semaev S'4 for K_0: y^2 + xy = x^3 + 1 over
F_2[t]/(t^131 + t^8 + t^3 + t^2 + 1), factor base V = {deg x < d} \ {0}, m = 3, generated by
`research/nagao_relations/solver_16/weil.py` (`buildS4`, `System.cmsClauses`), imported and run
unchanged. Reference: the panel's pair count C(A, 2) (A = admissible abscissae), with the scan
count 2^d - 1 next to it.

## Instances

- d = 6, 7, 8 (decision cells: 7 and 8). d = 9 exploratory, scan arms only, outside the rule.
- Per d: 8 uniform targets (non-decomposable) and 4 planted targets (decomposable), drawn with the
  repository's `uniformTarget` / `plantedTarget` from `random.Random(2026111500 + d)`, uniform first.
- Solver: pycryptosat 5.18.0, one thread, default options (as `weil.cmsSolve`), verbose=1 only to
  read the per-call conflict count ("c [solve] .. confl: N"). Decisions and propagations are not
  exposed by this binding and are not reported. Wall time is recorded, secondary (shared machine).

## Arms

| arm | instance | solve |
|---|---|---|
| a | `buildS4(..).cmsClauses()` as is | one free solve |
| b | a + `railify` (rails for every input of every AND gate, CNF+XOR post-pass) | one free solve |
| c | same instance as b | outer loop over x1 = 1 .. 2^d - 1, x1's d bits as assumptions, one incremental solver; stop at first SAT |
| a-scan (control) | same instance as a | same outer loop as c |
| L-scan (c, linear-leaf variant) | chained system S3(x1,xR,u) = 0, S3(x2,x3,u) = 0 with s = x2+x3, p = x2 x3, built with the repository's Descent/System; rails with selectors x1 and u only | same outer loop |
| L-plain-scan (control) | chained system, no rails | outer loop on 8 seeded sample leaves per target |
| L-free, L-rail-free | chained system, without / with all rails | one free solve, first 2 uniform targets per d only |

Caps: free solves 45 s (L arms 20 s); scan leaves 20,000 conflicts each (L-plain-scan 5,000);
a scan stops and is reported censored after 240 s. Censored runs count the conflicts spent as a
lower bound. d = 9: arms c and a-scan (a-scan on 64 seeded sample leaves), L-scan on the first 2
uniform targets; arms a and b are not run (the panel reports a censored at 300 s).

## Metric and pre-registered rule

Metric: conflicts per decided non-decomposable target (for scan arms the sum over all leaves),
mean of 8, and its multiple of C(A, 2). Decomposable targets are reported separately.

- **transfers**: arm b or arm c (either c variant) has mean conflicts <= 1/5 of arm a at d = 7 and
  at d = 8, AND its mean is <= 10 x C(A, 2) at both.
- **does not transfer**: for every one of b, c, L-scan the reduction against arm a at d = 8 is < 2x.
- otherwise **inconclusive**.
- Attribution (decided now, reported whatever the outcome): the reduction of a scan arm is
  attributed to the rails only if arm c is <= 1/2 of the a-scan control in conflicts at d = 8;
  otherwise it is attributed to the outer loop, i.e. to performing the scan.

## Prediction

From development probes (seed 999, one uniform target, d = 6, 7, 8; listed under deviations):
arm b is within a small factor of arm a (either direction) and is expected censored or slower in
wall time at d = 8; arm c costs a few conflicts per leaf (1 to 10), so far below arm a at d = 8
and within 10x of the pair count; at d = 7 arm a is already below 1,000 conflicts, so the 5x
threshold there is borderline. The a-scan control is expected within about 30x of arm c, so most
of the reduction is expected to come from the outer loop. Expected verdict: transfers by the letter
of the rule, or inconclusive on the d = 7 leg.

## Correctness gates (a failed gate voids the cell)

1. Own F_2^131 arithmetic (`dr.FastField`) agrees with the repository's `field.Pb` on products.
2. Ground truth by pair enumeration in own arithmetic (`dr.pairDecision`) for every target at
   every d: planted targets decomposable with the planted triple found, uniform targets not.
3. Every SAT model: the three abscissae lift to curve points with signs summing to R, checked with
   own arithmetic and with the repository's `weil.verifyProjected`.
4. Every decided answer of every arm equals the ground truth; arms agree with each other.
5. `railify` adds clauses only: the planted assignment extended to the rails satisfies arm b's
   instance (implied by gate 3 on arm b/c SAT answers).
