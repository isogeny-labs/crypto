# Frozen Koblitz n23 m4 F6 geometric four-sum and BSGS pilot

This directory contains a four-cell `experiment.protocol/v1` record and its native `crypto dataset` plan. The fixed population is one Koblitz curve seed (0), one generator index (0), one key index (0), both twist choices, and two solver adapters (`f6,bsgs`) at n=23 and m=4. Native mixed-radix indices are 0 F6 untwisted, 1 BSGS untwisted, 2 F6 twisted, 3 BSGS twisted. The official export checker therefore expects four arms, one checker-compatible shared instance ID `"0"` per arm (mapped to native `g0k0` in raw rows), and four measured rows. Opposite twists identify distinct public curves. Within a twist, F6 and BSGS use the same generated curve, generator and target; m4 records are not byte-identical to the prior m2 public records.

The F6 adapter is `F6WidePairIndex`, an exact geometric four-sum search over a saved signed finite domain. It is **not a general Gröbner F6 algorithm**. It retains a reconstructed pair table; positive PDP witnesses are independently group-replayed. The current native verifier does not independently certify exhaustive negative F6 outcomes from that table. F6 does not recover an ECDLP scalar. BSGS can produce an independently recovered scalar only after native verification; timeouts and failures stay in the four-cell denominator. Native whole-worker retired instructions and exact first/last fall-degree certificates remain null; wrapper wall time is an operational diagnostic and does not support a solver speed comparison. This is a follow-on pilot chosen by a deterministic first-index rule after the prior Koblitz n23 m2 campaign, not a pre-data prediction of an effect.
