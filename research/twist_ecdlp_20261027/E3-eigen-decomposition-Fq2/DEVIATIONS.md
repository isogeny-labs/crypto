# Deviations and implementation choices for E3-eigen-decomposition-Fq2

Logged per PREREGISTRATION.md section 10. Items marked EXPLORATORY would label results; none of the primary cells is affected unless stated.

1. **Run order (task instruction).** The task asked to run the positive control first. Section 9 lists tables (step 4) before semaev (step 5). run.sh runs PC1 (in e3_lemma.gp) and PC2 (e3_semaev.gp) before the table arms. Content of every step is unchanged.
2. **Scripts were written after the preregistration text, and a library (`e3_lib.gp`) existed before the other scripts.** `e3_lib.gp` (mtime 2026-10-21 05:17) was written by an earlier session after PREREGISTRATION.md (04:18) and before any data run; it had no recorded test. All other scripts (e3_grid.gp, e3_curves.gp, e3_model.gp, e3_lemma.gp, e3_tables.gp, e3_semaev.gp, e3_analyze.gp, plot_e3.py, run.sh) were written in this session. `SCRIPTS.sha256` was written after the scripts were finished and before the first run of `run.sh`; it covers e3_*.gp and plot_e3.py (run.sh is not hashed).
3. **Development test runs before the hash freeze.** To debug syntax and gp API use, the scripts were run into `dev/` directories before freezing: (a) on a tiny p=61 grid (E3DEV=1, outside the experiment grid); (b) a first debugging pass of e3_curves, e3_model, e3_tables (p=101 c=1 A; p=211 c=2 B; p=401 c=1 A), e3_lemma and e3_semaev on the real grid cells into `dev/o2`. Those outputs were seen by the author. No definition, threshold or grid value was changed after seeing them; changes after those runs were syntax/parenthesis fixes, a getenv fix (unset variables return 0 in gp, not ""), and the E3DEV switch. Final numbers all come from `out/`.
4. **Unspecified details resolved by the implementer (not in the preregistration):**
   - Curve selection: "keep the c-th one" is read as: seed `1000*p+c`, take the c-th valid curve of that stream. Even-order curves use c=0 (seed `1000*p`), requiring only #E even with a rational root of x^3+ax+b (non-singular), not primality.
   - Lemma audit (H4/NC1/P6): group law only, 4-subsets of V={0..27} for every curve, sign vectors up to global sign (8 of 16, counted twice since S -> -S preserves membership/violation status), so 327600 decompositions per curve. For the even-order curve, a point (x0,0) (f(x0)=0) is classed as E-part.
   - PC1: also checks generator orders, pi on generators and on 28 factor-base points, and the full point (not only x) of the 50 random pair sums.
   - NC2 test statistic: two-sample permutation test on the difference of mean per-target total X yield (j=1..m2-1), 2000 label permutations, seed 9002, add-one p-value; applied cell by cell (alpha=0.01, not corrected for multiplicity; the number of cells with p<0.01 is reported next to the number expected by chance).
   - D_2 Semaev timing is repeated 50 times per target (getabstime has 1 ms granularity) and divided by the repeats; X_4 timing is a single run. "Per solve" = total CPU ms / number of univariate root-solves (N_E per D_2 run; C(N,3) per X_4 run).
   - Semaev cells use the first 10 targets of the cell's 200-target draw (the draw interleaves A,B so the first 10 pairs are the same for any T).
   - rho_gen uses j=1..m (as in section 2). Additional columns (all j=1..m2-1, "rho_all"; control X_m "rho_Xmc") are reported as secondary. P4 pools all X relations j=1..m2-1.
   - Interval rule: 99% percentile interval of the 2000 paired-bootstrap ratio-of-totals; resamples with zero D yield are discarded (count recorded as boot_valid); resamples with zero X yield count as +infinity.
   - "Powered" uses the D_m total over the 200 targets (>=20).
   - PC3 "within factor 1.25" is read as measured/model in [0.8, 1.25].
5. **run.sh** is the single driver; the individual commands of section 9 are issued from it with the environment variables P, C, FAMILY.
6. The csv files of the pre-freeze debugging directory dev/o2 were deleted after the final run to avoid confusion with out/; dev/o3 (p=61 toy grid) is kept.
7. **Operation-count addendum (2026-10-26, post-run, no new experiment).** The task asked for operation counts as the primary cost metric. The frozen unit (Semaev work = root-solves x degree, `WD`, `WX` in `out/results.csv`) already is one; it was reported only as the ratio rho. `e3_opcounts.gp` (not in `SCRIPTS.sha256`, written after the run) re-derives from `out/results.csv` the univariate root-solves, solves x degree, the table arm's candidate x-sets and sign-vector group-sum evaluations, and per-relation versions, and checks that its work counts equal `T*WD`, `T*WX` of the frozen run (0 mismatches over 36 cells). `opcounts.sh` writes `out/opcounts.csv`, `out/opcounts.json`, `out/semaev_ops.json` and merges them into `results.json` under `op_counts`; `run.sh` calls it last. Field multiplications and polynomial-evaluation counts were NOT instrumented in the frozen scripts and are not reported; the Semaev solver's root-solve counts (`Dsolves`, `Xsolves`) are in `out/semaev.csv`. Everything in this addendum is derived arithmetic on recorded numbers and is labelled secondary.
8. **Replication (2026-10-26).** A full second run of `run.sh` into `replicate/` (earlier session, before item 7) reproduced `results.json`, `out/results.csv` and all table counts bit-identically (`diff -rq out replicate/out` differs only in wall-clock fields: `ms` columns, `timing.txt`, `env_date.txt`, and the Semaev timing lines of `semaev.out`/`semaev.csv`/`semaev_summary.csv`/`analysis.out`). The Semaev per-solve wall times are contention-dependent: original X_4/D_2 ratio 119.5, 81.0, 61.6; first replicate 80.8, 77.9, 80.6; `replicate/` was then re-run with the final `run.sh` after item 7 under heavy load (load average about 14): 177.3, 97.9, 101.5 (`replicate/out/analysis.out`). That final replicate matches the original `results.json` exactly apart from the Semaev wall-time fields.
