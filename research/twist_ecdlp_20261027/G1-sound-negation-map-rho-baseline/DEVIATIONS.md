Seeds are per cell, so order cannot change any number. No frozen file was modified.
2. Post-freeze addenda (no frozen file changed, no walk re-run): `opcounts_g1.gp` (operation-count tables: totals and per-step M, S, I, escapes, DPs, trails, native counters, R = steps / sqrt(n/2), r = 64 vs r = 32 step ratio, summed cell wall time; reads raw/ and e5_inputs/ only), `make_results_g1.gp` (assembles `results.json` from out/*.csv, out/summary.txt, out/RC.txt; every number is copied from those files, booleans are comparisons of them), `repro_quick.sh` (reduced replication). `run.sh` got two lines appended after the frozen analysis to call the first two addenda. The task asked for operation counts as the primary metric; the frozen analysis already priced M, S, I and the native counters, the addendum only tabulates them.

All other 64 cells exited rc = 0 with all planned trials. The NC1 b36 rows therefore rest on 12 and 10 trials (Wilson limits widen accordingly). The completed trials are the first ones in trial order, so this truncation does not select on outcome.

5. Pre-existing, not a deviation: out/run.log is empty (the driver prints only "done" to the launcher's stdout).
6. Replication diagnosis (post-hoc; no frozen file, preregistration, raw/ or original out/ changed). A full independent re-run (replicate2/full, run.sh on a copy) matched the original on 64 of 66 cells record for record (ignoring the done_ms header and the per-trial wall-ms field), and reproduced every scientific number except the two cap-truncated rows of item 3. Two causes of mismatch were found:
   a. Idempotency bug (fixed). `opcounts_g1.gp` and `make_results_g1.gp` write with PARI `write()`, which appends. `run.sh` truncates out/solve.csv and out/ratios.csv before the frozen analysis but not out/opcounts.csv or results.json, so a run in a tree that already holds those files (every replication copy) produced a doubled opcounts.csv and a results.json holding two concatenated, unparseable documents (the second built from the doubled table). Fix: both scripts now `system("rm -f ...")` their output file before writing; re-running them twice in a scratch copy on the existing raw/ gives byte-identical opcounts.csv, opcounts.txt and results.json to the originals. No number changed.
   b. Wall-clock cap (preregistered, not changed). `n1sab b36 i1` and `n1c2 b36 i1` are cut by the 840 s `timeout`, so the number of trials they complete depends on machine load. The original contended run stopped at 12 and 10 of 20 trials (rc = 124); the replication, on a quieter machine, finished all 20 (done_ms 585902 and 591015, rc = 0). The first 12 and first 10 records of the replication are identical to the original. The two rows therefore read: n1sab b36 0/12 (Wilson upper 0.243) original vs 0/20 (0.161) complete; n1c2 b36 1/10 (upper 0.404) original vs 4/20 (upper 0.416) complete. NC1 outcome (SEES DROP) is unchanged for both. The complete 20-trial values are the preregistered full sample; the original 12/10 values are a valid truncated prefix reported as such. All other outputs (summary.txt, solve.csv, ratios.csv, every other opcounts row) are identical; only the cell_wall_ms and summed-wall-time lines differ (timing, contention-affected).
   c. Cosmetic: the order of lines in out/RC.txt differs (xargs -P 2 completion order); the rc values are the same except the two cap cells above.
