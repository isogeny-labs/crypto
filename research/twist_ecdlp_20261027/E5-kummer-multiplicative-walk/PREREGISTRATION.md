## 1. Idea under test

x-only (Kummer line) multiplicative walk. State = x-coordinate x in F_q. Step:
`x -> x([k_j] .)` with `j = h(x)` choosing one of r small multipliers k_1..k_r, computed by a
Montgomery x-only ladder (differential addition), so the step needs only the curve constant A
(a24 = (A+2)/4) and never y. Because Montgomery E: y^2 = x^3 + A x^2 + x and its twist
E_d: d y^2 = x^3 + A x^2 + x use the same A, the walk function is literally the same code on E and E'.

Notation. n = prime order of the DLP subgroup <P>. Q = [a]P. H = subgroup of (Z/n)^* generated by the
multipliers. N = number of walk states reachable from one start = |{ x([m]P) : m in H }| = |H(+-1)|/2,
i.e. N = |H|/2 if -1 in H, else N = |H|. Tracked exponents: a P-side trail keeps e with current point = +-[e]P
(e <- e*k_j mod n); a Q-side trail keeps e with point = +-[e]Q.

### Theory being verified (T1-T5)
- T1 (orbit): the set of states reachable from x(P) has exactly N elements.
- T2 (what a collision solves): a P-trail/Q-trail collision x([e_P]P) = x([e_Q]Q) gives
  a = +-e_P / e_Q (mod n). Walks started in {x(rP), x(rQ) : r in H} can collide only if a in +-H; for
  a not in +-H the two state sets are disjoint, so there is NO collision ever (deterministic statement).
- T3 (collision time): in the pure two-sided design (P-trails and Q-trails kept separate) the first
  useful collision needs ~ sqrt(pi N) total steps (two independent sets of L samples collide when L^2 ~ N;
  E[L] = sqrt(pi N)/2 per side, total sqrt(pi N) = 1.77 sqrt N) plus distinguished-point overhead.
  Hence ~1.8-2.2 sqrt(N) with N ~ n/2 for H = F_n^*.
- T4 (twist): the step map on the x-line commutes with the group law of whichever twist x lies on; x lies on
  E iff f(x)=x^3+Ax^2+x is a square times B. Orbits never leave their twist, so a walk started on E' never
  collides with a walk on E (except through 2-torsion x, f(x)=0, which are not in prime-order subgroups).
  The twist gives no cross-curve information; running on E' is an independent DLP of size n'.
- T5 (cost): the x-only step costs a ladder (several differential add/doubling) plus one inversion to get an
  affine x for hashing, versus 1 affine point addition for additive rho. So per-step cost is higher; the step
  count is not lower than rho with the negation map. Prediction: no net improvement over matched rho.

Exploratory extension (not part of T1-T5): "mixed-start" arm K-mix starts trails at x([r]P+[s]Q) with random
(r,s) so every collision is useful and a in +-H is no longer required (collision of
(u+va)m = +-(u'+v'a)m' is a linear equation in a). Predicted gain: sqrt(2) in steps over additive rho without negation.

## 2. Hypotheses (composite, each with its own verdict)

- H1 (exact structure, T1+T2): zero mismatches in the exhaustive/orbit checks of Section 6.
- H2 (step counts, T3): K-pure total steps T satisfies mean(T)/sqrt(N) in [1.4, 3.0]; log2(mean T) grows
  with slope 0.5 per bit of n (95% CI inside [0.40, 0.60]); step-count ratios to additive rho are
  K-pure/A0 in [0.8, 1.3], K-mix/A0 in [0.55, 0.9], K-mix/A1 in [0.75, 1.15].
- H3 (twist, T4): ladder agrees with Weierstrass ellmul on E and on E' with 0 mismatches; step map never
  crosses twist class (exhaustive on a small field); 0 cross-curve collisions in all budgeted runs;
  K-pure on E' reproduces the same normalized step count as on E.
- H4 (cost, T5): the implemented-ladder step costs 21.5 M + 12 S + 1 I (SB multiplier set, see 5.3) against
  2 M + 1 S + 1 I for the additive affine step; total counted cost of every Kummer arm is above the matched
  additive arm at I/M = 3, 10 and 30, and no ordering holds across the whole band I/M in {3,10,30,100}.
- H5 (headline, "no improvement"): the Kummer multiplicative walk is NOT an improvement over matched additive
  rho in counted work. It is falsified only by the conditions in Section 8.

## 3. Numeric prediction (all fixed before data)

Let M_arm be the number of distinct states: K arms N (from H, computed exactly), A0: n, A1: n/2, K-mix: (n-1)/2.
R = mean(T)/sqrt(M_arm), T = total steps (both sides, dead trails included) until the first verified solution.

| quantity | predicted value / band |
|---|---|
| R for K-pure, H=F_n^*, b>=24, in-set a | 1.4 to 3.0 (centre ~2.0) |
| R for K-mix, A0, A1 | 1.0 to 1.9 (centre ~1.4; A1 higher from fruitless cycles) |
| slope of log2 mean T vs bit-length b of n | 0.50, CI inside [0.40, 0.60] |
| steps K-pure / A0 | ~1.0 (band 0.8-1.3): sqrt(2) fewer states cancels sqrt(2) loss from two separate sides |
| steps K-mix / A0 | ~0.71 (band 0.55-0.9) |
| steps K-mix / A1 | ~0.85 (band 0.75-1.15), i.e. no step gain beyond the negation map |
| orbit size vs N | equal, 0 mismatches |
| a not in +-H, K-pure | 0 collisions, 0 successes (deterministic) |
| cross-curve (P on E, Q' on E') | 0 collisions |
| counted step cost, K implemented ladder, SB | 21.5 M + 12 S + 1 I per step (mean over hash-chosen multipliers within +-3% on M and S) |
| counted step cost, A0 / A1 | 2 M + 1 S + 1 I (A1 adds a doubling 3 M + 2 S + 1 I per fruitless-cycle escape) |
| ideal-chain K step (chainsearch) | 3.0 to 4.5 differential ops/step on average, 15 to 24 M-equivalents excluding I |
| total cost ratio K-mix/A0, S=0.8 M | I/M=3: ~4.2; 10: ~2.3; 30: ~1.3; 100: ~0.9 (ordering flips inside the band) |
| total cost ratio K-pure/A0 | ~5.9, 3.2, 1.9, 1.3 at I/M = 3, 10, 30, 100 |

(Arithmetic: xDBL = 3 M + 2 S (the a24 product counted as M), xADD = 4 M + 2 S, ladder for an l-bit k =
1 xDBL + (l-1)(xDBL+xADD); SB bit lengths 2,2,3,3,4,4,5,5 -> mean l = 3.5; conversion x = X * Z^-1 = 1 I + 1 M.)

## 4. Baselines (matched, same n, same DP protocol, same seeds for a)

- A0: additive r-adding rho, r = 16, no negation map, mixed walk R = alpha P + beta Q, affine arithmetic
  written in GP (add: 1 I + 2 M + 1 S; same group, same Q, same a list as K arms). Collision on the full point.
- A1: additive rho with the negation map (canonical y <= (p-1)/2, signed exponent tracking), same r = 16 table;
  fruitless 2-cycle rule: if the new canonical point equals the point two steps back, replace it by its
  double (counted); longer cycles are removed only by the trail cap. This is the matched "rho with +-" reference.
- Neither baseline is a tuned production rho; GP interpretive overhead is shared by every arm, so counted
  field operations are the decisive cost and GP wall time is secondary and labelled as such.
- Index calculus: not run here. E5 is compared to matched rho; any statement about the repository's
  index-calculus baseline is out of scope and is not made. The gap to matched rho is reported as the distance
  remaining (ratio), not as a pass/fail gate.
- Unpriced native work: DP table lookups, hashing, trail starts (one scalar multiplication per trail by PARI
  `ellmul`) are NOT in the step counters. They are reported separately (number of trails, DP count) and each arm's
  total is shown at I/M in {3, 10, 30, 100} with S = 0.8 M, plus a S = 1.0 M variant; rankings are claimed only
  where they hold across the whole band. GAE pricing from the repository is not applied (not defined for this
  scratchpad task); the I/M band is the stated sensitivity analysis.

## 5. Design

### 5.1 Instances (gen_curves.gp)
For each bit length b in {20, 24, 28, 32, 36, 40} and instance 1, 2: setrand(1234567 + 1000*b + inst);
draw random prime p of b+3 bits and random A until
`#E = h*n` with h in {4, 8}, n prime with bit length exactly b, and `#E' = 2p+2-#E = h'*n'` with h' <= 16,
n' prime with bit length >= b-1. E: Weierstrass [0,A,0,1,0] over F_p. Twist with non-square d:
E_d: [0, A*d, 0, d^2, 0] with X = d*x (so Montgomery x = X/d is shared). P = [h]G (order n), P' = [h']G' (order n').
Montgomery x-line constant a24 = (A+2)/4. Montgomery form only (scope limit: general Weierstrass x-only
formulas are not tested). Record p, A, d, n, h, n', h', x(P), x(P'), factorization of n-1, n'-1.

### 5.2 Multiplier sets and H
SA = {2,3,5,7}; SB = {2,3,5,7,11,13,17,19} (headline); SC = first 16 primes (2..53).
H computed exactly: with g0 a generator of (Z/n)^*, l_i = znlog(k_i, g0), G = gcd(n-1, l_1..l_r),
|H| = (n-1)/G, -1 in H iff G | (n-1)/2, N = |H|/2 if -1 in H else |H|. If H != F_n^* on a headline instance
it is recorded and N is used; the headline ratios use only instances with +-H = F_n^* (index 1) and the others are
reported separately.
Proper-subgroup sets for controls: S_idx = {k^g mod n : k in {2,3,5,7,11,13}} with g = smallest odd prime dividing n-1
(instances without such a prime are skipped and the skip is reported).

### 5.3 Walk protocol (identical for every arm)
- Selector: j = floor(x / 2^d) mod r on the integer lift 0 <= x < p (uses bits above the DP bits).
- Distinguished point: x mod 2^d = 0, with d = max(3, floor(log2(sqrt(M_arm)/16))) (for proper-H cells d from N).
- Trails start at fresh random starts, are cut at a DP, or at cap 20*2^d steps (dead trail, steps counted).
  Starts: K-pure P-side x([r]P), Q-side x([r]Q) with r a random element of H (random product k_j^{u_j}, u_j uniform
  mod n); K-mix x([r]P+[s]Q), (r,s) uniform; A0/A1 same mixed starts. P/Q trails alternate for K-pure.
- Each DP is stored in a Map keyed by x (A0: by the full point). First DP seen on the opposite side (K-pure), or any
  second distinct (exponent) arrival (K-mix, A0, A1), gives a candidate a:
  K-pure a = +-e_P e_Q^-1; K-mix: solve both sign cases of (u+va) = +-(u'+v'a); A0: (alpha-alpha')/(beta'-beta); A1 same.
  A candidate counts only if x([a]P) == x(Q) is verified by PARI `ellmul` (not counted). Same-side/degenerate
  collisions are counted as "wasted".
- T = total steps over all trails (both sides, dead trails and DP overhead included) at the moment the verified
  solution is found. Budget 40*sqrt(M_arm) steps; exceeding it = failure, T right-censored at the budget and
  reported separately (the pooled mean is also given with censored values at the budget).
- Op counters: each xDBL adds (3 M, 2 S), each xADD (4 M, 2 S), each conversion (1 I, 1 M), each affine add (2 M, 1 S, 1 I),
  affine doubling (3 M, 2 S, 1 I). Counters live in the code at the call sites and are printed per trial.
- Ladder: start (R0,R1) = (P, 2P) [1 xDBL], then one (xDBL + xADD) per remaining bit of k.
- Ideal-chain variant (chainsearch.gp): exhaustive search of the shortest Lucas/differential addition chain for each
  k <= 53 with costs D = 3 M + 2 S, A = 4 M + 2 S; only tabulated and used to recompute the K cost; the walk itself
  uses the plain ladder.

### 5.4 Grid
Trials per cell (per instance): b=20: 80, b=24: 80, b=28: 60, b=32: 40, b=36: 24, b=40: 12; 2 instances each.
Arms: kpure, kmix, a0, a1 (on E, set SB); kpureT (K-pure on E' with n'); cross (b in {20,24,28}, 24 trials:
P on E, Q' on E'; budget 30 sqrt(N) steps; expected 0 collisions).
Ablations at b=28, instance 1 only: kpure_sa, kpure_sc, kmix_sa, kmix_sc (60 trials).
Proper-H cells at b=24, instances 1 and 2 (40 trials): pc1 (K-pure, a drawn from +-H), nc1 (K-pure, a drawn from
the complement of +-H), kmixidx (K-mix, same S_idx).
Exhaustive/identity checks (Section 6) are separate scripts.

### 5.5 Seeds (all fixed)
- instance generation: setrand(1234567 + 1000*b + inst).
- a list (paired across arms): setrand(20000000 + 100000*b + 10000*inst); T draws of a (uniform in [2, n-2]; for K-pure
  in-set restricted to +-H; for nc1 outside +-H).
- per-cell walk: setrand(10000000 + 100000*b + 10000*inst + 100*armid) with armid: kpure 1, kmix 2, a0 3, a1 4, kpureT 5,
  cross 6, kpure_sa 7, kpure_sc 8, kmix_sa 9, kmix_sc 10, pc1 11, nc1 12, kmixidx 13.
- additive step table: setrand(30000000 + 100000*b + 10000*inst), u_j, v_j random mod n.
- bootstrap: setrand(31337), 2000 resamples (stratified by cell).
- identity/exhaustive checks: setrand(41000000 + test id), ids listed in the scripts.

## 6. Controls

Positive controls (detector can see the effect):
- PC1 exhaustive small instance (b = 10, p ~ 2^13, n ~ 2^10, SB and S_idx): for every a in [1, n-1], orbit
  intersection of {x([m]P)} and {x([m]Q)} is non-empty iff a in +-H, and a walk with budget 200*sqrt(N)
  recovers the verified a for >= 98% of in-set a (stratified sample of 400 a values for walk runs).
- PC2 orbit size: for 20 random P at b = 16 and each of SA/SB/SC, enumerated |{x([m]P): m in H}| equals N exactly.
- PC3 recovery: pc1 cell, K-pure with a in +-H solves with verification in >= 95% of trials within budget.
- PC4 scale resolution: A0 mean steps at b+4 over mean steps at b equals 2^(4/2) = 4 within [3.0, 5.3]
  for each of (24,28), (28,32); shows the step metric resolves a known factor.
- PC5 counter check: sum of counters equals the count recomputed from the logged multiplier histogram
  (exact equality).
Negative controls (null / no-effect):
- NC1 nc1 cell: a not in +-H, K-pure, 0 verified collisions and 0 candidate x-matches across P/Q sides in 40 trials
  (deterministic prediction; any collision falsifies T2).
- NC2 cross-curve: P on E vs Q' on E': 0 x-collisions in all cross cells (exhaustive small-field partition in 6.1 too).
- NC3 A/A null: A0 normalized steps (T/sqrt n) between instance 1 and 2 of the same b: ratio of means, 95% CI
  contains 1 in at least 5 of 6 b values (type-I check of the comparison instrument; one miss is allowed at 95%).
- NC4 wrong-solution check: every reported success is verified by x([a]P)==x(Q); a deliberate wrong a (a+1) must fail
  verification in 100% of 1000 tests per instance.

### 6.1 Identity / exhaustive checks (check_identity.gp, check_exhaustive.gp)
1. Ladder vs `ellmul` on E and on E' for 2000 random x per (b <= 28, instance) and every k in [2, 53]: mismatches must be 0
   (x on E: f(x) square; on E': non-square; infinity handled: Z=0 iff [k]X = O).
2. Small field p ~ 2^13 (3 curves): enumerate all x in F_p, class = Legendre(f(x)) in {E, E', 0}; for every k in SB the
   step map never changes class (excluding image infinity and f(x)=0); the functional graph on x has no weakly-connected
   component containing both an E-class and an E'-class state apart from x with f(x)=0 / infinity.
3. Orbit sizes of 6.PC2.

## 7. Metrics

Primary: R = mean(T)/sqrt(M_arm) per cell with 95% bootstrap CI (percentile, 2000 resamples), success rate, number of
wasted collisions, number of trails, counted ops per step (M, S, I) per arm.
Derived: step ratio K-arm/A-arm (ratio of normalized pooled means over cells with b >= 28, stratified bootstrap);
log2-slope of mean T on b (OLS over cell means with bootstrap CI); total counted cost
C(I/M) = steps x (M + 0.8 S + (I/M) I) for I/M in {3 (batched inversion), 10, 30, 100} and the S = 1.0 variant; cost ratio
K/A at each I/M and the ordering-holds-across-band flag; gap to matched rho (A1) as ratio, reported as distance remaining.
Secondary (not decisive): GP microseconds per step.

## 8. Falsifiers (explicit)

- F1 (H1): any mismatch in PC1/PC2, any a in +-H not recoverable (budget allowing, <98% success) or any a not in +-H
  recovered. Falsifies T1/T2.
- F2 (H2): for b >= 24 in-set SB cells, at least 2 cells with the K-pure R CI entirely outside [1.4, 3.0]; or the slope CI
  not inside [0.40, 0.60]; or any pooled step ratio's CI (b >= 28) entirely outside its band in Section 3.
  Falsifies T3 (the numeric collision-time model), but not the correctness of the solver.
- F3 (H3): any ladder/ellmul mismatch, any class-crossing, any cross-curve collision, or K-pure E' normalized R whose CI
  excludes the E value by more than a factor 1.4 at b >= 28.
- F4 (H4): measured K-step counted cost differs from 21.5 M + 12 S + 1 I by more than 3% (M or S); or K-mix total cost
  is below matched A0 at I/M = 3 with the upper 95% bound < 1. (This is the "improvement found" condition.)
- F5 (H5, headline): H5 is falsified, i.e. the Kummer walk shows a verified improvement, iff K-mix (or K-pure) total counted
  cost at I/M = 3 is below that of matched A1, with the 95% CI of the ratio entirely below 1, using only verified solves
  and including every counted operation, at all of b in {32, 36, 40}. A ranking at a single I/M value is not an improvement;
  if the order flips inside the band the row is reported "unranked". Relabelling or accounting changes (e.g. dropping the
  inversion or the ladder's first doubling) do not count.
- Any run that crashes, times out (> 840 s per cell) or is incomplete is reported as missing, not imputed. Cells lost to
  time limits are listed in `out/MISSING.txt`.

Order of cells: small b first; b = 36 and 40 cells are run last, and a cell is skipped (listed as missing) if a prior cell of the

trial, a, success, T, T_P, T_Q, wasted, trails, DPs, M, S, I counts, multiplier histogram, microseconds) plus a header with
parameters, seed values and `gp` version, read back by analyze.gp.

## 10. Reporting rules
Every number in the final report is copied from out/summary.txt, out/summary.csv or a raw file named at the number.
Failed, partial or skipped cells are stated as such. All verdicts H1..H5 are stated per Section 8 with the observed bound,
including those that contradict the predictions in Section 3. Deviations from this file, if any, are logged in
DEVIATIONS.md with the reason and cannot change the verdict rules in Section 8 after data exist.

## 11. Known limitations (declared in advance)
Montgomery-form curves only; sizes up to 40 bits (asymptotics extrapolated by the slope test only); two instances per size;
GP implementation (counted ops decisive, time secondary); one hash selector; A1 handles only 2-cycles explicitly;
no batched-inversion implementation (modelled by I/M = 3); a Rust or projective-coordinate implementation could shift
constants but not step counts.
