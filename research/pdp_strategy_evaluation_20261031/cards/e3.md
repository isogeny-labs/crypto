### LEAD-EXO-four-list-ktree-join: Wagner k-tree / four-list join, on the random-binary ladder rows
Verdict: CLOSE for the ladder question. Named obstruction: the only homomorphic sum-compatible filter on these groups is the cofactor class, `log2 h` = 1.0 / 3.0 / 1.0 / 3.0 / 2.6 bits on the five rows, and LEAD-19's projection already spends all of it. The atlas `next_action` (measure W on E(F_p) toy families) is a different object and does not transfer.
Novelty: not new. LEAD-ICB-cofactor-torsion-quotients (closed, proof) says "no quotient for Wagner"; its `revisit_when` (large smooth cofactor, or a non-homomorphic filter with more than log2 h bits) does not hold at h = 2..8. LEAD-ICB-free-relations-self-collision is the four-list pair-pair join on the compact-orbit table (exhausted: 0.957-0.960x, net loss +5-9% in `ic price`). Not in my 19-lead study as a lead.
Evidence check: `analysis/o2-sum-compatible-filters/README.md` present (stale checkout), says toy N <= 65539 and "j=2 CLOSED". `KN-FIND-ffe1df` present and WITHDRAWS that headline (bucket-averaged; "NOT a closure"). The YAML `best_measured` repeats the withdrawn wording. `RESEARCH_IC_LEADS_AND_CONNECTIONS_20261010.md` 7(b) present, says the same as my obstruction.
Prediction: S(k-tree)/S(B) >= 1.00, derived, no measurement needed. (1) All five rows have r prime and gcd(h, r) = 1 (checked), so any homomorphism to a group of order < r kills <G> and factors through E/<G> = Z/h. Wagner's 4-tree needs about log2(r)/3 = 4.7 / 5.0 / 6.7 / 7.0 / 8.1 bits per level. (2) Without a filter, yield per group addition is arity-independent (KN-FIND-007), so arity buys nothing. Measured on the raw base, S(m=3 walk)/S(m=2 walk) = 1.62, 1.70, 2.53, 2.23, 3.90 (f2m15..f2m27, ratio of means). (3) Shape law: optimum ops is proportional to a^(1/3) b^(2/3) (a = table coefficient, b = walk coefficient); each extra filter bit would cut b by 2, worth 1.59x. The projection used h^(2/3) = 1.59 / 1.59 / 3.30 predicted against 1.29 / 1.58 / 3.36 measured, so the model is calibrated, and the bits are gone.
Decisive experiment: none on the ladder. Structural audit already done (r prime, gcd = 1, five rows). Kill criterion for any future filter claim: a computable map on E(F_{2^n}) points with more than log2 h bits of sum-compatibility, shown on the ladder instances.
Risks and contradictions found: the closure covers homomorphic filters only. Wagner over Z_p works through an integer-interval merge (Joux-Kippen-Loss); an order-compatible coordinate for curve points is unexamined as a theorem (repo 7(c) argues height is not sub-multiplicative). The m=3 ratios are unpaired means of one record.
Confidence: high for the ladder rows (group theory plus measured arity penalty); medium in general.
Sources: Wagner, CRYPTO 2002, https://www.iacr.org/archive/crypto2002/24420288/24420288.pdf (HTTP 403, not read; known via Dinur's abstract); Dinur, ePrint 2018/575 (abstract: N^(1/(floor(log K)+1))); Joux-Kippen-Loss, ePrint 2024/282 (abstract: interval merge over Z_p); Kosters-Yeo, arXiv:1503.08001 (abstract: one morphism to F_2); Minder-Sinclair, J. Cryptology 25 (2012), only a search snippet, not read.

### LEAD-ICB-kic-golden-base-exact-decomp: affine 2-flats, orbit-canonical lookup, SAT vs exact MITM
Verdict: CLOSE as a baseline lever (constant factor, dominated). Named obstruction: coverage cannot exceed the null (KN-FIND-007, exact identity; measured 70 = 70 at N7, 6189 against 6224 = 0.994 at N19) and "orbit-canonical lookup" is the existing compact-orbit table, which random-binary ladder rows cannot use (t = 1, negation already folded). The SAT arm stays an undecided stage diagnostic, not a closure (a timed-out run is not an obstruction).
Novelty: LEAD-ICB-frobenius-orbit-factor-base (compact-orbit is the incumbent), LEAD-ICB-generic-table-oracle. Literature: Karabina ePrint 2015/319 (base = points with x in an F_2-subspace), Trimoska-Ionica-Dequen ePrint 2019/313 and arXiv:2001.11229 (SAT/WDSat PDP; the KIC arms use CryptoMiniSat instead).
Evidence check (all present locally): `EXP-KIC-424885` raw-result matches the YAML exactly (SAT/MITM 1.702 [1.016, 2.685], eligible false). `EXP-KIC-3df18c`: best affine plane keeps 0.994 of the best unstructured coverage. `EXP-KIC-c3c732`: all 32 SAT workers UNKNOWN at the 2 s cap, no comparison. `EXP-KIC-7bcef8` / `d9c828`: canonical/expanded cold-job wall 0.751 [0.655, 0.864]; n19 M=1/32/512 = 0.764/0.825/1.003; n23 M=1/32/512 = 0.29/0.33/0.65. These are millisecond wall times against an expanded table that is not the baseline, i.e. table-build amortisation, not S. None has an EV record.
Generic bounds: constant-factor lever. Corrigan-Gibbs-Henzinger-Wu (abstract): structure on a delta fraction gives Omega(min(sqrt q, 1/delta)). The base itself covers |F|/#E of the points, about r^(-2/3), far under q^(-1/2). The sumset coverage F^2/(2r) is fixed by |F| for any design, and a table/MITM/membership oracle is enumeration in disguise. Only a non-generic algebraic oracle escapes, and that is the SAT arm, measured slower.
Prediction: S effect on ladder rows is 0. If decomposition were free, the saving is its probe: lookups are 1.0-2.5% of the walk phase (62-83% of S), so at most about 2% of S.
Decisive experiment: none for the baseline. For the SAT question only: rerun the N19 panel with the cap raised from 2 s to 60 s; kill if flat/MITM wall CI lower bound > 1 or censored again; CPU hours, small RAM and disk.
Risks and contradictions found: side observation, derived, wall-only. The binary table build uses one full `g.add` (one inversion) per pair; raw bases lie in an F_2-span, so x_i + x_j repeats at most 2^l - 1 times and an inverse table would cut the inversion. The projected base loses that. The prime batched build is counted identically (test asserts batch.adds == scalar.adds), so any such gain is invisible to counted GAE and would be accounting under the current unit.
Confidence: high on the closure for the baseline; low on SAT.
Sources: ePrint 2026/384 (abstract read; the q^(-1/2) threshold is my arithmetic from it); ePrint 2025/783 (Dinur-Keller-Marmor, abstract read, non-adaptive BSGS optimal below sqrt N advice); repo paths above.
