## Mechanism and concrete failure of the previous interface

`GainDsu` is an exact rank oracle for the large-prime coefficient block `A_L` **only** after summing duplicate LP keys modulo the *prime relation modulus* `ℓ`, dropping zero terms, and giving at most two distinct nonzero LP columns per row. It uses nonzero multiplicative potentials and component pinning. This is the frame-matroid setting of Zaslavsky's biased-graph work, not a generic graph-component count.

The public `add_row` previously used a `debug_assert!` for nonzero coefficients and incremented `rows` before checking `RowTooWide`. Thus a refused too-wide direct input increased `snapshot().left_nullity = rows - rank` in optimized builds, inventing one LP-cancelling relation in metadata. Repeated columns in a direct input bypassed normalization and were classified as a two-ended cycle, not as their combined single-coordinate equation. A failed composite-modulus inverse also left `rows` and `unions` incremented. These are admission/telemetry correctness defects; they are not a demonstrated ECDLP speed bottleneck.

The patch validates bounded arity, column range, distinctness, and each coefficient `1 <= a < ℓ` before any rank/counter mutation. Unordered distinct endpoints remain legal, preserving the existing closing-edge tests. It moves the row increment to after successful field arithmetic, and the union increment to after successful inversion. It introduces `LpGraphError::NonCanonicalRow` for malformed direct input. Collector input should still use `LpIndex::build` to normalize arbitrary repeated keys; the direct DSU is deliberately not a normalizer.

## Mathematical obligation

For a valid homogeneous row `a x_u+b x_v=0` with invertible `a,b`, a DSU component represents `x_u=p_u t_r`. Joining two components eliminates one free parameter; a cycle closes with scalar `γ=a p_u+b p_v`. If `γ=0`, it creates no rank; if `γ != 0`, it pins the remaining root and adds one rank iff not already pinned. Hence `rank(A_L)=v - (# unpinned components)` and the left-kernel dimension is `R-rank(A_L)`. Rejected inputs cannot be included in `R`; validation must be prior to the count. This formula and performance model require `ℓ` prime. The API's odd-modulus range check is not a primality test.

## New native regression definitions

- After accepting `(x_0+2x_1)=0` over F7, reject zero, nonreduced, repeated-index, out-of-range and three-entry direct rows without changing any `GainDsuSnapshot` field; two subsequent valid rows restore rank 3, cross-checked by the existing dense field oracle.
- Under deliberately invalid composite modulus 9, refuse `(x_0+3x_1)=0` when the pivot cannot be inverted, without consuming a row or union. A subsequent unit-coefficient edge must still be admitted. **This tests error-path atomicity only**, not a claim that arbitrary composite moduli support field-rank arithmetic.
