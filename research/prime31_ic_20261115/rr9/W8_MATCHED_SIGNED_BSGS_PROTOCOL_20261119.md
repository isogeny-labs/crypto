## Scientific question
At p=2147483647, E: y^2=x^3+847514846*x+2087444724, n=2147446831, cofactor one, G=(625037715,2100627251), what is the *same-runner*, **fully charged** cold/setup-shared 1024-Q performance of signed shared BSGS using the original Rust Arithmetic relative to the original W8 generic-grader 4-window index-calculus control (#4770)?  The same Q are generated by the seed stream embedded in #4770.  Do **not** compare unlike hosts, or claim that this native affine BSGS is the strongest independently optimized BSGS; retain #4532 as historical frontier context, not a matched speed record.

## Candidate/controls
- BSGS is a generic baseline, **not** the proposed non-generic solver. Build only once a baby table storing x(jG) and y(jG) for j=1..m, with m=32768, step=2m+1=65537. A signed match Q-i*(step G)=±jG yields log d=(i*step±j) mod n. Cover all d in 0..n-1 since i=floor((d+m)/step) and -m<=d-i*step<=m. Search i=0..ceil((n+m)/step). Include the exceptional identity j=0.
- Use `prime31_algebraic_ic::{Arithmetic,PRIME31,check_curve}` from pinned original crate commit `1df714645aa683cf975bc76fcacb9842cb4780fd`. Reuse its affine EC addition, scalar multiplication, counters and original cofactor-one check; no new independent group arithmetic for candidate.
- Reproduce #4770's exactly same 1024 target stream (seed, target xor, per-target splitmix state). The true scalars are never read by BSGS until after candidate answer is produced; use them only as verifier fixtures.
- Each arm includes curve certificate, target generation, all setup, table construction, work on all targets, full scalar verification, every failed probe, count group additions/field multiplications/inversions, and peak baby-table count.
- Same GitHub runner executes OLD / TERNARY / SIGNED-BSGS / SIGNED-BSGS / TERNARY / OLD (or balanced comparable paired order if changed **before data**). No cache of the target logarithms between runs; only the common per-algorithm table is shared within each batch.
- A separate Python BigInt curve implementation must independently regenerate the 1024 public targets, verify 1024 recovered d via dG=Q, inspect all counts and range coverage. Fail closed on mismatched targets.
- A/A check between BSGS runs must return identical answer bytes (except elapsed times), operation counts and x-coordinate transcript; variable host load remains possible.
