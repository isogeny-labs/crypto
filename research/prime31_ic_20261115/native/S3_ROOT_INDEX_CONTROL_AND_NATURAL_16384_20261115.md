## An exact algebraic root-index baseline (and why it is generic-equivalent)

Let `K(U)=prod_{i<=j} S3(x_i,x_j,U)`, with the B=31 canonical Dickson x base on the same ordinary prime-order curve `p=2147483647, a=847514846, b=2087444724, n=2147446831`. Every constituent S3 factor is at most quadratic in `U` and completely Fp-split for non-torsion affine base points. **Without consulting factor-base y values, known point-sum tables or any elliptic-curve addition**, split each pair's S3 with the exact finite-field quadratic formula, register its roots in `BTreeMap<u64,Vec<(i,j)>>`, and check the complete set of pair-support roots. The expected B31 multiset degree is `B²=961`; the prior source reported it is squarefree in this fixture.

For a public **abscissa** `t=x(Q)` only, iterate supported abscissae `u`. Compute all `v` satisfying `S3(u,v,t)=0` via the same quadratic solver; test membership of `v` in the precomputed coordinate index. Expand original factor-base pair indices and only **after algebraic discovery** verify signed four-point identities against the full public point `Q` with the reused `Arithmetic::add` and y values. Add explicit `target_x in pair support` identity-pair padding to cover four-term relations with a cancelling pair. Zero-polynomial S3 exceptions are **errors/undetermined**, never negative outcomes. An index-root collision remains tracked rather than discarded. Test all 224 nonidentity four-term signed B4 outputs generated by a quarantined group-law test-only oracle.

This is computationally efficient for small B but **is not a new non-generic attack**. The split S3 roots represent exactly the x-coordinates of ordinary group pair sums/differences, so indexing them is essentially algebraic meet-in-the-middle / generic pair-sum precomputation. The generic-equivalence risk previously established in the S3 discriminant notes remains. Do not promote this method into the novel/non-generic column, even if its query timing beats the dense polynomial quotient. Its value is (i) an independently implemented correctness oracle for polynomial eliminants, (ii) a cheap natural-target support census, and (iii) a hard baseline that future genuine target-dependent m8 elimination needs to justify beating.
