# Split-graph construction ladder: preregistered harness

This track retains d=3,4,5 on three prospectively fixed prime fields
`83,101,127`. Source: the complete-splitting theorem in
`../../SECANT_GRAPH.md`, the repository's 24-design register, PKM 2016
(`https://people.maths.ox.ac.uk/petit/files/16PKC_primeECDLP.pdf`), and the
standard chord/tangent/interpolation identities. This is not a novelty claim.

## Frozen selection

`spec.json` freezes seed315, field population and caps before data collection.
For each field, domain-separated SHA-256 proposes nonzero A and B. Accept the
first nonsingular curve whose j is neither0 nor1728, whose exactly counted
full group order is prime, at least23 and different from p. Keep every rejected
curve proposal and every counted operation. Curve choice never depends on
graph splitting or target outcomes.

For each d, hash-order the rational abscissae and choose d+1 distinct entries;
choose each ordinate sign from the same domain-separated hash. Interpolate h,
reject degree drops, then test all field abscissae for h²=f. Accept only exactly
2d distinct roots, preserving every rejection and the first success. This
forces d+1 roots by construction and leaves degree d−1 to split; an expected
splitting rate is a heuristic, not a bound or measured value.

Each accepted cell exports the candidate and two size-matched controls:
low-x and independently hash-selected x values. Control ordinate signs are
independent hashes and their exact interpolant degrees are retained. Both
signs appear in every point inventory. Controls keep their dense membership
constraints in secant inputs. Duplicate point sets are recorded.

Every affine target, both signs included, receives one dense input and all
four secant branches per arm. The identity target is separately recorded by
inverse-pair references. Full finite-target pair references are generated by
exact group addition. No full relation search is inferred from the local
homogeneous degree theorem. ICV1 and FB1 dump preimages follow the repository
formats; central registry/EC1 linkage is explicitly pending.

## Limits and admission

This is a scientific construction/yield run, not a unit test. Do not run it
until the parent verifies checkpoint/backend admission or receives an explicit
owner override. Building and running small fixed arithmetic unit tests is
development work. The default command refuses a run without a named admission
receipt; the receipt must be supplied by the coordinating parent.

```sh
cargo build --release --locked --offline --manifest-path PATH/ladder/Cargo.toml
timeout 180s bash -c 'ulimit -v 2097152; PATH/ladder/target/release/secant-graph-ladder run PATH/ladder/spec.json FRESH-OUTPUT --admission-receipt RECEIPT.json'
```

One CPU, at most2GiB address space; global soft deadline120s and outer cap180s.
At most256 curve proposals per field and512 graph proposals per curve/d cell.
The output is write-once. Timeouts/caps remain outcomes, not impossibility.
No paid-resource expansion is requested. All nine degree/field cells remain
in the manifest, including cells blocked by curve selection or the deadline.

Compact curve/graph attempt logs retain operation deltas and hypothesis hashes;
large systems files are reproducible execution artifacts. Parent controls their
archive/artifact-store retention. Timing is unqualified unless the admitted
runner meets its separately declared isolation requirements. Field operations,
hash calls, curve-counting work, group work, export work and serialization
payload bytes are reported separately; setup is never divided by target count
and called a single-target solve cost. Field arithmetic counts cover curve
selection, interpolation, splitting checks, exact factorization, controls,
group references and expected-root checks. Primitive coefficient assembly and
artifact-payload hashing are explicitly uncounted (`null`), so these records
do not claim a complete end-to-end operation total. Physical disk traffic and
RSS require the outer runner; serialization byte counts are not those metrics.

The admission receipt must explicitly record a genuine local exception using
`schema: secant-graph-run-admission/v1`,
`workload: secant_graph_d3_d4_d5_ladder`, `backend: local`,
`checkpoint_gate_passed: false`, `checkpoint_override: true`,
`backend_override: true`, `user_authorization_received: true`,
`max_seconds: 180`, `address_space_bytes: 2147483648`, a nonempty
`authorization_reference`, the exact `protocol_sha256` and 40-hex
`source_revision`. It does not assert that the failed S3 gate passed. Only the
coordinating parent may supply it after actual user authorization. No such
receipt is committed here.

Completed proposals are immediately journaled to JSONL files, including
rejections, before proceeding. Final summaries retain those journals plus
compact attempt arrays. At each arm, the run asserts finite ordered relation
total K²−K, K doubles, K identity inverse pairs, and equality between paired
target counts. It reports unordered counts and the fraction of finite targets
with a relation separately. These totals do not establish independent rows.
