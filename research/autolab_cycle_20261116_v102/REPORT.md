# C102: exact affine elimination reveals fill; local tables give a changed lead

The first hypothesis was exact XOR elimination before nonlinear search on precisely the same C101 necessary family. The output contract and proof are in xor_first_20261116_v102/PROOF_AND_REVIEW.md. Independent exhaustive truth tables passed 72 circuits: 874 literal assignments and 1,512 reduced assignments, with equal projected model sets and unique recovery.

The actual quotient has 17,399 atoms, linear rank 335 and 17,064 free atoms. Conservative propagation removes 71 of 17,323 AND constraints. It leaves 335,396 affine support terms and a maximum width of 999. Preprocessing took 0.586 seconds. Formulation took 9.643 seconds versus C101's 2.770. Both 45-second necessary searches returned UNKNOWN/timeout with zero models. C102 process lifetime was 45.340 seconds and process peak RSS 480,992 KiB versus C101 45.291 seconds and 287,804 KiB. Solver internal maxima were 330.5 versus 223.41 MB; these differ from process RSS. These single development diagnostics have no A/A/isolation qualification or completed root solve. Fewer symbolic variables did not make this encoding cheaper. Retain the exact quotient as a component, reject this naive rematerialization as the next default search.

The third experiment changed representation: enumerate exactly the fixed-trace split-quintic coefficient tables in fourteen small residue fields, preserving the same shared parameters. Every repeated/zero root is retained. It passed 948 literal factor-division controls and 224 actual parameter bindings against the numeric nilpotency oracle. Table sizes are 3,3,14,99,99,969,969,969 and six times 11,781. Exact bottom-up decision diagrams total 82,643 nodes, exceeding the preceding arithmetic circuit's 51,089 non-input gates. This profile does not establish that table SAT is faster; no table SAT search was run. Both positive and negative evidence remain.

All three experiments used lab.runner resume/run-ready with frozen hashes, 90-second outer deadlines, 4 GiB and CPU 0. Search included preprocessing/formulation within its original 45-second cap. Source, input, native-library receipts, process evidence and failed/inconclusive outputs are retained. Portable replay includes hash verification and deterministic small oracles. No original exact count or root completeness was accepted; no qualified speed ratio is available. The full 339-variable target and requested fields remain open. The frozen 2x release floor and user's 50x target are unchanged.

Next hypothesis: derive low-degree vanishing relations from the exact residue tables and keep only relations proved to vanish on every allowed tuple. Measure relation rank and added pruning before hard search; preserve all positive branches. Also compare native XOR retention or bounded local parity reuse against the measured fill, rather than another general parity expansion. This shifts effort from gate syntax to algebraic information.

Primary-source novelty review: CryptoMiniSat's own README documents XOR clauses and cites Soos, Nohl and Castelluccia, SAT 2009 (DOI 10.1007/978-3-642-02777-2_24). Its gaussian.cpp cites Han and Jiang, CAV 2012, When Boolean Satisfiability Meets Gaussian Elimination in a Simplex Way. Retrieved source excerpts are included with URLs in NOVELTY.md. Hence XOR/Gaussian SAT is prior art, not a new rootfinding algorithm here. No claim of novel table enumeration or decision diagrams is made.
