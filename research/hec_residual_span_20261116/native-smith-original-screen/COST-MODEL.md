# Favorable-to-quartic arithmetic screen [pcc:unverified]

This compares operation proxies on the exact original F61public inputs. It is NOT a wall-time/CPU lower bound, a calibrated instruction model, an asymptotic exclusion or an impossibility theorem for Smith isogenies. It screens the current provided-model implementation and current work allocation only.

For each prime modulus count a scalar-product proxy from the native16vector as M=v[4]+v[6]+v[11]: Fp::mul, Fp::mul_pre and raw polynomial convolution products. These endpoints are disjoint. Native inverse calls are I=v[9]. Conversion/preparation, REDCs, Euclidean integer iterations, additions, setup integer arithmetic and host work remain separate/unpriced. No blind sum of all16columns is used. Pic modular-product endpoints (meter columns0+1+2) and inverse backends(3+4) are disjoint from native endpoints and are added only to the same prime's M/I proxy.

Use the four-vector C=(M61,I61,Mell,Iell). For any nonnegative price vector w with w.C_baseline>0, cost_w(C)=w.C. This family permits arbitrary relative prices for field/subgroup products and inversions, but not arbitrary prices for omitted host/conversion/REDC operations. A result in this proxy does not prove a runtime ratio.

Baseline: strongest qualified normalized original hyperelliptic control (public D/T and branch-zero constraints, static affine forest, no late finisher). Charge eligibility, fresh prepared root catalogue, complete solve with its native verification, and an additional independent [k]D=T check. Fresh replay must reproduce all old normalized16vectors and report bytes, then the independently metered extra verification is added. This is deliberately generous to the baseline cost, making rejection harder. Both original source multiples1/17 and exact target seeds are retained.

Candidate lower bounds: calibrated frozen Pic/native vectors from native-smith-meter/PHASES.json, transcribed without scientific aggregation into records.rs. One bound is the full secant setup alone, charged cold to one target; all model construction, point search, Pic constructor, transport, online work and verification are set free. A second bound is online quartic IC alone, making all precomputation/transport free. These are favorable omissions because all proxy costs are nonnegative. Do not call either a complete candidate cost.

For each candidate vector A and baseline B compute rho=min_i A_i/B_i exactly. Then A_i>=rho B_i implies w.A>=rho w.B for all admitted w. If rho>1/10, that subset alone excludes a10xgain for the current implementation in this cost family. The anticipated stronger setup bound33/16 must be checked componentwise by integer cross-products after fresh baseline replay; retain failure if it does not hold.

Since a stronger original solver or rho would have cost at most this chosen normalized control in any particular price, failure against this concrete working IC comparator already prevents promoting the current candidate as a10xadvance over that comparator. It does not measure matched rho or establish the best possible solver cost. A positive speed claim would require full same-target construction/setup/transport/solve/verification plus CPU and rho evidence; this negative screen can safely favor the candidate by omitting its costs.

The current online code includes potentially removable redundant quartic subgroup/final checks. The secant setup includes potentially replaceable enumeration/rank work. A redesigned implementation requires a new protocol and new cost case; this screen does not exclude it. Larger fields, other kernels/models, genus2/genus4 and the full10xgenus2+objective remain open.
