## Accounting and admission order

Retain existing W/B/E/G/T, phase deadline and two work pools. All arithmetic is checked before addition/multiplication or usize conversion. Input/config/public/domain bytes and scalar lengths must first satisfy the outer bounded parse contract; compare coordinates/modulus to canonical decimal u64 before invoking any curve/group wrapper. Reject noncanonical/out-of-range coordinates; never silently reduce public coordinates.

B is cumulative modeled requested storage, including adapter-owned fixed scratch and heap capacity requests and exact native reservations, not RSS or arbitrary allocator overhead. Fixed scratch is charged once per attempt, even though reused. Distinguish that from cumulative repeated heap requests, which are never refunded. Keep charges visible after failed allocation or downstream refusal. `size_of::<T>()` and `Layout::array::<T>(n)` are authoritative for actual implementation layouts; numerical examples below assume the usual64-bit target and are checked, never hardcoded as ABI facts. A requested allocation means `try_reserve_exact` on an empty Vec after admission; this may return more capacity than requested, so track the admitted logical capacity separately and never use allocator spare capacity as authorization. This is not a bound on allocator usable size; do not use vec!, collect, clone, resize beyond capacity or infallible growth for data-sized allocations.

Freeze adapter-owned buffers before calling native: input terms/headers, all serialized slots, linear scratch, group scratch and fixed terminal state. Native receives only remaining B, so native cannot consume memory promised for its result, a first certificate or stop evidence. Original input and serialized input stay live across native; native report remains live during extraction/group, while no second basis object is created. Setup's4096 reservation is separately deducted exactly once. Report ownership transfers without cloning. No allocation is first performed and later retrospectively charged.

Work primitives: field add/sub/mul/sqr/conversion16units; exponent-coordinate read/comparison/update8units; bounded counter/array-index bookkeeping8units. Charge explicit loop upper schedules before each operation or chunk, not unchecked aggregate estimates. At most256 such primitives between deadline checks; callbacks check before and after. Loop bounds and checked counts are part of replay. These units are modeled work, never hardware instructions. Group-add G is an additional allowance, not a substitute for charging checking_work.

Parent-reservation/local-ticket rule: atomically check and debit a worst-case modeled-work reservation from the applicable parent pool before each bounded operation/chunk, and issue a local ticket of that amount. Nested operations spend the ticket only; they never debit the parent again. Unused consumed reservation is not refunded, including early infinity, deadline, allocation failure and callback refusal. Tickets for counting and writing are distinct and each paid once. Record reserved and performed primitive counts separately. For a tuple, reserve its m-1 G allowance and checking/evaluation/serialization tickets before entry; for certificate replay reserve m additional G allowance and its own tickets. G_reserved is nonrefundable, while G_performed increments only after an actual addition. Tuple count records entry once. A partial prefix must not claim reserved-but-unperformed additions.

Existing native/setup engines retain their internal reservation schedule: exclusively escrow the supplied remaining allowance while they run, then reconcile exact returned reserved work/bytes once into the parent and release only never-consumed escrow. This release is not a refund of consumed reservation. Do not debit the full escrow and then also debit the returned reservations. Native callbacks have their separate pre-reserved adapter retention tickets, so cannot spend the escrow. Every nested root/residual call uses the same mechanism. Deterministic verifier checks reconstruct tickets, consumed reservations and performed operations separately.

## Canonical chain construction without map/Value duplication

Implement local typed bounded construction in the new adapter file, with exact same original equations/order/schema as solvers.rs:1835–2008. No new shared support file is required. Constants: m<=15,V<=28,K<=32,P=2m-1<=29,Tmax=13(m-1)+(K+1)m<=677. Target substitution may lower counts, never increase them.

Scratch: two `[u64;33]` membership arrays, one `[CanonicalTerm;33]` term array, `[u64;32]` sorted distinct x codes, `[SmallPoint;64]` signed domain, and fixed parameter scalars. SmallPoint is a tagged infinity/affine canonical pair, with layout charged by size_of (do not assume enum24bytes). Collect codes by bounded insertion into the fixed array; compare original signed order separately. Membership multiplication uses the two arrays alternately, zeroing only the next K+1 region. Reserve sum(i=1..K)i=K(K+1)/2 coefficient-update iterations: each one mul, neg/sub, two additions plus index operations; at most128units/iteration. The arrays never grow.

Expand each of the fixed13 S3 raw terms directly into Mono28, with checked exponent updates and at most two target multiplications per affected term. Use allocation-free insertion sort on at most33 scratch terms; sum(j=1..r-1)j <=528 comparisons/moves. Each monomial comparison scans at mostV coordinates twice (degree then reverse lex), charged16V+8; moved term size is charged as8*(ceil(size_of(CanonicalTerm)/8)+1). Merge adjacent equal monomials in place and remove zero coefficients. This exactly replaces BTreeMap canonicalization, not a different equation set. Membership terms are already ordered by exponent; use the same bounded canonicalizer or the documented monotone shortcut, with exact differential controls.

Allocate native input headers with capacityP and each term Vec with exact surviving count after scratch canonicalization. Before each request charge `128+n*size_of(T)` as native Gate::vec does. Total requested input storage <=128+P*size_of(InputPolynomial)+128P+Tmax*size_of(CanonicalTerm), plus fixed scratch. At64-bit sizes24/64, this is<=47,864bytes, not a multimegabyte guessed JSON-tree envelope. Input terms are the single typed original source used by native and independent residual evaluation. No Vec<Vec<u32>> or domains clones are retained.

Preserve existing input JSON fields using custom borrowed Serialize views over typed arrays. Exponents serialize as exactly V integers; coefficient/modulus/coordinates use stack decimal formatting (maximum19digits); domain/role fields are generated by index, not retained Values/Strings. Fixed names use stack byte arrays or Serialize wrappers. Schema fields such as legacy native_modulus_limit_exclusive are reproduced for canonical compatibility, not interpreted as the current engine's limit. Compare parsed schema/value equality and canonical bytes where the established serializer promises byte equality in tests, rather than silently changing public equations.

No unconditional promise every K fits the input slot. First run a checked counting serializer, stop as soon as slot cap is exceeded; only then fill the already reserved bounded slot. Counting and writing both consume work proportional to visited bytes/tokens. No native call follows input_slot_limit. Counts for max shape m15/K32 and small original-chain D2/K1 controls must be frozen in tests; numerical fitting is not guessed from the677-term count.

## Serialized storage and retained basis

Keep existing eight slot fractions and sum<=E. Allocate all eight byte buffers once with their fixed caps before native (`8*128 + sum(cap)` storage), fill using a Write implementation that checks remaining capacity before copying and never grows. Counting serializer has no output buffer and fails at cap+1; a bounded writer remains mandatory even after counting. Decimal conversion uses fixed20byte scratch for u64 and40 for u128. Terms are streamed from borrowed arrays; no serde_json::Value basis tree or pretty-print buffer. Charge both passes separately, at least8units/output byte plus explicitly charged coordinate scans. This cost is intentionally visible and may censor large bases; do not reset W to serialize them.

For a native term, JSON exponent width is <=5digits per u16, plus comma, with canonical coefficient<=19digits. A safe term upper envelope is128+6V bytes, <=296; this is a bound on the chosen fixed schema, not a requirement to allocate296 for every term. Fixed native header is counted separately, then exact bounded counting determines fit. Native basis may have many terms despite basis_count<=256. Do NOT assume the input677 bound applies to output.

On output-slot/work/deadline refusal, retain a small native metadata record with `basis_retained=false`, explicit `basis_retention_stop`, actual complete/partial native statistics, and no basis. Preserve native stop separately from retention stop. Do not truncate a polynomial or silently retain a prefix as a complete basis. Linear extraction is not attempted without full retained basis. Independent group verification can continue only within remaining budgets; it cannot change the failed retention label or claim reported-basis extraction. This is a real finite-resource stop, not support for a nominal extraction profile. Useful original-chain controls must pass retention and extraction gates where those capabilities are advertised.

Store events directly into their reserved byte slot with strict global count<=4096. Do not retain an additional Vec<Event>. Reader uses cap-checked file metadata AND capped read to defend file growth, checked aggregate bytes before parsing and array visitors which reject lengths before push. Do not deserialize to Value then measure its shape. Replay may read one slot at a time; retaining every raw slot concurrently is bounded by E but must be charged if chosen.

## Linear-candidate extraction scratch and schedule

Preserve the frozen deterministic substitution algorithm, not a new Gaussian/full-root substitute. Before extraction scan borrowed basis lengths with checked arithmetic. Per-polynomial scratch ceiling L=8192 terms; a larger polynomial yields `linear_term_limit`, not 'no roots'. Allocate two reusable scratch arrays of L CanonicalTerms with requested capacities (2*(128+L*size_of(CanonicalTerm))); at64-byte terms this is1,048,832bytes. Reserve before native so the later basis cannot crowd this out. Also reserve fixed28 assignments,28 source IDs and29 transition states; do not clone full polynomials or serialize each intermediate remainder.

For a pass, copy one polynomial into scratch while substituting bound coordinates. Each term scans V exponents and uses binary exponentiation only for nonzero assigned powers. Native u16 exponent implies bitlength<=16: at most32field mul/sqr per exponent; charge the exact conservative schedule before that term and check chunks. Zero out substituted exponents. Stable bottom-up merge between the two admitted arrays canonicalizes in <=ceil(log2 L) rounds, <=L comparisons and L copies per round; comparator costs<=16V+8, copies as above. Merge equal monomials in place, summing coefficients. No recursive sort or allocation. Work exhaustion may leave a diagnostic partial pass but cannot create an assignment record.

Choose lowest remaining variable then lowest eligible basis ID as frozen, using at mostV+1 complete passes. A variable pivot requires that the entire canonical remainder is affine in that one variable. Invert a!=0 by fixed binary exponent p-2 using borrowed Fp64Arithmetic: at most122multiplications, plus conversion and final a*inverse==1 check.4096work is sufficient for this field schedule at16units/primitive plus bounded scalar bookkeeping; charge once before inverse. No root routine, Euclidean unbounded loop or auxiliary coordinate enumeration. Record compact variable/basis ID/a/b/value and cumulative charges, not the whole scratch polynomial. Missing pivots remains nonlinear_or_underdetermined; contradiction remains encoding-relative. Partial basis is not a complete ideal certificate.

Original-system evaluator uses canonical u128 product/modp, fixed coordinates/residue arrays, <=677 original terms; it never delegates to native Montgomery arithmetic. Both p and factors<=2^61-1 imply product<2^122, addition<2^62. Exponents in originals<=32 (binary length<=6); count every term/coordinate scan and up to12mul per nonzero exponent. Replay uses the same mathematical specification but separately implemented canonical kernel, not producer function invocation. This is exact finite arithmetic, not floating point or random evaluation.

## Capture boundary and required scope before end-to-end claims

The preceding B covers adapter mathematical/storage requests and native/setup reservations. It does NOT establish bounds for existing process setup, allocator metadata, public CaseData Value construction, manifest/capture maps or filesystem/kernel buffers. The existing Linux worker sets both RLIMIT_AS soft/hard limits before exec (ml_dataset/mod.rs:1640–1667), bounding child virtual address space rather than RSS. Original supervisor deadline remains necessary; OOM can still interrupt persistence. Neither this OS boundary nor B proves whole-process allocation-failure recovery. E is canonical artifact bytes; live copies/capture events remain separately charged to original CaptureLimits, never assumed to fit E automatically.

For bounded adapter-to-capture requested-storage admission, parent must separately reserve solvers EventSink and capture.rs. Freeze this narrow API contract:

- Add `CaptureEmitter::event_typed<T: Serialize>` and the corresponding generic EventSink/live helper. EventSink is an enum, so no object-safe serialization framework is needed. Typed payloads serialize into the unchanged bound envelope (schema, binding hash, sequence, previous event hash, event, newline), using reusable pre-admitted storage and a writer enforcing the logical event cap before every copy. No intermediate Value or parse-back-to-Value is permitted. Count first under its own work ticket; the writing pass must still enforce the cap.
- Atomically check remaining event count and aggregate stream bytes before commit. Preserve existing digest chaining, sync/commit ordering, sticky failure and terminal head semantics. Restrict the typed helper to adapter-owned event kinds using a trusted closed discriminator; callers cannot emit the reserved emitter-owned payload kind. Payload notifications are encoded by the emitter itself.
- Use only the Bound route for this supervised profile; refuse Legacy routing rather than falling back to its allocating serializer or fs::read idempotency check. Existing legacy APIs/behavior remain unchanged.
- Publish payload bytes by borrowing the admitted canonical buffers, with unchanged path/role/encoding/hash identity and duplicate-byte idempotence. Keep storage::check_file streaming. Pre-admit bounded event/descriptor/head serialization storage for this new entrypoint. Existing manifest maps, CaseData and filesystem internals remain under the original outer capture/supervisor boundary; this entrypoint is not an undertaking to replace the whole worker allocator.
- Tests compare exact event-envelope bytes against the legacy encoder for admitted small typed records, reject reserved-kind injection, exercise exact/one-less per-event and aggregate limits, duplicate identity, callback refusal and post-write failure. Test logical capacities even if Vec returns excess physical capacity.

The mathematical core can be implemented immediately in its reserved child with this finite interface obligation. Dispatcher activation still waits for typed capture/central integration and fixed controls. Label the resulting contract bounded mathematical requested storage plus bounded capture entry and Linux child RLIMIT_AS, never whole-process allocation recovery or measured RSS. No additional capture scope is acquired by this document.
