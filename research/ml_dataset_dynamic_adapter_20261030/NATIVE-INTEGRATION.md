## Escrow, settlement and callback admission

A `NativeEscrow` value records opening cumulative counters, supplied work/bytes, phase deadline and one-shot settlement state. Opening escrow does NOT debit supplied limits as consumed reservations. The native call has exclusive access to its supplied allowances, while callback code can access only its separate pre-admitted observer tickets and event slot. Neither side can debit the other's allowance. On return, validate report.reserved<=supplied and add those exact reservations once to the parent, even for observer/deadline/work/allocation/invalid-input stops. Unconsumed escrow becomes available afterward; consumed reservation is never refunded. Do not add all event-reported reservation snapshots: they are cumulative native snapshots. The final Report is the settlement source, with acknowledged event snapshots checked for monotonicity and bounds.

Concrete finite callback work policy to freeze before implementation: after setup/input/pre-admission, withhold at most one quarter of remaining algebra work as an **observer escrow**, leaving the other three quarters available to native (both are still the same original algebra pool). This is internal allocation, not added work or a fresh case budget. It is escrow, not an automatic consumed debit: each callback first consumes its exact fixed worst-width row/count/write/capture ticket from that escrow, and unused escrow is released after the native call. The typed event serializer has bounded fixed fields only; its maximum row/envelope length and per-pass work are computed from maximal u64/usize widths and the closed enum strings. If remaining observer work or event-slot bytes cannot admit the next row, refuse the callback with an explicit ObserverWorkLimit/ObserverBytesLimit, preserve prior acknowledged rows, and retain native Stop::Observer separately. Do not shrink dynamic Limits.events to disguise this as the native global event cap, and do not borrow back native escrow while the call is running. This deterministic suballocation may cause honest censoring and must be in receipts/controls; no assertion that every4096 events can fit within W.

Before callback acknowledgement: check the original phase deadline, remaining global4096 count, monotone source-local sequence, cumulative native reservations within its escrow, event slot row capacity, and local work ticket. Serialize the small typed row directly into the event slot with rollback to its original logical length on refusal; optionally forward through the already-admitted Bound typed capture bridge using separately charged count/write tickets from the same observer escrow. Capture refusal is sticky. A row accepted into local bytes but refused by durable capture must not increment the acknowledged global/source count; save at most one fixed inline unacknowledged diagnostic and roll back the local acknowledged prefix. No allocation per event and no repeated event-budget reset.

Setup consumes the same shared event count first. Native receives Limits.events=4096-acknowledged_setup_events (and later phases receive the actual remainder). Global row includes source enum, global sequence, local sequence, source stage, consumed source work/bytes and original binding. Native report.acknowledged_events must equal acknowledged native rows, not include attempted/unacknowledged callbacks. Only acknowledged terminal native rows are required to match report terminal counters; a stop without terminal notification is recorded honestly.

Settlement must be unconditional after run returns, before any fallible retention. A typed settlement error is fatal to interpretation and prevents all success claims. Tests exercise double settlement, over-limit reported counters, zero/partial receipts, callback refusal and deadline, plus a second native call consuming only the settled remainder. Do not use Drop to silently erase unhandled settlement; keep the closure-based API structured so a returned native Report is always settled before it can escape.
