## Actual frozen structure

1. Cold setup, native_solver824–843 and1255 onward: build p square-root vectors by scanning every y, then p rational-y vectors by evaluating h at every x and cloning the corresponding root list. O(p) field operations and O(p) storage for fixed quintic degree. LinearSolver::new1018 scans p positions again, assigning one node per x with a nonzero ordinate. This setup repeats per cold target; sharing it would change the accounting boundary unless separately reported.
2. Each eligible degree2 walk (at most16;1311 onward) calls point_sieve_candidates850–994. It allocates p empty bucket Vecs, scans all p x, evaluates u and v, handles roots of u separately, and gathers denominators for rational ordinary points. It builds an additional denominator vector and prefix vector, performs one batch inverse when nonempty, and three batch multiplications per denominator plus explicit inverse-check multiplications. It enumerates every rational ordinate for ordinary x, computes lambda=(y-v(x))/u(x), and pushes x into its lambda bucket. Two complete p-bucket passes count then insert collision candidates; exceptional support is appended afterward. Candidate ordering is the tracked ordered set's ascending lambda order.
3. Candidate verification801/1330: complement computes `(v+lambda*u)^2-h`, exact division by u and a remainder assertion before checking root count. For a degree2 divisor/quintic this is a bounded-degree cubic computation: O(1) field work per candidate, not an O(p) root scan. Accepted three-root candidates still perform quotient-root tests, curve tests and Jacobian addition checks. Eliminating these validations would change the accepted evidence contract.
4. Graph/residual elimination: symbolic forest stores sparse affine offsets over protected small variables. `expression` traverses parent paths and accumulates sparse maps; size-balanced union bounds parent depth logarithmically in large-node count, but does NOT bound symbolic expression width. Residual::insert80–141 eliminates against ordered pivot rows with BTreeMap updates, normalizes a new pivot via scalar inverse and retains it. A row of width w can touch multiple pivots, each with width up to S (small columns). Worst-case work is O(S^2 log S) per emitted constraint for tree-map updates, and retained dense basis size O(S^2), before explicit caps intervene. This is an upper bound, not the observed case.

The 25million residual coefficient cap limits retained/working residual terms according to source, not total arithmetic, all graph offsets, all heap allocation or seconds. Collector keeps a pending unincorporated constraint outside the residual retained limit. It is incorrect to infer a wall-time or whole-memory bound from that cap.

## Bounds at p=186379 (derived, not measured)

For16 eligible walks, the full-x sieve visits at most16p=2,982,064 x positions; two bucket scans add at most32p=5,964,128 bucket visits. Those counts exclude setup, ordinate probes, polynomial coefficient scans, assertions, sparse-map work and allocation. They do not identify the timeout's dominant phase.

A `Vec<u64>` header is24bytes on the intended64-bit Rust ABI: p bucket headers alone are4,473,096bytes per sieve, before element buffers and allocator overhead. This is an ABI-derived layout amount, not observed RSS. Each x has at most2 rational ordinates, so ordinary bucket pushes are at most2p=372,758 per sieve. Under the valid smooth genus2 model, the sharper affine-point Hasse bound is p+floor(4sqrt(p))=188,105; use only under those curve hypotheses. All denominator locations, ordinary plus exceptional, are distinct x, so their total is <=p. Degree2 u gives <=2 exceptional roots.

The quotient q_lambda has degree3 with nonzero leading coefficient -h5. Ordinary entries are distinct quotient roots. Thus an ordinary bucket reaching three roots cannot exceed three in the valid domain. The all-lambda exceptional branch is unreachable on a smooth quintic under valid Mumford congruence; it remains present in generic software and singular fixtures. Candidate count is bounded by floor(Nordinary_ordinate_probes/3)+2, not automatically equal to this bound. These facts are mathematical preconditions, not unchecked optimization licenses for arbitrary input.

## Non-lossy prospective changes and obligations

A. Reusable compact sieve workspace. Replace p Vec headers with fixed three-root slots/counts plus a touched-lambda list, or a flat root buffer with offsets. Reset only touched entries and derive collision count during insertion; sort candidate lambdas before verification to retain the exact order. For valid smooth inputs, storage is O(p) with bounded roots per bucket. Preserve overflow detection/fallback for outside-domain input; prove exceptional appends cannot cause loss or double counting. Preserve original root order if verifier/group operation counts depend on it. Account every initialization/copy/scan; buffer reuse changes allocation/clock observations and requires a new instrument binding.

B. Scan only ordinary rational-x support plus the at-most-two exceptional u-roots. Setup already knows the rational-point inventory. Ordinary x without rational y can never generate a candidate; their only relevance is potential u=0. Therefore an exact iterator over rational x together with a proven-complete quadratic root routine can replace the full-x scan without relation loss. This is still O(p) in general and root finding is not free: charge quadratic factoring/square-root/inverse work, merge/deduplicate exceptional roots, preserve old reverse-denominator and root iteration order if exact stream/counters are intended. A simpler first change can retain full scan while reusing arrays, reducing implementation risk.

C. Exact residual/offset representation changes. Sorted contiguous sparse rows permit merge-based axpy instead of per-term BTreeMap logarithms; dense rows/bitsets or sparse-to-dense switching may suit fill-in. They must preserve coefficient arithmetic, smallest-column pivot selection, cancellation, pending-row retention and exact cap tests if retaining old terminal outcomes. Preflight an entire row's final width is NOT equivalent to current transient working-cap checks. Path compression may reduce repeated expression reconstruction but must compose signed/scaled symbolic offsets exactly, preserve emitted row space, and count all compression work. It cannot borrow the paper's near-constant graph-edge cost when offsets are wide.

D. Larger algorithm changes are separate protocols. Alternate small/large partition, Markowitz pivots, block linear algebra or retaining three-large relations can preserve mathematical information under a redesigned solver, but alter relation admission, elimination order, cap outcomes or stopping semantics. They need prefix row-space equivalence and new prospective comparisons, not an assertion of same frozen algorithm. Full setup, verification, inversions, graph processing, relation root finding and unsuccessful work stay in costs.
