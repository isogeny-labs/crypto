# Campaign protocol

The canonical machine-readable protocol is [`protocol.json`](protocol.json),
generated by [`build_protocol.py`](build_protocol.py).  It is intentionally in
`draft` state: no fresh data have been collected. Trusted publication run
`41241104247` has now bound the exact static binary and EKS image, but the
finite implementation roster and queue-safe shard list are not yet frozen.

The non-negotiable comparison rules are fixed:

- cold, one-target E2E scope;
- separate prime, random-binary, Koblitz, j=0, j=1728, generator-orbit,
  extension-field, transfer, and solver-backend domains;
- eight public targets per cell, one warmup, six measured rounds;
- strongest applicable accounting-correct rho reference and an identical rho
  A/A control in every frontier shard;
- pricing weights 0, 0.1 and 1 GAE per native operation;
- L2 required for wall time, replay-all, retained failures and timeouts;
- scaling language only after all four sizes in a domain complete;
- no cross-ranking of unlike native solver counters.

[`IMPLEMENTATIONS.md`](IMPLEMENTATIONS.md) closes the named implementation
space. The current nine specs are planning artifacts: they omit several
required domains and their 4,704 planned processes cannot safely fit the
queue's 3,600-second whole-job limit. Before execution, the trusted executor
must split them into candidate/reference/A-A shards, add the missing census and
frontier cells, validate every request, freeze the exact shard roster on
`main`, and pass `scripts/checkpoint.sh gate` before the first warmup. The
immutable identities already published may not be changed after data are seen.
