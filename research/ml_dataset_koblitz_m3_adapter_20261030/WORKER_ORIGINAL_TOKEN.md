# Worker verified-original token

The worker now calls `verify_and_store_worker_originals` in solvers.rs in place of its prior known-answer replay, factor-base replay and original-file writes. The helper performs those same two independently checked stages under their original telemetry labels, writes the same three files, and returns a private token only after all succeed. A storage failure retains already registered files but returns no token. No shared SolverData or CaseData fields changed.

The token holds immutable references to the exact configuration, public value and factor-base value, the root and optional attempt binding, and fixed-size public/factor-base digest arrays and lengths. It does not hold the private witness. The helper checks bound configuration/attempt files before verification. The internal bound worker entry requires the same borrowed objects, the same root/live directory, and the same attempt; it checks the original files against the saved hashes again and rejects an inconsistent supplied execution context before starting capture. These checks protect against substitution and original-file changes between storage and dispatch. File authentication is setup work, not a native algebra operation count.

Legacy calls keep the existing public solver APIs. The shared worker uses the new internal entry only when a bound capture context exists. Existing mathematical solver routing is unchanged. In particular, the Koblitz m3 adapter remains test-only and does not yet skip its independent original_math replay. Its next integration must consume this token while admitting bounded decoding/copying under the original resource allowance. Root-acknowledgement transfer is also still required. The token does not certify complete setup resource accounting or retired instruction counts.

New software controls use real frozen plan/config/run/attempt files and generated original inputs. They check successful verification/storage and bound enumeration, exact digest binding, changed public/factor-base/config files, substituted objects, wrong root/attempt, invalid known answer/factor base, and conflicting original storage. The broader ml_dataset suite is required because mod.rs and solvers.rs are shared runtime paths. Its source snapshot and terminal result are retained separately.
