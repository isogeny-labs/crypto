# Independent accounting review — baseline and pending patches

Read-only baseline inspection; no worktree edits, builds or cloud activity. External projection-dedup and terminal-cap implementations have been requested from their owners for review. This document is not approval of unseen patches.

The existing parent storage quote is `32*payload_length+65536` modeled checking work. It is not retired instructions. Fresh generic parent publication presently hashes the borrowed payload in `CaptureEmitter::payload_parts`, hashes it again in capture `storage::write_bytes`, and hashes it again for the root `storage::write_bytes`. Existing-name paths additionally hash disk bytes to verify idempotence/collisions. Generic fresh capture also writes a payload and committed event/head; root publication writes another payload. The dedicated witness path already avoids generic capture and validates its acknowledged witness receipt before root publication. Producer input with a receipt is explicitly skipped by the parent and must never be republished.

Any new lower operation-path quote must correspond to operations actually absent from that path. Reusing a descriptor alone does not eliminate file validation on an untrusted existing root, nor prove capture acknowledgement. Require exact binding/limits, payload identity, digest, length, authentic committed sequence and prior receipt before bypassing generic publication. Preserve root collision checks and all acknowledged receipts on a later error. A root-only path still performs hashing/writing unless a concrete implementation eliminates those operations; charge them. Parent delivery verification must independently select/recompute the same path-specific quote rather than trust a lower number in the receipt.

The terminal cap proposal is a different improvement: it narrows future worst-case reservation, not necessarily actual work performed. Current output admission reserves `32*65536+65536` checking work, `2 MiB+128 KiB` scratch and `4*65536+4096` trace. A smaller explicit cap may justify smaller future reservation only if assembly, candidate frame and final returned outcome obey it on success and all failure paths, and added validation/serialization passes are covered. Keep the scratch bound unless peak allocations are independently bounded. Do not refund already admitted work or renew original deadlines.

Review controls required on forthcoming patches: actual same-byte digest and pointer/owner movement; preexisting identical and different capture/root names; stale/forged sequence; missing acknowledged receipt; stop between capture and root; successful root followed by expired clock; capped finalization failure retaining receipts; largest counters/all rejected-root slots/partial diagnostics; central replay acceptance of honest partials and rejection of forged lower accounting. Compare actual operations removed with the before/after quote formula, while retaining model-scope labels.

### Native projection

No concrete apply blocker found. The projection receipt is generated inside BoundNativeEvents and updated only after typed capture acknowledges the event and its exact payload-plus-newline bytes enter the canonical buffer. Pending/unacknowledged bytes remain a separate raw artifact. The receipt travels with the fixed canonical events slot; parent publication skips only that slot's generic live payload. Root `storage::write_bytes` still hashes actual bytes and refuses differing existing content. Its full modeled32/byte quote remains unchanged, so this patch removes actual duplicate capture hashing, payload-file writing and generic event/head publication without claiming a lower admitted work reservation.

Central replay authenticates the committed prefix, strictly parses the native event type, compares extracted raw payload JSON to the parsed event, checks original binding, one-based native sequence and capture sequence, then hashes exact extracted bytes plus newline in order. It compares count, last sequence and length to the receipt, and root digest to that independently reconstructed digest. A generic captured payload for this slot is rejected when the projection receipt is present. Receipt absence retains legacy verification behavior. The receipt is not presented as a proof of native operation execution or an independently anchored producer work ledger.

Added controls cover both F4/F5, preserved root collision bytes, absence of duplicate generic payload, correct root byte identity, parent replay, mutations of binding/count/last-sequence/length/removal and no retry after failure. Useful additional controls remain: zero acknowledged events with a pending raw event; same-length root-byte corruption with refreshed artifact digest; duplicate generic payload plus a projection receipt; and a clock stop immediately after an acknowledged boundary. These are coverage gaps, not demonstrated source defects. Existing central native-capture replay remains necessary alongside the new parent projection check.

### Terminal cap: actual production source-domain audit

A typed public transport is not logically required to bound this particular closed native constructor. I traced the actual `run_verified_worker_entry` output construction, `quote_artifact_owners`, `visit_retained_artifacts`, `take_parent_artifacts`, `PreMatrixInputStore`, root storage and delivery return paths. Current output has fixed keys; scalar values are fixed literals, enums, booleans, nulls or u64 counters. The failed-parent diagnostic uses a static logical path and fixed quote/ledger fields. Its original limits are u64 values. No filesystem error text, external key, public curve JSON, native equation array or free-form caller string is copied into the outcome. Both error strings are fixed literals.

Root descriptors come from fixed canonical slots, fixed raw slots, fixed witness identity or fixed delivery identity. Storage constructs their SHA256 as64hex and length as u64. Parent owner admission rejects more than10 retained owners; alternative input receipt transfers are moves of the same root, and delivery adds one. Twelve reserved rejection slots therefore conservatively cover the actual private production sources. This bounds the actual returned root metadata even though the generic helper type is Value.

The documented30096-byte conservative bound is compatible with these constructors and includes finalization fields and frame overhead. The guard's extra `8*32768+4096` is explicitly modeled pass work, covering bounded structural scans, nested size counts, two outcome counts and one frame count; it is not a hardware instruction claim. Existing scratch reservation remains unchanged. Net782336 fewer future reserved work units and131072 fewer reserved trace bytes are conditional accounting effects, not measured runtime savings or refunds. Parent-delivery cap remains16KiB.

Thus the narrower reservation is defensible **for the current closed production constructor domain**, once implementation checks pass. It must not be described as a universal cap for arbitrary Values injected into the private helper. Exceptional schema-invariant diagnostics remain retained in full; future constructor additions must re-establish the source-domain bound. A small typed constructor would improve maintenance enforcement but is not a prerequisite derived from the existing source alone.

I found an exceptional-path verifier mismatch in the first terminal patch: an expired entry followed by a failed final guard changed `capture_finalization.stop` from Deadline to Serialization while preserving first_stop Deadline. Revision `ec1bc0...` fixes this by retaining an existing finalization stop and adds an expired/malformed-output control invoking `verify_reported_capture_finalization`. That correction is source-reviewed, not test-verified. No remaining concrete apply blocker found in this revised patch. Run actual native outcome/partial/collision controls and central replay before treating the narrower reservation as validated.
