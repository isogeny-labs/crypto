# Koblitz m3 outcome and artifact verification contract

Preserve the current dataset outcome policy: supervisor timeout, trace_budget_exhausted, and worker_failed clear outer completion and positive-verdict claims. A retained, independently replayable witness is recorded separately from the censored outer verdict. Do not use parent set_witness helpers that unconditionally set solver_completed=true.

Verification inputs must be original authenticated config/public/factor-base files, the admitted attempt and limits, and hash/role/encoding/path-checked artifacts. Never build trusted inputs from solver-return JSON. Independently verify the descended ANF over all eight selector assignments; replay signed prefix arithmetic against original points; independently parse and replay saved witness bytes. These checks do not certify native matrix derivations or instruction counts.

Bind the saved signed replay to the actual typed-event prefix, including its exact order and acknowledged count. The optional unacknowledged event may extend the arithmetic prefix by one, but cannot increment the acknowledged count. A witness published before event refusal may correspond to this last unacknowledged candidate. Require its verified ordered tuple to be present among the replayed candidate tuples. Validate its durable receipt identity against the capture payload commitment and exact witness file, not merely a producer-provided boolean or hash.

The original addition allowance covers enumeration plus independent producer witness-check calls. Save both counters and their sum; cap witness-check calls at three for the first publication path and retain partial counts on failure. Report these as producer counters unless execution evidence independently establishes them. Do not treat reference verifier operations as measured producer work. A complete arithmetic enumeration requires all64 ordered triples and192 additions; a completed recorded enumeration additionally requires all192 events acknowledged and no pending event.

An exhaustive negative mathematical finding requires a complete independently replayed domain and no matching tuple. An outer completed-negative claim also requires an uncensored, fully persisted terminal result and the registered pipeline phases. A positive witness does not imply an exhausted domain or completed solve. A native matrix report alone proves neither kind of PDP result.

Keep first_fall_degree, last_fall_degree, retired_hardware_instructions null and reject any unproved full-execution, exact-instruction, native-basis-derivation, or ECDLP-completion claims. Expose bounded matrix metadata under its measured/reported scope. Existing generic status conventions use partial for a bounded native run and verified only with supported completed positive claims; do not introduce a new status without updating central schema consumers.

Before dispatch: freeze exact artifact path/role/encoding registry; implement strict result counters and stop/phase rules; integrate canonical and retained-prefix verifier paths; preserve supervisor censoring; test rehashed semantic mutations, missing/duplicate/wrong-role artifacts, missing receipts, wrong attempts, false negative and false completion claims. Then run focused tests, shared capture tests, applicable lint/full gates, and original-bound CLI fixtures with S3 restore/replay. This contract is design work, not an implemented verifier or permission to launch a new scientific cloud campaign.
