# Original input capture and root storage before matrix work

The staged pipeline persistence callback now receives its actual shared capture counter. Existing in-memory fixtures leave that counter unchanged. A new PreMatrixInputStore callback admits its storage work, memory and trace against the same producer Budget, verifies the live attempt/limits/count, publishes the canonical original equations to bound capture, then writes the root input file. The next native matrix event continues from the advanced stream count. It permits one publication attempt and retains capture/root acknowledgements before the final clock check.

The callback follows capture then root storage, preserving the parent verifier's acknowledgement ordering. This refines the earlier root-only design proposal: explicit callback access to the shared counter permits the original input publication to be ordered in the authenticated stream before matrix events. Root acknowledgement transfer into parent ownership/worker registry is still required to prevent later publication or writing again. The helper is staged, not a runtime profile.

The new control invokes both actual F4 and F5 matrix engines. It exercises successful input storage, a conflicting root file, a conflicting capture file, a selected post-write deadline, wrong capture identity, and one-less storage work. Failure must prevent matrix invocation while retaining whatever publication succeeded. The success control independently matches stored input bytes and verifies the native capture sequence including the inserted payload event. A repeated publication attempt is rejected. An actual original-context producer entry and acknowledgement handoff remain subsequent integration work.

Storage uses the existing declared payload-length/metadata tariff, not a measured instruction count. Clock and process-supervisor semantics remain unchanged. Validation source and terminal outputs are preserved separately; no new scientific dataset or cloud job is launched by this increment.
