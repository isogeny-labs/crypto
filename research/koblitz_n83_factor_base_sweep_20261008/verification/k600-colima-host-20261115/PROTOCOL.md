## Qualification and stop rules

After a successful start, record `colima status`, `colima ssh` OS/kernel/architecture and cgroup version, `docker --context colima-n83-arm64 info` architecture, memory and cgroup driver, exact mounted path visibility, and host/VM free space. A successful host gate requires native `aarch64`, Docker API responsiveness, cgroup v2 hard memory enforcement, zero-swap capability, and enough memory/disk for a later 12 GiB build container. A read-only `docker info` alone is insufficient: run a bounded no-work container control under `--memory=4g --memory-swap=4g --cpus=1 --pids-limit=64 --network=none --read-only`, inspect actual cgroup limits and terminal Docker status, and retain the image ID used. The control uses a pinned public image and does no N83 search. If image availability prevents the control, classify the host gate as incomplete, not passed.

If Colima start times out, is interrupted, changes architecture, lacks hard limits or exhausts host disk, stop and preserve the failure; do not infer the K600 solver's behavior. Do not start the charged build, positive/natural relation arms, or D18 worker from this host check. Any VM provisioning and image pulls are setup and must be separately charged in a future cold IC comparison where applicable. Write a terminal result, raw receipt, source-linked diagram and inspected PDF, including negative/inconclusive outcomes.
