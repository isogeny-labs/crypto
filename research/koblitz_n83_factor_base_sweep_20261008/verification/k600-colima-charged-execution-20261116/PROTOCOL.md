## Hypothesis, controls and cost

A no-work admission must verify the clean committed source, exact plan blob and script, all three archive hashes, producer ELF/hash, host architecture, 12 GiB hard memory, zero swap, four CPU quota, 512 PIDs, Docker socket access, new output directory and absent source-labelled runtime image. It may not start a build stage. The [admission launcher](admit.sh) runs with no network under a 120-second cap and retains its raw log and receipt. Any failed check stops before the producer.

After a passing admission from the **same clean source commit**, the [build launcher](build.sh) runs the native producer exactly as `build-producer run COMMITTED_BUILD_PLAN_JSON /build-output/charged-20261116-attempt-1` in the pinned toolchain image. It uses the same source/Git/alternate/archive mounts read-only, a new output mount, Docker socket, hard cgroup and `gtimeout 2700`. The three producer stages retain their original 1200/900/300-second caps. The launcher retains raw outer log/receipt, Docker inspect and cleanup status, and output-local `build.json` or `failure.json` plus stage records. A timeout, nonzero exit, OOM, source drift, missing receipt, hash mismatch or failed cleanup is a STOP. Do not launch K600 worker from a stopped build.

The controller's 3,600-second allowance precharges build, stage, freeze and preflight before worker arms. Bootstrap and toolchain provisioning are separate setup intervals; the cold one-target ledger must price them explicitly. This build alone does not measure relation yield, rank, descent, matched rho or total IC runtime. The requested minimum fully charged cold one-target factor base remains unresolved until those measurements and controls pass.
