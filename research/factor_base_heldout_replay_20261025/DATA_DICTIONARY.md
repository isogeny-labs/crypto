# N12 independent-host replay data dictionary

All numeric cost values are source-addition equivalents (GAE). The price contract is `(M + (S/M)·S + (I/M)·I)/source-addition-field-cost + logical-price·(uncharged native logical operations + field additions + bit operations)`. The native evaluator reports its measured counters; the replay validator recomputes the price grid. A ratio is candidate cost divided by matched rho cost. A **target ratio** divides costs for one target. A **ratio of sums** divides summed candidate cost by summed rho cost over all targets in a scope. These are distinct statistics.

`results/raw/evaluation-bits*.jsonl` contains all 420 unmodified native records, 60 per bit size. Each record contains source workload and target IDs, target derivation, candidate and same-process rho results, phase counters, and verification flags. `results/receipts/evaluation.tsv` gives exit code, row count and UTC boundaries for each bit size. `results/receipts/member-hash-checks.txt` is the Pod's native SHA-256 check of the 11 frozen input members. `results/attempts/` contains terminal states and setup-failure receipts for v1 and v2, plus the v3 Pod, EC2 instance identities and Job status. The v1/v2 runs have no target rows.

`results/validated/targets.jsonl` and `targets.csv` contain one row per frozen target. `replay_present` is false if no replay row exists. `replay_verified` and `rho_verified` require the recovered scalar to equal the planted scalar and to recompute the source point. `identity_match` compares target derivation and source/workload identity with the original row. `counts_match` compares all candidate and rho counters, phases and source-addition units. `candidate_GAE`, `rho_GAE`, and `candidate_over_rho` are null/empty when the row is missing, invalid or identity-mismatched; the `error` field states why. No target is silently excluded from the expected 420.

`results/validated/price-grid.csv` holds 36 cells per scope: all 420 targets and each 60-target bit-size slice. Columns `S_per_M`, `I_per_M`, and `logical_price` define the pricing cell. `candidate_GAE` and `rho_GAE` are sums over the scope; `candidate_over_rho` is their ratio. When any expected row is missing or invalid, the scope's costs and ratio are null/empty and `outcome` is `null`. Otherwise `outcome` is `win` for ratio below one, `loss` above one, or `tie` at one. `results/validated/summary.json` gives validation totals, target-level wins, per-scope ratio of sums and outcome counts. `files[].byte_identical` compares each raw replay JSONL file byte-for-byte with the frozen original; the paired SHA-256 fields make this reviewable.

`ratio-by-size.svg` plots all 420 target ratios as blue circles on a base-2 logarithmic vertical scale and each bit-size ratio of sums as an orange diamond; hovering over an SVG circle shows the workload ID and ratio. `REPORT.pdf` and `REPORT.md` are presentation artifacts generated from the native output. Wall times in the Job receipts are diagnostic and are never substituted for operation counts.
