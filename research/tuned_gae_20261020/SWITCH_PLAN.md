# Switching the canonical GAE to the tuned definition: what must change

Status: not done in this pass. `Calibration::pin`, `ecbench::band` and
`ecbench::full_price` still read the legacy tables. The tuned tables exist as
`docs/ic/calibration_tuned.json` and `src/cryptanalysis/ecbench/full_prices_tuned.json`
(both stamped `"gae_definition": "tuned-batched-affine-add/v1"`, generated by
`gae-reference retable`). Line numbers are those of the tree this was written
against; re-grep before editing.

## Principle

A record's price is a function of its counts and the table that priced it.
`band.rs` subtracts the calibration-priced GAE and re-charges the counts at
weight `w` using the table it reads, so a sealed record must be band-processed
with the table that priced it. Therefore the definition travels with the record
(`gae_definition`), and each reader picks the table from the record, never from
a global.

## 1. Two tables, one selector (`src/cryptanalysis/ic_boundary.rs`)

* `:260` `const PINNED_CALIBRATION = include_str!("../../docs/ic/calibration.json")`.
  Add `PINNED_CALIBRATION_TUNED` (`calibration_tuned.json`) and
  `pub enum GaeDefinition { Legacy, TunedBatchedAffineAdd }` with `as_str()`
  returning `"legacy-untuned-affine-add/v0"` (the implicit definition of every
  existing record) or `"tuned-batched-affine-add/v1"`, and `from_str()`.
* `:287` `fn pinned_ratios(regime, instance)` and `:280`
  `pub fn pinned_calibration_ratios(regime, instance)`: add a `GaeDefinition`
  parameter (or `_in(def, ...)` variants) and choose the document by it.
  The legacy signature stays and means `Legacy`.
* `:320` `Calibration::pin(regime, instance)` and `:262` `PinOutcome`: add
  `pin_in(def, ...)`; store the definition on `Calibration` (new field next to
  `pinned_units`, `:242`) and report it in `PinOutcome`.
  `Calibration::pin` keeps meaning `Legacy` until the default is flipped (step 6).
* `:6842`-`:6865` `price_phase`: unchanged. It multiplies counts by
  `ns_per_x / ns_per_add`, which `pin` has already set to the table's ratio.
* Row-lookup keys are unchanged: the tuned tables use the legacy keys
  (`prime/bench-10bit`, `koblitz/K_0 / GF(2^13)`, ...), so
  `curve_id::same_curve` fallback at `:296` works on both.

## 7. Flip order (so no sealed record changes meaning)

1. Land `GaeDefinition`, the `_in` readers, the stamps and the band change with
   `Legacy` the default for absent stamps; run `cargo test --release` and
   confirm every committed session band table and the Round-5 reprice are
   byte-identical.
2. New runs opt in with `gae_definition: "tuned-batched-affine-add/v1"` in the
   spec / `--gae-definition tuned`. Do not mix definitions inside one band table.
3. Only then consider changing the default for new specs; never reinterpret
   a record without a stamp.
4. Re-pin on the ledger's isolated host (the legacy ratios are from a 2.10 GHz
   Xeon and, for `koblitz/K_0 / GF(2^23)`, an Apple M4 Pro under load) by
   running `gae-reference --from-calibration`, `gae-reference field
   --from-calibration`, `gae-reference retable` there, so the tuned table's `R`
   and `F` and the legacy ratios come from one host.

## Open items that change the tuned numbers (not code plumbing)

* `row_op` (`calibrate_row_ops`, `ic_boundary.rs:6798`) was tested only against
  a straight Montgomery rewrite, which did not beat `u128 %` on subgroup orders
  under 2^32 (F measured 0.84-0.91, clamped to 1). A lazily-reduced or
  vectorised elimination could be several times faster; the tuned `row_op`
  ratio is therefore an upper bound.
* `legendre` is priced class (c) (a Jacobi symbol with `%`, no field multiply).
  A binary Jacobi would be faster; same direction of bias.
* Inversion units use the batched figure (`f_inv_batched`). They are batchable
  at the call sites (`decompose_prime`, `ic_boundary.rs:5666`-`:5700`, scans a
  list of independent candidates) but the code does not batch them today;
  `derivation.<row>.units.ns_per_inversion.new_if_inversions_not_batched` gives
  the price if it never does.
