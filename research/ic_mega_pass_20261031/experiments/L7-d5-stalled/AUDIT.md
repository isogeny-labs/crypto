So validation finished before the main runs and the protocol precedes every run, but only by 7-19 s. The PROTOCOL header says "written ... 09:05", which is later than the runs' start; the stamp is wrong (the file was created at 09:00:25). Cosmetic, but it is a false timestamp.
3. Validation is real. validate.jsonl has 18 cells with 0 mismatches, equal to RESULTS.json. I re-ran the engine against the Python reference (MP-comm_alg-1/tensor_closure) on fresh seeds the experiment did not use: n=9 s=3..5, n=11 s=3..4, n=13 s=3, arms A,C1,D1,B,RM: 30/30 equal in [dim, low, one] (several with one=1). I also exercised the CPUCAP path (n=25, C1, cap 1 s): it returns a record with capped=1 and one=0, i.e. an undercount, as L2's audit warned. This confirms the README's rule that capped records are inconclusive. Neither L7 run hit its cap, so the L7 numbers do not depend on that path.
4. Instance identity. I regenerated n=31 k=16 C1 s=1 with N1 lib.system() and ran d=4 with both gf2close5 and N1's gf2close: both give (dim 37293, low 2821, one 0), equal to N1 raw and to L1. So the generator used here makes the same instance that N1, L1 and L2 called "stalled at W_4".
