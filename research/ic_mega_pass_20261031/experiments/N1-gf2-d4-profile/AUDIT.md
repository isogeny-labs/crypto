## Problems / findings
A. Prior-art omission and scope. The treatise already has this measurement on this diagonal (brief/treatise/falldegree.tex, Thm lfdexact and Thm lfd5): d_F = 4 on all 29 random-subspace instances with 15<=n<=33; d_F >= 5 certified (1 not in W_4) at n=33 (T33a/b, random subset of ker Tr), 35 (R35, U35, Q35), 37, 45 (P45a, Semaev default subspace), and exactly 5 at R35a (n=35, k=18). PROTOCOL.md does not cite this. Consequences: (i) A/C1/C2 reaching 1 in W_4 on every UNSAT draw at n<=31 is a replication of known data, not a new result; (ii) the chosen range stops at n=31, just below the known onset of d_F>=5 (n=33..35), so the design cannot see the transition that the programme already reports, and "d_F<=4 persists" is not supportable as a trend statement; P1 as written is close to a foregone conclusion given prior art; (iii) there is no structured positive control for non-refutation at d=4. R35a / T33a-type instances (n=33,35) would be the known-answer positive control, or extending to n=33,35 (closure matrix 66,712 columns at n=35, ~560 MB per process, 3 processes OK) would straddle the onset.
B. Pilot-contaminated predictions. P3 (B, RM: low_4 = n(N+1), 1 not in W_4) was written after the pilot showed exactly 483, 675, 899 for B and RM at n=21,25,29, and it is a counting identity (n equations plus N*n degree<=3 products x_v f_i, no cancellation), not an empirical risk. P1 was also written after seeing A with 1 in W_4 at n=29. The protocol discloses the pilot, but the README must label P3 as a null calibration and P1/P4 as partly pilot-informed, not as "confirmed predictions".
C. Statistics. With U=8..10 UNSAT draws per arm per n, "100%" has a one-sided 95% Clopper-Pearson upper bound on the failure rate of about 26-31% per (arm,n); a rise in failure rate with n below that is undetectable, so P1's trend clause ("a rate increasing with n would be evidence") has little power. A, C1, C2 (and D1, per MP-comm_alg-1's own audit: same low-rank mechanism) are not independent replicates of one another; do not pool them into one large denominator. A's solution count is always even (a<->b swap symmetry), so UNSAT-conditioned samples of A and B/RM differ in conditioning; mention it.
D. Unsaved validation artifacts. PROTOCOL claims FES vs brute force (30 systems) and bsols vs FES (150 instances n=9..21) "all equal", but no script or output for the 150-instance check is in the directory (festest.py has no saved output). I reproduced equivalent checks above (brute force vs bsols/FES nsol, all 240 recorded n=19 arm-seed pairs + 36 at n=21), but the claimed artifact is missing. Also the closure validation vs MP-comm_alg-1 stops at d=4,n=17; n=19..31 at d=4 rests on that plus my 5-instance spot check, which should be saved in the directory and stated.
E. Budget rule is not implemented. run_main.py contains no cost check; the "stop if projected > 2.5 h" rule is manual. Reported `cpu` sums child-process clock() only (excludes Python system generation, random_matched, rank_s); for n=25 wall (243 s) > cpu (183 s) with 3 threads, because generation runs serially. State this accounting in the README and record which n were actually run and why the last one is the last.
