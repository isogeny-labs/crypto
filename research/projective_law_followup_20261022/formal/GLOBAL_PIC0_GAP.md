## Precise missing bridge

The proposed target is a curve-specific theorem about the rational function `g = n/b - Y` (with `b ≠ 0`) and the effective divisors represented by the two input Mumford pairs and the residual pair. Under the source-style validity, separability/smoothness, and branch guards, it must identify **every** zero and pole with multiplicity on the actual projective curve, including nonrational closed points, branch overlap, repeated roots, and the `c=0` degree-drop case. It must then prove the divisor equality for `g` and identify its divisor as principal in a concrete divisor group. Only then can the existing abstract `residual_represents_input` turn the equality into a class relation; connecting the returned Mumford representation and compiled Rust law is a later, separate gate. The familiar schematic equation `div(g) = D₁ + D₂ + Z_res - m·∞` is a **proposed target**, not a checked theorem here; `m` must be derived separately for each degree branch.

The smallest useful next formal components are: (1) define a function-field element and a concrete closed-point divisor/order map for the actual weighted-Proj curve; (2) prove finite support and local orders at **all** closed points, extending the current rational-point statements; (3) specialize the infinity valuation to that function and prove the degree-drop pole orders; (4) identify the resulting residual divisor with the source returned pair, including involution and normalization; (5) instantiate `PrincipalClassInterface` or construct the appropriate degree-zero Picard class map. The first component is prerequisite for a non-tautological global theorem. The pinned Mathlib `Mathlib/RingTheory/PicardGroup.lean` defines the Picard group of a **commutative ring** via invertible modules and explicitly lists the sheaf connection as TODO; it is not a ready-made divisor/Pic0 bridge for this projective curve. A targeted search of the pinned `Mathlib/AlgebraicGeometry` tree found no divisor/Picard curve file; this is a search result, not a claim that no usable generic API exists elsewhere.

The general geometric pattern is described by the [Stacks Project, principal divisors and pushforward](https://stacks.math.columbia.edu/tag/02RS) and [Picard groups of curves](https://stacks.math.columbia.edu/tag/03RN). Those sources guide the proposed formal obligations; they do not certify a Lean implementation.
