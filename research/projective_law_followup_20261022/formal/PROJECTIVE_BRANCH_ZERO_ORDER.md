# Conditional zero order at an actual projective branch

This is a formal local-geometry packet, not a new target experiment or cost comparison. The [PDF](PROJECTIVE_BRANCH_ZERO_ORDER.pdf), [diagram](projective-branch-zero-order.svg), and [standardized gate CSV](projective-branch-zero-order.csv) index the [local](WeightedProjBranchZeroOrder.lean), [norm-composition](WeightedProjNormBranchZeroOrder.lean), [source-style](WeightedProjSourceBranchZeroOrder.lean), [actual-quintic head](WeightedProjQuinticHead.lean), and [actual-quintic specialization](WeightedProjSourceBranchActualQuintic.lean) Lean sources. Their saved compiler logs sit beside the sources.

For a field `K`, a rational simple root `a` of the quintic, and the **actual weighted-Proj structure-sheaf stalk** `R` at that branch, the checked theorem states: if local elements `N,B,t : R` satisfy `N = (x-a)t` and `B` is a unit, then `ord(N-B*y)=1`. It uses the previously checked projective DVR, `ord(y)=1`, and `y²=(x-a)q` with `q` a unit, plus the generic branch zero-order lemma. The local DVR criterion is described in [Stacks Project Lemma 10.119.7](https://stacks.math.columbia.edu/tag/00PD).

The checked `projective_norm_branch_zero_order` composes this local theorem with the separately checked [branch norm-factor transport](BRANCH_NORM_FACTOR.md). Under an explicit polynomial norm identity, a rational support root, simple branch geometry, and a unit `B` in the actual projective stalk, it proves `ord(n(x)-B*y)=1` for the polynomial `n` evaluated through the checked projective coefficient and `x` maps. This is a single kernel-checked chain of implications; the polynomial `f` in the norm identity is still supplied separately from the curve's `fAt` root hypothesis.

`projective_coeff_unit` proves that a nonzero field coefficient `b` maps to a unit in this stalk. The corollary `projective_norm_branch_scalar_zero_order` therefore replaces the abstract unit premise with `b≠0` and concludes `ord(n(x)-b*y)=1`, where `b` denotes its checked stalk image. This matches the common branch's scalar nonzero guard at the level of the stated polynomial model.

`source_style_projective_branch_zero_order` instantiates the chain with the proof-side common 2+2 coefficient expressions and the separately checked source-style polynomial identity. It assumes valid Mumford input congruences, normalized quintic head (`degree≤5`, coefficient of `X⁵` equal to 1, coefficient of `X⁴` equal to 0), nonzero determinant, rational simple branch of the actual curve, `f(a)=0` for the supplied polynomial, and a root of the product of the two input supports and residual support. Under those precise conditions it proves `ord(n(x)-b*y)=1` in the actual weighted-Proj branch stalk. The supplied `f` and the actual curve's `fAt` are separate hypotheses; this theorem does not infer their equality.

`WeightedProjQuinticHead.lean` proves that the weighted-Proj quintic evaluates to `fAt` and has exactly the normalized head needed above. The checked `source_style_actual_quintic_branch_zero_order` applies the source-style theorem with that actual quintic, removing the separate `f(a)=0` and polynomial-head assumptions. Its remaining hypotheses are valid Mumford input congruences, nonzero determinant, rational simple branch, and a root of the two input supports times residual support. It still does not link a compiled Rust execution to the source-style polynomial model.

The same quintic-head source proves that its polynomial derivative at a rational point equals the local `derivativeAt` expression. The corollary `source_style_actual_quintic_branch_zero_order_of_separable` therefore replaces the explicit simple-root premise with separability of the actual quintic. Valid input congruences, nonzero determinant, a rational branch root, and a norm-support root remain explicit.

These theorems do **not** prove that the compiled Rust numerator equals the mapped polynomial `n` at every branch, that its coefficient `B` is always a unit, or that all finite and infinity orders combine to the claimed principal divisor. The global `Pic⁰` class equation and universal compiled-law semantics remain open. No frozen 1,260-target row or matched-rho cost ratio changes.
