# First all-closed-point divisor construction gate

**Scope:** 28 October 2026, new isolated branch from `67404e62b14423c8adcd226e759b417e78f46f53`. This is a bounded API/proof investigation, not a global divisor or Pic0 theorem. No new Lean declaration passed a kernel check in this packet. The exact finite-field script below is a diagnostic, not a Lean formalization or a DLP experiment.

Pinned Mathlib has the right *conditional* generic-point API: `Mathlib/AlgebraicGeometry/FunctionField.lean` defines `Scheme.functionField` as the generic stalk, makes it a field under `[IsIntegral X]`, and gives `germToFunctionField` and its injectivity under the same hypothesis. The actual weighted-Proj study has checked affine and point-stalk domains (`Common22SeparableAffineDomain`), a two-open cover (`WeightedProjCover.two_basic_opens_cover`), and smoothness/properness over the stated odd-characteristic squarefree hypotheses (`WeightedProjSmoothFinal.smooth`, `WeightedProjBase.weightedProj_proper_over_K`). It has **no checked `IsIntegral` instance for the whole weighted-Proj scheme**, and no map from the source-style `n/b-Y` into its generic stalk. That is the first type-level gate to a concrete function-field element. The pinned `Mathlib/RingTheory/DedekindDomain/FiniteAdeleRing.lean` proves finite support of height-one valuations for a Dedekind domain; the actual affine chart has no checked `IsDedekindDomain` instance or closed-point identification, so that API cannot yet supply the curve's divisor automatically.

The need to include nonrational closed points occurs inside the source-style common 2+2 hypotheses. Over `F₃`, take

```
u1 = X² + 1,       u2 = X² + X + 2,       v1 = v2 = 0,
f  = u1*u2*(X+2) = X⁵ + 2X³ + X² + X + 1.
```

Both monic quadratics have no `F₃` root (`u1` values `1,2,2`; `u2` values `2,1,2`). The exact polynomial gcd `gcd(f,f′)=1`, so the monic quintic is squarefree. Both valid Mumford congruences hold because `u1∣f` and `u2∣f`; the common 2+2 determinant is `B=1`. Here `n=0`, `C=0`, and `U=2X+1` satisfy the source norm identity `n²-u1*u2*U=B²*f`. Each `u_i` is irreducible of degree two (no roots), so the support `(u_i,Y)` gives a degree-two closed point of the affine curve with residue field `F₃[X]/(u_i)`; neither is represented by an `F₃`-rational `(x,y)` point. The [stdlib exact-arithmetic checker](global-divisor-counterexample.py) verifies the polynomial statements and prints every intermediate result; SHA-256 `6ac9e98e2991f512762aed43b588b6948300178df2e49fc30f43e6a1facb523b`. The closed-point interpretation uses the standard quotient argument and has **not** been formalized in Lean here.

The smallest concrete next Lean sequence is: (1) prove `IsIntegral` for the actual weighted-Proj curve from its domain charts and cover, then define the source `g` in `Scheme.functionField`; (2) prove the affine coordinate ring is Dedekind or construct an equivalent all-closed-point valuation index and prove finite support; (3) link the quadratic Mumford support ideals, including the degree-two example, to closed points and their DVR orders; (4) add the infinity point valuation and prove the principal divisor of `g`. These are separate gates from the already checked rational-point DVRs. A scratch Lean probe of the finite example was stopped after four minutes without compiler output; no compiler/axiom success is claimed and no unverified Lean source is committed.
