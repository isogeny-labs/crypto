Read actual lab.runner normalize_manifest, Laboratory.initialize/load/merge/journal/record/validate/provenance/run_one and CLI paths; inspected prior20261109v1/v2/v5/v6 sealed-parent receipts and registration helper. Existing precedent preserves terminalstate/chain hashes and links a fresh small epoch to the sealed prior ledger. Current storage issue is metadata amplification, not a scientific result.

Runner initialize accepts only a ledger lacking journal.jsonl, creates pending entries for NEWmanifest specs and records initial state. Merge/resume will not remove old state items and disallows changing program_id/projectroot/ledgerdir, so shortening a manifest inside the current initialized ledger would NOT eliminate journal state amplification. Renaming the entire old ledger and initializing an empty active ledger is the appropriate distinct-epoch mechanism. Use same programid/projectroot/activeledgerdir and unchanged gate/8xtarget, with an explicit compact sealed_parent chain.

Preconditions: acquire old .lock with exclusive nonblocking flock; verify no running or pending-orphan attempts and no concurrent runner; hash/check complete journal chain, terminal record SHA, state-cache bytes and value equality of terminal state/cache; read-only validate all old provenance and attempt hashes. Laboratory(old).load(recover=False).validate() is metadata-only and avoids writing the cache. CLIvalidate/status call load(recover=True), which atomicrewrites the2.38MiBcache and can consume additional disk by breaking stagehardlinks: avoid them on the old ledger. Require passed preservation validation before rename.

Preservation: require absent seal directory and absent backup manifest path. Move old ledger directory on the same filesystem (no copy/deletion) and move exact original manifest bytes into PROGRAM_BEFORE_SEAL.json under that preserved directory. Verify inode/hash/size and terminalstate/record agreement after moves, retaining every original attempt, raw evidence, source, immutable manifest snapshot and earlier sealed-parent reference. Do not rewrite old state/spec ledgerdir paths to the new sealed location: those are historical identity bytes. Do not CLIresume the sealed ledger, because its historical program ledgerdir differs from actual sealed directory and recovery could write history.

New manifest: only fresh experiment IDs with no artifact collisions; dependencies/retry_of must name experiments inside the NEWmanifest because normalize_manifest rejects unknown historical IDs. Cross-epoch dependencies or retry rationale belong in explicit metadata unless a new admitted runner supports sealed-parent resolution. Preserve old pending/error IDs and full status/count synopsis in compact parentreceipt, not reset/disappear them. Newactive status is epoch-only; cumulative reports must link/count sealed history.

Duplicate prevention is epoch-local in run_one: it scans only active state's attempts. A fresh epoch must NOT bypass scientific no-identical-retry policy. Before newadmission compare new experiment fingerprints/command+source+input identity with historical attempts, with concrete changed-assumption rationale for any intentional retry. Distinct ID/output pathname alone is insufficient. Do not copy multi-megabyte prior state into new program metadata; parentreceipt carries hashes/path/status synopsis and previous sealed-parent link.

Transition is reversible: if newinit fails, preserve any partial fresh ledger/manifest as a separate failed transition artifact before restoring oldpaths; never overwrite/delete either version. Crash points between directory move, manifest move and exclusive newmanifest write need durable phase/receipt evidence and distinct recovery paths. Do not run newscience until init, resume, validate and sourcefreeze succeed.

This design preserves evidence while reducing active journal amplification. It does not reclaim old disk, weaken the gate, retry a prior result, claim scientific success or provide an actual helper-execution receipt. Physical/archive paths in later portable checkpoints must include the newly sealed ledger and historical manifest; no history may be dropped from the archive chain.
