# F37 chord completeness: proposed finite experiment

Status: canonical protocol DRAFT, source instruments and frozen analysis unimplemented. No data or run is claimed. `protocol.json` uses `experiment.protocol/v1`; a valid draft does not establish launch readiness or mathematical correctness. [pcc:unverified]

## Question and acceptance

Can the three-branch chord solver reconstruct exactly the actual ordered signed relations for every declared query, without a pair oracle feeding its algebraic work? The primary acceptance predicate is ZERO missing/extra rows in every completed cell, with all branch, source and column controls passing. This is a complete known finite census, not a random-sample significance test. A finite pass is an implementation result at this scope; a false row or missed positive control invalidates the instrument. [pcc:unverified]

Useful yield, relevant solver degree and original DLP benefit remain the next component/pipeline acceptance criteria. This first census does not substitute for public setup, cold separate-target recovery, charged collector schedules or a full source frontier comparison. Both complete solvers returning the same rows cannot establish a strict per-query union gain. [pcc:unverified]

## Population, deterministic order and references

Use all 84 lexicographically sorted size-three subsets of the nine unsigned nonzero subgroup abscissae on each actual curve. Four roles are main, native twist, main base transported through Phi, and twist base pulled back through I. Transport column order and signs explicitly rather than resorting them invisibly. Supply every query point in the actual cyclic subgroup, including O: 336 role/policy arms times 19 queries = 6,384 planned cells per instrument. The 18 nonidentity point labels construct/check public fixtures outside the solver; candidate input is a point and the three base points only. No scalar lookup is an input or output shortcut. [pcc:unverified]

Run a new Rust candidate and a separately implemented C++ arithmetic auditor/reference. No shared field/group/polynomial code; the reference independently enumerates actual signed point pairs and expands candidate witnesses. Direct enumeration has no named matrix degree. A same-code A/A repetition checks determinism, not host variance. Interleave candidate/reference by query and alternate model-first order on successive policy indices. No timed primary metric, throughput claim or confidence interval is planned. [pcc:unverified]

## Positive, negative and semantic controls

Before full data, freeze actual planted distinct and diagonal relations generated from each supplied base point by group addition, plus O from B+(-B). Keep their construction outside recovery and mark them controls. Failure to admit an expected relation invalidates the instrument. Negative controls are extra/omitted roots, a dropped diagonal branch, a false source/map, swapped columns, dependent row advertised as new rank, a forged polynomial witness, missing failed query, false public log/scalar at the later recovery stage and a free second collector call at the later collector stage. Rehash altered payloads; rejection must leave no success receipt. Do not claim an unimplemented later-stage control passed. [pcc:unverified]

The A/A replay must reproduce all rows and counters, excluding explicitly diagnostic clocks and host IDs. Record complete branch outcomes, failed roots and lifts; deduplicate projected coefficient rows before rank. Preserve ties, empty sets and rank-zero/identity cases.

## Resource and freeze discipline

Use only existing LOCAL resources, at most two workers; each native/build/proof stage <=600 seconds and one new scientific window <=3600 seconds. No paid compute, EKS, AWS/auth probes or broad-credential fallback. No automatic infrastructure retries are authorized in this first design; preserve the original failure.

Current prerequisite order is: explicit branch checkpoint scope, truthful current RESUME and successful unmodified official gate; implement/freeze Lean/native source and controls; labelled fixed first-case engineering preflight with outcomes preserved; then a new version with exact source, binary, analysis and input hashes plus observed runtime estimate frozen before the affected full-census data. The full census must not quietly shrink if the estimate or budget fails. Preserve unfinished coverage, amend transparently and keep its original requirement open. No current native path or prospective runner exists.

The native output must include ordered roots/signs/rows, branch identities/witnesses, subgroup/source bindings, rank traces, all field/group/polynomial/map request vectors and exact case membership. Publish one canonical `experiment.export/v1`, raw failures/controls/hashes, independent audit, faithful scoped Lean/axiom report, source-bound identity records, a graph/PDF and signed PCC standing where available. A producer flag, hash or self-check alone is not signed verification. [pcc:unverified]

The existing split-graph/secant study is a required antecedent and applicable source-side cost baseline, alongside direct enumeration and univariate elimination. Its previous F4/censored extraction records are not rerun, imported as fresh data or used to supply candidate answers. No comparison against an intentionally weaker old dense solver alone can establish a chart benefit. [pcc:unverified]
