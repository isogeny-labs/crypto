# Chained-S3 SAT on N83, m = 2…9: summand ordering and root-finder tables (preregistration)

Frozen 2026-10-31 before the measured run. Follow-up to
`research/n83_msweep_20261024`, where the full-width chained-S3 SAT
decomposer decided only m = 2 within 180 s.

## Question

On the pinned N83 fixture (`icv1-f2m83-t6151469093347-cdcc5432`,
`KoblitzCurve::known_n83_k1`), base = Frobenius union of span(1, z)
(167 points), how many public and planted queries does each decomposer arm
decide for m = 2…9 within the caps, and at what cost (solver conflicts,
wall seconds)?

## Arms (same targets, arm order rotated per target)

| id | arm | what a refutation means |
|---|---|---|
| A0 | `unordered` — the shipped default of `sat_decompose_chained_s3_any_m` | no decomposition |
| A1 | `all-summands` — x_1 ≤ … ≤ x_m (`order_all_summands`) | no decomposition |
| A2 | `all-summands+t2.2` — A1 plus root-finder tables: y_k ∈ x(signed (k+1)-sums) for k+1 ≤ 2, y_k ∈ x(R − signed (m−k−1)-sums) for m−k−1 ≤ 2, intersected; cap 300,000 points per table | no decomposition |
| A3 | `all-summands+affine+t2.2` — A2 over the all-affine identity pattern only | no decomposition free of zero-sum sub-multisets (reported separately, never ranked against A0–A2 as the same question) |

## Targets and caps

- Seed 20261031. Per m: 3 public targets `[a]G` and 2 planted sums of m
  base points, generated by `examples/n83_chain_sat_bench.rs`.
- Per query: 300,000 conflicts and 120 s wall (`ChainS3Options::wall_budget`);
  a capped query is `undecided`, never refuted.
- Command per m:
  `target/release/examples/n83_chain_sat_bench <m> 2 3 2 300000 20261031 unordered,all-summands,all-summands+t2.2,all-summands+affine+t2.2 120`
- Four shards in parallel (m = {2,9}, {3,8}, {4,7}, {5,6}), one core each,
  `RAYON_NUM_THREADS=1`.

## Measurement

Counted unit: solver conflicts (host-independent). Wall seconds include table
construction and are an L0 diagnostic (shared 4-vCPU cloud VM). Every
witness is re-added in the curve group (`verified`).

## Decision rule (frozen)

- Positive control: every arm must return a verified witness for every
  planted target it decides; an arm that returns `refuted` on a planted target
  is a soundness failure and voids that arm.
- Improvement claim (A2 or A1 over A0): more decided public queries at some
  m, with no planted target lost, or fewer conflicts on every paired target
  both arms decide. Reported per m as decided counts and paired conflict
  ratios; no pooling across m.
- A3 is reported in its own column.

## Limits declared in advance

One base size, one curve, 5 targets per m, L0 host, wall caps. Relation
collection is not a DLP; no IC-versus-rho claim. EKS (AGENTS.md §9a) is not
used: this workload is not an ecbench method and the session has no aws CLI
for the bridge; conflicts are the primary unit for that reason.
