# Continuation hypotheses, before candidate measurements

Baseline source: `1340a6176`; retained local executable digest in
`baseline-binary.sha256`. Initial native comparisons run independently on a
dedicated ephemeral host before these hypotheses are assessed. These are
profiling-based hypotheses, not native performance conclusions.

1. The completed generalized API's existing n23 planted Callgrind profile
   attributes45.50% of Ir to scalar Gray enumeration,8.70% to malloc internals
   and7.67% to free internals. It also shows a whole JSON equation clone and
   general BigUint polynomial verification. Borrowing the equation tree,
   short-circuiting zero/one factors exactly, and dispatching supported Boolean
   quadratics to the existing checked wide Gray kernel should lower complete
   API cost. Keep independent original-equation verification and exact counts;
   retain the scalar fallback and a switch to force it for comparisons. Test
   powers beyond one, extension coefficients, every output coordinate, output
   caps, more than64 coefficient equations, and unsupported wide shapes.
   This integrates existing SIMD search; it is not a new search algorithm.

2. The single-write GF(2) table builder currently compiles its entry loop for
   the portable target. Row clearing already dispatches AVX2/AVX-512. An
   opt-in `KIC_GF2_VECTOR_TABLES=1` should build each entry with the same ISA,
   using raw output stores until every vector word is initialized. Test all
   supported vector/scalar variants against independent subset XORs, poisoned
   reused storage, partial last groups and suffixes around vector boundaries.
   Mathematical rows, ranks and counted word XORs must remain identical.
   Default policy stays unchanged pending isolated native qualification.

Each candidate gets same-input A/A and at least five interleaved A/B pairs,
with exact output equality, recorded noise/intervals and holdout fixtures.
Retain neutral or slower candidates in the evidence and leave them disabled.

3. The existing cold `rootfind-mitm` n23 setup profile attributes61.60% of
   its677,727,775 Ir to scalar field inversion. Its folded pair table performs
   1,074,331 abstract additions for1,036 abscissae. Build the exact same
   folded table in original insertion order, batching256 second operands
   for each fixed first operand through the backend's existing `PairedAdd`.
   Keep every table key/witness, identity/negation/doubling exception, and
   abstract addition charge. Probe verification stays unchanged. Opt in with
   `KIC_ROOTFIND_BATCH_SETUP=1` or `batch_setup=1`; keep scalar default pending
   native qualification. Compare both complete map contents and witnesses on
   binary and prime fields, including2-torsion and degenerate sums. The full
   table option retains its separate behavior. This targets cold setup, not
   query-only cost, and requires a fresh same-host native comparison.
