# PROTOCOL: canonical Picard arithmetic on smooth plane quartics (W1)

Frozen 2026-10-18, before any measurement. Workstream W1 of

`claude/quartic-pic-canonical-20261018`. Revisions after this commit are
recorded in the README as deviations; this file is never edited.

## Question

Can `Pic^0(C)(F_q)` of a smooth plane quartic `C/F_q` (q an odd prime,
q < 2^31) be given arithmetic with **class-unique keys** (key(x) = key(y) iff
x = y in the group), using only `F_q` linear algebra, so that the degree-6
key collisions of `research/ghs_cubic_quartic_ic_20261012/` disappear? And
what does one group operation cost, in `F_q` multiplications, as q grows?

## Method (design under test)

Notation. `S_n` is the space of ternary forms of degree n over `F_q`;
`F` is the quartic; sections of `O(n)` on `C` are `S_n / F S_{n-4}`.
`K` is the canonical class (line section). Fix a rational point `P0` and the
base divisor `D_inf` = residual of `P0` in the tangent line at `P0`
(`D_inf ~ K - P0`, effective, degree 3, rational).

* **Class representation.** `x in Pic^0` is stored through the class
  `x + D_inf in Pic^3`. Riemann-Roch on a non-hyperelliptic genus-3 curve
  gives: `h^0 = 1` (a unique effective degree-3 divisor `D`, not collinear)
  or `h^0 = 2` (the class is `K - P` for a unique rational point `P`; the
  effective divisors are the residuals of the lines through `P`). Keys:
  `Gen(I_2(D))` (the reduced echelon form of the 3-dimensional space of
  conics through `D`, which determines `D`) and `Exc(P)` (normalised
  coordinates of `P`). The zero class is `Exc(P0)`.
* **Divisors are never stored as point lists.** An effective divisor is
  carried by a subspace of forms whose base scheme is exactly the divisor
  (a "generating space"), so no extension-field arithmetic and no root
  finding enter the group law. Sums of divisors are products of generating
  spaces; residuals in the section of a form `c` use the ideal-quotient
  rule `e in I(R)  iff  e*v in c*S + F*S for all v in I(Z)` (valid when
  `I(Z)` is locally generated by the spaces used; checked by dimension
  counts at every step).
* **Addition.** `Z6 = D_x + D_y`; take the 4-dimensional space of cubics
  through `Z6`; impose the extra order at `P0` to get the 3-dimensional space
  of cubics through `E7 = Z6 + P0`. If a conic passes through `E7`, then
  `E7 ~ 2K - P` and the result is `Exc(P)`; otherwise take the residual
  degree-5 divisor `R5` of a cubic, the unique conic through `R5`, and the
  residual of that conic, which is the unique degree-3 divisor `D_z` with
  `D_z + K ~ E7`.
* **Negation.** Conic through `D_x + 2 P0` (a pencil gives `Exc(P)`), residual.
* **Zero, doubling, subtraction, scalar multiplication** are explicit:
  zero short-circuits; doubling is `add(x, x)`; scalar multiplication is
  left-to-right double-and-add.
* **Smoothness** is certified by `S_7 = (F_X, F_Y, F_Z)_7` (linear algebra),
  not assumed.
* An independent second reduction path (cubic residual `R6` of `Z6`, then the
  cubic through `R6 + D_inf`) is implemented in the test module only and used
  as a cross-check; the library path is the one above.

If a step of this design fails on a case the design did not foresee, the
implementation may add a fallback; every fallback is counted, and the
fraction of operations that took it is reported. A fallback is never silent
and no test is relaxed to accommodate one.

## Cost unit

`F_q` multiplications (a counter in the arithmetic), with `F_q` inversions
counted separately and priced at their measured multiplication-equivalent
(time of `inv` / time of `mul`, measured at each q on the pinned cores);
additions and subtractions are counted but not priced. Wall time on the
pinned cores is recorded beside the counts. The counters are part of the
public API (`FqCounter`).

## Instances (frozen)

1. **GHS quartics.** The nine `F_q` quartics of
   `research/ghs_cubic_genus3_build_20261012/results/run-20261013T0320Z.jsonl`
   (q in {5, 7, 11}); the `quartic_Fq` field is the quartic.
2. **Random smooth quartics.** A xorshift64* generator seeded with
   `20261018 + q`; coefficients uniform in `F_q`; keep the first 3 quartics
   per q in {5, 7, 11, 13} that are smooth (certificate above) and have at
   least one rational point.
3. **Scaling quartics.** For q = the largest prime below 2^k,
   k in {8, 12, 16, 20, 24, 28, 31}: the first smooth quartic with a rational
   point from the same generator seeded with `20261018 + k`.

## Validation (pass/fail, exact; nothing is relaxed)

V1. **Class count.** At q in {5, 7, 11, 13} on every instance of 1 and 2:
    enumerate every effective degree-3 divisor over `F_q` (multisets of
    rational points with multiplicities, rational point + conjugate pair over
    `F_{q^2}`, one orbit over `F_{q^3}`, built with explicit extension-field
    arithmetic); the number of distinct keys must equal `#Jac(F_q)` computed
    from the `L`-polynomial using `#C(F_{q^k})`, k = 1, 2, 3 (brute-force point
    counts). The number of divisors enumerated must equal the coefficient given
    by the zeta function.
V2. **Group law.** On every instance of V1: 300 random triples for
    associativity and commutativity; `x + (-x) = 0`; `#Jac * x = 0` for 100
    random `x`; the full Cayley table at q = 5 on one instance; results
    independent of the representative chosen for exceptional classes and of
    the auxiliary cubic; agreement of `add` with the independent second
    reduction path on generic results; the relation that all line sections of
    `C` with four rational points sum to the same class.
V3. **Key uniqueness.** For effective degree-3 divisors `D1, D2` (enumerated),
    `key(D1) = key(D2)` iff the extension-field geometric test says
    `D1 = D2` or both are collinear with the same residual point.
V4. **GHS transfer agreement.** For each GHS instance at q in {5, 7, 11}:
    for every valid transfer `phi(nG)` from `quartic_ic.rs` (dumped by
    `dump_extra.rs`, which reuses that file unmodified), compute the class of
    its degree-6 divisor; report (i) the number of distinct degree-6 keys, (ii)
    the number of distinct canonical keys, (iii) whether canonical keys
    separate exactly the classes (a map `n -> key` that is constant on cosets
    of `ker`), (iv) `key(phi((a+b)G)) = add(key(phi(aG)), key(phi(bG)))` for
    all tested pairs, (v) the list of degree-6-key collisions resolved (same
    canonical key, different degree-6 key) and any canonical-key collisions
    that are not explained by a repeated `n mod ell`.
V5. **Smoothness certificate** accepts the nine GHS quartics and all
    instances above and rejects planted singular quartics (a node, a cusp).

## Measurements (after V1-V5 pass)

M1. **Operation cost.** For each scaling quartic: 200 random pairs; record per
    operation type (add generic, add with an exceptional operand, double,
    negate, scalar multiplication by a random 64-bit scalar, key encoding)
    the count of `F_q` multiplications, inversions, additions, wall
    nanoseconds (median and interquartile range over the 200), and the number
    of operations that used a fallback or an exceptional path. Classes are
    generated before timing from random rational points.
M2. **Fits.** Multiplications per add against `log2 q`; wall time against
    `log2 q`. Reported as fitted slope with its interval; the expected shape
    (counts nearly flat in q, inversion cost growing like `log q`) is a
    prediction, not a requirement.
M3. **Setup cost** (P0, `D_inf`, smoothness certificate, finding a rational
    point) recorded separately and not charged to operations.

## Claim hygiene

Synthetic instances only. Magma, Sage, PARI and msolve are not installed:
every speed statement is "not compared with an external implementation"; no
fastest-implementation claim. No key-recovery, sub-rho or deployed-curve
claim. The counts in M1 are operation counts of this implementation, not a
bound for any other.
