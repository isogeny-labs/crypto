## What was built

`src/cryptanalysis/plane_quartic_pic.rs` (registered in `src/cryptanalysis/mod.rs`):
`Pic^0(C)(F_q)` of a smooth plane quartic, q an odd prime below 2^31, with
class-unique keys. A class `x` is stored through `x + D_inf in Pic^3`, with
`D_inf ~ K - P0` for a fixed rational point `P0`.

* typical class (`h^0 = 1`): the reduced echelon 3x6 matrix of the conics through the unique
  effective degree-3 divisor (`PicClass::Typ`);
* exceptional class (`h^0 = 2`, class `K - P`): the normalised point `P` (`PicClass::Exc`);
  the zero class is `Exc(P0)`.

Divisors are never stored as point lists and no extension field or root finding enters
the group law: a divisor is carried by a *generating space* of forms in
`R = F_q[X,Y,Z]/(F)` and residuals use the ideal-quotient rule
`e in I(R) iff e*v in (c) for all v in I(Z)` (valid because the spaces used are
generated by complete base-point-free linear systems; completeness is checked by rank at
every step and generating spaces are lifted in degree when it fails, counted as `lifts`).

Add (the library path, [diagram](reports/add_pipeline.svg)): `Z6 = D_x + D_y`; the 4
cubics through `Z6`; the 3 cubics `V` through `E7 = Z6 + P0`; a conic through `E7` means
`E7 ~ 2K - P` and the result is `Exc(P)`; otherwise, for a cubic `c` in `V` the conic `q'`
through the residual `R5` satisfies `q' v = c g_v` for `v in V`, and the three `g_v` are
exactly the conics through the sum divisor (`D_z + K ~ E7`). Neg: the conic through
`D_x + 2 P0` and its residual; a pencil of conics (`= L * l_i`) gives `Exc(l_1 x l_2)`.
Exceptional operands use the line section through `P` minus `P` (any line: tested).
Double, sub, scalar mul (left-to-right double-and-add on `u128`) are derived.

### Public API (for W2b and W3b)

```rust
pub type Pt = [u32; 3];                                   // normalised projective point
pub struct PlaneQuartic;                                  // not Sync (Cell counters)
PlaneQuartic::new(q: u32, f: [u32; 15], p0: Pt) -> Result<PlaneQuartic, PicError>
    // f in the order of mons_of_degree(4) (X^4, X^3Y, X^3Z, X^2Y^2, ...); certifies smoothness
pub enum PicClass { Exc(Pt), Typ([[u32; 6]; 3]) }          // canonical form; PartialEq/Eq/Hash
PicClass::key(&self) -> PicKey                            // class-unique key ([u32; 19])
c.zero() -> PicClass;  c.is_zero(&x) -> bool;  c.eq(&x, &y) -> bool
c.add(&x, &y) / c.sub(&x, &y) -> PicClass;  c.neg(&x);  c.double(&x)
c.mul_scalar(&x, k: u128) -> PicClass
c.point_class(P: Pt) -> PicClass                          // [P - P0]  (= -Exc(P))
c.exceptional(P: Pt) -> PicClass                          // Exc(P) = [P0 - P]
c.class_from_conics(rows: Vec<Vec<u32>>) -> PicClass      // 3 conics through a non-collinear D
c.reduce_deg6(&Gen) -> PicClass                           // class of (effective Z6) - 2 D_inf, Z6 given
                                                          // by a generating space, e.g. 4 cubics (k = 3)
c.gen_of(&x) -> Gen                                       // generating space of an effective rep of x + D_inf
c.counter() -> FqCounter {mul, inv, add};  c.reset_counter();  c.stats() -> PicStats
PlaneQuartic::rational_points_bruteforce, smoothness_certificate, next_smooth_quartic_with_point,
find_rational_point, largest_prime_below_pow2   // instance generation (setup, not charged)
```

`reduce_deg6` is what W2b uses for the descent: a degree-6 effective divisor `Z6` (for
example `phi(Q)` plus factor-base lines) enters as the 4 cubics through it
(`Gen { k: 3, rows }`, vectors over `mons_of_degree(3)`), and the result is the class of
`Z6 - 2 D_inf` in `Pic^0`. `V4` below shows this on the GHS transfer divisors.

### V4: agreement with the degree-6 keys of `quartic_ic.rs`

split GHS instance that `quartic_ic.rs` builds at each q, every valid transfer
`phi(nG)`: its deg-6 key, the key of the degree-3 representative that `quartic_ic.rs`'s own

scalar multiplication at small q where `P0` falls in a support). Inversions priced at the

and none took an exceptional result (2 had `P0` in the support at k = 8; at every k none lifted and none had an exceptional result, for all four group operations).

M2 fits (OLS against `log2 q`, 7 points, 95% t-interval; `results/m2_fits.jsonl`):
generic add multiplications `0.56 [-0.25, 1.37]` per bit (consistent with flat); priced
`18.5 [9.5, 27.4]` per bit (the inversion price grows); wall `207 [136, 278]` ns per bit.
The prediction (counts nearly flat in q, inversion cost growing with `log q`) held; it was
not a requirement.

M3 setup (not charged): smoothness certificate about 45 us, `PlaneQuartic::new` incl. base
point setup 110-146 us (15 multiplications, 2 inversions), finding the instance and a
rational point (incl. root finding mod q) 85 us to a few ms; see `setup` records.

The constants are those of this implementation (dense echelon linear algebra on at most
22-dimensional spaces, no sparsity exploited); they are operation counts, not a bound for
any other implementation.

## Deviations and choices the protocol left open (recorded, protocol not edited)

* V4 covers the three split instances `quartic_ic.rs` builds (one per q), not all nine GHS
  quartics: that file can only build the first split instance per q and the protocol
  requires reusing it unmodified. The nine quartics all pass V1-V3 and V5.
* `dump_extra.rs` obtains `phi(nG)` as 4 cubics through the degree-6 divisor; the
  degree-6 class is `class(Z6) - 2 D_inf` and `phi` needs the constant base shift `B`
  (above); `B` is inferred from the data and then verified on every pair, not given a priori.
* Random-instance coefficient order is `mons_of_degree(4)` (a descending, then b), values
  `output % q`, rejected quartics continue the same stream. `P0` = first rational point in
  the order `[1,x,y]`, `[0,1,y]`, `[0,0,1]` for q <= 64, otherwise the first point found by
  random lines (`find_rational_point`).
* M1 and the tests were run through a stand-alone crate that `#[path]`-includes the module
  (the repository's lib target did not finish building on the oversubscribed host in
  time); the repository-pinned `cargo test --release --lib plane_quartic_pic` result is
  stated in the PR.
* Doubling goes straight to degree-5 products (the six symmetric products of a conic space
  span only a 6-dimensional space of quartics) and is a designed path, not a counted lift.
* Wall times are from a host with load average above 80 shared with a frozen long run;
  counts are not affected.
