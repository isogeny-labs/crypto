A real existing incompatibility is fixed: old original_math inspected each candidate row's top-level lifts, while v2 rows nest coordinates within units. The new helper accepts both schemas with the same 255-coordinate, two-lift setup envelope. It bounds outer units and aggregate nested coordinates before full replay, rejecting malformed arrays and overflow without truncation. V2 replay first builds complete candidate units, so retained-prefix size alone is insufficient: sampled candidate_limit, full subspace size, and conservative Frobenius union size span_size*(n/k) must also fit 255. Explicit legacy size4 has at most255 candidates. Large valid recipes are explicitly outside this bounded native setup, not silently changed. Later independent replay checks the claimed Frobenius degree and full recipe, so malformed degree metadata cannot authorize arithmetic.

Natural recipe tests are unrun and retain explicit failures.
