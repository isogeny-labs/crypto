# Standalone public-point recovery

T-1789, 2026-11-07. Producer software evidence, unsigned and not independently verified. [pcc:unverified]

The recovery API now connects the standalone projected character source to the frozen quartic/bitplane program. Before returning a candidate it computes [candidate]P and requires exact equality with the supplied target. A failed equality returns Error::Verification. The old adapter performed this check only in its test harness.

## Construction and domain

`generate.py` extracts the existing compiler prefix byte-for-byte except for removal of its old source module, then adds a shape accessor and a test-only corruption hook. `generation.json` binds both source and output. Decoder arithmetic is unchanged. Program construction still enumerates the public scalar field and constructs its coefficient system; this is not a new compact uniform compiler.

`Source::new` accepts public prime-field curve, base, subgroup order and allocation/window limits. It inherits the standalone source domain: caller-certified primes p and r, p>3, odd r>=7, r!=p, gcd(r,p-1)=1, p and r within the native word bound, and v2(p-1) equal to 1 or 2. Targets belong to the subgroup generated by P. The initial sign query validates the target before any affine addition. Identity is represented by None. Program/order mismatch and insufficient window bounds reject before querying.

Recovery queries Q,Q+P,... for the initial window. If the decoder requests a disambiguating offset, it advances to that offset and evaluates only the requested additional sign. Candidate verification uses binary double-and-add and rejects candidates outside [0,r). No unknown scalar label is passed to the runtime API. Work counters describe this adapter's sign requests, point advances and verification additions; they are not a comparative timing panel.
