# Resultant accounting instrument

Three preserved native backends now share a scalar-return accounting boundary: scalar remainder-tree accumulation, ordinary Euclidean quotient classes, and recursive half-GCD quotient classes. All compute the same projected root resultant for caller-certified prime p with v2(p-1) in {1,2}. Scalar accumulation includes its final projection explicitly. Input parsing precedes accounting; context construction, root products, polynomial work, terminal projection, and temporary destruction are inside. Output formatting is outside. This is polynomial-resultant accounting, not whole-source or recovery accounting.

`generate.py` inserts event counters without changing arithmetic expressions. `generation.json` binds all original/generated bytes and every replacement with its occurrence count. Reverse application reconstructs all three original files exactly. Every production `%self.p` and inverse normalization site is covered by the enumerated expression audit; degree/exponent arithmetic is deliberately excluded. Function-entry counts include all production helpers. Test-only code is retained unchanged except helper entry instrumentation in conditional declarations; it is not compiled by this standalone binary.

`meter.rs` counts eight arithmetic/event dimensions, helper entries, and ten allocator dimensions. Products include reduction; additions/subtractions/negations include their terminal reduction. Normalize counts independent canonical reductions; do not add these dimensions as if they were equally priced machine operations. Inverse calls and integer EEA steps are separate. Projection is an event whose internal products are also counted. Calls overlap internal arithmetic and each other, so summing all counters would double-count work.

Observed allocator calls cover alloc, alloc_zeroed, realloc and dealloc. Requested bytes sum allocation requests and each realloc's new size, including failed requests. Live/peak bytes count successful requested storage, removing the old requested size before adding a successful realloc's new size. They exclude allocator metadata, fragmentation, process RSS and transient copying during realloc. Compiler optimization may eliminate or merge allocations; use only the pinned build for comparisons. No safety conclusion relies on allocation counts. Callbacks delegate pointer/layout operations to System and use only nonallocating atomics with overflow flags.

The runner is single-thread only. Outside allocations must remain alive throughout the interval; no allocations may escape. The scalar-return API and zero-final-live check enforce part of that contract, but cannot identify every balanced misuse of preexisting pointers. The standalone entry point satisfies it. Nested spans are rejected; a guard disables accounting on an error or unwind. Counter overflow or invalid accounting rejects a row. Primality is an input-contract obligation, not checked by the runner.
