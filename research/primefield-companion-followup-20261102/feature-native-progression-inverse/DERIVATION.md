# Shared inverse in progression setup

Let r be caller-certified prime, 1<=d<r, and 0<s<r. Every factor in d! is nonzero modulo r, so F=d! and sF are units. Set u=(sF)^(r-2). Then F*u=s^(-1) and s*u=F^(-1). Substitution leaves the scaled grid samples, inverse-factorial recurrence, Lagrange weights and evaluation methods unchanged. Both original checks s*inv_step=1 and F*invfact[d]=1 remain. The same invalid-domain guard runs before any setup work.

The predecessor computes pow(s,r-2,r) and pow(F,r-2,r). The new constructor computes pow(sF,r-2,r) plus three scalar multiplications: sF, F*u and s*u. Factorial construction, both verification multiplications, polynomial work, sample evaluation and weights are unchanged. The constructor adds no vector, tree, cache field or inverse-factorial storage.

For this exact binary pow implementation, B(n)=bit_length(n)+popcount(n) multiplication calls: each loop squares, including its last iteration, and each set bit multiplies the accumulator. The source-derived change per setup is therefore one fewer exponent-r-minus-two call and B(r-2)-3 fewer scalar multiplication calls. For r>=7 this saves at least two scalar multiplication calls. Examples: r7 saves2; r97 saves10; r257 saves13; r65537 saves29. These are algebraic/source counts, not timing observations or end-to-end cost measurements. The formula applies wherever progression setup is reached, irrespective of which width policy selected d.

The arithmetic claim is conditional on the existing prime-field contract. Over a composite modulus d! may be a nonunit; no composite-field extension is claimed. Integer degree/modulus validation, allocation failure behavior and the checked inverse identities are retained. Reordering factorial construction ahead of sample construction may change the order of work before an exceptional failure, which is not a successful-path cost claim.

The qualification checks every sample against direct polynomial evaluation and every weight through w_i * product_(j!=i)(i-j)=sample_i, avoiding the factorial-inverse implementation in the reference. Cached evaluation is checked on all first points for selected small primes, including degree r-1 and zero polynomials. A gated software assertion requires exactly one Fermat-inverse entry in setup. Inherited recovery stdout is compared with the preserved predecessor. Producer checks remain unsigned pending independent signed verification. [pcc:unverified]
