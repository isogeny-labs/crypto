# Matched adaptive monomial instrument (panel not launched)

One binary contains four-column baseline, combined-monomial candidate, and A/A routed to the same baseline entry point. Both arms use the same meter, allocator, forward verifier and20 saved public target coordinates. The14x12x17 counter arrays retain product/inverse helpers, integer inverses, Euclid steps, popcounts, comparisons, character calls, allocator event/byte volumes and four exponent-setup primitives. Product helpers occur over distinct moduli; a summed count is not a weighted field or machine cost.

Compilation, calibration, preparation, initial and extra geometry/transport/residual, decoder and verification remain distinct. Teardown of program, source and prepared objects is explicitly charged to their fixed stages. For each target, analysis adds the complete fixed cost to its query. This is a derived single-target event view, not cold allocator/cache timing. Harness formatting, raw input parsing and row storage are outside the algorithm counters. Requested/freed bytes are cumulative event volumes, not peak or net memory. Additions, branches, moves and some inline arithmetic remain uncounted.

Execution is grouped baseline/candidate/A-A, with output ordered by target. The protocol records that fixed order honestly; it supports deterministic counters only. Exact A/A equality is required. Runtime consumes public points; scalar labels only assert outputs after recovery.

## Validation and replay

`generate.py baseline` and `generate.py candidate` produce15 modules per arm. `verify_instrumentation.py <arm>` checks exact forward/reverse transforms and rejects appended-byte corruption in originals and generated files. Run generators only in a scratch checkout.

The selected native development test checks identity and one exceptional point in both arms and A/A, including unchanged geometry/decoder/verification arithmetic, placement, teardown events and exponent counters. One test passes,414 inherited tests filtered. The release binary compiles and --describe executes no kernel. Full20-target mode was not invoked. Compiler version and host description were recorded before build.

`python3 -m unittest discover -s <this-directory> -p test_analyze.py -v` runs synthetic parser tests. The parser rejects malformed shapes/types, duplicates, missing rows, wrong schedule/results, A/A mismatches and misplaced counters. A synthetic setup regression confirms that a query reduction cannot hide increased fixed cost. Three methods pass; these are not measured results.
