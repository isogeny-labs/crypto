## Native deterministic screen

The prototype deliberately uses a separate small affine-curve implementation
instead of calling the candidate source. It selects the largest subgroup found
on `y^2 = x^3 + 7` over `F_223`, constructs the sixteen-entry joint table,
and compares the joint base-4 evaluator to two independent scalar
multiplications.

It then constructs a first coefficient pair that must produce infinity,
followed by a deterministic successful pair. Separate baseline and candidate
streams must return the same canonical point and coefficients and stop at the
same cursor. The command and complete output are retained in
`receipts/r34_50.txt`:

```text
R34-R50 PASS p=223 order=42 coefficient_pairs=1764 retry_attempts=2 discarded=1 draws=4 cursor=2
```

This establishes only the stated toy-domain equalities and retry bookkeeping
for that producer-side program `[pcc:unverified]`. It is not the production
implementation, a timing, or an end-to-end improvement.

3. Add explicit `setup_attempts`, `setup_discards`, and post-setup RNG digest

4. Compare legacy and candidate initial state for every jump, walker, retry,
   counter, RNG digest, and subsequent trajectory.
5. Compose only the accepted source change into C0. Do not add this prototype's
   delta to any other lane's estimate.
6. Run timing only after the existing checkpoint, isolation, calibration, and
