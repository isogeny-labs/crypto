## API frozen before implementation

- `TypedEventKind::WidePrimeDynamic`: closed trusted discriminator, serializes as `wide_prime_dynamic`. No caller-supplied string and no reserved payload-commit variant.
- `TypedEventBuffer::requested_bytes(event_cap)`: checked cap+128 requested-storage tariff, accepting512..=MAX_EVENT. `try_new(event_cap, admitted_requested_bytes)` rejects before allocation if tariff exceeds supplied remaining admission; constructs an empty Vec with try_reserve_exact once. The supplied admitted_requested_bytes is a caller assertion, not authentication against its ledger. Caller must charge the requested tariff once before construction. Physical spare capacity does not increase logical cap. Buffer is caller-owned/reusable, avoiding emitter/borrow conflicts and implicit setup allocations for legacy callers.
- `CaptureEmitter::event_typed<T: Serialize>(kind, &payload, &mut buffer)`: capture owns event object `{kind: fixed discriminator, payload: T}`. Fields are not flattened; nested caller `kind` fields cannot impersonate top-level payload commits. This is a finite schema refinement from an unconstrained generic event API; parent EventSink wrapper forwards the typed discriminator and payload, no Value conversion.
- Serialize unchanged outer envelope in existing field order, including newline. Count with checked bounded writer first, then check event-count/stream/local-cap admission, then serialize into the reusable preallocated buffer with a logical-cap writer. Both passes enforce their byte cap; a differing length on the second pass rejects before commit. Caller-side serialization must be deterministic; arbitrary custom Serialize code is trusted Rust, not a sandbox. No capture-created intermediate Value or unbounded serializer. Count and write are separate caller work tickets, not measured instructions.
- Commit through existing commit_event; failures are sticky through reject/commit_event. Retain failed encoded bytes only as unacknowledged buffer diagnostics. Existing legacy event/payload APIs, emitter-owned payload notifications, descriptor/head/filesystem accounting and hash semantics remain unchanged. They remain within outer capture/supervisor scope; this additive API does not claim to eliminate all their allocations.
