# Preserved export defects and lossless successor

The raw session, original exporter and all earlier reviewed records remain
byte-identical. All versions below remain local; their hashes and byte sizes
are in DATA-RECEIPT.json. These are post-run metadata views of the same 24 calls.
No solver, point audit, sample or measurement was added by correction.
[pcc:unverified]

1. **export.json** preserves the inherited CSV's replicate 0 for both seeds.
   The canonical `(arm, instance_id, replicate, warmup)` key omits seed, causing
   12 duplicate-key findings. Review 05 checked record consistency before this
   canonical check; it is not an acceptance of the canonical cell keys.
2. **export-v2.json** maps the two declared seeds to ordinal slots 0/1 and adds
   `native_replicate:0` to preserve the raw value. The captured canonical checker
   reports zero findings. Review 06 nevertheless found five unexpected changes:
   u-4-101 oracle seconds `1.9122045619999999` became `1.912204562`, and its counter
   and top-level wall seconds `1.9178180999999999` became `1.9178181`; u-4-202's two
   wall values `3.6425995650000003` became `3.642599565`. A default serde_json Value
   round trip caused them. V2 fails the exact-preservation requirement.
3. **export-v3.json** uses the separate `independent/export-lossless` package
   with `serde_json/arbitrary_precision`. Recursive all-field whitelisting
   passes before and after serialization, including all number lexemes.
   Its manually supplied `created` header was 12:40 UTC, ahead of the actual
   recorded 12:38 generation. Preserve it but use the next view for publication.
4. **export-v3b.json** is the final view, generated by the same frozen lossless
   executable with current UTC read from `date`. It differs from v3 only in
   `created`. Both share the adapter-format export ID ending `V3-LOSSLESS`;
   filename, timestamp and SHA256 distinguish the immutable artifacts.
   The final captured canonical check has zero findings. [pcc:unverified]

The allowed original-to-final changes are `export_id`, `created`, one appended
note, each run's seed-ordinal `replicate`, and added counter `native_replicate:0`.
Everything else, including measurements, outcomes, targets, protocol binding and
artifact hashes, must compare exactly to original v1. Slots 0/1 refer to two
**different public targets per curve**, not repeated measurements of one target.

The first lossless regression test failed because the synthetic fixture omitted
the existing export_id/created fields; its phase 08 record is retained. The
fixture was completed, and phase 08b passes all seven tests plus strict all-target
Clippy. This repair did not change solver code or data. The original four v2
tests lacked fractional-value coverage and therefore missed the rounding defect.

Reviews 05 and 06 and their 301/39-entry manifests remain immutable. A new
lossless review is a successor, not a relabeling of either prior review. Schema
acceptance, exact preservation, arithmetic validation and authenticated execution
provenance are separate checks. [pcc:unverified]
