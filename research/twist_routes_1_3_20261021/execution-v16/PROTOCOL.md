This is the sizing prerequisite for the user's three requested cost/compression/
held-out experiments. It runs only six disjoint sizing curves, public p59/p827
development controls and six positive A/A executions. The twelve future held-out
curves and their DLP outcomes remain untouched. All inputs and source lineage
come from the independently admitted v15/reference-v2 result. Original failed

## Fixed plan and scope

PLAN.json has174 one-target executions:96 ordinary/twist constructor/collector/
compression cases,32 matched alpha map/scalar cases,40 DLP references and6
known-answer A/A/positive cases. All are requested, including unsupported maps,
underfills, ambiguity and resource failures. There is no outcome-based refill
or repetition. The six controls run first; later order is frozen deterministic
hash interleaving. Controls use Q=2G with an actual repeated-G two-term relation.
They must recover2, verify the source point and emit nonzero native/backend ROI
counts. The group and GP-poly A/A sets have three fresh processes each; they
measure deterministic-instrument nuisance, not population variance.

Each ordinary or maximal-twist base gets identical anchor/alpha information.
Sizing uses B=ceil_to_multiple8(2*ceil(r^(1/4))) on larger curves and B8 on the
old controls. Group collection and alpha cases use8B query offsets; native and
GP full-root sizing use16, with this difference explicit rather than ranking
unequal tasks. Both compressed and uncompressed representations retain the
same permitted equations and target fiber. No comparative advantage is decided
by this pilot. Later paired plans use identical output workloads and queries.

References are native Brent rho, negation/cycle-escape rho, BSGS, negation BSGS
and external PARI elllog, on each identical public target and resource cap.
The maximal-twist constructor charges PARI ellgroup and native seed/order
tests; actual rational degree17 map construction/action is charged where used.
Unsupported map attempts remain failed method attempts, not zero-cost wins.

## Cost boundary and verification

The unit is single-event Callgrind simulated user-space guest instructions Ir.
It is not cycles, wall time, primitive field operations or calibrated GAE. Every
algorithmic native/library/IPC instruction inside the frozen markers is charged;
no foreign-unit conversion is used. This is a complete software profile of the
implemented interval, not a claim of complete hardware/system cost or fastest
available arithmetic. Original calibrated-primitive E27 acceptance stays open.

Exclude public input parsing/program loading, fixture/known-target generation,
trace transport and result-file serialization. Start before method setup and
end after original-point recovery verification. Setup is paid cold separately
for every target. No cross-target sharing or batch cost division. The six
exclusive phases are setup/discovery/base/catalog/known constraints; query
generation; decomposition; signs/verification/deduplication; linear algebra;
recovery/source-point verification. Rho references name walk/collision work.

Native and resident GP guest instructions are charged to their actual phase.
Every explicit ROI must be nonzero, all trace instructions must be assigned
exactly once, and all implicit non-ROI trace totals must be zero. Raw single-
event traces are retained. A second native parser independently recomputes
every total from raw files. The counted boundary is identical for all methods;
wrapper/resource-sizing clocks are not admitted performance measurements.

All raw signed witness multiplicities and deduplicated equations are retained.
Independent GP group enumeration checks the complete supplied-base witness sets,
all query rows, known coefficient equations, original/reduced affine fibers,
kernel dimensions/spans, target projections and source-point recovery. Actual
alpha roots/degree17 normalized maps are independently rebuilt with ellisogeny
and generic rational-function/endpoint checks. Byte-identical mathematical
payloads can reuse one recorded verifier case; every raw execution and counter
is still audited and linked, not pooled as independent DLP recoveries.

The abstract affine parameterization and one-edge substitution Lean lemmas
have passed fresh native axiom audit. The concrete finite field/matrix/curve
bridge remains externally checked, not fully formalized. Target projection
uses the verified v14 criterion; full column rank is not silently substituted
for the actual one-target recovery question. General curve-model/constructor
ordering fidelity and global fastest-rho certification are not implied by
provided-base GP checks; the original full campaigns retain their criteria.

## Limits and decisions

One thread/CPU0,4GiB sampled aggregate process-tree RSS,120s per cell,3600s
campaign bound and1.5GB raw-directory bound after verified lossless per-cell
compression. Original expanded bytes are removed only after exact fresh
decompression/hash equality; compressed raw traces and their original hashes
remain. This handles the observed2.1GiB free disk without deleting old evidence.
All failed/capped/not-started cases remain in the plan/ledger. A counter or
positive-control failure stops the pilot; no silent retry. Transport/process/
hash/GP-stderr admission remains strict. The independent GP audit has600s/4GiB.

Prospective worst-case envelope is174*120s; actual global cap is3600s. These
are caps, not calibrated runtime estimates. Record actual L0 elapsed values
only for sizing and separate fixed setup from per-query work. Use observed
resource requirements to freeze subsequent complete plans; do not use favorable
DLP outcomes to select or replace the held-out population. Input generation
used no DLP/cost outcomes, and this pilot uses only disjoint sizing fixtures.

Frozen source/binary/GP/library/Valgrind hashes, plan, analysis and protocol plus
successful Setec checkpoint gate precede profiles. Use the standing authorized
bounded local L0 fallback after fresh ECR AccessDenied, with no paid allocation
or IAM changes. No clock-based performance, statistical population, asymptotic,
NIST or novelty conclusion is made. Literature is the v15 primary-source review,
Callgrind client ABI/manual, parent accounting contract and prior exact/cost
evidence. The full three-part user task remains open until subsequent runs.
