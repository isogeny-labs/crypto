## Result in brief (measured values, scope stated)

* **Candidates.** With the unreduced loop taking every base abscissa as first summand and the reduced loop one representative per
  Frobenius orbit, the candidate pairs per target fall by `m / reps` against the ordered loop (`m²` pairs) and by about half that
  against the PS-0/PS-2 unordered loop (`m(m+1)/2`): from 7.667 (`n = 11, w = 2`) to 40.697 (`n = 41, w = 3`) against the ordered
  loop, i.e. 0.697 to 0.993 of `n`; for `w = 3`, 0.909 at `n = 11` and 0.982 to 0.993 at `n >= 23`.  The shortfall from `n` is the
  boundary orbit of `T` (`x = 0`, size 1, counted with weight 1) and, at `(33, 3)`, a size-11 orbit (Table 1).
* **Counted operations follow the candidates.**  Counted field multiplications per target fall by 0.997 to 1.004 of the candidate
  factor against the ordered loop and 1.001 to 1.056 against the unordered one (the frozen criterion: at least 0.8), 14 settings,
  full scans (Table 2).  About 10.0 to 11.3 multiplications per pair in every loop.
* **The reduction does not keep the verdict of a single target.**  The reduced loop run on the target alone returns exactly the
  oracle's decompositions that contain a representative (112/112 targets), which is about `1 - (1 - reps/m)³` of them; it returned
  the unreduced verdict on 84 of 112 targets and answered no on 28 of the 66 decomposable ones.  The frozen "identical verdicts
  and solution sets" holds for the reduced loop run over all conjugates of the target (112/112 equal), which visits 1.007 to 1.435 times
  the pairs of the ordered unreduced loop on the one target (Tables 4 and 5), and for the 2-torsion reduction (below).
* **2-torsion.**  `T` preserves no Hamming-weight base: 0 of the base's abscissae have their `T`-image in the base, in the `x`
  frame and in the `u = 1/(x+1)` frame, in all 14 settings (`u -> u + 1` is the complement, weight `n - wt(u) > w`).  On the nearest
  `T`-closed base `B± = {wt(u) <= w or wt(u) >= n - w}` the reduction is exact (pair factor 1.978 to 1.9998, closure equals the
  oracle and verdicts kept on 94/94 targets), so the combined factor `2n` of the protocol is not available on the weight base
  (Tables 10 and 11).
* **Leaf.**  Counted multiplications per pair, weight base in the ONB over the subspace control: 0.953 to 1.078; model bit operations
  at the control rung with `3l` nearest `n`, control scaled to the weight base's degree: 1.316 to 1.488 (raw, each at its own
  degree: 0.287 to 1.919).  The stop condition (above 2) is not triggered in any of these (Tables 7 and 8).  Wall time: a labelled
  note in Table 9, on which the ONB kernel is a portable software product and the control uses `pclmulqdq`.
* **Accounting.**  The candidate factor is a stage constant: per candidate the reduced and unreduced loops give the same hits
  (ratio 1.000 at `(11, 3)` on 14,505 and 2,872 hits, 0.992 at `(23, 3)` on 6,105 and 536; the other settings have too few hits to
  say), so relations per candidate are unchanged, and the Frobenius factor `n` is the one already in the product law.  PS-6 must not
  credit it a second time (section 6).

## 3. Method

**Setting.** `K_0: y² + xy = x³ + 1` over `F_{2^n}` in the type-II optimal normal basis of `Type2Onb` (the panel's curve and basis;
`a = 0`, `b = 1`). Base `B_w = {P : wt_ONB(x(P)) <= w}`, `w ∈ {2, 3}`, `n ∈ {11, 23, 29, 33, 35, 39, 41}`
(14 settings). Targets: the panel's, regenerated with the panel's generator (SplitMix64, seed 20261011, 6 uniform + 2 planted
sums of three base points, `m = 3`); their abscissae are compared with the panel's own output wherever the panel was run.
The question is `m = 3`: `R = ±P_a ± P_b ± P_c` over base points (the pairs-and-solve loop of the plan).

**The field.** One `u64` per element (the library's coordinate order, so words are comparable with `Type2Onb`). Product: the
cyclic convolution of the two symmetric `(2n+1)`-bit words `E(a) = Σ a_i (z^i + z^{-i})` (`γ_iγ_j = γ_{i+j} + γ_{i−j}`);
square: the coordinate permutation `i ↦ fold(2i)`, no gate; inverse: Itoh–Tsujii (`⌊log₂(n−1)⌋ + wt(n−1) − 1` products);
Montgomery batch inversion. Checked against `Type2Onb` (Table 12).

**The pair kernel** (`kernel.rs`, same row structure as `examples/pdp_speedup/kernel.rs`). For a first summand `P₁`: `U₊ = P₁ + R`,
`U₋ = P₁ − R` (two exact additions per row); the `2·cnt` denominators `x_U + x₂` of the row are inverted together; for each second
summand `P₂` the four candidate thirds are `x(U₊ ± P₂)`, `x(U₋ ± P₂)`, `λ = (y_U + y₂)/d`, `x = λ² + λ + d`, `d = x_U + x₂`,
`λ̃ = λ + x₂/d` (`a = 0`: no `+1`). The leaf is the popcount `wt(x₃) <= w`. A pair whose denominator vanishes, or a row with
`P₁ = ±R`, goes through the exact group law (`curve::add`, every special case) and is counted in the same counters.

**Loops** (one row per first summand):

| loop | first summand | second summand | pairs |
|:--|:--|:--|--:|
| `U-ord` unreduced, ordered | every base abscissa | every base abscissa | `m²` |
| `U-unord` unreduced, the PS-0/PS-2 convention | every base abscissa | from the first one on | `m(m+1)/2` |
| `R` reduced | one representative per Frobenius orbit (the smallest word), the orbit size recorded | every base abscissa | `reps·m` |

A reduced run over the orbit of the target (`R^{(k)} = σ^k R`, mapped back by `σ^{-k}`) is the *closure* run (Table 5). Orbit sizes are
computed, not assumed: the orbit of `x = 0` (the point `T`) has size 1 and is counted as a representative of weight 1; `Σ` of the
representatives' orbit sizes is checked equal to `m` on every setting (Table 1). Every run is made in full-scan mode (every pair, all
hits collected) and in first-witness mode (stop after the pair that gave the first hit).

**The 2-torsion loops** (`torsion.rs`, §5.3).  On `B± = {P : wt(u) <= w or wt(u) >= n - w}` (`u = 1/(x+1)`, in `x` terms
`x = 1 + 1/u`, liftable only; `u = 0` is `O` and is excluded, `u = 1` is `T`), ordered loops: all base abscissae as first summand, and one
abscissa per class `{x, 1/x}` (plus `T` alone).  The leaf is a table probe (membership of the third's `x` in `B±`: the `u`-weight test
would need an inversion per candidate).  Ground truth: the pair-table oracle on the same base.  The closure of the reduced set
translates two non-`T` members by `T` (`x -> 1/x`).

**Oracles.** (i) The panel itself (`examples/hamming_nb_sat_panel`, `--m 3`, the panel's seed and target counts, SAT arm cut to 1 s so
that only its exact pair-table reference matters): `truth_decomposable`, `ref_count`, `x_r`, `base_points`. (ii) `oracle.rs`, the same
predicate with the same meet-in-the-middle structure, one pass over all pair sums `a ± b` for all targets of a setting, keyed on
`x(R ± p)`; it also reproduces the panel's `ref_count` (the raw sum of the pair-table multiplicities), which fingerprints the table.
It is the only oracle at the bases where the panel's own code is out of reach (README section 6).

**Counted units.** Per `(P₁, P₂)` pair and per target: `mul` (field products, those inside inversions included), `sqr`, `sqr_k`,
`inv`, `batch_mul` (3 per inverted denominator), `add`, `popcnt`, and the vocabulary of the library's `semaev_decomp::opcount`, so
that the control kernel is charged in the same words. `M = mul + batch_mul` is the "counted field multiplications" of the tables.
The *bit-operation model* (`model.rs`) prices each operation at its schoolbook two-input gate count in each field; it is a
convention and is labelled so wherever used. Wall times in the records are `ms_unisolated` (shared container) and are notes.

**The control.** The PS-2 scalar group-law kernel (`examples/pdp_speedup/{group,kernel}.rs`, copied unchanged in structure), run on the
first 6 uniform and 2 planted targets of each PS-0 corpus (`baseline_v1/corpus/corpus_l{8..12}.txt`, `a = b = 1`, polynomial basis,
`V = ⟨1, z, …, z^{l−1}⟩`) with the library's counters (`--features pdp-opcount`), full scan of the pairs `i₁ <= i₂`.

## 4. Algebra for `K_0` (a = 0, b = 1), re-derived and re-checked

*Group law.* With `a_1 = 1`, `a_2 = a = 0`, `a_6 = b = 1`: `−(x, y) = (x, y + x)`; for `P₁ ≠ ±P₂`,
`λ = (y₁ + y₂)/(x₁ + x₂)`, `x₃ = λ² + λ + x₁ + x₂ + a`, `y₃ = λ(x₁ + x₃) + x₃ + y₁`; doubling `λ = x + y/x`,
`x₃ = λ² + λ + a`, `y₃ = x² + (λ + 1)x₃`. With `a = 0` the PS-1 kernel's `+1` (there `a = 1`) disappears from every candidate third.
The lift of an abscissa is `y = xz`, `z² + z = x + a + b/x² = x + 1/x²`.

*Translation by `T = (0, 1)`.* `P = −P` forces `x = 0` and then `y² = b = 1`, so `E[2] = {O, T}` with `T` rational. For `P = (x, y)`, `x ≠ 0`:
`λ = (1 + y)/x`, `x(P + T) = λ² + λ + x + a = [(1 + y)² + (1 + y)x + x³ + a x²]/x² = [(y² + xy + x³ + a x²) + 1 + x]/x² = (b + 1 + x)/x²`,
and `b = 1` gives `x/x² = 1/x`. So `x(P + T) = 1/x` for every `P ∉ {O, T}` (checked, Table 13: 0 mismatches in `P` and `−P`, exhaustive for
`n ≤ 23`, 4,191,705 points at `n = 23`, about 10⁵ sampled points at each of `n = 29 … 41`). The same derivation gives `1/x` for the `a = 1` curve of
PS-1 (the `a x²` term is absorbed), so PS-1's use of it was right; the point here is that it holds for `a = 0` too.

*The exactness theorem of `ps1_algebra/README.md` §3.* Its proof uses: (1) `y + y^q = x` for the two roots of `Y² + xY + (x³ + a x² + b)` (Vieta; independent of
`a, b`), so a non-liftable `x` gives `σP = −P`; (2) `E[2]` is rational and `x_T = 0` lifts, so a single non-liftable summand is impossible; (3) `x(P + T) = 1/x`
(`b = 1`); (4) Semaev's lemma for `S₄ = Res_t(S₃(x₁, x₂, t), S₃(x₃, x₄, t))`. None uses `a = 1`; the statement transfers verbatim: for `x_R ≠ 0` rational, every root of
`S₄(·, ·, ·, x_R)` in `V³` is a rational decomposition unless exactly two abscissae are non-liftable and (F1) `x_a = x_b`, `x_c = x_R`, or (F2) `x_a x_b = 1`, `x_c x_R = 1`;
so if `x_R ∉ V` and `1/x_R ∉ V` the group-law enumeration and the `S₄` root set coincide. **Checked** (Table 14, `S₃ = (x₁x₂ + x₁x₃ + x₂x₃)² + x₁x₂x₃ + 1`, which
vanishes on every sum of two points in Table 13): exhaustively for `V = F` at `n = 3, 5, 9` and for the weight bases `wt <= 2, 3` at `n = 11` (all 1057 targets), with the
`S₄` roots from the resultant of the two quadratics and the decompositions from the exact group law. For the weight base the degenerate targets are those with `wt(x_R) <= w` or `wt(1/x_R) <= w`.

### 5.3 The 2-torsion symmetry

*Where it applies.*  Translation by `T` preserves a base `B` exactly when `B` is closed under `P -> P + T`.  In the `x` frame that
is `x -> 1/x`; in `u = 1/(x+1)` it is `u -> u + 1`, the complement in the ONB (`1 = γ_1 + ... + γ_n` is the all-ones word), of weight
`n - wt(u)`.  So a set `{u : wt(u) <= w}` is closed iff `n <= 2w`; with `n >= 11 > 6` it never is, and neither frame's weight base
is: the tables count 0 images in the base out of 22 to 5,371 liftable abscissae per setting.  It applies to bases built to be
closed: a subspace containing 1 in the `u` frame (the repository's choice; the Frobenius-invariant ones need the factor `x - 1`
of `x^n - 1`) or a union such as `B±`.  What was tested is `B±`, the weight base together with its complements.  The reduction:
`(P1 + T, P2 + T)` has the same four thirds as `(P1, P2)`, so a loop taking one representative of each class `{x, 1/x}` as first
summand visits half the ordered pairs, and the closure of its solutions under translating two summands by `T` is the full set (the
point `T` itself is a class of one: `T + T = O`, so pairs through `T` are not paired off; that is the boundary correction).

## 6. What the reduction decides, and the accounting rule

*Observations first, interpretation after.*

**Observed.**  (i) The reduced loop on a target is sound and incomplete: its solutions are exactly the oracle's that contain a
representative (112/112), about `1 - (1 - reps/m)³` of them (Table 4, bracket), and it returned the unreduced verdict on 84 of 112
targets (28 of 66 decomposable targets answered no).  (ii) Run over all conjugates `σ^k R` and mapped back, its union is the
unreduced set (112/112) at 1.007 to 1.435 times the pairs of the ordered unreduced loop (2.0 to 2.6 times the unordered one).  (iii)
Hits per candidate third are the same in both loops where the counts allow a comparison (Table 5).  (iv) To the first witness on a
decomposable target the reduced loop costs about the same as the unreduced one where it keeps the verdict (`(11, 3)` 1.000,
`(23, 3)` 1.001, `(29, 3)` 1.169) and less where it does not (Table 3), but then its answer is wrong.  (v) The counted operations of
every loop are the pairs times 10.0 to 11.3 multiplications: the model's factor and the counted factor agree.

**Reading (interpretation, labelled).**  Frobenius sends a decomposition of `R` to one of `σR`, not of `R`: `S(σR) = σ S(R)`.  For a
fixed target the representatives therefore search a `1/n`-th of the first-summand space and find a `~3/n`-th of the solutions; the
rest of `S(R)` is the reduced loop's solutions for the *other* conjugates, which a decision about `R` must also run.  The `n` is
spent on `n` targets, one for one: it is a re-labelling of work for the single-target question, and an exact answer costs about as
much as the unreduced ordered loop.  For collecting relations, one decomposition of `R` already gives `n` conjugate relations
through the Frobenius action in both loops, and the yield per candidate is unchanged, so the reduction does not change relations
per unit work: it is the `n` that "the product law already divides by" (PLAN §7, risk 4).  By the test of `AGENTS.md` §3 the candidate
reduction is **relabelling** for the single-target decision oracle (the headline count fell, the exact answer's cost did not) and
**accounting** for relation collection (the factor is already in the product law); the frozen class (engineering) is kept in the
header.  The `T` reduction is an exact factor 2 (**engineering**) where it applies, which the weight base is not.

**Accounting rule (protocol).**  This task's factor is a **stage constant**: the measured values are `m/reps` (about `n`) for the
ordered loop and about `n/2` for the unordered loop, on candidate pairs and on counted multiplications.  PS-6 must not apply it to a
whole-method ratio again; the Frobenius factor `n` is in the product law.  No whole-method figure is stated here.

## 7. Deviations from the frozen protocol, gaps and blockers

1. **The frozen success criteria are not all met as stated** (section 1, rows 6-8): identical verdicts and solution sets hold only
   in two of the three readings (all conjugates; `T` on a `T`-closed base); the factor is about `n` or `n/2`, not `2n`, because
   `T` does not preserve the weight base.  The criteria are not weakened here; the results are reported against them.
2. **The panel's own oracle was not run at `(39, 3)` and `(41, 3)`.**  Reason: a resource limit, not an impossibility.
   Its pair table (`~5·10^7` and `~5.8·10^7` additions on the library's inversion; 449 s for the table alone at `(33, 3)`) and a full
   scan of the pair table per refuting target (3 of 8 and 6 of 8 targets) would hold the benchmark lock for many hours per setting.
   Substitute: the example's pair-table oracle (`oracle.rs`), a different implementation of the same predicate, which reproduces the
   panel's `x_R`, verdict and `ref_count` on every one of the panel's targets that exist (96) and agrees with the
   kernel on all 112.  The requirement "every kernel answer verified against the panel's oracle" stays open for those 16 targets.
3. **The 2-torsion test at `(35, 3)`, `(39, 3)`, `(41, 3)` ran on 2 of 8 targets** (idx 0, uniform, and 6, planted) for time.
4. **`T` was not run on a Frobenius-invariant subspace containing 1**, the `u`-frame base the repository uses elsewhere, nor in a combined
   orbit-and-`T` loop; only the candidate count of such a loop is derivable (`n` times 2 against the ordered loop) and it was
   not run.
5. **"Nearest `l`" of the control** is ambiguous: Table 8 gives the rung with `3l` nearest `n` and the rung with the nearest base
   size, and the range over all five rungs.  For `n = 11` and `n = 41` no rung is near in `n` (`dn = +13`, `-5`); the scaled column
   uses the model's `(n/n_l)^2`.
6. **The bit-operation model is a convention** (`model.rs`); the counted-operation comparison does not depend on it.  The ONB
   product of the example is a software cyclic convolution; the wall note in Table 9 compares it with a hardware-assisted
   polynomial product and says nothing about the bases.  A hardware-assisted normal-basis product was not attempted.
7. **Theorem check scope**: exhaustive at `n = 3, 5, 9` (`V = F`) and `n = 11` (`wt <= 2, 3`); for larger `n` the exactness statement is
   a proof (§4), not an exhaustive check.  The panel's SAT arm (S3 chain with a free intermediate, lifting and blocking) was cut
   to 1 s and not used.
8. **Hosts**: the run spans two host classes and two container restarts (section 2); counts are unaffected.
9. **`benchmarks/` and the validation gate.**  AGENTS.md asks a result PR to copy its visual record into `benchmarks/<YYYYMMDD>-<slug>/` and add a
   row to `benchmarks/README.md`.  The entry [`../../../benchmarks/20261011-pdp-ps4-symmetry/`](../../../benchmarks/20261011-pdp-ps4-symmetry/)
   (report PDF, four SVG graphs, a 150 dpi PNG render of each, a README) is added, made by `copy_benchmarks.sh` from the report.
   **No row was added to `benchmarks/README.md`**: the validation gate (AGENTS.md, `docs/VALIDATION_GATE.md`) admits a row only with a
   `VALIDATION.json` pointing to a replay certificate, a validator report and a rho reference matched to the protocol, and a PS-4
   stage/counting result has none; the pre-gate freeze (`benchmarks/PRE_GATE.json`) may only shrink, so it cannot take a new row, and
   `scripts/validation_gate.py check` fails a PR that adds an unvalidated row.  This result is **unvalidated (pre-gate) in the sense of
   the gate: not validated, not admitted**; the entry's README says so, and nothing here claims validation.
10. **Tooling.**  `gh` had an invalid token in this container; the PR was opened through the GitHub connector.  `PLAN.md` §8 was not
   edited (outside the permitted paths); the PS-4 row should read: partial (frozen success criteria met in two of three readings;
   see `ps4_symmetry/README.md`).
