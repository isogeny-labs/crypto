# PS-7: implementation decisions, fixed before the first measured run

Protocol: [`../protocols/PS-7.md`](../protocols/PS-7.md) (frozen; **not edited**).  This file records the choices
the protocol leaves open, so that the numbers in [`README.md`](README.md) cannot have shaped them.  It was
written after the code compiled and before any measured run of the arms (the run commands are in
[`run_ps7.sh`](run_ps7.sh); every raw record in [`raw/`](raw/) is newer than this file's first commit).
Anything that turned out differently is a named deviation in the README, never an edit here.

## D1. Inputs

* **Uniform rungs.**  `l = 8, 9, 10`, `n = 3l`, PS-0's moduli and curve.  The 16 targets of a rung are the first
  16 *uniform* targets of the PS-0 corpus (`baseline_v1/corpus/corpus_l{8,9,10}.txt`).  PS-0 draws them from
  SplitMix64 seeded `20261011 + l` (`corpus.rs::SEED_BASE`); the protocol's "seed 20261011" is read in PS-0's
  convention (base seed, plus `l`), which is what makes the verdicts checkable against the stored corpus.  Each
  target is a curve point; the harness re-derives it from the frozen generator and aborts if it differs from the file.
  Found and refuted targets are both kept, as drawn.
* **Regression corpus.**  The 60 inputs of `research/index_calculus_baseline_20260914/regression/`
  (`n, l = 15,5 / 17,6 / 19,6`) are the instances of upstream `mtrimoska/EC-Index-Calculus-Benchmarks`; the repository
  carries their parameters (field, target abscissa, label) in `semaev_corpus::CORPUS`, and the harness uses those
  parameters with each instance's **own modulus** (not the bench's).  The upstream DIMACS/ANF files are not used
  (the WDSat binary is not part of this experiment).  Reference verdict: exhaustive search of every sorted triple of
  `V^3` through the crate's general `S4` evaluator (`corpus::brute_roots`, which shares nothing with the leaf or the
  shell), which must agree with the corpus' `truly_sat`.  The algebraic-only input `n19l6-19-U` is therefore *found*.

## D2. The leaf

* On the uniform rungs: PS-2's group-law leaf (`kernel.rs` formulas), candidate set `S = B`, the rational
  (liftable) abscissae of `V`, exactly the plain loop's set.  The shell calls it for **one pair at a time**, so the
  two denominators of a pair share one inversion (Montgomery's trick on two elements) instead of the row-batched
  inversion of PS-2's loop; the row points `U± = P1 ± R` are cached per `x1`.  The loss of batching is a property
  of a per-pair theory, not an accident of the implementation; it is priced, and a control arm (`a1u`) runs the plain
  loop over the same one-pair leaf so the shell's overhead can be split from the batching loss.
* On the regression corpus: the group-law leaf needs a point `R`; the corpus targets need not be abscissae of
  rational points (`n19l6-19-U` is not), and the corpus question is algebraic.  The leaf there is PS-0's independent
  enumerator (`corpus::pair_roots`: quartic in `x3`, `gcd` with `L_V`) over all of `V`.  Where the target is liftable and not
  degenerate (PS-1's theorem), the group-law leaf is run as well (`--leaf group`) and must agree.

## D3. Pair space and arms

Pair space `{(a, b) : a <= b, a, b in S}`, `|S|(|S|+1)/2` pairs (the plain loop's, PS-2).

| arm | solver code | branching order | conflict explanation |
|:--|:--|:--|:--|
| `a1`  | PS-2 `ScalarKernel` (row-batched) | lexicographic by construction | none |
| `a1u` | pair loop over the shell's leaf (control) | lexicographic | none |
| `a2`  | **library** `Solver::solve_with_lazy_clauses`, as shipped | priority class on the pair bits, VSIDS within, phase 0 first | `g ∨ d`, `g ∨ ¬d` |
| `a2p` | library, same | same | the bare guard `g` (the library's level-0 path; control) |
| `a2l` | example-local copy of the solver, hooks active | static lexicographic, 0 first | `g ∨ d`, `g ∨ ¬d` |
| `a2h` | the copy, hooks inactive | as `a2` | as `a2` |
| `a3`  | the copy, hooks active | re-evaluated minimum vertex cover (D5) | as `a2l` |

The library has no branching or learnt-clause hook and tracked files were off limits, so `a2l` and `a3` run on
`examples/pdp_ps7/sat_hooked.rs`, generated by `gen_sat_hooked.sh` from `src/cryptanalysis/sat.rs` (git blob
recorded in its header) plus one method (`solve_with_hooks`) and one trait.  `a2h` against `a2` (every solver counter,
the verdict, every root, the leaf visits) is the check that the copy is the library; it is run (`fidelity`) and reported.
"The same branching order in both arms of a comparison" is read as: arms 1 and 2l share the lexicographic order (so
leaves visited are comparable), arms 2l and 3 differ **only** in the decider, and no order is tuned per target or per
rung.  The native order of `a2` is the library's own (it is a dynamic, activity-based order); it is a separate row, not
a stand-in for the static order.

## D4. The encoding

Variables: the `3l` coordinate bits (summand-major, most significant first), `d`, and the `l-1` prefix-equal
variables of the constraint `X1 <= X2` (the plain loop's pair order).  Static (original) clauses: `X1 <= X2`, and, for
`S != V`, one clause per summand and per value outside `S`.  Branch priority on the pair bits.  The theory fires when
`X1` and `X2` are both assigned (the library's trigger rule is "all trigger variables assigned": the `2l` pair bits).
No third in `V`: install `g ∨ d` and `g ∨ ¬d` (`g` = negation of the pair literals), so that the solver meets an ordinary
conflict and analyses it; a third `t`: `g ∨ (X3 = t)` per bit (all combinations of bit positions for several thirds).
The solver's conservative path for a bare, fully falsified clause (backjump to level 0, no conflict counted) is the
control `a2p`.  Search is for the first model (measured runs) or for all models with blocking clauses (`--all`, the
verification runs).

## D5. The dynamic order (arm 3)

Graph: vertices are the `3l` coordinate bits; an edge joins two bits that occur together in a monomial of degree >= 2
of the library's descended symmetrised `S4` system (`weil_descend_s4`: correspondence equations over `x`, Semaev
equations over `e`).  At every decision the assigned bits are substituted (assigned-0 kills a monomial, assigned-1
drops out, equal residual monomials of one equation cancel), the graph of the unassigned bits is rebuilt, an exact
minimum vertex cover is computed (complement of a maximum independent set; among maximum independent sets the last
in lexicographic order, so that covers prefer early variables), and the decision is the cover vertex of largest
residual degree (ties: lowest lexicographic position), value 0 first; no edge: the lowest unassigned bit.  The
`e`-component never shares a monomial with an `x` bit and is not changed by `x` assignments, so it cannot influence
the choice; it is measured (`graph-stats`), not covered per node.  Counters: decisions, decisions that differ from the
lexicographically first unassigned bit, cover size, search steps.

## D6. Units and the criteria, as numbers

* **Leaves visited per target** `L`: pairs sent to the leaf (a pair is evaluated at most once).  **Pairs `P`**: the pair
  space.  **Pairs saved** `P - L` (refuted targets: every pair is evaluated or removed unevaluated).
* **Conflicts**: solver conflicts (each analysed conflict learns exactly one clause).  Always printed next to `L`
  (a conflict count without leaves is inadmissible).  For `a2p` the learned clauses are the theory's guards (`L`).
* **Pairs pruned per learned clause**: pairs excluded by a learned clause beyond the pair whose refutation produced it
  is `saved / learned`; the pairs a clause removes in total (the pair itself plus those) per learned clause is
  `P / learned` over a refuted target, which exceeds 1 exactly when `L < P` or learning is not one clause per leaf.
  Clause-level cube sizes and marginal exclusions are also logged (arms with the learnt-clause hook).
* **Success (frozen reading)**: some realisation of arm 2 or arm 3 (`a2, a2p, a2l, a3`) has, at two or more rungs
  (`l = 8, 9, 10`), a mean over the rung's refuted targets of `P/learned > 1` **and** `L < P`, with verdicts identical to the
  corpus on every target.  **Stop**: `L = P` (nothing saved) on every refuted target of all three rungs, for every
  realisation.  The regression corpus is reported with the same quantities and does not enter the rule.
* **Counted bit operations**: the leaf's work is priced in PS-1's gate model (fused ternary-logic issues; product,
  squaring, inversion, zero test and subspace-membership test from `ps1_algebra/raw/gates.jsonl`; additions `n` gates)
  from *counted* field operations: the one-pair leaf counts its calls; the plain loop's counts are derived from the
  structure of `kernel.rs` (per row two exact additions and one batch inversion of `2*cnt` elements; per pair four products,
  four squarings and the additions and tests of the candidate chains) and are not instrumented.  The shell's work is the
  solver's counters (`clause_visits + clause_lit_visits + analyze_lit_visits + propagations + decisions`) plus the
  literals the theory installs, the decider's scans (for arm 3 also the monomials examined and the cover search steps),
  each counted step charged as one 64-bit word operation, i.e. 64 bit operations (the repository's convention for a word
  XOR).  This is a convention and a lower bound on what a clause visit costs; the raw counters are reported so another
  weighting can be applied.  The leaf is never counted as free.  The regression corpus' quartic leaf has no gate model
  here: its bit operations are **not computed** (leaves, conflicts and pruning only).
* **Wall** is a note: a separate pass without the accounting hooks, on a reserved core through
  `tools/isolated_bench.py run`, contended runs reported.
