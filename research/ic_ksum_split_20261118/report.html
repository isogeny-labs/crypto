1. Baseline, phase breakdown and levers

Baseline (incumbent). The pruned k-sum pipeline of research/ic_ksum_prune_20261115 (validated, VAL-20261115-276156): ic.pipeline with oracle = ksum:m=<k>,prune=1, the factor bases of that study, default target source walk, k = 4 and 5.

Phase breakdown (step 1; prior data only). analysis/phases.mjs reads the prune study's committed sessions (measured rounds, 432 runs per row and arm) and splits the counted cost S (w = 0) of ksum5-p / ksum4-p (analysis/phases.json):

phase share of S, ksum5-p (8 rows) share of S, ksum4-p
table build (oracle_setup adds) 29-55 % 22-53 %
walk steps (one add a trial) 13-55 % 16-49 %
walk set-up and restarts (16 jumps, start, pooled offsets: about 48 scalar multiplications a run) 5-47 % 5-52 %
probe confirmations, linear algebra, factor base, verify at most 4 % at most 4 %

The set-up share is largest on the small rows (B15 47 %, B18 45 %), where 48 scalar multiplications are large against sqrt(r).

Lever A (new code, commit fc0babc73e): split=1. KSumTable::build_negation_folded_split forms every k-sum as its (k-2)-summand prefix plus one precomputed pair sum P_j + P_l (two additions per abscissa pair; the other sign patterns are negatives). The 2^{k-2} C(a-1, k-1) partial sums of level k-1 are never formed; the pair table costs 2 C(a-k+2, 2) adds. Same visiting order and identity skips: identical table, keys, inserts and collisions (unit tests split_build_is_the_same_table_with_fewer_adds, split_runs_are_identical_but_for_fewer_setup_adds). Default off. Real group additions removed from the build, not an accounting change; the pair table is a vector indexed by point pair (memory reads, as the base's own point reads, not counted by either arm).

Lever B (existing option): targets=stride-renew. The pipeline's existing target source R <- R + S, S <- S + T after each relation (TargetSource::StrideRenew): three draws of [a]G + [b]Q (S, T, R0; 6 scalar multiplications) instead of the walk's 16 jumps, start and pooled restarts, and no self-collision restarts (R0 + kS repeats only after r steps). One addition a trial, as the walk. A different target stream: outputs are not identical, so this lever is tested on verified answers and paired cost.

Questions. (Q1) Is split=1 cheaper than the incumbent, row by row, at every weight of the section 5a band, with identical outputs? (Q2) Is the combined pipeline (split=1 + stride-renew) cheaper than the incumbent, row by row, at every weight?

T1 (primary, Q1): X = ksum5-ps; secondary ksum4-ps.
