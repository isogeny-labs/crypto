# Five-curve exact schedules

Source and inputs were committed and pushed at 7e8109ea2a65 before this attempt. publication.txt retains a hosted descendant containing that source; binary-check.txt and input-check.txt check the exact native-v17 binaries and seven fixture JSON files. The command was `timeout -k 10s 120s /tmp/cm-marked-scalar-build/bench --structural research/cm-marked-scalar/fixtures-v2`. Exit 0; 90 complete rows, all correct, all timing_reported=false. Clocks were disabled.

The scope is schedule-scope-v2.json: five curves, three arms, six widths. group-count-minima.json is `jq -s 'group_by(.curve) | map({curve:.[0].curve,group_count_minima:(group_by(.arm)|map(min_by(.doubles+.adds)))})' rows.jsonl`. The chosen minimum uses equal weight for D and A solely as a displayed count; it is not a runtime optimum or external performance comparison. All widths, negations and arms remain in the raw rows.

Counts cover the named public_mul routine's explicit group operations, including odd-point table construction and fused small-scalar action. Backend field operations, coordinate conversion, allocation and map setup are not represented by D+A. In the explicit-map arm, D/A/N count the correcting scalar only. The raw Map.apply calls add, for each nonzero point through both maps and closure, exactly (8*ell+10) explicit Field.mul calls, 8*ell Field.add calls and two Field.inv calls. This is derived directly from three full Horner evaluations per map and the four final multiplications, plus two endpoint scales; it excludes backend conversion calls and setup. No total latency is inferred from this vector.
