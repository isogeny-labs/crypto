# Bounded inline block planner

The existing block circuit and first-encountered tie rule stay fixed. This separate implementation replaces each DP transition/node's term vector with an inline array of two signed labels, and the planner's label tree with a bounded bitset. A single column has at most two terms; a folded block has at most one. With radices at most 32 and widths at most 7 the largest odd-table label is 32*63=2016. Accepted recoded length remains at most 2048, maximum block span 16. The two live-state DP entries and cost key (D+A,N,D,steps) preserve the original order and strict comparison.

The result reserves the selected number of inline steps once. Existing Big/digit vectors, the state vector, final step vector and prefix construction still allocate. Point-bank construction/normalization uses the existing implementation's circuit and a separate executor accepting inline steps directly; no conversion or installed plan enters that executor. No claim about total allocator calls, allocator duration or faster execution follows from this source change. Every allocation, bitset initialization, recoding, transition, reconstruction and destruction must remain charged in any later cold worker.

Before use, software qualification compares exact steps, ties, counts, signs, table metadata and transitions with the frozen original planner; reconstructs integer action using the existing separately coded GMP model; checks small exhaustive optima, signed/zero/leading/identity cases, all five original-mu point actions and every retained bank label; and rejects out-of-domain inputs. P-192 primary; P-224/P-256/P-384/P-521 retained. This qualification is untimed software validation, not a new parameter census, allocation benchmark or e2e timing amendment.

Bound: one build and one qualifier, each 120 seconds, 2 GiB address space, one process/thread; no unchanged retries. If source changes are required, preserve the failed version/receipt and publish the changed source before qualification. No cloud submission, budget/cap/role change, generator/controller restart or repeated timing preflight. Source and PR updates precede the qualified execution.
