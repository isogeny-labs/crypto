# Replay certificates for the degree-bounded closure

Format `chainsd-cert/v1`, written by the native engine (`native/`, env `CHAINSD_CERT=FILE`)
and verified by the independent C checker `native/checker/chaincheck.c`.

```
chainsd-cert/v1
p <p> k <k> kshift <k> uni 0 D <D>
generator a:b:c a:b:c ...        # the reduced S_3(x1,x2,t) as characters x1^a x2^b with coefficient c
s <v> <r>                        # one line per closure step: new row = (variable v) * (basis row r), reduced
...
end rank <R> one_in_V <0|1>
```

Variables `v < k` are the shifts `x1 -> x1 * x1^(2^v)` (exponent `a -> a + 2^v mod 2^k`); `v >= k`
act on `x2`.  Row 0 is the generator.  Columns are the characters of weight (popcount) `<= D`.

## What the checker verifies

The checker replays the steps with its own exact `F_p` arithmetic (lazily reduced 64-bit rows,
weight-descending column order with mask-ascending tie break, canonical echelon reduction) and
accepts only if

1. every step's source row has weight `<= D-1` (the degree budget of the pinned computation:
   `V_D` may only multiply elements of degree `<= D-1`), and every step is a new basis element;
2. the claimed rank equals the replayed rank and the claimed membership of the constant `1`
   agrees with the replayed one;
3. for a **lower certificate** (`one_in_V 0`): the full closure sweep passes, i.e. for every
   basis row of weight `<= D-1` and every variable the shifted row reduces to zero.  The span is
   then the full iterated degree-bounded closure `V_D`, and `1 ∉ V_D` certifies `LFD > D`
   (`sd > D`);
4. for an **upper certificate** (`one_in_V 1`): the constant is in the span, so `1 ∈ V_D`
   certifies `LFD <= D` (`sd <= D`).

```sh
cc -O2 -o native/checker/chaincheck native/checker/chaincheck.c
native/checker/chaincheck certs/family_p12289_n11_k8_D4.cert      # exit 0 and {"verified":true,...}
```

## Instances

| file prefix | p | A | B | t | admissible (`2^(k+1) | p-1`, unit by `family_S3_ne_zero`) |
|---|---|---|---|---|---|
| `family_p12289_n11_k*` | 12289 | 1210 | 0 | 11 | yes for k <= 11 (n = 11 is a non-square mod 12289) |
| `family_p65537_n3_k*` | 65537 | 18 | 0 | 3 | yes for k <= 15 (n = 3 is a non-square mod 65537) |

`A = n^2 (n-1)`, `t = n`.  Both instances have zero grid zeros at every listed depth (engine
`family` command; the Lean theorem proves it for all admissible depths).

## Regeneration

`gen_family.sh` regenerates the p = 12289 certificates (deterministic: the engine's closure
order is fixed by the column order and the work queue).  The p = 65537, k = 10, D = 5 lower
certificate is generated by

```sh
CHAINSD_CERT=certs/family_p65537_n3_k10_D5.cert native/target/release/chainsd closure 65537 10 18 0 3 5 verify
```

SHA-256 hashes of the committed certificates are in `SHA256SUMS`.
