# Exact sparse blocks as a rootfinding route

Status: unexecuted theory/experiment design, 2026-11-15. This document supplies a correctness contract and falsifiable next measurements. No measured speedup or novelty is asserted. [pcc:unverified]

## Exact dependency and block contract

Let K be any finite field, let each labeled variable x_j have a declared domain D_j contained in K, and let F be a finite list of polynomials with canonical coefficients. First combine equal monomials and cancel zero coefficients over K. If using domain normal forms, prove evaluation equivalence on the declared product domain before constructing incidence. An incidence edge (F_i,x_j) exists whenever a nonzero remaining monomial contains x_j with positive exponent. This can conservatively overestimate functional dependence, but must never underestimate it.

Choose any matching between equation and variable vertices. This is a combinatorial choice, not a claim of algebraic independence or a nonsingular Jacobian. Call unmatched variables U. For each matched equation F_i with matched variable p(i), introduce a directed edge x_j -> p(i) for every other variable appearing in F_i. Fix an outer assignment to all variables in U, and topologically order the strongly connected components of the remaining directed graph. All variables in a matched equation then belong either to its pivot's component or to predecessor components. Retain every unmatched equation as a residual constraint, checking it as soon as all its variables have been assigned. Nonzero constant equations reject the current branch; identically zero equations impose no condition.

For each predecessor assignment, solve ALL roots of the component's matched equations on its labeled domains, then branch over each returned tuple. A component may become underdetermined after specialization; in that case its free coordinates must be retained/enumerated exactly. Structural matching does not permit division by a pivot coefficient. If a solver uses division, split into the nonzero guard and its complementary zero branch; the zero branch requires its own exact solver or explicit UNKNOWN status. The union over all outer assignments and all component tuples, filtered by residual equations, is precisely the original solution set.

Proof: each original root fixes exactly one outer assignment. Inductively its restriction to each component satisfies the specialized component equations and therefore appears in that component's complete root set. Residual checks cannot reject it. Conversely each emitted full tuple satisfies every matched equation and every residual equation and has all coordinates in the declared domains, so it is an original root. Coordinate labels and canonical deduplication preserve ordered tuple semantics. This proves set completeness, not local algebra/scheme multiplicities. Repeated source positions remain separate labeled coordinates. If any component or outer enumeration reaches a work/output cap, return UNKNOWN with verified lower-bound tuples, never an empty-set certificate.

The proof applies to prime fields, binary extensions and odd extensions. The specific regular doubled-root formulas in this cycle use characteristic two and do not transfer unchanged to odd characteristic. Ordinary binary and Koblitz curve inputs require separate admitted curve/target fixtures even when the graph theorem is common.

## Why a Jacobian is unsafe

In characteristic two, F(X,Y)=X^2+Y has formal derivative dF/dX=0, but X is indispensable: F(0,0)=0 while F(1,0)=1. Over GF(2), the system X^2+Y=0, Y=0 has the unique root (0,0). Dropping the X-dependency and treating X as free incorrectly adds (1,0). Over characteristic p the same counterexample is X^p+Y. Field equations X^q-X=0 are zero functions on K and may be removed after that semantics is proved; their use as structural pivots does not establish independence of the remaining nonlinear equations. A visually sparse derivative matrix is not an exact polynomial dependency certificate.

## A block linear specialization

For an exact linear system A k=b, fixed invertible row/column permutations merely relabel solutions. Connected components of the bipartite nonzero graph give independent blocks; a matched SCC decomposition can give triangular rather than disconnected blocks. Every unmatched row must still be checked, including all-zero left sides with nonzero right sides. Reconstruct one particular solution and a full kernel basis, then replay A k0=b and A v=0 for every basis vector, as well as rank/nullity. These checks audit the construction; independent tiny exhaustive equality is still needed to catch omitted kernel directions.

For a partition A=[[B,C],[D,E]], k=(u,v), b=(f,g), on the guard det(B)!=0 one has u=B^{-1}(f-Cv) and (E-DB^{-1}C)v=g-DB^{-1}f. This is an exact affine bijection between Schur-system solutions and full-system solutions. If the guard fails, fall back to complete elimination; never discard that parameter branch. A small apparent boundary does not promise sparse Schur complements: record fill-in and the cost of reconstructing/verifying solutions.

The characteristic-two regular doubled-root reduction fixes h,a,y_a with a!=0, a!=z and ha+k!=0, expresses r,s as K-affine functions of the SAME k, then constructs the quotient cubic. Its two variable coefficients are F2-affine maps of k. The W2/W3 projection therefore gives an exact binary matrix whose full incidence includes every Frobenius-square contribution. For n=83,d=18 there are at most79 scalar constraints on83 k bits; consistency implies nullity at least4, not at most4. Actual rank, block sizes and candidate cap decide whether enumeration is admitted.

## Falsifiable optimization leads and limits

1. Compare exact incidence of the original 339-variable/332-equation model, the guarded chart, and the final binary matrix. A source-chain drawing alone is insufficient: record largest SCC, separator size, nonzeros, density, all unmatched constraints and Schur fill. If the actual matrix has one large irreducible block, permutation-only block speedup is refuted for that cell; investigate algebraic specialization or a different basis instead of claiming hidden blocks.
2. Adjacent outer parameters do not imply a low-rank matrix update. Multiplication by any nonzero field element on an n-dimensional field representation is invertible, so changing a multiplier can change a multiplication matrix by full rank n. Measure rank(A(theta')-A(theta)) before proposing inverse-update reuse. A projected map can have smaller rank, but that must be measured/proved.
3. A potentially useful project combination is guarded chart elimination, exact block/Schur solving, and caching equal residual constraint spaces with the original coordinate labels. Existing research/advance/fiber_solver.py already implements specialization, canonical coefficient-row-span caching and unary propagation; those mechanisms and classical graph decomposition are prior project work, not a novel contribution. A new claim would require a genuinely new reduction/complexity property or a qualified empirical gain.

If H outer assignments survive, N_i predecessor states reach block i, and C_i is the charged local solve cost, total work is preprocessing + sum_i sum_{states} C_i + residual checking + extraction/verification/serialization. H can be exponential; block decomposition does not remove it. Explicit output alone costs at least proportional to the number of returned tuples. For the current actual regular branch, all other h,a,y_a, the excluded common-factor k=ha, a=0 and nonrational/original auxiliary branches remain outside the conditional experiment. A fast empty conditional fiber is not an end-to-end all-roots solve.
