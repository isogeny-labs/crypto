The residual sweep, exhaustively (2026-10-28)

Lead ICP-residual-partial-relations. Sizes 20 to 44 bits, three sessions each, the sweep against the generic searches and the pair-table incumbent, with variants (no sign fold, distinguished points, pair-table hybrid) and base-shape controls.

Findings

  • What it is. A birthday collision search that runs through the index-calculus pipeline. Evidence: (1) at a fixed base the counted S does not grow with the curve (slope of log2 S against log2 r, 95% bootstrap interval: B=2 -0.025 [-0.034, -0.017], B=8 -0.014 [-0.020, -0.009], B=32 -0.019 [-0.023, -0.014], B=128 -0.017 [-0.021, -0.013]), exactly like rho.negation -0.010 [-0.022, +0.001], bsgs.negation -0.007 [-0.013, -0.002] and kangaroo -0.023 [-0.031, -0.016]; the tuned pair-table incumbent grows: +0.071 [+0.069, +0.074]. (2) The collision rows found equal the birthday count N²/(r 2k) in every variant (ratios 0.7 to 1.2, table below). (3) Replacing the smallest abscissae by pseudo-random strided ones changes S by 1.03 [1.00, 1.07]: the base has no index-calculus structure to contribute. (4) Adding the pair table changes S by 1.00 [1.00, 1.00]. (5) With a known-log base a single collision row pins the logarithm (rows used = 1): that is a baby-step/giant-step-style search (S ratio to the abscissa base: progression 0.65 [0.61, 0.69], random scalars 0.35 [0.33, 0.37]).
  • Cost model. A target contributes 2B signed residuals, one group addition each. After N such additions the expected number of colliding pairs is N²/r (classes {Z, -Z}: N²/(2 r/2)), without the sign fold N²/(2r), and N²/(r 2k) when only residuals whose hashed abscissa has k trailing zero bits are kept (equal abscissae hash alike, so a pair collides only if it passes the filter). The solve stops when the column of d is pinned, which takes K collision rows: K = 1.12 B + 4.0 for the abscissa base (least squares over sizes 20 to 36), 51% of the rows linearly dependent, and K = 1 for a known-log base. So N = sqrt(K r) and S = N/sqrt(r) is about c sqrt(K): flat in r, growing like sqrt(B) once B exceeds a few, smallest at the smallest base. The table holds N entries (N/2k with the filter).
  • Placement at 36 bits. rho.negation 1.29, rho.negation_lanes 1.33, bsgs.negation 1.29, kangaroo 1.97; the sweep is 2.28 at B=2, 3.85 at B=8 and 11.89 at B=128; the tuned pair-table incumbent is 42.2. The generic searches stay flat to 44 bits and the plain B = 2 sweep to 40 bits (past that only the limited-memory variants run: memory). The sweep sits between the generic searches and the incumbent, at the generic searches' exponent.
  • Distinguished points (B = 8, paired S against the plain sweep, pooled over sizes). k=2 1.44 [1.40, 1.48], k=4 2.57 [2.48, 2.66], k=6 5.01 [4.76, 5.28]. Stored residuals fall by only 2.7, 5.9 and 11.9 times (not 4, 16, 64: the run lasts longer), while S grows 1.45, 2.64 and 5.17 times, so S x memory falls to 0.53, 0.45 and 0.43 of the plain sweep's and then flattens. The trade never reaches rho's constant memory at a rho-like S.
  • Memory (table entries, 36 bits). sweep B=2 375346, B=8 748282; bsgs.negation 103364 baby steps; kangaroo 1562 distinguished points; rho.negation none; the pair-table incumbent 4194304. The counted unit does not see any of it. The small-base sweep needs several times BSGS's memory for a larger S, which is the sense in which BSGS dominates it.
  • Verdict. Not a genuine index calculus: its exponent is the generic one and the algebraic structure of the base contributes nothing measurable. It is a real, verified and cheap arm of the pipeline (the lowest S of any abscissa-base arm we have measured; the known-log bases are lower still and are collision searches by construction), but under the owner's rule that relabelling is not an improvement it does not go on the leaderboard; the owner decides.
