# Bounded line-FFT correctness qualification

Date: 2026-11-23. Parent task: isogeny-labs/crypto PR #5049.
Standing: producer-only local qualification, [pcc:unverified].

## Question

Does the binary line transform on the **full unfiltered** root set
`V_k = {X in F_p : D_(2^k)(X,1)=0}`, at `p=2147483647`, implement evaluation,
interpolation and multiplication in `F_p[X]/(D_(2^k))` exactly?

This is an established Circle-FFT specialization. It is not a proposed new
ECDLP complexity bound, a relation extractor, or an implementation on the
elliptic lift-filtered or pair-sum spectrum.

## Frozen inputs and checks

- `k=1,...,8`; root-set sizes 2 through 256.
- Four deterministic dense coefficient vectors per depth, generated by the
  explicitly coded xorshift64 generator and fixed seeds. Each vector has one
  coefficient for every basis element.
- Basis `b_i(X)=product_j D_(2^j)(X,1)^(bit_j(i))`, for `0<=i<2^k`.
- Production `dickson_abscissae`, field multiplication and field addition are
  copied byte-for-byte from the sibling `native/production.rs`. Its exact
  extraction is described in `production-source-manifest.json`; that manifest
  pins the full upstream source and source ranges at crypto revision
  `bd20b95dce44a91d7f74a1367853e724f280a3b6`.
- Check every output against an independent reference which expands each basis
  polynomial into monomials, uses `u128` modular arithmetic, and evaluates by
  Horner. The reference does not call the transform or its field helpers.
- Check all inverse roundtrips.
- For each of the four vectors, multiply it by the next vector cyclically.
  Compare transform multiplication with independent schoolbook polynomial
  multiplication followed by monic remainder modulo `D_(2^k)`.
- Check rejection by the reference of two deliberately wrong variants at
  `k=8`: one altered forward twiddle and one incorrect inverse normalization.

## Acceptance and bounds

All 32 forward cases, 32 inverse cases, 32 quotient products and both negative
controls must agree with their stated predicates. Any failure is retained and
reported; no tolerance is permitted. This checks no timing, resource crossover,
relation yield, useful rank, logarithm recovery, or complete index calculus.
The largest dense object is a univariate polynomial product of degree 510;
there are no multivariate tuple tables. Compile and run are each bounded by
60 seconds. No remote or paid execution is submitted.

## Exact transform

Write `f(X)=E(X^2-2)+X*O(X^2-2)`. Production ordering gives pairs `x,-x`
above `t=x^2-2`. Forward outputs are `E(t)+x O(t), E(t)-x O(t)`.
Inverse outputs are `(f(x)+f(-x))/2` and `(f(x)-f(-x))/(2x)`.
All twiddle inverses are precomputed and checked; `x` is nonzero on every
nontrivial level. This implementation uses the normalized inverse directly.

The coefficient basis is already the binary hierarchical basis; monomial
conversion is a reference check, not silently included in a fast-transform claim.
With precomputed twiddles this algebraic transform uses `O(B log B)` field
operations and `O(B)` live field-element storage for `B=2^k`. The recursive
proof-of-concept allocates temporary vectors and is not an optimized backend.

## Custody

`qualify.sh` writes the protocol/source SHA-256 manifest before compilation,
copies the inputs into a fresh attempt directory and compiles that immutable
copy. It retains compiler output, native output, exit codes and binary hash.
It refuses to overwrite an existing frozen attempt. This is local custody,
not independent signed PCC verification or full-root crate validation.
