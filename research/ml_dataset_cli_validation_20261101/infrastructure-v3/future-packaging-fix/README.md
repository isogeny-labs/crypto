# Future CLI export packaging correction (external draft)

The pinned checker37e193bf from_rows function takes rows, protocol, protocol path, export ID, metric mapping and optional file prefix. Its CLI exposes no arm commit/binary or analysis-script input. export_skeleton leaves these null; cmd_from_rows writes then validates. Therefore binding after a successful CLI exit is unreachable for this frozen contract. Changing row columns or a metric map cannot provide these fields.

The proposed driver calls the unchanged official from_rows function under the original pinned offline validator environment via a retained Runner command. Before final validation it binds arm commit/binary from the frozen protocol, requires equality to prepared source/binary, rejects conflicting existing values, and attaches the existing authenticated phase evidence and retained analysis script. The exact 46-case/92-observation rectangle and existing producer/replay evidence checks remain intact. The script digest must match both prepared driver and frozen analysis plan. Official protocol/export schemas and lint_export with file verification must pass before the final export is written exclusively. The null-metadata conversion is preserved separately as experiment.export.unbound.json. The existing separate CLI check-export remains as a second independent command check; conversion itself happens once and no invalid final export is temporarily published.

Failure diagnostics now inspect actual command argv entries, counting unsuccessful/unfinished dataset invocations as present. Missing or malformed argv makes absence unknown (null), never true. Non-dataset labels do not count. The original v1-v3 artifacts remain unchanged.

Five unit guard methods passed in the cached offline jsonschema4.26.0 environment. Tests cover instrument conflicts/duplicate arms/prepared mismatches; actual argv and unknown inventories; binding-before-validation, rejection without final publication and no overwrite; refusal of a failed attempt; and a synthetic92-row official conversion showing exactly five original metadata findings and zero after binding with file verification. The whole packaging test mocks phase evidence and the checker to assert sequencing; the separate official test uses synthetic rows and original protocol/code metadata only. No original dataset rows, generation, solver replay, prepare, freeze, cloud operations or source-worktree mutation occurred.

This is a future tooling draft, not an executable amendment. It retains the v3 admission logic as patch base: parent must create a new version and bind the changed driver hash throughout the future protocol before use. No retry of the failed v3 fixture is permitted. Existing generation parameters, budgets, timeout changes, case schedule, seed42 and scientific acceptance functions are unchanged. This patch does not revise historical failure statuses or accepted derived exports. The proposal does not claim Rust runtime or S3 validation.
