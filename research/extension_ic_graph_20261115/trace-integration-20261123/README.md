# Opt-in unit descent and checked trace integration

The Rust graph IC pipeline now exposes normalized five-variable reduction,
checked trace reuse on five coordinates, and an original-six-coordinate traced
control. Graph collection, sparse rank/kernel recovery and affine/elliptic checks
are preserved. Original APIs retain their original solver choices.

Entry points are reexported from src/cryptanalysis/jv_sieve_two_large_prime.rs:

- run_extension_fast_unit_deferred_pair_dlp_on(spec, seed, options, trace_reuse)
- run_extension_traced_deferred_pair_dlp_on(spec, seed, options)

The new example jv_sieve_fast_unit_deferred_compare adds methods
fast-unit-deferred-pairs, traced-unit-deferred-pairs and traced-six-deferred-pairs
beside existing IC, table, graph and four rho options. Dedicated worker calls
clear the process cache inside the cold interval and assign distinct arity scopes.
Callers of the opt-in library solver must manage their run scope; the low-level
solver does not clear a process-wide cache on every residual. Every fallback and
attempt remains recorded. Graph collection is unchanged by the coordinate change.

The memory-safe checker accepts one raw graph worker at a time:

```text
one-arm-checker WORKER.raw.json PUBLIC.json EXPECTED_40_HEX_SOURCE NEW_PROOF.json
```

It writes an exclusive-create proof with raw/public hashes, complete mathematical
replay and three comparison digests: full collection excluding only the original
rank inner-wall field; descent/affine geometry; non-descent primitive phases.
Comparisons must also require identical public input, source, seed and declared
options. A digest is not an independent signed verdict or complete-cost proof.
Six-coordinate failed attempts retain the public residual and solver flags;
the checker does not independently solve their whole root sets. The separate
captured full-cohort six-root replay covers only that exact saved cohort.
