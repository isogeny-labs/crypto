# Round 67: Jacobi prefilter for public polynomial discriminants (2026-11-20)

## Scope and code

Three production Rust paths in `src/cryptanalysis/prime_radical_root.rs`:
1. `RadicalRootCtx::quad_monic`, discriminant `b²-4c`.
2. `RadicalRootCtx::quad_roots`, discriminant `b²-4ac`.
3. `RadicalRootCtx::cubic_depressed`, Cardano discriminant `(q/2)²+(p/3)³`.

For canonical, nonzero discriminants, p >= 2^20 and prime p=3 mod 4, `sqrt_discriminant` computes the binary Jacobi character before a square-root exponentiation. Because p is prime, character -1 proves that no square root exists. Character +1 defers to the original, independently checked square-root implementation. Other primes and noncanonical inputs retain the old path. This is variable-time and is **not for secret-dependent operations**.

## Native Rust A/B: source-exact compiled Rust

The isolated benchmark script `round67_jacobi_isolated.py` compiles the current production Rust module twice with and without the new prefilter and the three call-site changes, and runs 13 alternating before/after trials with identical seeded workloads. Reported numbers are median nanoseconds per root-finding call, from the Ubuntu 24.04 GitHub Actions runner with Rust 1.100.0. Exact A/B root-output comparisons: **1,824 passed**, including monic/general quadratics and depressed cubics at p=7, 11, 31, 101, 1e9+7, and 2^61-1. The source's own round-67 regression test adds independent constructed-root and square-root comparisons.

The regression on guaranteed-root quadratics is **material and must not be hidden**: the extra Jacobi divisions are overhead on quadratic residues. The optimization is for rejection-heavy inputs; it is not a universal improvement. A further fast-path change should be conditioned on the expected root-hit distribution if profiling establishes one.

## Linux perf status

This local runner lacks the `perf` command. A direct `perf_event_open` syscall was attempted for software task-clock, hardware CPU cycles and instructions; **all three returned EACCES (errno 13)** with `perf_event_paranoid=2`. No PMU or `perf stat` performance claims are made. Local before/after numbers are CPU-pinned wall-clock measurements; actual compiled-Rust timings come from CI.

## Decision / next experiment

Retain as a specialized positive result for random/rejection-heavy quadratic extraction, but flag the known-root regression and avoid asserting an unconditional net improvement. Benchmark real polynomial distributions from ECC relation finding, including root yield and p mod 4, then decide whether to narrow or revert the Jacobi dispatch. Measure full root-extraction throughput, root candidates/sec and end-to-end index-calculus relations/sec. PR remains unmerged pending broader repository validation; unrelated historical-artifact recovery failures are not evidence about these arithmetic results.
