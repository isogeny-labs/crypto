# Round 118: narrow prime-field inverses and cached polynomial leading inverses

**Date:** 2026-11-22. **Status:** experimental / draft PR [#4909](https://github.com/isogeny-labs/crypto/pull/4909). **File:** `src/cryptanalysis/prime_radical_root.rs`. **Final source A/B:** [GitHub Actions #45061250981](https://github.com/isogeny-labs/crypto/actions/runs/45061250981).

## Changes retained

1. `Fp::inv`: use `u32` Euclidean quotient and remainder arithmetic for primes at most `u32::MAX`, preserving `i64` Bézout coefficients. Public inputs only; the existing 64-bit implementation is left intact for larger primes. The exact branch is selected after the existing unit and half-unit inverse shortcuts.
2. `RadicalRootCtx::inv_leading`: reuse the `inv2`, `inv3`, and `inv4` constants already computed per context for nonmonic cubic normalization and two nonmonic quartic normalization sites. All other leading coefficients use `Fp::inv`.

**Rejected/reverted:** fast `quad_roots` inverse dispatch for leading coefficients 2, 3, and 4; a source-exact random nonmonic quadratic control over p=4294967291 measured 0.9667x before the revert. The final branch uses its original quadratic inverse dispatch.

## Source-exact production Rust A/B

The two source-exact Rust harnesses reconstruct their frozen predecessors from the current production Rust module, compile baseline and candidate together at `rustc -C opt-level=3`, compare outputs, and run 13 alternating A/B trials on a pinned CPU. Test substitutions provide an intentionally unused Frobenius fallback (benchmark shapes never call it). These are **production arithmetic code paths**, not C++ performance projections.

### Narrow inverse only: random nonzero field inverses (ns/op)

| p | First run before | First run after | Speedup | Final run before | Final run after | Speedup |
|---|---:|---:|---:|---:|---:|---:|
| 65,521 | 20.088 | 19.208 | 1.046x | 22.831 | 20.725 | **1.102x** |
| 1,000,000,007 | 45.923 | 42.287 | 1.086x | 46.204 | 41.673 | **1.109x** |
| 4,294,967,291 | 45.857 | 43.309 | 1.059x | 53.718 | 45.898 | **1.170x** |

The same checksum-matched workloads also covered small and near-modulus inverses. A >32-bit control, p=2^61-1, was unchanged by this dispatch and showed large run-to-run noise; do not attribute its apparent timing changes to the optimization.

### Incremental cached small-leading inverses: complete structured roots

| Workload | First run speedup | Final run speedup |
|---|---:|---:|
| p=65,521, cubic with leading coefficient 3 | 1.026x | 1.008x |
| p=1,000,000,007, cubic with leading coefficient 3 | 1.014x | **1.024x** |
| p=4,294,967,291, cubic with leading coefficient 3 | 1.022x | **1.026x** |
| p=1,000,000,007, quartic with leading 3 and zero constant | 0.995x | 1.024x |
| p=4,294,967,291, quartic with leading 3 and zero constant | 1.003x | 1.031x |

Random nonmonic quadratic and cubic controls generally stayed close to parity but showed unstable tails: in the final cumulative inverse run, p=4,294,967,291 quadratic measured **0.967x**, and p=65,521 quadratic measured 0.986x. The final p=1,000,000,007 quadratic measured 1.080x, but a prior run was only 1.011x. **No consistently positive full-root speedup is established**.

Both harnesses completed **82,000 independent inversion comparisons** and **6,144 random polynomial-root comparisons** per execution; all source-exact test and checksum comparisons passed. Inversions also passed a `u128` modular multiplication oracle.

## Local Linux perf screening

Intel Xeon Platinum 8573C, GCC 14.2.0, pinned CPU 0, 17 alternating A/B trials, two separate local executions. Linux `perf_event_open` **software task-clock** counters measured the isolated C++ arithmetic reproductions. PMU hardware cycles, instructions, and cache-misses returned ENOENT; the `perf` command-line executable was not installed. These C++ results **are not Rust production timings**.

| Uniform random inversion | GCC run 1 before -> after ns | Speedup | GCC run 2 before -> after ns | Speedup |
|---|---:|---:|---:|---:|
| p=65,521 | 64.932 -> 48.975 | **1.326x** | 62.915 -> 48.302 | **1.303x** |
| p=1,000,000,007 | 114.385 -> 86.932 | **1.316x** | 115.310 -> 93.359 | **1.235x** |
| p=4,294,967,291 | 136.678 -> 102.729 | **1.331x** | 134.086 -> 103.949 | **1.290x** |

The local independent implementation passed 300,000 randomized inverse comparisons beyond the benchmarking corpus. Original and proposed functions were checked against `a * inv(a) mod p == 1`.

Additional candidates were **screened and rejected** rather than added to production:
- p=65,521 pseudo-Mersenne reduction `2^16 = 15 mod p`: local isolated multiplication 0.607x and complete quadratic control 0.843x.
- p=65,521 power-2047 addition chain: local complete quadratic control 0.931x, even though the isolated power reached 1.054x.
- Generic left-to-right top-bit exponentiation: local 2047-power control 0.745x, and 1e9+7 square-root exponent 0.786x.
- A fixed addition chain for p=1,000,000,007 sqrt exponent: 0.889x isolated C++ modular-power control.

## Merge gate

**Keep PR #4909 draft and unmerged.** Individual inverse operations are faster in source-exact Rust; structured small-leading cubics improve by about 1-3% in repeated tests, but the complete random-root results are not stable enough for an unconditional acceptance decision. Full repository validation and actual ECC2K binary-field relation throughput are still not established. These are prime-field radical root optimizations; no ECDLP relation-per-second speedup is claimed.
