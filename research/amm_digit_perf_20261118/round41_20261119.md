# Round 41: reject cached Barrett for rootfinding after compiled-Rust A/B

**Date:** 2026-11-19. **Status:** experiment completed, all production Barrett edits reverted.

## Hypothesis and implementation

The bounded producer (`Producer::mul`), its independently implemented certificate verifier (`Replay::times`), and the cubic/quartic radical field (`Fp::mul`) all have a canonical 32-bit prime multiplication path using `(a*b)%p`. We tested a cached reciprocal `m=floor(2^64/p)` and the exact one-correction reduction `q=floor(a*b*m/2^64)`, `r=a*b-q*p`, with a single conditional subtraction.

The arithmetic is correct for canonical `a,b<p<=2^32-1`: the approximate quotient is at most one below the exact quotient, and both the 64-bit product and `q*p` are in range. These changes did not alter the bounded producer's resource-charging calls, field work counts, or replay event formats.

Three code paths were implemented on this PR and compared to exact before-version source in isolated production Rust tests. The radical-field path was reverted first after a large native regression; the two bounded paths were subsequently reverted after native kernel and complete-solver measurements showed no meaningful gain. The implementation is available in the Git history if future compilers or hardware warrant re-screening.

## Conclusion

The C++ mirror suggested a plausible 19%–41% arithmetic-kernel gain, but a compiled-Rust A/B decisively rejected it for the radical engine and did not support a meaningful bounded-root throughput gain. The bounded engine's approximately 22 ns per field multiplication includes repeated `Instant::now` / hard deadline enforcement, dwarfing the few-nanosecond modulus operation.

**No production speedup is claimed for round41.** Reverting both implementation branches preserves round40's faster, tested code. Further improvements should target reducing the number of polynomial operations in dense degree-8 modular powering/splitting, rather than replacing a cheap modular reduction inside an expensive accounting loop. Always validate with complete solver and independent replay.
