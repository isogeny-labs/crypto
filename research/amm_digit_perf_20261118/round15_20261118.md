# Rootfinder optimization round 15 — 2026-11-18

## Changes committed on PR #4706

Production module `src/cryptanalysis/prime_radical_root.rs`:

1. A new `Ring::cube` hook delegates the Fp2 specialization to a four-Fp-product identity for `(a+b*i)^3`, instead of composing the six-Fp-product square and multiplication.
2. The three repeated cubing sites in `Cube::root` (residuosity, 3-adic digit extraction, and inverse-power update) use the specialized hook, accelerating the complete AMM cube-root kernel for fields with `v3(p²−1)>=3`.
3. The `p≡5 (mod 8)` square-root path now uses the one-exponentiation Atkin formula and the existing precomputed square root of `-1`, with square-verification for both roots and nonresidues.
4. A trial Fp2 norm specialization was **reverted** after actual Rust benchmarks showed severe regressions, down to **0.462x** at `p=17497`. Cardano inverse-scaling consolidation was screened locally but not committed.

## Profiling limitation and rejected candidates

The local `perf` executable is not installed; `perf_event_open(PERF_COUNT_SW_TASK_CLOCK)` returns `EACCES`, and modifying `kernel.perf_event_paranoid` fails with permission denied. Local results therefore use `steady_clock` wall-clock medians; no hardware cycles, instruction counts or CPU task-clock measurements are claimed.

Local correctness comparisons covered 1024 random Fp2 elements per prime, repeated cubings, and 512 residues plus 512 nonresidues per sqrt prime. GCC UBSan passed. Actual Rust production-module tests compare many more random Fp2 cubes, norms, square roots, and full AMM outputs against frozen previous implementations.
