# Round 59 (2026-11-20): unit-binomial coefficient folds

Production source: `src/cryptanalysis/prime_root_bounded.rs`, in PR #4706.

## Four optimized operations

For a **monic** modulus `m(x)=x^d+c` where `c=1` or `c=p-1`, coefficient cancellation uses `x^d=-c`. For each nonzero coefficient at index `high >= d`, fold it into index `high-d` with **one modular subtraction/addition**, then clear the high slot. This removes repeated zero-coefficient scans, multiplication by a unit, and trim calls from:

1. `Producer::division` (synthetic quotient and remainder);
2. `Producer::reduce_monic` (modular powers);
3. independent `Replay::remainder`;
4. independent `Replay::cancel_monic`.

The producer preserves per-nonzero cancellation gate charging; the independent verifier preserves its per-degree charging. Unsupported moduli fall through to existing algorithms. A wider `c != 0` fast path was rejected after actual-Rust screening showed ~0.95–1.03x/no reliable improvement for `c=17`.

## Local before/after validation

A separate C++ kernel reproduction was compiled with GCC and Clang `-O3 -march=native` and pinned to CPU 0 on Intel Xeon Platinum 8370C. Each of 13 alternating A/B trials executed 18,000 operations. **150,528** coefficient-exact checks passed across p=3,5,7,101,1e9+7,1e9+9,2^61-1; degrees 2..8; numerator lengths through 17; constants +1,-1,17 and random values. GCC UBSan passed.

These C++ results are independent arithmetic reproductions **not native production Rust**.

## Perf limitations

The local `perf` executable is absent. Direct `perf_event_open` attempts for task-clock, cycles, and instructions returned `EACCES (13)` under `kernel.perf_event_paranoid=2`. Consequently, local timings use `std::chrono::steady_clock`, **not hardware event counters**. No IPC, cache-miss or cycle-level attribution is claimed.
