# Round 51 (2026-11-19 PT): structured polynomial multiplication in bounded Fp rootfinding

## Change set

In `src/cryptanalysis/prime_root_bounded.rs`, the root producer now specializes two families of polynomial products:

1. **Scalar factors**: `1*f=f`; for any other nonzero constant, scale each coefficient directly without a redundant addition into zero.
2. **Monic linear factors**: `(x+c)f=x f+c f`, requiring only `n` scalar multiplications and `n-1` additions for an `n`-coefficient input. The `c=0` case is an exact coefficient shift with no field operations. These replace approximately `2n` multiplications and `2n` additions in the generic schoolbook product.
3. **Independent verifier**: `Replay::convolution` uses the same algebraic identities with a separate output-coefficient traversal and independently charged field operations. This avoids calling the producer for certificate verification.

The generic dense/sparse schoolbook paths remain unchanged. Existing budget, validation, and deadline checks remain active on every executed field operation, and the initial polynomial-operation work charge remains in place. Reduced `field_work` is expected and intentional. No constant-time or end-to-end ECDLP claim.

A randomized Rust wide-arithmetic reference test covers six primes from 3 through `2^61-1`, input sizes 2/4/8, both operand orders, `x`, `x+c`, and scalar factors. A native-Rust comparison harness uses exact production Rust source for both baseline (R51 markers removed) and candidate, compares complete root/event/certificate output, and records kernel plus end-to-end timings. See `round51_linear_products_isolated.py` and `.github/workflows/radical-root-arithmetic.yml`.

## Actual production Rust: successful isolated CI

[Passing GitHub Actions job (November 19 PT)](https://github.com/isogeny-labs/crypto/actions/runs/44647823987/job/135994948364). The job compiled the **actual production `prime_root_bounded.rs`** twice using Rust 1.100.0, with the R51 blocks removed in the baseline. It passed 63 direct polynomial and complete root/event/certificate comparisons across three primes. Thirteen alternating A/B trials were recorded for each kernel and complete solver plus independent replay.

At p=1,000,000,007 with eight input coefficients, the **native Rust producer** improved **2.011x** for multiplication by `x+37` (778.95 to 387.37 ns), and the **independent verifier** improved **2.344x** (1356.03 to 578.62 ns). Direct `x`-shift improved **10.077x producer / 24.729x verifier**; scalar `1` improved **12.301x / 23.172x**; constant `2` improved **1.815x / 1.896x**.

For the p=1,000,000,007 degree-8 complete run, producer charged field operations decreased from **20,929 to 20,834** and replay from **19,892 to 18,718**. Other control primes remained correct. Complete solver times are single-call per trial and should be interpreted as indicative, especially near 1.00x; results do not imply a measured relation-finding speedup.

**Validation status:** dedicated native Rust A/B CI passed. Repository-wide validation was not demonstrated by this isolated job; the broad `radical` job was canceled on this run. The in-file wide-reference Rust regression test is present but was not executed by the isolated script (which compiles the test-free production module); C++ equivalence and UBSan passed independently.

## Rejected candidate: deferred modular reduction

I also evaluated coefficient-wide lazy convolution (`u128` buckets) and dense square accumulation. Ungated C++ microkernels showed 1.5-2.6x dense-product gains; when modeling mandatory per-field deadline checks, a 7-coefficient product regressed to 0.93-0.98x, and 9-coefficient gains fell to 1.02-1.05x. **Not retained in Rust**: no compelling production advantage.

## Profiling constraint

The `perf` command is absent locally; a compiled `perf_event_open` probe returned `EACCES` for software task-clock and hardware cycles/instructions with `perf_event_paranoid=2`. Consequently no Linux perf counters were collected; only wall-clock timing. Do not misrepresent these as perf hardware-counter data.
