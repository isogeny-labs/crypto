# Round 120, 2026-11-22: p=5 (mod 8) discriminant Jacobi screening

**Implementation:** `src/cryptanalysis/prime_radical_root.rs` gates a binary Jacobi prefilter on canonical `p >= 2^20, p % 8 == 5` inputs for `sqrt_discriminant`. Nonresidues are rejected before modular powering; quadratic residues use the existing (p+3)/8 root exponent and conditional correction with the cached square root of -1. Standalone `sqrt()` and noncanonical inputs retain their previous path. Only public coefficients; variable-time.

**Native Rust status:** New workflow `.github/workflows/radical-root-round120.yml` and source-exact A/B harness `research/amm_digit_perf_20261118/round120_five_mod_eight_ab.py` are committed. No Round120 native Rust CI run was observed after the GitHub API commits; Rust correctness or speedup is **not yet confirmed**. A production regression test covers p=13, 101, 1,000,000,021, 4,294,967,197, and 2,305,843,009,213,693,693.

## Alternative candidates rejected in local screening

- Binary extended-GCD inverse (signed/unsigned correction): 0.44x–0.76x vs existing Euclid across fields p=65,521, 1e9+7, 2^32-5, 2^61-1.
- Compare the first p=5 mod8 candidate root's square to `-a` instead of performing a second square: uniform gains small/inconsistent, known-square regressions. Not applied.

**Decision:** PR #4909 stays **draft/unmerged**. The Jacobi prefilter is favorable on random coefficients but regresses guaranteed-square/known-root cases by as much as ~16%. Require native Rust source-exact validation and representative workload mix, or make the prefilter explicitly opt-in, before merging. No ECC2K relations/s improvement claimed.
