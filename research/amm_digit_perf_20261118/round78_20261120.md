# Round 78: trace polynomial division and monic linear roots

Date: 2026-11-20 (America/Los_Angeles). PR: [#4866](https://github.com/isogeny-labs/crypto/pull/4866), stacked on #4864.

## Production changes

Modified `src/cryptanalysis/prime_root_trace.rs`:
1. Monic `X^k` division is a coefficient split with the same independently verified Division event.
2. Degree-short dividends return a zero quotient and the input as remainder without long-division setup.
3. Monic linear factors `X+c` use one-pass synthetic division; zero quotient digits do not generate zero field operations.
4. Monic linear roots skip the unneeded `inv(1)` certificate event pair and the multiplication by one.

The independent verifier's arithmetic and complete-root certificate checks are unchanged. A source-level Rust regression test checks 128 producer division cases across four primes against independent `vdiv`, plus 12 full `solve -> verify` correctness cases. The test passed in the second full-source Rust workflow.

## Native production-source-exact Rust A/B

Passing [Rust 1.100.0 benchmark workflow](https://github.com/isogeny-labs/crypto/actions/runs/44862066405); optimized, 13 alternating A/B trials, medians (nanoseconds). The harness extracts the production polynomial methods and uses reduced standalone event plumbing, rather than compiling the full crate.

| Case at p=1,000,000,007 | Before ns | After ns | Speedup |
|---|---:|---:|---:|
| Division by X^4 | 128.605 | 105.046 | **1.224x** |
| Degree-short dividend | 95.954 | 72.921 | **1.316x** |
| Synthetic monic-linear division | 213.778 | 206.340 | **1.036x** |
| Monic linear-root extraction | 41.028 | 24.491 | **1.675x** |
| Dense general division control | 335.437 | 338.127 | **0.992x** |
| Sparse general division control | 229.878 | 234.535 | **0.980x** |

All 1,728 before/after Rust polynomial/root outputs matched. The monic linear-root case saved half the scalar field operations and removed two Inverse events.

A candidate fixed-degree generic division loop was rejected and reverted after native Rust results showed **0.906–0.956x** speedups (regressions) across several dense and sparse controls. Candidate monic polynomial multiplication and squaring were also rejected based on GCC/Clang regressions.

## Profiling limitation

The local Linux image lacks the `perf` executable. The direct `perf_event_open` syscall returned EACCES for task-clock, CPU cycles and instructions (`perf_event_paranoid=2`). Therefore reported timings use paired clock measurements, **not perf hardware counters**. Local raw CSVs, source, sanitizer and perf diagnostics are archived separately.

## Full-source-file solve + independent-verify A/B (two passing runs)

These **end-to-end root API measurements** compile the exact complete Rust producer and independent verifier source from Round77 and Round78 in isolated Cargo crates. Only the unrelated bounded module and field-primality admission check are stubbed for four known test primes. Each test processes eight constructed polynomials per case, with 13 alternating A/B trials and full output equality checks. This is **not** full-repository integration, nor index-calculus relations/sec.

- First passing run: [44862163754](https://github.com/isogeny-labs/crypto/actions/runs/44862163754).
- Second passing run: [44862380275](https://github.com/isogeny-labs/crypto/actions/runs/44862380275). Also passed the new production-source `round78_division_paths_match_independent_euclid_and_certify` Cargo test: 128 direct comparisons and twelve full `solve -> verify` regression cases.
