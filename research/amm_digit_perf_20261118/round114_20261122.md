# Round 114 (2026-11-22): prime-field radical root-finding optimizations

Code: [`prime_radical_root.rs`](https://github.com/isogeny-labs/crypto/blob/automation/radical-root-mersenne-sqrt-round114-20261122/src/cryptanalysis/prime_radical_root.rs) • [draft PR #4909](https://github.com/isogeny-labs/crypto/pull/4909).

## Three changes committed

1. `Fp::powm`: for `p=2^61-1` and square-root exponent `(p+1)/4=2^59`, use 59 modular squarings and skip the general binary-exponentiation loop. Other cases retain original behavior.
2. `RadicalRootCtx::sqrt_discriminant`: for canonical `p=2^61-1` elements bypass variable-time binary Jacobi and run the fast square-root power plus independent `r²=a` check. Noncanonical and other primes preserve the old path.
3. `Fp::inv`: use algebraic inverses for `1,-1,2,-2` instead of Euclid; preserve general inverse fallback, and zero behavior.

The public-input variable-time implementation must **not** be used for secret scalar operations.

## Production Rust A/B: successful source-exact benchmark

[Passing Round114 dedicated CI](https://github.com/isogeny-labs/crypto/actions/runs/45039748692) compiled Rust 1.100.0 with `rustc -C opt-level=3`, reconstructing baseline by removing exactly the three new code spans from the same production file, and ran 13 alternating A/B trials. Source-exact 5,072 root/arithmetic equivalence comparisons passed. All eight workload/checksum pairs matched.

| Workload (`p=2^61-1`) | Before ns | After ns | Speedup |
|---|---:|---:|---:|
| Mersenne square root, known squares | 5,256.541 | 5,078.361 | **1.035x** |
| Mersenne square root, uniform canonical | 5,136.805 | 5,085.523 | **1.010x** |
| Isolated square-root exponent | 246.019 | 247.234 | **0.995x** |
| Isolated special-constant inverse | 8.378 | 4.401 | **1.904x** |
| Isolated general inverse | 168.291 | 163.207 | 1.031x |
| Complete monic quadratic root, known roots | 5,292.043 | 5,138.352 | **1.030x** |
| Complete monic quadratic root, uniform | 5,147.013 | 5,122.985 | **1.005x** |
| Complete depressed cubic root, uniform | 6,779.026 | 6,661.273 | **1.018x** |

**Interpretation:** The full-root results are ~0.5–3.5% improvements, much smaller than isolated inversion gains. The isolated square-root exponent was slightly slower (0.995x), so do not claim it provides a standalone speedup. Root timings include construction of the radical context for each call in the benchmark; a warm-context benchmark could differ. All results are from a single dedicated Rust run and should be replicated.

## Local `perf_event_open` screening (C++ reproductions, NOT Rust)

Intel Xeon Platinum 8573C pinned to CPU 0; GCC 14.2 and Clang 17, `-O3 -march=native`, 15 alternating A/B trials; median **software task-clock** ns/op via Linux `perf_event_open`. The `perf` CLI was absent; hardware PMU events returned `ENOENT` and were not measured. The figures are independent **C++ algorithmic reproductions**, not source-exact Rust results.

Local C++ equivalence tests passed 1,800,000 power comparisons, 602,010 discriminant comparisons and 150,000 inversions per compiler. All 38 local workload/compiler checksum comparisons matched. The C++ results cannot replace the native Rust results above.

## Investigated and rejected

- Dense Mersenne column convolution for quartic/octic powers: promising GCC product-only improvements up to 1.446x, but Clang width-eight product regressed to 0.897x and complete dense degree-eight modular power stayed near 0.99x. **Not committed**.
- Specialized polynomial high-degree remainder path: large GCC regression (~0.5x) in complete dense degree-eight modular-power reproduction. **Not committed**.
