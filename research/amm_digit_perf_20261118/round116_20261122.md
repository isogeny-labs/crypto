# Round 116 (2026-11-22): canonical root-coefficient normalization

Implemented in `src/cryptanalysis/prime_radical_root.rs` on draft PR #4909. Reuse the reduced leading polynomial coefficient already computed while trimming zero padding, and bypass modulus division for canonical words. Noncanonical inputs remain supported and the degree/zero-polynomial error handling is unchanged.

## Final source-exact production Rust A/B

**Passed on November 22, 2026:** [Round116 native Rust run](https://github.com/isogeny-labs/crypto/actions/runs/45050592948), Rust 1.100.0 optimized release, CPU-pinned, **13 alternating A/B trials**, medians in ns/op. The harness reconstructs the frozen pre-round116 source from the current Rust module and compiles both together. **24,728 randomized before/after equivalence comparisons passed, with matching nondegenerate checksums on every measured workload.**

**Ablations and rejections:** The ungated normalization measured 0.933x on 1e9+7 linear roots; an attempted direct monic-linear shortcut measured 0.858x. Both were rejected. The final code uses the original normalization for inputs of length at most two and the canonical fast normalization for larger polynomials. That dispatch measured 1.175x on 1e9+7 linear roots, 1.101x on quadratics, and only a 0.5% worst visible regression on the 2^61-1 cubic control. The earlier local C++ end-to-end analogue above did not model this final Rust dispatch and does not supersede these native results.

The independent source regression test is in `src/cryptanalysis/prime_radical_root.rs`; the dedicated exact harness is `research/amm_digit_perf_20261118/round116_normalization_ab.py` with workflow `.github/workflows/radical-root-round116.yml`. The local runtime lacked rustc/cargo, so Linux task-clock profiling used C++ reproductions, while the source-exact Rust measurements ran in GitHub Actions.

**Decision:** Keep PR #4909 draft/unmerged pending full repository validation, repeated native Rust performance on another runner, and actual index-calculus relations per second. This is a prime-field radical root finder, not the ECC2K binary-field relation pipeline; no ECC2K end-to-end speedup is claimed.

## Replication and broader CI update

A second independent CPU-pinned native Rust run also **passed**: [Round116 replication](https://github.com/isogeny-labs/crypto/actions/runs/45050685168), with another 24,728 equality checks and 15 matching workload checksums.

The **quadratic speedups reproduced**: p=65,521 **1.0297x**, p=1e9+7 **1.0753x**, and p=2^61-1 **1.0270x**. The **linear speedups did not reproduce** on the second run (0.9866x, 0.9896x and 0.9936x, respectively), so the initial 1.175x linear peak is not a stable performance claim. The cubic and padded cubic results also varied around 1.0x.

[Broader radical-root correctness workflow](https://github.com/isogeny-labs/crypto/actions/runs/45050685311) was **not fully green**: the older round46 bounded-quadratic job failed to compile its frozen baseline (missing `split_scalar_pow` and `split_character_power` methods), while the older round42 Mersenne-chain job failed an expected operation-count assertion. These are distinct legacy workflow jobs, not evidence of wrong roots in the round116 exact A/B, but the broader validation gate remains uncleared. The dedicated Round116 source-exact and workflow-syntax jobs passed.

**Acceptance remains blocked**: retain draft status, avoid merge, and validate the 1.03–1.08x replicated quadratic improvement against end-to-end prime-field root finding and real relation throughput.
