# Round 116 (2026-11-22): canonical root-coefficient normalization

Implemented in `src/cryptanalysis/prime_radical_root.rs` on draft PR #4909. Reuse the reduced leading polynomial coefficient already computed while trimming zero padding, and bypass modulus division for canonical words. Noncanonical inputs remain supported and the degree/zero-polynomial error handling is unchanged.

## Local Linux performance-counter measurements

**Hardware:** pinned Intel Xeon Platinum 8573C, Linux `perf_event_open` software task-clock, GCC 14.2 and Clang 17 (`-O3 -march=native`). Hardware cycles, instructions, cache misses returned ENOENT; the `perf` CLI was unavailable. **All local timings are C++ algorithmic reproductions, not production Rust.** Isolated normalization uses 17 alternating A/B trials. The full linear/quadratic root dispatch analogue uses 15 alternating trials.

| Isolated coefficient normalization | GCC before/after (ns) | GCC speedup | Clang before/after (ns) | Clang speedup |
|---|---:|---:|---:|---:|
| p=65,521 canonical degree 4 | 25.88 / 7.38 | **3.51x** | 14.33 / 6.66 | **2.15x** |
| p=1e9+7 canonical degree 4 | 25.43 / 8.24 | **3.09x** | 15.60 / 7.84 | **1.99x** |
| p=2^61-1 canonical degree 4 | 23.04 / 8.71 | **2.64x** | 24.94 / 7.26 | **3.43x** |
| p=1e9+7 padded length 8 | 36.46 / 13.85 | **2.63x** | 22.11 / 14.96 | **1.48x** |

## Validation and acceptance

Added a Rust independent modulo-reference normalization regression test across six primes and a source-exact native Rust A/B runner at `research/amm_digit_perf_20261118/round116_normalization_ab.py`, wired into `.github/workflows/radical-root-round116.yml`. It compiles frozen pre-change versus exact candidate modules with the same rustc and times full linear, quadratic, cubic, padded and noncanonical workloads in 13 alternating trials.

**Native Rust validation has not completed:** no associated PR-triggered run was reported after GitHub connector writes. The local runtime does not have rustc or cargo, and external package installation was unavailable. Hence no source-exact Rust speedup is claimed. The substantial isolated C++ gains are not sufficient to clear mixed end-to-end control results.

**Decision: keep PR #4909 draft/unmerged** pending native Rust A/B, full repository tests, consistent whole-root improvement, and end-to-end cryptanalytic throughput. This is prime-field radical root code; ECC2K binary-field relations/sec were not measured.
