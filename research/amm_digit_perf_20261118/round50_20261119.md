# Round 50: quadratic modular halving and Vieta root reconstruction (2026-11-19)

Four operations in `src/cryptanalysis/prime_root_bounded.rs` are optimized in the producer and independent certificate verifier:

1. Compute the first root with parity-based modular halving, instead of multiplying its numerator by the inverse of 2.
2. Recover the second root from `r0 + r1 = -b` (Vieta's identity), avoiding its extra numerator and modular multiplication.
3. Implement the independent verifier's halving with a separate parity branch.
4. Reconstruct its second root using Vieta, while still checking both roots by direct polynomial substitution.

The odd-prime, canonical-residue and <=2^61-1 field constraints are preserved. Each non-field halving charges work/deadline but does not falsely charge a field operation. The code is variable-time.

## Local screening, rejected candidates, and perf limitation

CPU-pinned AMD EPYC 9V74, GCC and Clang C++ arithmetic reproductions, 13 alternating trials: GCC saw 3.9–4.9x faster isolated quadratic root finishing, but Clang **regressed to 0.40–0.47x**. These are compiler-sensitive C++ kernel measurements, **not Rust production speedups**.

A subtraction-based Jacobi alternative was rejected after 262,144 correctness comparisons: p=1e9+7 GCC 72.85→130.10 ns (0.56x), Clang 79.54→143.69 ns (0.55x). A width-three scalar exponentiation candidate was also rejected for inconsistent compiler results. The local UBSan tests passed for both programs.

The local `perf` executable was unavailable. Direct `perf_event_open` task-clock, hardware cycles, and instructions all returned `EACCES` under `perf_event_paranoid=2`; therefore only wall-clock measurements were collected locally, **not perf counters**.

No measured improvement to index-calculus relations/s, ECDLP throughput, or general degree-eight root-finding is claimed. Repository-wide CI still suffers an unrelated missing historical artifact (`research/weak_curve_properties_lean_20261011/root_lib.stdout`).
