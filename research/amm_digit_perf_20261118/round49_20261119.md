# Round 49: binary-Jacobi quadratic-character optimization (2026-11-19)

Four production code paths in `src/cryptanalysis/prime_root_bounded.rs` were optimized: producer quadratic Frobenius discriminant, producer quadratic-split character checks, independent certificate-replay quadratic Frobenius discriminant and replay quadratic-split character checks. These use a charged binary Jacobi symbol instead of modular exponentiation for the **quadratic character**, not for computing square roots. Every Jacobi iteration checks the deadline/work budget. The method is variable-time, not suitable for secret-dependent constant-time cryptography.

## Local profiling

CPU-pinned C++ arithmetic reproductions (4096 values, repeated 12 times per trial, 13 A/B pairs) passed **40,960** reference comparisons per compiler and GCC UBSan. Fastest binary-Jacobi version, median ns/op for p=1e9+9:
- GCC 14.2: 128.36 to 86.76 ns (**1.480x**).
- Clang 17: 145.80 to 72.04 ns (**2.024x**).
For p=2^61−1: GCC 223.10 to 174.42 ns (**1.279x**); Clang 272.87 to 164.83 ns (**1.655x**).

These standalone C++ arithmetic figures are **not production-Rust speedups**. The compiled Rust A/B results above are the basis for judging retention.

`perf` was unavailable locally. Direct `perf_event_open` returned `EACCES` for software task-clock, hardware cycles and instructions (`perf_event_paranoid=2`). Local measurements therefore used CPU-pinned clock timings, not PMU counters. CI native Rust was not hardware-`perf` profiled.

Index-calculus relation-generation throughput remains unmeasured. Keep the PR unmerged until broader repository validation and integration checks are resolved.
