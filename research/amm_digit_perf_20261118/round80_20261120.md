# Round 80: eliminate redundant identity arithmetic in root extraction (2026-11-20 PT)

## Scope and implementation

Base: Round79 commit `90035259af3e8a3ea37ebf8396d5bdad86ec5c22`. Source: `src/cryptanalysis/prime_root_trace.rs`. Draft PR: [#4870](https://github.com/isogeny-labs/crypto/pull/4870).

Optimized five pathways, while retaining the independently checked certificate schema:

1. **Producer Fermat inverse:** since `p-2` is odd for odd prime `p`, consume the first exponent bit directly and start with `acc=value`; no `1*value` field operation. Hoisting avoids a branch inside the remaining exponentiation loop, including the p=3 edge.
2. **Producer polynomial-power setup:** short degree inputs are already reduced, and the residue of one is one for positive-degree divisors. Avoid corresponding division allocations/events.
3. **Producer polynomial powering:** with accumulator one, the first multiply-and-reduce returns the already-reduced base; avoid redundant Product/Division events.
4. **Independent verifier:** use the same *algebraic identities* but retain separate verifier arithmetic in `vpower` and `PowerStep` replay.
5. **Linear-root extraction:** monic linear polynomials need only `0-h[0]`; the nonmonic path still performs inverse and multiplication.

No certificate bytes were assumed to be trusted without replay; the verifier recomputes the modular-power relation from each state. Legacy Round79 terminal-step compatibility remains tested. Counter changes reflect fewer executed operations; historical event counts are not expected to be identical.

**Longer CPU-pinned source-exact validation (preferred stress screen):** [run #44871205490](https://github.com/isogeny-labs/crypto/actions/runs/44871205490). | --- | ---: | ---: | ---: |

The 61-bit quadratic workload regressed ~1.4% in the longer controlled run despite positive 8-case results. **Do not infer a universal solver speedup or merge yet.** Per-host timing drift still exists even with CPU affinity. Additional ablation or representative field-workload measurement is required to decide whether the change is a worthwhile default in the 61-bit quadratic path.

The earlier **pre-hoist** candidate passed source-exact CI as well ([run](https://github.com/isogeny-labs/crypto/actions/runs/44870700502)), but its p=1e9+7 linear case regressed 0.972x. Replacing the per-iteration inverse identity branch with a single hoisted first exponent bit removed that regression in the follow-up run. This is a separate code revision, not a repeat measurement of the final source.

Each native run matched **117 before/after workload trial rows × 8 polynomial inputs**, with strict root-set correctness, independent verifier pass and new tests. The follow-up source includes tests for work budgets and failed sinks; subsequent test-only edits add smallest-prime p=3/5/7/11 coverage.

## Local CPU-pinned measurements

Local host: Intel Xeon Platinum 8573C, GCC and Clang, `-O3 -march=native`, 13 alternating paired C++ kernel-reproduction timing trials. Equivalent polynomial powers were checked across 200 exponents × 9 p/degree configurations; inverse checks covered 400 scalars × 3 primes; GCC UBSan passed. These reproduce selected arithmetic identities but omit the Rust trace events, sink, allocations and verifier. Results vary by field/degree, with both wins and regressions; **do not substitute these kernel timings for the native Rust full-solver table**. Full raw CSV and C++ code are in the accompanying local benchmark archive.

`perf` could not run locally: no installed `perf` executable and `perf_event_open` returned `EACCES` for task-clock, cycles and instructions (kernel `perf_event_paranoid=2`). C++ timings use steady_clock, not hardware counters.
