# Round 65: unit-binomial and affine-linear Frobenius (2026-11-20)

## Production changes

[PR #4706](https://github.com/isogeny-labs/crypto/pull/4706) modifies four independently metered paths in src/cryptanalysis/prime_root_bounded.rs.

1. Producer Frobenius powering for monic x^d+c, c=+1 or -1.
2. Independent certificate-verifier Frobenius powering for the same unit-binomial moduli.
3. Producer Frobenius powering for any affine x+delta modulo monic x+c, rather than only x.
4. Independent verifier Frobenius for the same affine-linear inputs.

The identities are exact over Fp:

- (x+delta)^p mod (x+c) = delta-c.
- x^p mod (x^d+c) = (-c)^floor(p/d) * x^(p mod d).

For c=-1 the scalar power is 1. For c=1 its value is (-1)^floor(p/d), determined by parity. General c not in {+1,-1} uses the original scalar exponentiation. Both code paths normalize nonmonic input divisors first. Public-input rootfinding only; no constant-time claim.

## Compiled production Rust before/after

[Dedicated successful native Rust CI job](https://github.com/isogeny-labs/crypto/actions/runs/44755399608/job/136353705697), Rust 1.100.0, optimized build. It passed **1,344 exact kernel-output comparisons** and **36 complete root/event/certificate-stream comparisons** across small and large primes, unit and nonunit coefficients, and monic and nonmonic divisors. ## Local compiler comparison and perf limitation

Local AMD EPYC 9V74, CPU pinned, GCC and Clang at -O3 -march=native; 13 alternating trials per workload. The C++ arithmetic mirrors passed 81,200 comparisons and GCC UBSan. They are **not compiled Rust**; the affine-linear old mirror is only a scalar lower bound on actual Rust polynomial exponentiation, so the mirror speedups must not be represented as production results.

The local Linux perf executable is absent and direct perf_event_open probes returned **EACCES** for software task-clock, CPU cycles and instructions. perf_event_paranoid=2; sandbox lacks CAP_PERFMON and the sysctl is read-only. Accordingly **no PMU hardware counters were collected**; local measurements are from steady_clock. Real perf stat and perf record require a PMU-enabled host.

## Interpretation and status

These improvements apply to precisely restricted polynomial shapes, not generic dense root finding. The complete native Rust root-extraction/certificate speedups are demonstrated on twelve workloads (including nonunit controls), but index-calculus relations per second remains unmeasured.

Code, regression tests, source-exact Rust A/B harness, workflow and this report are committed on PR #4706. The dedicated CI job passed; the PR remains open awaiting broader repository validation, including unrelated historical-artifact recovery failures.
