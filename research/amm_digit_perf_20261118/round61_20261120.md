# Round 61: missing-linear-coefficient products and scalar power (2026-11-20)

## Code changes

Four production Rust paths in `src/cryptanalysis/prime_root_bounded.rs`:

1. **Producer::product**: detect the frequent even/sparse shape where the constant term is nonzero but the linear coefficient is zero. Select the existing zero-eliding row-major kernel instead of charging finite-field multiplication for zero terms.
2. **Replay::convolution**: independently detect the same shape in output-diagonal certificate convolution; retain verifier-specific traversal.
3. **Producer::split_scalar_pow**: do not multiply the first selected power by identity in low-to-high square-and-multiply (retain an explicit deadline-accounted exponent-one path).
4. **Replay::split_character_power**: initialize from the leading exponent bit, avoiding a square and multiply of identity. A single-bit exponent still checks the deadline.

No dynamic allocation, change in modulus mathematics, or removal of the bounded gate. Scalar operations saved through zero-elision are no longer charged as field work; per-operation deadlines remain checked for arithmetic that is actually performed. This is public-input, variable-time code and makes no constant-time claim.

## Local profiling and perf limitation

AMD EPYC 9V74, GCC 14.2 / Clang 17, `-O3 -march=native`, pinned CPU 0, 13 alternating A/B trials. Local C++ reproductions include a wall-clock read in each field operation to approximate deadline-check overhead; they do **not** include the production Rust work meter or its exact control flow. For missing-linear-coefficient sparse products the mirror measured ~2.96x (GCC) and ~3.0x (Clang) producer improvements and ~2.9x verifier improvements. Local dense controls were mostly near 1x. The mirror screened an additional `Replay::cancel_monic` zero-factor shortcut; its mixed ~0.95x–1.05x results did **not** justify committing it.

We attempted `perf`. The local `perf` CLI is absent. Direct `perf_event_open` probes for software task-clock and hardware cycles/instructions all returned **EACCES (13)** under `kernel.perf_event_paranoid=2`; thus there are **no hardware perf counters** to report. CPU-pinned wall-clock timings are reported instead. Full raw mirror source, GCC/Clang per-trial aggregate CSV, Linux perf diagnostics and command outputs are provided in the conversation artifact `rootfind-round61-20261120.zip`.

## Follow-up

Sample polynomial shapes and **actual relation-generation calls** to learn the fraction taking these four paths. The overall root-finder and index-calculus relations/second have not improved measurably here. Retain the sparse dispatch only if its frequency offsets the ~1.5% dense producer overhead. PR #4706 remains open; dedicated Rust CI passed, but repository-wide validation is tracked separately.
