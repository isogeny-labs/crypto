# Round 68: verified Jacobi-positive roots and first-window powering (2026-11-20)

## Implementation

Two changes are committed in `src/cryptanalysis/prime_radical_root.rs`:

1. **Jacobi-positive square root:** `sqrt_discriminant`, used by monic quadratics, general quadratics and Cardano discriminants, now returns (a^{(p+1)/4}) immediately after a Jacobi +1 when (p\equiv3\pmod4) and `a` is canonical and nonzero. For prime `p`, Jacobi +1 is a certificate that (a^{(p-1)/2}=1), so the previous verification square was redundant. All other inputs keep the existing `sqrt` path. Variable-time, public inputs only.
2. **Leading window initialization:** generic `rpow` sliding-window exponentiation initializes its accumulator directly from the most-significant odd-power table entry. This omits up to four squarings of one and one multiplication by one. The original binary path for sparse/short exponents remains unchanged.

No change to root ordering or API. A production Rust test compares new Fp and Fp2 window-power results against independent binary powers over six primes.

## Local profiling and negative controls

An AMD EPYC 9V74 was CPU-pinned. GCC 14.2 and Clang 17 compiled independent C++ arithmetic reproductions with `-O3 -march=native`, benchmarked using 13 alternating before/after trials and `steady_clock`. These are not compiled Rust timing results:

- Dense 128-bit Fp2 exponent, p=1e9+7: GCC **1.027x**, Clang **1.062x**.
- Dense 128-bit Fp2 exponent, p=2^61-1: GCC **1.025x**, Clang **1.062x**.
- A p=5 (mod 8) square-root shortcut was **rejected**: random input GCC **0.887x**, Clang **0.971x**.
- A Mersenne 2^59 squaring shortcut was **rejected** after GCC **0.866x** despite Clang **1.060x** on random inputs.
- A polynomial input-canonicality shortcut was **rejected** after noncanonical input regressions to **0.78x-0.85x**.
- A division-free binary Jacobi variant was **rejected** after inconsistent results across compiler/prime/mix.
- Extending the Fp2 exponent change to all binary exponents was **rejected**; the committed production patch optimizes the sliding-window branch only.

GCC UBSan passed the selected C++ mirrors. The local `perf` executable was absent; direct `perf_event_open` for task-clock, CPU cycles and instructions returned `EACCES` (kernel perf_event_paranoid=2). **No PMU measurements were obtained**. Local speedups are clock timings, not hardware-counter claims.
