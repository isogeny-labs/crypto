# Round 72: imaginary Fp² multiplication

Date: 2026-11-20

## Change and proof

In `src/cryptanalysis/prime_radical_root.rs`, three new guarded subcases of `Fq2::mul` exploit coefficients known to be zero:
- `(bi)(c+di)=(nbd)+(bc)i`, two base-field products instead of three.
- `(a+bi)(di)=(nbd)+(ad)i`, two products.
- `(bi)(di)=nbd`, one product.

The existing real-scalar and generic dense multiplication formulas are preserved. A shared `x.0==0 || y.0==0` guard runs even for generic inputs; this is an important potential regression.

The complete-cubic tests regressed by roughly 2.1% and 1.6%. This single run is too little evidence to identify a reproducible end-to-end regression, but certainly **does not establish an improvement**. Sparse multiplication may be rare in cubic workloads.

## Local C++ reproduction and perf limits

CPU-pinned GCC 14.2 / Clang 17, AMD EPYC 9V74, `-O3 -march=native`, 13 alternating before/after trials. At p=2^61-1 the imaginary-left, imaginary-right, both-imaginary cases measured 1.705x / 1.578x / 2.179x with GCC and 1.379x / 1.401x / 1.655x with Clang. These are *C++ arithmetic reproductions*, not production Rust; 10,752 coefficient-pair comparisons were exact per compiler, and GCC UBSan passed.

Local Linux `perf` was absent; `perf_event_open` returned EACCES for task-clock, cycles, and instructions (perf_event_paranoid=2). Local numbers are wall-clock timings, not PMU counters.

## Decision

**Keep PR #4854 draft and unmerged.** Only isolate or enable imaginary specialization once instrumentation shows enough imaginary multiplication frequency to offset the guard on dense/real cases. Before promotion, rerun complete cubic and representative index-calculus relations/sec multiple times with profiling on a host permitted to run `perf`. Rejected for now as a global performance improvement despite faster rare-case arithmetic.
