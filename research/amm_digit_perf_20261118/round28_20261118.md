# Round 28: scalar polynomial operations and trinomial squaring

Date: 2026-11-18 (America/Los_Angeles). Changes in `src/cryptanalysis/prime_root_trace.rs`.

## Changes

1. `vproduct`: specialize multiplication with any constant polynomial, including zero and one, using a single coefficient pass.
2. `vsquare`: recognize three-term sparse polynomials and compute their square using six field multiplications. Modular accumulation handles overlapping diagonal/cross terms, e.g. positions (0,3,6).
3. `vdiv`: division by a degree-zero non-unit uses one inversion and coefficient scaling rather than generic long division.

## Local before/after measurements

Pinned AMD EPYC 9V74 CPU 0, GCC 14.2 / Clang 17, `-O3`, median of 13 interleaved AB/BA trials, 128 cases, nanoseconds per operation. These are **standalone C++ reproductions, not compiled production Rust**.

Local GCC/Clang reproductions passed 16,128 exact comparisons over seven primes; GCC UBSan passed. `perf` was absent and `perf_event_open(PERF_COUNT_SW_TASK_CLOCK)` returned EACCES (13). Results therefore use pinned wall-clock timing, **not hardware counters or perf task-clock**.

The native-Rust benchmark and frozen-reference equivalence harness live in `round28_verifier_isolated.py`, run through `radical-root-arithmetic.yml`. **Do not infer whole-rootfinder or index-calculus relation speedups from these microbenchmarks.** The four-term dense-square control showed a 4–5% C++ regression and needs native-Rust regression screening.
