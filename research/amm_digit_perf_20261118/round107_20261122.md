# Round 107: P61 traced inverse addition chain and constant inverses

Date: 2026-11-22 UTC. Draft PR [#4880](https://github.com/isogeny-labs/crypto/pull/4880).
Source: `src/cryptanalysis/prime_root_trace.rs`. Frozen before-Round107 baseline: `1561ce05a62418906b6a10dfd7523738c9304cc5`.

## Production code changes

1. **Traced P61 inverse addition chain.** Since `p-2=2^61-3=4(2^59-1)+1`, build exponents `2^k-1` for k=2,4,8,16,32,48,56,58,59, then append two squares and a multiplication. This computes a nontrivial inverse with **60 squares + 10 multiplications** instead of 60 squares + 60 multiplications. All 70 operations still emit field events, honor the work/event caps and are independently checked.
2. **Constant inverse shortcuts.** For every supported odd prime, return exact `inv(1)=1`, `inv(2)=(p+1)/2`, `inv(-1)=p-1` and `inv(-2)=(p-1)/2` without field operations. Preserve inverse begin/end events; verifier independently checks the inverse identity.
3. **Native Rust regression tests added.** 1,031 deterministic P61 residue checks against the pre-existing independent `vpow` reference, exact field-op counts, and end-to-end prime-field roots/certificate replay for quadratic and linear polynomials over four prime fields.

## Local Linux perf measurement

CPU-pinned (AMD EPYC 9V74, logical CPU 0), GCC 14.2 / Clang 17, `-O3 -march=native`, 15 alternating A/B trials each configuration. Direct `perf_event_open` returned Linux **software task-clock**; hardware cycle/instruction counters returned ENOENT. `perf` CLI was unavailable.

| C++ reproduction | Before ns/inv | After ns/inv | Speedup |
|---|---:|---:|---:|
| GCC arithmetic only | 218.5 | 176.3 | **1.240×** |
| GCC traced-operation vector | 933.0 | 539.3 | **1.730×** |
| Clang arithmetic only | 214.7 | 187.8 | **1.143×** |
| Clang traced-operation vector | 300.0 | 248.5 | **1.207×** |

These are **local C++ reproductions, not source-exact Rust measurements**. A separate small-constant C++ reproduction measured 99–361× isolated gains, but that fast path omits Rust event construction/sink overhead and therefore must not be interpreted as whole-root-finding throughput. The traced reproduction records each field event to a vector and consumes the event contents to prevent dead-store elimination; its event sink is not identical to Rust. Each compiler passed 100,007 reference-inverse checks and multiplicative identities; GCC UBSan passed.

## Native Rust acceptance status

The dedicated source-exact A/B harness `round107_full_ab.py` and workflow `rootfind-round107-inverse.yml` were created on the draft branch. The harness compares complete solver results and exact inverse values against the frozen Round106 source; it does not demand identical trace-operation counts, which legitimately change. **Round107 source-exact Rust A/B passed** on the active workflow after adding `#[inline(never)]` to `Engine::inv` to reduce codegen overlap. The 34 tests passed (one ignored), and 702 paired A/B result checksums matched. Separate monic modular-power regressions remain; see the measured table below. Older historical A/B workflows that checksum full event/counter streams may fail under intentional trace changes.

**Hold PR #4880 as draft and unmerged** until repeated monic-workload regressions, broader CI, and real relation-generation throughput are resolved. This prime-field trace optimization has **not** been measured for ECC2K index-calculus relations/second.
