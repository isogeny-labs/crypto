# Round 63: Synthetic linear division and Horner remainder (November 20, 2026)

## Production Rust changes

In `src/cryptanalysis/prime_root_bounded.rs`, optimize four independent
code paths for monic `x+c` with `c != 0, +1, -1`. Existing shortcuts for
`x`, `x+1` and `x-1` remain unchanged.

1. **Producer division:** directly construct synthetic quotient and remainder
   without modifying and repeatedly trimming a copy of the dividend.
2. **Producer reduction:** Horner evaluate at `-c`.
3. **Independent replay remainder:** fixed-index Horner calculation without
   mutating the numerator polynomial.
4. **Independent replay modular cancellation:** independent Horner calculation
   preserving replay's original per-degree field operation count, including
   zero-high-coefficient cases.

Algebraic identity: `f(x)=(x+c)*q(x)+f(-c)`. Producer paths charge only
nonzero high cancellations as before; replay remainder preserves fixed degree
checks and skips multiplications at zero accumulator; replay cancellation
retains one multiplication/subtraction per degree. All paths remain bounded,
public-input, and variable-time.

## Local GCC/Clang reproduction and perf attempt

Intel Xeon Platinum 8573C, CPU-pinned, 13 alternating A/B trials,
24,000 repetitions per timed trial. The local code is a smaller **C++ arithmetic
reproduction**, not a compiled production Rust benchmark. It is included with
all 48 GCC and 48 Clang result rows, deterministic equivalence tests, and
UBSan diagnostics in the round-63 local archive.

For degree-8 dense 1e9+7 under GCC -O3, the arithmetic mirror improves:
division **1.56x**, reduction **1.64x**, verifier remainder **1.59x** and
verifier cancellation **2.90x**. Clang confirms positive improvements;
magnitudes are not transferable to the Rust implementation, which spends
substantial time on per-field-work deadline checks.

The installed environment lacks the `perf` CLI, and direct
`perf_event_open` returned **EACCES** for software task-clock, hardware
cycles and instructions even as UID 0. No PMU measurements are available.
The local results are CPU-pinned wall-clock timings; Rust CI timings use
`Instant` and `black_box`. Do not label either as hardware perf counters.

## Interpretation and next steps

This is a bounded, correctness-preserving kernel-level improvement, **not**
a verified improvement in full solver throughput or index-calculus
relations/sec. Profile the actual relation-generator call distribution
before further specializing rare polynomial shapes. Host PMU access or a
self-hosted perf-enabled runner is necessary for instruction/cycle studies.
