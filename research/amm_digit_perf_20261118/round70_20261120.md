# Round 70 · Fp2 Frobenius powers (2026-11-20)

## Production changes
In `src/cryptanalysis/prime_radical_root.rs`, for canonical nonzero dense `x=a+bi` over the quadratic nonresidue extension:

1. Compute `x^(p-1) = conjugate(x)^2 / Norm(x)`, using one public-input base-field inverse instead of an extension-field exponentiation.
2. Compute `x^(2(p-1))` by squaring that result.
3. When `e=lo+p*hi`, `p>=2^20`, `min(lo,hi)>=1024` and `0<|lo-hi|<=256`, factor `Norm(x)^min(lo,hi)` and power only `x` or its conjugate to the small exponent `|lo-hi|`.

All other exponents retain existing Frobenius joint-bit powering, with original sparse-input and noncanonical fallbacks. Variable time; only public input rootfinding.

## Rejected experiments

- Binary extended-GCD modular inverse was **0.21x–0.38x** of Euclid on tested GCC/Clang workloads: **not deployed**.
- Early nonsquare detection for p≡5 mod8 square roots measured **0.93x–0.99x** of the existing path: **not deployed**.
- Generic MSB-first Fp powering showed compiler-dependent gains/regressions at large exponents: **not deployed**.

## Limits

Neither complete quadratic/cubic/quartic solver throughput nor index-calculus relations per second has been established for these structures. The special exponents may have low hit frequency in practical index-calculus workloads. The broad repository validation includes unrelated historical artifact recovery failures; the dedicated production-Rust round-70 workflow passes.

[Latest native Rust round-70 CI](https://github.com/isogeny-labs/crypto/actions/runs/44803725876) **passed**, with **4,480 Fp2 and 256 complete cubic before/after equality checks**. The production code now checks for the rare special exponents before inspecting coefficient shape, reducing branch overhead in ordinary cubic/AMM powering.

**End-to-end caution:** In the preceding [native Rust run](https://github.com/isogeny-labs/crypto/actions/runs/44803583210), complete cubic medians were **0.965x** and **1.017x** respectively. This run-to-run variation makes a solver-wide speedup **inconclusive**. Measure invocation frequency in the actual relation-finding harness before drawing ECDLP throughput conclusions.
