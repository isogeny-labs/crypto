# Root finding round 77: symmetric squaring and unit-polynomial fast paths

Date: 2026-11-20 (local); 2026-11-21 UTC. Stacked on round76 (#4863).

## Source changes

Four producer-side optimizations in `src/cryptanalysis/prime_root_trace.rs`:

1. **Symmetric polynomial square in modular powering.** Use one multiplication per off-diagonal coefficient pair, double with `FieldOp::Add`, and use `FieldOp::Square` on diagonals. Keep the independently checked `Product` event.
2. **Multiply by one.** Copy the other polynomial when either operand is `[1]` instead of emitting useless field multiplications. Still emit `Product`.
3. **Divide by one.** When the divisor polynomial is `[1]`, clone the canonical quotient and emit the usual `Division` identity without long-division iterations.
4. **Sparse GCD normalization.** Do not multiply zero coefficients by the normalization inverse. The `GcdEnd` value is unchanged.

Public prime fields, event and work limits, independent verifier, and caller-facing APIs remain unchanged. Root outputs and mathematical identities are preserved, but field-operation traces and counters are intentionally smaller.

## Local paired benchmark

Environment: Intel Xeon Platinum 8573C; GCC 14.2 and Clang 17; `-O3 -march=native`; CPU affinity; 96 sample polynomials × 96 iterations × 13 alternating paired trials; nanoseconds per operation. **This is a C++ producer-kernel reproduction, not native production Rust.** 1,152 before/after output comparisons passed. GCC UBSan passed.

| Workload, p=1,000,000,007 | GCC before | GCC after | GCC paired speedup | Clang paired speedup |
|---|---:|---:|---:|---:|
| dense degree-8 polynomial square | 265.509 ns | 197.991 ns | **1.387×** | **1.341×** |
| sparse degree-8 polynomial square | 88.916 ns | 84.840 ns | 1.041× | 1.151× |
| polynomial division by `[1]` | 83.852 ns | 65.609 ns | **1.296×** | **1.264×** |
| polynomial multiplication by `[1]` | 59.700 ns | 45.372 ns | **1.295×** | **1.285×** |

Dense square per-input field events were 145 -> 109 (**24.8% fewer**); sparse square 23 -> 17; multiply-by-unit 9 -> 0. Other prime sizes 65,521 and 2^61−1 also improved across all four local workloads.

Raw local results and C++ reproduction: see downloadable round77 bundle from the automation results. A source-exact Rust A/B benchmark with 13 paired trials and polynomial equality checks is committed at `research/amm_digit_perf_20261118/round77_trace_isolated.py`, with a dedicated GitHub Actions workflow.

## Linux perf limitation

The container lacks the `perf` executable, and direct `perf_event_open` requests for task-clock, cycles, and instructions each returned EACCES (13) with `perf_event_paranoid=2`. Therefore all local results above are paired clock timings, **not hardware-counter measurements**.

## Merge gate

The production implementation should remain a draft until native Rust source-exact A/B is green, existing trace certificate tests and broader cargo suite are green, and complete `solve + verify` throughput plus relation generation/sec are measured. Isolated arithmetic gains should not be represented as established E2E index-calculus speedups.
