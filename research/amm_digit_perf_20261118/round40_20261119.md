# Round 40 (2026-11-19): fast constant and linear Frobenius root extraction

Production: `src/cryptanalysis/prime_root_bounded.rs`, [PR #4706](https://github.com/isogeny-labs/crypto/pull/4706). Commit `f07386aa49a2f2a0bcb7096512193a64d2016691` (source), CI added in `f76bce180526ac250a98104aeb495314141cd42e`.

## What changed

1. **Producer, constant polynomial modulus.** Return zero directly from polynomial exponentiation for a nonzero degree-zero modulus. This avoids normalization/inversion, polynomial multiplication, and reduction. The quotient ring is zero, including for exponent zero.
2. **Producer, linear Frobenius.** For `base=x` and exponent `p` modulo `a*x+b`, normalize the modulus to `x+c` and return the constant `-c`. Since `(-c)^p=-c` in `Fp`, it is identical to generic exponentiation.
3. **Producer, linear/constant GCD.** At the initial `gcd(f,x^p-x)`, return monic `f` directly if `deg(f)=1`, or `1` for nonzero constant `f`. Both equalities hold over a prime field.
4. **Independent verifier.** Separately derive the same linear/constant polynomial remainder and initial GCD in certificate replay, preserving event validation but avoiding the generic algorithms. Verifier arithmetic remains separate from the producer.

All paths retain canonical input validation, resource limits, deadline checks at charged stages, and exactly the same event types and values. This is public-input variable-time optimization, not a constant-time claim.

### Local perf screening

Standalone GCC 14 and Clang 17 C++ *arithmetic mirrors* were compiled with `-O3` and run on pinned local CPU affinities with 13 alternating pairs and 1,024 randomized correctness comparisons per case, across p=487, 1e9+7 and 2^61-1. All 9,216 cases per compiler passed, and GCC UBSan passed after correcting an empty-polynomial edge case in the **local mirror**. Unlike prior runs, direct Linux `perf_event_open` **software task-clock is available**, and the code measured it alongside wall-clock. The `perf` executable itself is missing; hardware PMU cycles returned `ENOENT`. There are **no hardware-cycle/instruction counts**.

Representative local GCC **software perf task-clock** medians at p=1e9+7 (ns per *power-operation surrogate*): constant 422.08 -> 2.63, monic linear 9,401.44 -> 106.33, nonmonic linear 11,329.69 -> 116.48. These mirror numbers are **not Rust** and are not substituted for complete solver timings above. The C++ mirror has different optimization and normalization details and should be considered only directional screening.

## Scope / next decision

The high-value linear/constant work is confirmed. Focus next on measurable degree-3-through-8 improvements, especially polynomial modular powering and dense splitting on representative *random* inputs. Before claiming speedup for the index-calculus application, run the complete relation-generation harness with identical factor bases and scalar samples. PR #4706 remains draft until repository-wide validation clears; a dedicated isolated CI pass is not a substitute for the full test suite.
