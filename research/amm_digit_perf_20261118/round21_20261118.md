# Round 21: amortize fixed inverses and cache AMM Sylow squares (2026-11-18)

## Production changes

All changes are in `src/cryptanalysis/prime_radical_root.rs` on draft PR #4706.

1. **Small constant inverses during `RadicalRootCtx::new`:** derive `2^-1`, `3^-1`, and `4^-1` directly from congruences. For prime `p>=5`:
   - `inv2=(p+1)/2`
   - `inv3=(2p+1)/3` if `p%3==1`, otherwise `(p+1)/3`
   - `inv4=(3p+1)/4` if `p%4==1`, otherwise `(p+1)/4`
   - `inv27 = inv3^3 mod p`; two field multiplications
   - reuse `inv2` or `inv3` when the first quadratic nonresidue is 2 or 3, avoiding another Euclidean inverse.
   
   All intermediate products fit in `u64` since `p<=2^61-1`. The code retains an extended-Euclid fallback for other nonresidues.

2. **AMM `w^2` cache:** precompute the other primitive third root of unity once per `Cube` context, instead of performing one Fp/Fp2 squaring per cube-root operation for `s=v3(|K*|)>=2`.
3. **AMM `c_inv^2` cache for `s=2`:** avoid a repeated Sylow-correction square for third digit `h=w^2`. Larger `s` already uses the precomputed inverse-squares array.

The `Cube::root_inner<const CACHED: bool>` method provides two compile-time-specialized versions for exact before/after benchmarking, avoiding a runtime conditional. The public `root` uses the cached variant. All operations are variable-time and **only suitable for public root-finding inputs**.

## Correctness, limitations and next gating decisions

- Native Rust tests verified inverses match extended Euclid for 14 primes including p=5 and 2^61-1, cached factors match direct squaring, and roots match uncached and prior implementations.
- The isolated compiled-Rust correctness/paired-benchmark CI job passed on the above run.
- The full repository/library CI was still running at the last check and is known to have unrelated compile/fixture problems in previous rounds.
- Full context creation, whole cubic/quartic rootfinding, fallback rates, ECDLP relation yield, GPU acceleration, and constant-time behavior are **not established**.
- Keep PR #4706 draft pending full-library validation and representative end-to-end measurement. Reevaluate near-noise cache gains before merging.
