# Round 20: sparse Fp2 exponentiation and already-depressed quartics (2026-11-18)

## Changes
- `Fq2::pow` uses the subfield identity `(a,0)^e = (a^(e mod (p-1)),0)` for nonzero canonical `a`; this eliminates extension-field products for real Fp2 operands.
- For a pure-imaginary canonical operand `x=(0,b)`, `x^2=(n*b*b,0)`. Compute `y=(n*b*b)^((e/2) mod (p-1))` in Fp and return `(y,0)` for even `e` or `(0,b*y)` for odd `e`. Zero/noncanonical operands retain the existing semantics.
- In quartic Ferrari solving, skip the depression coefficient arithmetic whenever the normalized cubic coefficient `b1` is zero; the polynomial is already depressed. Exact zero-constant quartics factor out `x` before normalizing all four coefficients, saving one field multiplication.
- Added frozen-before Frobenius-power comparison, small-field quartic brute-force checks, and paired native-Rust benchmarks in the isolated GitHub Actions job.

All paths are variable-time, restricted to public root-finding inputs. The quadratic extension must use a legitimate quadratic nonresidue.

## Local measurement

Host Intel Xeon Platinum 8370C, pinned to one available CPU, GCC 14.2 and Clang 17, `-O2`, 13 AB/BA paired trials, median ns/op. Linux `perf_event_open` software task-clock also tracked CPU time. The `perf` executable and hardware PMU counters were unavailable (`PERF_TYPE_HARDWARE` returned ENOENT); measurements below are wall clock, with task-clock in agreement. These are **faithful C++ arithmetic reproductions**, not native Rust; Rust CI timing is separately gated.

| Operation | GCC old | GCC new | GCC speedup | Clang speedup |
| --- | ---: | ---: | ---: | ---: |
| Fp2 power, real, AMM e3, p=487 | 267.59 ns | 61.24 ns | 4.37x | 3.86x |
| Fp2 power, imaginary, AMM e3, p=487 | 279.29 ns | 83.60 ns | 3.34x | 2.87x |
| Fp2 power, real, AMM e3, p=1,000,000,009 | 1107.23 ns | 277.10 ns | 4.00x | 3.02x |
| Fp2 power, imaginary, AMM e3, p=1,000,000,009 | 1138.74 ns | 337.92 ns | 3.37x | 2.63x |
| Already-depressed quartic coefficients, p=1,000,000,007 | 50.28 ns | 5.18 ns | 9.71x | 4.58x |
| Already-depressed quartic coefficients, p=2^61-1 | 35.82 ns | 4.73 ns | 7.58x | 3.59x |

Control: Fp2 generic `(a,b)` at p=1,000,000,009 with AMM e3 was 1197.70 -> 1182.43 ns (1.01x) in GCC; Clang 1455.84 -> 1280.40 ns (1.14x). Pure-subfield speedups do not imply the same improvement for generic Cardano radicals.

**Important negative control:** Local standalone depressed-quartic coefficient benchmarks observed dense-input regression: p=1,000,000,007 GCC 81.01 -> 98.89 ns (0.82x), Clang 47.99 -> 54.71 ns (0.88x). The benchmark's out-of-line wrapper adds a function call for dense inputs; a compiler-inlined follow-up still showed some overhead. Production Rust dense quartic timing is required before retaining this fast path unconditionally. Isolated coefficient speedups are not complete quartic-root speedups.

A separate norm/difference signed exponent decomposition was **rejected** for general inputs: GCC p=1,000,000,009 AMM_e3 regressed to 0.55x; although it improved p=2^61-1 for the same exponent, it is not a safe general replacement.

## Validation and status

C++ before/after equality checked across p=487, 17,497, 998,244,353, 1,000,000,009 and 2^61-1, real/imaginary/generic operands, and eight exponents including 0 and 2^128-1; quartic depression before/after checked for zero and nonzero cubic terms across three primes. GCC UBSan checks passed after removing a pre-existing undefined unused `clzll(0)` expression in the **benchmark reproduction only**. Code changes compile and correctness are gated by GitHub Actions' actual Rust isolated tests; the local environment lacks rustc. End-to-end quartic and relation-finding throughput remain unmeasured.
