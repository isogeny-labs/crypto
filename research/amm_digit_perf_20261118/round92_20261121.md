Source: `src/cryptanalysis/prime_root_trace.rs`. Draft PR [#4880](https://github.com/isogeny-labs/crypto/pull/4880). Comparison baseline Round91 commit `d13f9f17589af06a90fd74978165ad916dbe0e7b`. Rust 1.100.0 optimized source-exact producer/verifier A/B, pinned GitHub Actions CPU, 13 alternating trials, medians. The separate source-exact test validates certificate tampering and full root results.

## Retained optimizations

1. **Elide final unused modular square** in `Engine::pow` when shifting exponent to zero. Keep final PowerStep and all needed computations. The independently implemented verifier checks legacy traces with terminal squaring and new traces without it (only when the terminal base matches the previous, independently verified state). Native Rust Round91 -> square-only comparison passed [run 44931133389](https://github.com/isogeny-labs/crypto/actions/runs/44931133389): up to 1.0265x complete quartic solve+verify.
2. **Elide trivial power initialization polynomial divisions** when a base has lower degree than modulus and when 1 is already reduced. Avoid quotient/remainder copies and Division events without changing any actual residue. The independent verifier still reconstructs the initial residues.

The final candidate passed **two independent native Rust A/B workflow executions**, each containing 312 matching cumulative case/trials and 312 matching incremental case/trials (1,248 matched comparisons across runs). Both targeted Rust tests passed. Baseline / candidate returns matched on every A/B case.

### Rejected alternatives

Benchmarked fixed-degree dense monic cubic and quintic division over p=2^61-1. Local AMD EPYC 9V74 CPU-pinned GCC 14.2 and Clang 17 algorithmic reproductions gained up to approximately 1.3x, with exact quotient/remainder checks and GCC UBSan passing. But the production Rust source-exact CI [44930743401](https://github.com/isogeny-labs/crypto/actions/runs/44930743401) showed regressions: monic cubic width 8 **0.879x**, width 12 **0.891x**, quintic width 16 **0.983x**. **Reverted** these changes. Additional quadratic/quartic specializations were rejected in local compiler screening.

Some **unchanged** 61-bit division controls measured 2–6% slower during the accepted optimizations. This is evidence of codegen/layout drift or benchmarking noise, not the result of an accepted division optimization. Therefore do not describe this as a polynomial-division speedup.

### perf limitation and acceptance

Local `perf` CLI unavailable; direct `perf_event_open` for CPU cycles and task-clock returned **EACCES** (kernel `perf_event_paranoid=2`). No hardware PMU measurements. Paired CPU-pinned `steady_clock` local tests and native Rust `Instant` tests are elapsed-time measurements, not measured CPU cycles/cache misses.

**Keep PR draft/unmerged** pending broader repository validation and addressing earlier sparse-product/small-field degree-eight regressions. This round validates quadratic/quartic *complete solve+verify*, but does not prove degree-eight improvement or any increase in index-calculus relations per second.
