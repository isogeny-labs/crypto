# Round 110: verifier unit-binomial remainder and source-exact A/B repair

Date: 2026-11-22. Draft/unmerged PR #4880.

## Code and correctness

- **Fix to previous CI:** the Round109 harness declared Cargo package `round109-source-exact` but tried to run `round107-source-exact`. Updated the executable path. [Round109 source-exact PASS](https://github.com/isogeny-labs/crypto/actions/runs/45017392178): 36 passed Rust tests, one ignored, 858 checksum-matched A/B comparisons.
- **New verifier optimization:** for a monic polynomial `x^d + 1` or `x^d - 1` (`d>=4`), `vpower_reduce` dispatches a specialized remainder operation. Each high coefficient is cancelled by one modular subtraction/addition, with no coefficient multiplication or generic inner-loop scan. The existing dense/nonunit reducer and producer trace remain unchanged; certificate checking remains independent. Optimized source commit `866bb8e1869fd29a3d5f6ec385818ea7d6088542`.
- **Independent oracle:** new Rust test compares verifier remainder with u128 long division over 4 primes, degrees 4/5/8, both unit signs and 384 generated products per configuration (9,216 cases, including extreme coefficients and trailing zeros). Native Rust job below is the acceptance gate.
- **New A/B infrastructure:** `round110_ab.py` and `rootfind-round110-ab.yml` compare frozen Round109 against optimized source, including x^d +/- 1, dense and near-miss controls, verifier quartic power and complete root extraction + verification.

AMD EPYC 9V74 CPU-pinned, GCC 14.2/Clang 17 separate before/after C++ algorithmic reproduction binaries, 13 alternating A/B trials, two executions, **Linux perf_event_open software task-clock** (hardware cycles/instructions unavailable). These are NOT production Rust speedups.

A separate GCC ASan/UBSan test passed 432,000 reference comparisons using independent u128 long division. **The GCC dense/near-miss regressions are material** and may be caused by compiler code layout. Do not accept without source-exact production Rust measurements.
