# Round 54: dense polynomial accumulator fast paths

**Date:** 2026-11-20 UTC. **PR:** [#4706](https://github.com/isogeny-labs/crypto/pull/4706). **Native Rust validation:** [passing round-54 CI](https://github.com/isogeny-labs/crypto/actions/runs/44668367615/job/136063195601).

## Code changes

Four production paths in `src/cryptanalysis/prime_root_bounded.rs` now avoid an unnecessary modular addition when a coefficient is first populated:

1. **Producer::product**: the first multiplicand row and final multiplier column introduce distinct output coefficients, which can be assigned directly.
2. **Replay::convolution**: for dense inputs, the first element of each independent output diagonal is assigned instead of added to zero. Sparse inputs retain their existing path.
3. **Producer::square**: the two endpoint diagonal terms and first-encounter off-diagonal terms bypass addition to zero; subsequent terms still accumulate normally.
4. **Replay::square_diagonals**: the first term of each dense output diagonal initializes that coefficient. The independent diagonal traversal is retained.

For two eight-coefficient inputs, a dense product performs **113 instead of 128** finite-field operations in the local arithmetic mirror. Each dense square removes **15** accumulator additions. All operations remain budget/deadline checked when invoked; skipped zero additions are no longer charged. The code is variable-time public-input cryptanalysis, not a secret-safe constant-time implementation.

## Exact native Rust validation

The added `round54_dense_accumulators_isolated.py` reconstructs the immediately preceding production code from explicit R54 markers, compiles both versions with `rustc -O`, and verifies:

- producer/replay dense operation outputs match;
- root sets, event streams, and independent certificate replay match for complete degree-2/3/4/6/8 workloads across three primes;
- 13 alternating Rust A/B trials are executed for isolated operations and degree-4/8 complete extraction.

The isolated [round-54 job passed](https://github.com/isogeny-labs/crypto/actions/runs/44668367615/job/136063195601), including both correctness and benchmark steps. **Exact numeric native-Rust timings were written to the CI artifact, but have not been recovered here**, so this report does not claim their numerical speedup. Nor does it claim an overall relation-generator improvement.

## Linux perf limitation

Local `perf` CLI was not installed. Direct `perf_event_open` attempts for software task-clock and hardware cycles/instructions all returned **EACCES (13)** under kernel 6.18.57, `perf_event_paranoid=2`. Thus the local results are CPU-pinned steady-clock timings, **not perf hardware counter data**. Hardware PMU profiling requires a host or runner that permits performance events.
