# Round 73: one-fold canonical Mersenne multiplication (2026-11-20)

## Production code changed

This round removes an unnecessary second end-around-carry fold from **five independent root-finding arithmetic paths**:

1. `src/cryptanalysis/prime_radical_root.rs`: `Fp::mul`, used by quadratic, cubic, quartic, Fp2 and AMM root extraction.
2. `src/cryptanalysis/prime_root_bounded.rs`: `Producer::mul`, budgeted bounded root extraction.
3. `src/cryptanalysis/prime_root_bounded.rs`: `Replay::times`, independently replayed root certificate arithmetic.
4. `src/cryptanalysis/prime_root_trace.rs`: `field_value`, trace-producing field arithmetic.
5. `src/cryptanalysis/prime_root_trace.rs`: `vmul`, independent trace-certificate verifier.

For `p=2^61-1` and canonical `0 <= a,b < p`, write `t=ab`. Because `t < p^2 < 2^122`, both `t & p` and `t >> 61` are below `2^61` and their sum `s` lies in `[0,2p)`. With `2^61 ≡ 1 (mod p)`, `s ≡ t (mod p)`. **One** conditional subtraction (`s >= p ? s-p : s`) is sufficient. The previous second fold was redundant for canonical operands. Noncanonical and other-prime fallbacks remain unchanged. Public-input, variable-time arithmetic only.

## Before/after local A/B

AMD EPYC 9V74, pinned to one CPU, GCC 14.2 and Clang 17, `-O3 -march=native -std=c++20`. Exact production-equivalent old/new modular reduction in independent C++ reproduction. 8,208 canonical operand pairs (8,192 deterministic pseudo-random plus 16 boundary cases), 150 repetitions/trial, **13 alternating before/after trials**. Median nanoseconds per modular multiplication.

| Compiler | Before (ns) | After (ns) | Isolated speedup |
|---|---:|---:|---:|
| GCC 14.2 | 1.30490 | 1.24384 | **1.049x** |
| Clang 17 | 1.62476 | 1.36596 | **1.189x** |

These are **C++ reproductions**, not production Rust timing, nor end-to-end root extraction or index-calculus throughput. The compiler disagreement and per-trial variance warrant confirmation in production Rust and on representative workloads.

## Correctness and negative controls

- `(a*b)%p` in independent 128-bit arithmetic agrees with both implementations on 8,208 cases per compiler, including 0, 1, `p-2`, `p-1` boundaries; GCC and Clang both passed.
- GCC UBSan passed (no diagnostics). The new Rust `canonical_mersenne_products_match_wide_modulo` test adds 36 edge products and 16,384 deterministic products, and an ignored 13-trial native Rust A/B benchmark. The preexisting `round31_bounded_canonical_ops_match_wide_reference` and `round22_fast_trace_field_exact_under_frozen_arithmetic` tests cover the other paths.
- A separate candidate optimized Fp2 dense squaring using two field multiplications instead of three, plus nonresidue multiplication by 5. On the local C++ A/B this **regressed dense squaring** (GCC 0.843x at `p=1e9+7`, 0.848x at `p=2^61-1`; Clang 0.873x and 0.748x). It was **not shipped**. A dense-multiplication change also regressed, and was rejected. 196,608 C++ before/after equality checks passed per compiler for those rejected candidates.

## Linux perf and limitations

`perf` executable is unavailable in this runtime. Direct `perf_event_open` on software task-clock, hardware CPU cycles and hardware instructions returned `Permission denied`; `perf_event_paranoid=2`. The reported numbers use `std::chrono::steady_clock` with CPU affinity, **not hardware counter profiling**.

This benchmark is isolated scalar multiplication. There is **no established complete root-finder speedup or relations/s improvement** in this round. Run the ignored native-Rust A/B benchmark with `cargo test --release --lib benchmark_canonical_mersenne_fold -- --ignored --nocapture` and the existing field/certificate tests in CI before merging. Adopt only if native and representative end-to-end performance remain non-regressing.

[Dedicated native Rust job 136609615622, run 44829227868](https://github.com/isogeny-labs/crypto/actions/runs/44829227868/job/136609615622), Rust 1.100.0, optimized `rustc -O`, **13 alternating A/B trials**, each arm compiled from the actual production `prime_radical_root.rs` with only the old extra fold restored in the baseline. All equality tests passed: 16,420 Fp scalar products, 14,336 Fp2 arithmetic comparisons and 256 complete cubic-root comparisons.

| Workload | Before | After | Speedup |
|---|---:|---:|---:|
| Canonical Fp product, p=2^61−1 | 2.4705 ns | 2.1198 ns | **1.1655x** |
| Dense Fp2 product, p=2^61−1 | 14.757 ns | 14.441 ns | **1.022x** |

The 32-bit-prime cubic control changed even though its scalar multiplication implementation is unchanged. That illustrates run noise; the complete 61-bit cubic result is a **single-run positive observation**, not yet proof of a durable end-to-end improvement. Some individual Fp2 input classes also regressed (for example, real-left multiplication 0.971x); do not merge solely on this isolated run. The CI job verifies the radical Rust code; the bounded and trace modules retain their in-repository wide-arithmetic oracle tests but their full cargo suite was not executed here.
