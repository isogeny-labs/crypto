# Round 29 — sparse trace-verifier root arithmetic (November 18, 2026 Pacific)

Production path: `src/cryptanalysis/prime_root_trace.rs`, PR [#4706](https://github.com/isogeny-labs/crypto/pull/4706).

## Committed algorithms

1. **Four-term polynomial squares**: After the existing sparse prefix guard recognizes the first three nonzero coefficients, inspect the remaining tail once to detect exactly one fourth term. Compute four diagonal and six off-diagonal field products, accumulating collisions of like degrees. General dense inputs still use the prior symmetric algorithm. The existing specialized one-, two-, and three-term branches are preserved.
2. **Monic binomial division**: For a divisor `x^k+c` with `k>=3` and nonzero `c`, each quotient step changes only one remainder coefficient, not all `k` coefficients. The preexisting `x^k` and `x+c` paths are retained.
3. **Rejected screen: selective verifier PowerStep squaring.** It showed ~1.7–2.3x on local C++ binomial mirrors, but compiled-Rust improvements were only 1.02–1.03x and a trinomial control regressed to 0.96–0.98x. The attempted production change was **reverted** in commit `251daf46`. The native Rust benchmark preserves a comparison of this rejected alternative, **not** a claimed production optimization.

All optimizations are variable-time on public polynomial coefficients. No claims of secret-independent execution are made.

AMD EPYC 9V74 (pinned CPU 0), GCC 14.2.0 and Clang 17.0.0, `-O3`, 13 AB/BA trials, 128 input fixtures. A locally compiled standalone C++ implementation mirroring the production arithmetic passed **18,816 exact comparisons per compiler**; GCC UBSan passed.

| Dense divisor control | 220.544 → 222.370 ns | 0.99x | 0.98x |

Perf was attempted on the local Linux worker. The `perf` binary is absent, and both the software `PERF_COUNT_SW_TASK_CLOCK` and hardware `PERF_COUNT_HW_CPU_CYCLES` `perf_event_open` calls returned `EACCES` (errno 13), including as container root. Consequently these are CPU-pinned wall-clock medians, **not PMU event timings**. The container's `/proc/sys` mount is read-only and lacks `CAP_PERFMON`. Do not interpret C++ mirror timings as compiled production Rust.
