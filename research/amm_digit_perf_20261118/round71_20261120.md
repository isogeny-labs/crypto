# Round 71: sparse Fp² arithmetic for radical root finding

2026-11-20. Branch: `automation/rootfind-sparse-fp2-round71-20261120`.
Builds on round-70 Fp² Frobenius work (PR #4845). This is **not** an index-calculus throughput claim.

## Production changes

`src/cryptanalysis/prime_radical_root.rs`, `impl Ring for Fq2`:

1. **Multiplication with either real operand**: scalar multiplication of `(a,0)` by `(c,d)` requires two Fp products, rather than three for dense Karatsuba.
2. **Sparse squaring**: `(a,0)^2=(a²,0)` and `(0,b)^2=(n·b²,0)`; avoid dense three-product path.
3. **Real cubing**: `(a,0)^3=(a³,0)`; use one Fp square plus one Fp product instead of the four-product dense cubing formula.

Dense code remains algebraically unchanged after the guards. Deliberately **rejected** an imaginary-cube shortcut and imaginary-operand multiplication guards after local screening showed double-digit dense regressions for some compiler/workload combinations. Avoid secret-dependent use: the radical routines already use public, variable-time inputs.

## Local reproducible C++ arithmetic-mirror A/B measurements

AMD EPYC 9V74 (container, CPU0 affinity); GCC 14.2 and Clang 17, `-O3 -std=c++20 -march=native`. Genuine Fp² quadratic-nonresidue parameters: `(p,n)=(1_000_000_007,5)` and `(2^61-1,3)`. 13 alternating A/B trials; per-trial operations include 256 samples repeated 100 times. Medians are of per-trial speedup ratios (not necessarily the ratio of independently tabulated medians). Units: nanoseconds per operation.

| Operation/input | GCC 1e9+7 | Clang 1e9+7 | GCC 2^61-1 | Clang 2^61-1 |
|---|---:|---:|---:|---:|
| Fq2 mul, real lhs | 2.01× | 1.93× | 2.03× | 2.65× |
| Fq2 mul, mixed shape | 1.34× | 1.35× | 1.36× | 1.43× |
| Fq2 mul, dense control | 1.00× | 1.00× | 1.03× | 1.00× |
| Fq2 square, real input | **4.00×** | 3.57× | 2.96× | 3.24× |

| Fq2 square, dense control | 1.00× | 0.99× | 1.00× | 1.02× |

The optimized real-only cube has a **2–5% dense-path regression**. Do not merge on kernel timings alone; measure complete cubics and real workload sparsity.

C++ arithmetic-mirror correctness passed every deterministic sample; GCC UBSan passed. These timings are **not production Rust measurements**. Source-exact native Rust A/B equivalence, kernel timings, and complete cubic timings are implemented in `round71_sparse_fp2_isolated.py` and wired to `radical-sparse-fp2-round71.yml`.

## Linux perf limitation

`perf` is not installed; `perf_event_open` returned `EACCES` for software task-clock, cycles, and instructions, despite a numeric `perf_event_paranoid=2`. Therefore local wall-clock timings were collected rather than performance-counter data. See the local artifact archive for raw trials, source and probe output.

## Follow-up decision

Native production Rust exactness and root-extraction benchmarks must pass before accepting this change. If dense cubic workload throughput regresses materially, remove the real-only cube guard (the isolated gains alone are insufficient). Only claim index-calculus relations/sec improvement after profiling representative relation-finding inputs.

## Source-exact production Rust validation (CI passed)

[GitHub Actions run 44812484065](https://github.com/isogeny-labs/crypto/actions/runs/44812484065) compiled both original and optimized production-Rust modules using Rust 1.100.0 and ran **43,008 exact arithmetic comparisons** plus **256 complete depressed-cubic root comparisons**. Both suites passed.
