# Round 121 (2026-11-22): narrow Jacobi for prime-field roots

**Final outcome: keep 32-bit Jacobi narrowing; revert generic sparse Fp2 multiplication. Keep PR #4909 draft and unmerged.**

## Production change retained

In `src/cryptanalysis/prime_radical_root.rs`, `RadicalRootCtx::sqrt_discriminant` now uses 32-bit rather than 64-bit Euclidean remainders for *all* eligible canonical discriminants over 32-bit prime fields. The earlier special handling at `p=2^32-5` is preserved. No extra prefilter is added, and the 61-bit path is unchanged. The operation is variable-time and must only be used on public root-finding inputs.

The new unit tests cover 150,000 independent Fp2 product comparisons and 20,480 Euler/square-root checks. A separate source-exact native Rust harness checks the frozen previous Jacobi against the current implementation.

## Rejected after profiling: dynamic sparse Fp2 fast path

We implemented the algebraically valid identity `(a,0)*(c,d)=(ac,ad)` inside `Fq2::mul`, saving a field multiply on left-sparse operands. Standalone native Rust A/B showed **1.51–2.01x** on sparse multiplication, but recurrent dense controls slowed **4–6%** on 32-bit fields. The corresponding *complete native Rust cubic solver* showed no robust speedup: two source-exact trials, 768 cubic equivalence comparisons each, measured roughly **0.98–1.03x** across uniform and constructed-three-root workloads, with adverse cases. Therefore the generic sparse dispatch was **reverted** (commit `3d21ff6687a6a749839b599ca99737f88b15c509`).

## Local Linux perf investigation

AMD EPYC 9V74, CPU pinned to first allowed CPU, GCC and Clang optimized C++ reproductions. Using `perf_event_open` with `PERF_COUNT_SW_TASK_CLOCK`, we measured 15 alternating A/B trials per execution, repeated independently. The `perf` CLI and hardware PMU counters were unavailable. GCC ASan/UBSan and 300,000 randomized Fp2 oracle comparisons per compiler passed.

- Isolated left-sparse Fp2: approximately **1.76–2.19x** across compiler/field pairs, but dense-path regressions led to rejection.
- Narrow 32-bit Jacobi in complete monic quadratic C++: p=1,000,000,021 uniform approximately **1.00–1.06x** across runs, and p=4,294,967,197 approximately **1.01–1.04x** on uniform inputs, with noisy known-root controls.
- Rejected both-sided sparse branching, cold out-of-line sparse dispatch, modulus-gated sparse dispatch, and adaptive 64→32-bit Jacobi switching after compiler-dependent regressions.

**Do not conflate local C++ perf counter results with the native Rust measurements above.**
