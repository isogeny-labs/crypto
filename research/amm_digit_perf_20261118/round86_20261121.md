# Round86: traced producer monomial-shift and monic-linear products

Date: 2026-11-21. Branch `automation/rootfind-structural-sparse-round86-20261121`, PR #4877. Based on Round82, avoiding the experimental Round83–85 stacked changes.

## Changes

Two production arithmetic paths in `src/cryptanalysis/prime_root_trace.rs`:

1. When either operand is a monic power `X^k`, polynomial multiplication becomes a coefficient shift. The Product certificate event is retained, but no scalar field-work or Field events are charged.
2. For a monic linear factor `X+c` multiplied by a polynomial with at least seven coefficients, compute each result coefficient in one pass. Zero coefficients skip field multiplication and unnecessary addition; the independent certificate verifier still reconstructs the result with its existing algebra.

The earlier multiplication-by-one fast path is preserved and dispatched first. The independent verifier is not modified. A monomial-squaring shortcut was rejected in screening and removed from the production patch.

## Local analogue screening

CPU-pinned AMD EPYC 9V74, C++20 `-O3 -march=native`, GCC and Clang, 13 alternating A/B trials, median ns. A behavioral model includes output vector handling and a scalar field-event ledger, but does **not** reproduce Rust's allocation/event serialization/code generation. Local correctness: 2,304 matched polynomial product/square examples per compiler; GCC UBSan passed.

At p=1,000,000,007 and operand length eight:

| Operation | GCC before / after (ns) | GCC speedup | Clang speedup |
|---|---:|---:|---:|
| Monic X^7 times polynomial | 138.0 / 73.6 | 1.88x | 1.70x |
| Monic X+c times dense polynomial | 182.3 / 147.6 | 1.23x | 1.02x |
| Monic X+c times sparse polynomial | 176.1 / 144.7 | 1.22x | 0.98x |

These numbers describe **isolated C++ analogues**, not production Rust gains.

## Source-exact native Rust A/B

[Successful workflow](https://github.com/isogeny-labs/crypto/actions/runs/44899847547): Rust 1.100.0, CPU-pinned GitHub-hosted runner, 15 alternating A/B trials; 450 checksum/completion-matched comparisons across 30 full solve+verify and verification-only cases. New monomial/linear exactness tests and six existing certificate tests passed.

Representative full solve + independent verify median times:

| Prime and workload | Before (ns) | After (ns) | Speedup |
|---|---:|---:|---:|
| p=1e9+7 degree-eight | 1,415,206 | 1,370,041 | 1.033x |
| p=1e9+7 quartic | 144,695 | 143,283 | 1.010x |
| p=2^61-1 quartic | 421,669 | 403,445 | 1.045x |
| p=2^61-1 fully split quartic | 750,991 | 714,311 | 1.051x |
| p=2^61-1 degree-eight | 3,424,996 | 3,519,779 | **0.973x regression** |
| p=65,521 degree-eight | 568,118 | 606,202 | **0.937x regression** |

Verifier-only timings changed up to several percent even though the verifier source was unchanged, so code layout and noisy shared-runner scheduling may materially affect the apparent improvement/regression. The two degree-eight regressions are a reason **not** to merge.

The isolated Rust harness stubs out unrelated bounded API and prime validation; it includes the complete root trace producer and independent verifier, but not index-calculus relation generation.

## Linux perf

Local `perf` executable unavailable; a direct `perf_event_open` probe returned EACCES for cycles and task-clock, with `kernel.perf_event_paranoid=2`. No PMU-based cycle, instruction, or cache-miss claims are made.

## Acceptance decision

Remain draft. Check repeat native A/B for 61-bit and 16-bit degree-eight cases; isolate shape dispatch versus event savings, profile on a perf-enabled CPU, run full repository gates, and measure relation-generation relations/s. Do not treat a faster isolated polynomial operation as proof of end-to-end improvement.
