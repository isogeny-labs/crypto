# Round 13: fused Tonelli and quartic arithmetic (2026-11-18)

Continuation of draft [PR #4706](https://github.com/isogeny-labs/crypto/pull/4706).

Three optimized production Rust code paths in `src/cryptanalysis/prime_radical_root.rs`:
1. **Tonelli–Shanks:** for odd `t2 >= 1024`, compute `h=a^((t2-1)/2)`, `t=h²*a` and `r=h*a`, sharing one exponentiation across the two initial states. For `t2=1`, eliminate both exponentiations. Preserve the original two-power path for small `t2`, which showed compiler-dependent regressions.
2. **Quartic depression:** replace general modular products by constants 2,3,6,8 with modular doublings/triplings. Keep the old implementation for `p=2^61-1` after a native Rust regression.
3. **Quartic resolvent:** compute `2P` and `4R` using modular doublings.

**Regressions / subsequent guard:** Native Rust `p=2^61-1` quartic depression ran 19.542→20.425 ns (0.957x); production now uses the frozen prior path there. For short `t2`, the new fused Tonelli candidate was inconsistent; the latest code retains original two-power path, but branch cost means `p=97` square measured 47.547→49.936 ns (0.952x). `p=998244353` square measured 641.489→654.431 ns (0.980x). Do not claim gains at these primes.

The CI `fused_tonelli_and_quartic_coefficients_match_frozen` test passed; it checks exact outputs of both algorithms across small/exhaustive and large/random primes. The latest p=2^61-1 guard is a follow-up commit, so its native rerun should be checked separately.
