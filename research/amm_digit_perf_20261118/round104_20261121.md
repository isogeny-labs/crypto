# Round 104: quartic Mersenne column accumulation (2026-11-21)

Status: **experimental draft PR #4880**. The source-exact native Rust [A/B workflow](https://github.com/isogeny-labs/crypto/actions/runs/44990017845) was queued at this report's creation; no production Rust speedup or end-to-end ECC2K relation throughput is claimed yet.

## Production changes

- `quartic_mul`: for `p=2^61-1`, accumulate each of seven convolution columns into `u128` and reduce once per output coefficient, rather than 16 per-product reductions.
- `quartic_square`: exploit symmetry and use `u128` columns for four diagonals and six off-diagonal products.
- `quartic_mersenne_reduce`: three pseudo-Mersenne folds; each column is bounded by `4*(p-1)^2 < 2^124`, so `u128` accumulation cannot overflow.
- `vpower`: enable degree-four quotient-ring specialization for the 61-bit Mersenne field. Retain previous small-field dispatch and leave the certificate replay path unchanged.
- Independent randomized/extreme-value polynomial oracle tests expanded, including `round104_mersenne_quartic_column_extremes` and 61-bit dispatch.

## Local A/B timing (C++ algorithmic reproduction only)

CPU-pinned Intel Xeon Platinum 8370C; GCC 14.2 and Clang 17 `-O3`, two independent executions, 15 alternating A/B trials each. All timings are median ns per approximately 16-bit quartic modular exponentiation, **not production Rust**.
