# Round 30 root-verifier arithmetic optimization, 2026-11-18

## Production code changes
- **Nonmonic linear division:** reuse the synthetic remainder loop, eliminating repeated polynomial trimming.
- **Monic quadratic and sparse-trinomial division:** handle at most two coefficient updates per quotient digit, including sparse powers of x. Skip zero digits.
- **General polynomial division:** descend over a fixed degree range instead of allocating and trimming the remainder every iteration; skip zero divisor coefficients.
- **Gap-aware symmetric polynomial squaring:** skip zero coefficient pairs for five-or-more-term sparse inputs while preserving the dense code path and earlier <=4-term specializations.
- **Regression guard:** preserve the existing monic binomial fast path for degree >=3. Initial actual-Rust measurements showed a 2-4% regression when replacing this already-optimized path with the new fixed-degree loop, so it was restored in commit 4182e5c.

## Local perf restrictions and end-to-end limits
The local environment has no \`perf\` executable; direct \`perf_event_open\` returned EACCES for software task-clock and hardware CPU-cycle counters. Consequently, local timings use pinned steady-clock rather than hardware PMUs.

These changes concern the *independent verifier* in \`src/cryptanalysis/prime_root_trace.rs\`. They do not demonstrate improved solver/root-extraction throughput, index-calculus relations per second, or GPU performance. Full-library CI remains separate from the isolated production-Rust checks. The repository-wide workflow-file parse job is blocked by a preexisting missing \`research/weak_curve_properties_lean_20261011/root_lib.stdout\` store artifact, not a Rust parse error.
