# Round 52: monic x factor division/remainder fast paths (2026-11-20 UTC)

**Production code:** `src/cryptanalysis/prime_root_bounded.rs`. **PR:** [#4706](https://github.com/isogeny-labs/crypto/pull/4706).

Four separately implemented paths now exploit the identity `f(x) mod x = f(0)`:

1. `Producer::division`: division by monic x uses a coefficient shift for the quotient and constant for the remainder.
2. `Producer::reduce_monic`: reduction modulo x takes the constant coefficient without field arithmetic.
3. `Replay::remainder`: independently return the constant residue for a monic x divisor.
4. `Replay::cancel_monic`: independently cancel higher terms modulo x by projection.

Each path retains the existing initial gate/deadline checks. The nonzero-linear Horner/synthetic division optimization was investigated but **reverted**: true Rust A/B results showed ~0–2% improvements with occasional regressions and negligible end-to-end value.

## Native Rust verification

**Passing job:** [Round 52 production-Rust A/B and equivalence](https://github.com/isogeny-labs/crypto/actions/runs/44654364024/job/136016867028), from source commit `fa691ded5fd2103e4599f3228744385ee0f33745`. The benchmark script compiles the exact production file twice, with and without R52 sections, using `rustc -O`. Thirteen alternating before/after trials, medians; 207 exact kernel / complete-root-event-certificate cases matched, for p=1,000,000,007, 1,000,000,009, and 2^61−1. No failures.

p=1,000,000,007, degree-7 polynomial; dividing/reducing by x:

| Native Rust operation | Before (ns) | After (ns) | Speedup |
|---|---:|---:|---:|
| Producer quotient + remainder | 275.36 | 60.00 | **4.590x** |
| Producer remainder-only reduction | 243.03 | 33.70 | **7.213x** |
| Replay remainder | 248.36 | 35.77 | **6.942x** |
| Replay modular cancellation | 240.68 | 33.66 | **7.151x** |

p=1,000,000,009: 4.687x / 7.224x / 6.936x / 7.155x, respectively. p=2^61−1: 4.550x / 7.220x / 6.939x / 7.147x, respectively. Nonzero-linear control timings remained approximately 1.00x.

**Complete rootfinding and independent certificate replay were essentially unchanged.** Degree-8 complete workflows:

| Prime | Before (µs) | After (µs) | Speedup |
|---|---:|---:|---:|
| 1e9+7 | 1,616.298 | 1,617.480 | 0.999x |
| 1e9+9 | 1,342.677 | 1,347.126 | 0.997x |
| 2^61−1 | 2,771.344 | 2,776.333 | 0.998x |

For these workloads the x-divisor path is not an important fraction of the total cost. No generic rootfinding or index-calculus throughput benefit is claimed.

## Local profiling

GCC 14.2 and Clang 17 C++ reproductions compiled with `-O3 -march=native`. The copies model a gate check via `clock_gettime`; these are not the compiled Rust and cannot establish production speedups. At p=1e9+7, degree 7, div-by-x `quotient+remainder` GCC 222.089 -> 39.324 ns (5.65x); Clang 225.100 -> 40.978 ns (5.49x). Div-by-x `remainder`: GCC 209.923 -> 31.695 ns (6.62x); Clang 225.441 -> 38.218 ns (5.90x). Three primes, three lengths and 256 pseudorandom polynomials per configuration were checked for exact arithmetic agreement. GCC UBSan passed.

The Linux `perf` executable was unavailable locally, and direct `perf_event_open` probes for software task-clock, CPU cycles and instructions all returned `EACCES`. Local measurements are wall-clock-based, **not perf counters**. Raw C++ mirror sources, outputs and perf diagnostics are available in the downloadable round-52 bundle attached to the automation run.

## Follow-up

For meaningful complete-root improvements, optimize degree-6/8 polynomial exponentiation and reductions. More importantly, benchmark the accumulated work against index-calculus relations/sec. R52 improves a special algebraic case rather than typical distinct-root workloads.
