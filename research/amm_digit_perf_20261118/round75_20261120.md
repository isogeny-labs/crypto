# Round 75: sparse trace arithmetic and cached Barrett reduction

Date: 2026-11-20 (America/Los_Angeles). Target: `src/cryptanalysis/prime_root_trace.rs` in the full independent-certificate polynomial root engine.

## Three production changes

1. **Producer convolution**: skip multiplication and addition when the right coefficient is zero (the existing left-zero skip is preserved).
2. **Producer polynomial division**: skip multiplication and subtraction for zero divisor coefficients. The quotient, remainder, and polynomial events remain unchanged, but field-op events/counters are intentionally reduced.
3. **Producer canonical 32-bit field multiply/square**: precompute `floor(2^64 / p)` once in `solve`; use 64x64-to-128 high multiplication and at most one correction. Keep the previously validated general arithmetic for noncanonical values, the 61-bit Mersenne prime, and other moduli. The independent verifier's arithmetic is unchanged.

For canonical a,b < p <= 2^32-1, the reduction is exact:

```
product = a*b                      // fits u64
q = floor(product*floor(2^64/p)/2^64)
r = product - q*p
return r >= p ? r-p : r
```

The floor reciprocal underestimates the true quotient by at most one when product < 2^64.

## Locally measured C++ arithmetic reproductions

Host: AMD EPYC 9V74 (Linux 6.18.57), one CPU pinned, GCC and Clang native optimized builds, 64 pseudo-random polynomial inputs per workload, 13 alternating A/B timing trials with 100 repeats each. The reference and optimized polynomial outputs agreed on every tested input. Median timings in nanoseconds per polynomial operation are below for `p=1,000,000,007`, nominal degree 8. **These are source-equivalent C++ kernel reproductions, not compiled production Rust or complete solver measurements.**

| Sparse convolution | Clang | 69.403 | 51.492 | **1.348x** | 3312 -> 1014 |

The `after` path in this table combines zero-coefficient skips and cached Barrett multiplication. Separate skip-only and arithmetic-only controls are recorded in local `summary.csv`. Clang showed variability and different speedup patterns, so extrapolation from one compiler is inappropriate. The C++ reproductions do not allocate per-field `RootEvent` objects, so exact tracing overhead remains unmeasured.

An additional independent C++ arithmetic test covered primes 65521, 1,000,000,007 and 4,294,967,291. GCC measured 1.29x to 1.36x isolated 32-bit modular multiplication improvement. Its complete polynomial-product performance was workload dependent; some Clang polynomial workloads regressed, so no speculative verifier change was committed.
