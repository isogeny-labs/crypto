# Round 69: Cardano Fp2 finishing-stage reuse (2026-11-20)

## Production change

In `src/cryptanalysis/prime_radical_root.rs`, the casus-irreducibilis branch of `RadicalRootCtx::cubic_depressed` now:

1. Computes (N(u)=u_0^2-nu_1^2) with the existing `Fq2::mul_nonresidue` specialization (for n=2 or 3).
2. Forms the common scalar `m / N(u)` once, then multiplies its two conjugate components instead of first constructing `u^-1` and separately scaling both parts by `m`. This eliminates one general Fp multiplication.
3. Reuses the `Cube<Fq2>` context's cached `w^2` whenever `v3(p^2-1)>=2`; the valuation-one case intentionally computes the square because that cache is initialized to one for s=1. This avoids an unnecessary Fq2 multiplication for the large-prime path.

All transformations are exact field identities. No change to public APIs or root order. This implementation is variable-time and is intended only for public-input root finding.

## Rejected optimizations

- Generic MSB-first binary powering saved one conceptual multiply, but regressed common dense-workloads under both compilers (GCC 0.865x, Clang 0.864x at 1e9+7); it was **not committed**.
- Early-return for unit correction in the 3-Sylow case produced 1.348x on the isolated GCC 1e9+7 stage, but **0.772x** for the 61-bit modulus, so the generic change was **not committed**.

## Rust verification

`research/amm_digit_perf_20261118/round69_casus_finish_isolated.py` constructs a frozen before-variant from the compiled production file, checks the literal finishing-stage source on small and large primes, compares complete cubic root sets, and benchmarks both the finishing stage and full three-root cubic. `.github/workflows/radical-root-arithmetic.yml` adds a dedicated Rust job for it.

The correctness comparison must include fields with `v3(p^2-1)=1`: they are the regression guard for using a cached `w^2` that is not populated in that case.
