# Round 14: Frobenius Fp2 powers, modular half and monic linear roots (2026-11-18)

Continuing [PR #4706](https://github.com/isogeny-labs/crypto/pull/4706).

## Changes to the production Rust rootfinder

* `Ring::pow` now allows field-specialized exponentiation. `Cube<R>::new/root` uses it instead of hardcoding `rpow`; `Fp` retains its previous generic exponentiation by default.
* In `Fq2::pow`, use `x^p = conjugate(x)` and `e = lo + p*hi`: a joint binary exponentiation computes `x^lo * conjugate(x)^hi` with at most `ceil(log2(p))` extension-field squarings, rather than up to `ceil(log2(p*p))`. When both exponent bits are set, multiply by scalar `Norm(x)` via two Fp multiplies instead of a full Fp2 multiply.
* When `lo == hi`, `x^e = Norm(x)^lo` needs **only Fp arithmetic**. This is particularly effective for exponent `(p²-1)/3` or `t = (p²-1)/3^s` when divisible by `p+1`.
* Preserve the prior binary/window method for tiny exponents, exponents outside `[p,p²-2]`, zero, and noncanonical public inputs.
* `Fp::half(a)` computes `(a+(a mod 2)p)/2` with a shift/add on canonical inputs; replaces multiplication by `inv2` in monic quadratic, Cardano cubic and Ferrari quartic paths.
* The linear-root case now skips inversion for monic polynomials and for zero constant terms. Cubic repeated-root algebra uses two modular additions for `3q` instead of general multiplication.

The before-control runs the same `Cube::root` implementation with identical precomputed constants and arithmetic, but its Fp2 ring uses the previous generic `rpow` rather than new `Fq2::pow`. Inputs are 256 deterministic cubed Fp2 elements, three repetitions per sample.

## Local Linux perf-event measurements

Pinned Intel Xeon Platinum 8573C, GCC/Clang -O2, thirteen AB/BA pairs. Used `perf_event_open(PERF_TYPE_SOFTWARE, PERF_COUNT_SW_TASK_CLOCK)` and wall-clock. The `perf` executable is **not installed**; attempted `PERF_COUNT_HW_CPU_CYCLES` and `PERF_COUNT_HW_INSTRUCTIONS` both returned `ENOENT`. Therefore no hardware-cycle/IPC claims.

These local figures are **independent C++ mirrors** of the field arithmetic, not compiled Rust:

| p=1,000,000,009; operation | GCC task-clock before → after (ns) | GCC speedup | Clang speedup |
|---|---:|---:|---:|
| Fp2 `x^(N/3)` | 1,440.156 → 197.358 | **7.297x** | **6.741x** |
| Fp2 AMM `x^e3` | 1,400.794 → 786.398 | **1.781x** | **1.750x** |
| Fp2 `x^t` | 1,424.640 → 187.234 | **7.609x** | **6.915x** |
| Modular half | 3.391 → 1.067 (wall clock) | **3.177x** | **4.161x** |

Local C++ correctness checked the old and new powers on 513 Fp2 inputs (including zero) times 3 AMM exponents across five primes, plus 4,096 modular-halving inputs across four primes. Production Rust separately checks diverse exponents including randomized u128 values, zero/noncanonical inputs and exact old/new complete Fp2 AMM roots.
