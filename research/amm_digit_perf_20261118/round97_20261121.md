# Root finding optimization: Round 97 (2026-11-21)

**Status:** Candidate on draft PR #4880; **do not merge yet**. Source baseline `baf8f8621b7a764f0f5705100f36af1090615db7` (Round 96); candidate `4aa3b8ea7cedbda9d5779b4210c92aac5e6e584c`.

## Change

The independent prime-field root-certificate verifier previously called `vdiv()` for every modular power reduction and discarded its quotient. A new `vpower_monic_remainder()` subtracts multiples of a normalized monic modulus directly and returns only the residue, eliminating a quotient allocation. This applies to modular-power multiply residues, square residues, and verifier PowerStep replay. Monic linear/quadratic control cases keep existing specialized paths. The high-degree loop is out-of-line to avoid bloating the small-modulus hot path. Both the producer's arithmetic trace and the certificate format are unchanged.

## Local software perf counters

On an Intel Xeon Platinum 8573C pinned to CPU 0, `g++ -O3 -march=native` and `clang++ -O3 -march=native` C++ reproductions ran 15 alternating A/B trials for 18 field/degree/sparsity configurations. Local `perf_event_open(PERF_TYPE_SOFTWARE, PERF_COUNT_SW_TASK_CLOCK)` succeeded. GCC median configuration speedup was 1.392× (range 1.048–2.227×); Clang median 1.586× (range 1.003–1.836×). The C++ baseline deliberately keeps the returned quotient allocation live. Both compilers passed 90,000 randomized equivalence cases apiece; GCC UBSan passed.

The `perf` CLI is not installed here, and direct hardware cycle/instruction counters returned ENOENT. These are software task-clock and paired elapsed-time measurements, **not hardware PMU counters**. C++ data is an algorithmic reproduction rather than production Rust performance.
