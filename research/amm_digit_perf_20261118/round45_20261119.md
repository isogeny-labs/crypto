# Round 45 (2026-11-19): quadratic Frobenius and linear-part GCD elimination

## Retained changes

In `src/cryptanalysis/prime_root_bounded.rs`, avoid generic degree-two polynomial modular exponentiation and polynomial Euclid for the producer **and** independent certificate replay. For a normalized quadratic `f(x)=x²+b x+c` over the admitted odd prime `Fp`, put `D=b²-4c`:

* If `D=0`, `x^p mod f = -b/2`; a repeated root remains.
* If `D` is a nonzero square, `x^p mod f = x`; the quadratic splits with distinct roots.
* If `D` is nonsquare, `x^p mod f = -b-x`; the quadratic has no field roots.

The producer computes the quadratic character using right-to-left scalar powering. The verifier uses a separate left-to-right scalar powering implementation. The result is only selected when exponent equals `p` and the base is canonical `x`, so split powering `(x+delta)^((p-1)/2)` is unaffected.

When extracting the linear part `g=gcd(f,x^p-x)` of a quadratic, the three cases yield respectively `g=x+b/2`, `g=f_monic`, and `g=1` without generic polynomial GCD. The verifier applies the same mathematical identity independently after checking the producer's event. No change to the root/event/certificate format.

Clang confirms a substantial reduction, but compiler-sensitive timing and gate/deadline cost explain why full native Rust gains are smaller.

The local `perf` executable was unavailable. Direct `perf_event_open` for **software task-clock, hardware cycles and hardware instructions** each failed with `EACCES` (errno 13), `kernel.perf_event_paranoid=2`. Thus local figures above are **CPU-pinned wall-clock timings, not hardware-PMU/perf counters**. The raw C++ sources, CSVs, UBSan output and kernel diagnostics are packaged in the round-45 automation attachment.

## Rejected candidates

* Dense degree-8 Karatsuba: C++ micro-kernel improved as much as **1.477x** (GCC) and **1.327x** (Clang), but actual compiled Rust produced about **1.000–1.001x complete-root speedup**, occasionally a small regression; reverted the production change and removed its CI job.
* Fixed-range monic remainder and division: pinned local C++ controls were often neutral or slower, e.g. degree-8 dense monic remainder **0.99x**; not retained.
