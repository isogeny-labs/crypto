# Round 17: cache AMM Sylow digit factors (2026-11-18)

## Source changes

Production `src/cryptanalysis/prime_radical_root.rs` now builds the per-field
`c^(-3^j)` table and its squared factors `c^(-2*3^j)` once in `Cube::new`.
For successful cube-root extraction with `s=v3(|K*|)>=3`, the active AMM
3-adic digit loop previously **re-cubed the inverse generator once per root
per digit** and **squared a correction factor for digit 2**. It now performs
two indexed reads for these factors instead. Specialized `s<=2` paths do
not allocate the tables. All exponents/branch conditions are unchanged.

New test `cached_sylow_factors_match_precache_roots` compares exact Fp/Fp2
root outputs for 10 primes on cube and mixed inputs against a frozen
pre-cache path. The ignored `bench_cached_sylow_factors` contains 13
AB/BA paired native-production-Rust timing trials, also including
`s<=2` controls. The isolated CI workflow now runs both.

### Rejected candidate

We separately screened replacing the extra multiplication by quadratic
nonresidue `n` in Fp2 norm calculation with the existing small-n
addition helper. Its standalone GCC/Clang timings varied, including
regressions of 0.973x (Clang cubes p=487) and 0.981x
(GCC cubes p=2^61-1), so **no norm rewrite was committed**.

### Caveats and next gates

- Native Rust CI benchmarks were queued on commit; no native Rust
  speedup claimed until isolated CI finishes.
- Per-context table initialization and memory cost are excluded from
  microbenchmarks. Measure full `RadicalRootCtx::new + roots()` at
  1, 10, 100, 1,000 roots per context before merging.
- No full polynomial-rootfinder, GPU, or ECDLP speedup is established.
- Variable-time arithmetic is intended for **public** rootfinder inputs.
