# Full-library qualification gate

## Cold baseline attempt

The original gate ran on a separate genuine checkout of exact baseline
7d61e3b45de6e93d235345a0061dae08db1f8b44, with unchanged default features
and Cargo.lock:

```sh
cargo test --release --lib --locked
```

It used one build job, a task-specific Cargo home/target directory and a
fixed 600-second deadline. The controller reached that limit while Cargo was
compiling isogeny_algos, before root-library tests started. The process group
was terminated with SIGTERM (exit -15). No compiler error or test outcome
was emitted. This is incomplete validation, not a failing test or an OOM
diagnosis. [pcc:unverified]

## Acceptance

The full unfiltered root-library suite must complete on a source revision
whose relevant library, manifest, lock and build dependencies match the
review head. Record build/test outcomes and source identity. Do not replace
that condition with a filtered suite, no-run build, feature pruning, ignores,
or the standalone study checks.

The named obstruction, now the duplicate production test module on the
final checked revision, is
[vitse-prime31-full-library-validation](../../problems/vitse-prime31-full-library-validation.md).
Source-bound native audit results remain usable at their stated development
scope while this broader integration gate is open.
