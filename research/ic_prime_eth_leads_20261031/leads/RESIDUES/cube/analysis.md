# B. Cube-class check (SYNTHESIS section 5 item 5), 2026-11-02
Pre-registration: ../PREREG.md. Size b=9 only (m=3, l=s=3, |F|=4, 10 curves selected on |F| only, 16 targets each = 160 instances; 84 SAT, 75 UNSAT, 1 cap-hit "direct" run). b=12 was not attempted: A showed 0/160 solved at 1e5 conflicts, so no cube comparison is possible there.
Method: 3 window bits fixed -> 8 cubes (units appended to the CNF), each cube solved by kissat 4.0.4 default with --conflicts=100000; direct = plain kissat on the same CNF (same cap). Classes (bit 0 = LSB of a window): hi = top bit of x1,x2,x3; lo = LSB of x1,x2,x3; one = all 3 bits of x3; rnd = 3 random window bits per instance. Total CnC cost = sum over all 8 cubes (SAT instances are not credited for stopping early). 5120 cube solves. Raw: raw/cube_results*.jsonl (merged, duplicates dropped), raw/sweep/ (direct), raw/B_table.txt.
Statistic: per-curve median over its 16 instances of log2(CnC/direct), mean over curves, 95% CI = bootstrap over the 10 curves (4000). Positive = cube-and-conquer costs more total work than plain kissat.

Reading. Every class costs more total work than the direct solve, on both conflicts (1.5x to 2.5x) and propagations (1.9x to 3.3x), CI excluding 0 everywhere; by the pre-stated rule none "helps". SAT and UNSAT instances behave alike (class x status table in raw/B_table.txt; e.g. hi: +0.55 SAT, +0.54 UNSAT). The ordering is the same on both metrics (hi < one < rnd < lo), so propagation counting does not rescue any class and amplifies the penalty (cubes re-propagate shared structure). The only favourable number is the largest-cube/direct ratio, 0.65x to 0.83x of the direct solve: with 8 workers the wall time (conflict proxy) would be at best 1.2-1.5x lower for 1.5-2.5x more total work, a parallelism trade, not an algorithmic gain. Top bit of each window (hi) is the least-bad class; lowest bits (lo) is worst, which is what one expects if the solver already branches on high bits first (not tested).
Limits: one size (b=9), 3-bit cubes only (no cube depth sweep, no lookahead/march-style cubing, no cube ordering/early stop for SAT), kissat default for both arms, 10 curves with |F| fixed at 4, 144 unique targets of 160 (planted repeats), conflict cap 1e5 (1 direct and 1 rnd-CnC cube hit it; the ratios treat them as lower bounds), `nice` unavailable so no CPU times. This says nothing about exponents; it agrees with the prior verdict that the SAT lane at this encoding gives constants only.
