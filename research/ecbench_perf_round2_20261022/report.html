Not done

Most of a prime rho step is its one field inversion (~110 ns at 32 bits). Batching inversions across walks (Montgomery's trick, in-order commit) would keep every walk and group-operation count but change the counted field_ops (inversions per step), which the accounting contract says must be what the code performed; that is an owner decision, not an identical-output change. Barrett multiplication and a quotient-1 Euclid shortcut were measured slower on this host (microbench/).
