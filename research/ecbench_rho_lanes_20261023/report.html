rho.negation_lanes: Pollard rho with batched inversions (2026-10-23)

A new ecbench method beside rho.negation, whose code and counts are unchanged. It runs rho.negation's step rule (negation classes, look-ahead, cycle escape, distinguished points) as lanes walks in lockstep on a prime curve; each round's additions share one field inversion (Montgomery's trick). Every addition any lane performs is charged, including the walks still in flight when another lane's collision recovers the logarithm, so S is a few percent above rho.negation's. The field_ops block records the work actually done: 3(n − 1) multiplications and one inversion per round of n additions, then 2M + 1S per addition, against rho.negation's 2M + 1S + 1I.

Four sessions per curve on one binary, every arm alternated within each session over the same targets and rounds; warm-up excluded. The A/A control (rho-neg-aa) is a second copy of the reference arm. Every session replays exactly (ecbench verify --replay-all, 2200 replays). At 32 bits a rho step's single field inversion (word extended Euclid, about 110 ns) was most of its wall time; shared over a round it costs a few nanoseconds, and the step becomes instruction-bound (about 680 instructions per group operation in Callgrind, for both methods).

This is a wall-time result. In the counted unit (S, GAE/√r) the lanes method costs 4–30% more than rho.negation, so it is not a stronger matched rho reference for index-calculus comparisons, which are made in that unit.
