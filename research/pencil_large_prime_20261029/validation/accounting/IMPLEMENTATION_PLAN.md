# Source-bound pencil counted-cost completion plan

This is preparation, not an experiment or frozen amendment. No repository was
changed and no cohort was run. The source manifest binds the inspected files.

## Original required outputs versus supplemental evidence

The frozen four-followup protocol requires all 1,260 public known-answer targets,
independent source checks, all cold algorithm phases, raw/normalized targets,
all 36 arithmetic/logical prices, failures retained, graph and PDF. It explicitly
names field additions, hashes, graph and scalar work. The exact grid is
S/M={0,0.5,1}, I/M={1,10,100,1000}, native GAE/logical={0,0.1,1}.
The representative point is (0.5,10,0.1). `historical-price-contract.json` records
both original analyzers' exact category formula and their scalar asymmetry.

Qualified whole-method-call time is a separate legitimate metric. New allocator
instrumentation is NOT required merely to compare this timer or existing RSS.
RSS, allocator events/bytes, harness/parent time, checkpoint costs and cloud costs
have no historical GAE weight; preserve them separately without inventing a
price. A complete cold wall comparison cannot silently replace the specifically
requested 36-cell operation-price result. Conversely the cost model need not
pretend to count every machine instruction or allocator implementation detail.
It must declare and cover every semantic category it prices consistently.

## Step 1: native analyzer-only work (no algorithm rebuild)

1. Implement a versioned cost-contract parser and explicit category whitelist in
   Rust, rather than summing every `_uncharged` suffix or every numeric field.
   Freeze all 36 inherited cells, units and source-addition denominators. Record
   historical formula separately; never overwrite old ratios.
2. Reuse `scalar_ledger::pencil_atomic` and `rho_atomic` with checked arithmetic.
   In the inherited model atomic scalar addition/negation, multiplication and
   inverse each contribute one native event. Do not give scalar inversions the
   base-field I/M price. Removing expanded inverse multiplies changes the old
   pencil interpretation, so identify this as a symmetric-model amendment.
3. Build disjoint field/base/symbolic/scalar categories from exact raw paths.
   Refuse missing categories, invalid subtraction or count overflow. Preserve
   all original counters and normalized values in output. Residual row updates
   are diagnostic if their arithmetic is already in primitives; map-call plus
   comparisons cannot both be casually priced as a single same-kind event.
4. Join exact workload, stream seed, arm, source/build and run identity. Verify
   candidate and rho outcomes independently. Emit null candidate prices for
   caps/failures and require complete denominators for a full-cohort total.
5. Emit per-target cells, slice/cohort ratio-of-sums, phase breakdowns and
   coverage flags. Avoid a winner-selected subset or average-of-ratios. No
   existing partial raw stream becomes complete through analyzer arithmetic.

Required analyzer assertions: exactly 36 distinct cells; correct representative
cell; denominator positive and same paired source unit; disjoint category sum;
phase plus setup equals cold total; preserved integer inputs; counter overflow
refusal; warmup exclusion with retained flow; no computed ratio for failed or
missing partner. Test synthetic counters with hand-derived exact prices,
independent scalar helper event traces, missing fields and cap fixtures.

## Step 2: instrument changes requiring a new binary/image

A. Initial source/scalar primality validation currently calls unmetered
`engine::is_prime` before internal setup metering. Add a native primitive-ledger
context around the actual outer validation. Reuse the existing implementation
or factor a counting callback through it; do not replace its arithmetic or add
extra primality calls to rho solely for symmetry. The reference records zero
for absent validation work, and actual work when present. Tag modulus domain.
Miller-Rabin powers are ordinary multiplications, not inversions. Preserve
constructor primality counts already in the symbolic ledger and count them once.

B. Add counted wrappers for actual non-symbolic BTreeSet uses in the sieve and
for corresponding reference hash/key/lookup operations. Preserve numeric key
order, iterator size hints, candidate ordering and random draw sequence. Define
separate structural observations (API calls, key comparisons, visits) and choose
an explicit nonoverlapping priced set before results. Do not count all three
indiscriminately as historical 'one logical operation'. The current historical
analyzers establish the weight, not an exhaustive new event-definition mapping;
that mapping needs a reviewed amendment before claims.

C. Add loop-local native counters at node inventory construction, root-list
cloning, sieve scans, bucket traversal, initialization/copy and candidate
verification bookkeeping. Reference jump-table/walk state and graph traversal
use the same event definitions. Count actual iterations and rejected attempts;
never infer work solely from final rank, retained coefficients or successful
relations. Record countable teardown/report/calibration overhead separately if
included in the declared cold semantic boundary.

D. Allocation observations are optional supplemental output, not a new GAE
requirement. If retained, install the existing System-forwarding observer once
in the ecbench binary and open equivalent candidate/reference method regions.
The current candidate passes None and must not claim observed allocation. A
thread-local scoped enable guard must exclude serialization and unrelated
concurrent activity; preserve missing values when unavailable. Keep successful
requested layout bytes, call/failure counts and net growth distinct from RSS.
No allocation price is implied by instrumentation.

Required instrument checks: unchanged mathematical outputs/order/streams; exact
counts on a small independently traced prime/composite validation; rejected-row
and empty/full bucket cases; checked phase totals including between-phase work;
no double counting constructor validation; independent known set operation
sequence; symmetric wrapper semantics; scope reset/teardown tests. Rebuild and
re-pin binary/image after these changes. Old records cannot reconstruct missing
actual comparisons/allocations reliably and must not be backfilled by estimates.

## Step 3: review and frozen execution

The cold clock path may proceed under its qualified, already explicit scope
without waiting for supplemental allocator counts. To discharge the original
counted-cost requirement, complete Step 1 plus mandatory coverage in Step 2,
freeze the event-definition amendment and analysis source, then collect required
cohort records with that instrument. If run costs make separate clock/count
instruments undesirable, finish this instrumentation before the cohort and
measure both once, without changing caps or targets.

Retain the original p739 gate then upper p186379 target0/replay, 25m coefficients,
8GiB and3600s. Do not extend after a scientific cap. Preserve every computation,
control, warmup, gate, replay, interruption and restore cost in the export.
CRIU computation is timing-invalid and the fresh L2 benchmark epoch is separate.
Infrastructure costs are study costs, not hidden additions to the algorithm's
GAE denominator; report both scopes clearly.

## Specific unresolved design decision

The original logical unit weights are known; the mapping from newly instrumented
map/sieve primitives into a disjoint logical event set is not yet frozen. No
numerical performance result may choose that mapping after seeing the data.
This plan proposes implementation points and assertions, not new favorable
weights or a complete-cost claim.
