## Borrowed lookup copies (pre-data clarification)

A successful borrowed map lookup charges one entry visit. If its caller materializes the returned entry into owned values with `.copied()`, `.map(|&v| v)`, or `let/while Some((&k,&v))`, charge one copy event; a tuple is one collection element. The two `first_key_value` consumers in graph anchoring and residual pivot processing follow the same rule as the reference `seen.get` extraction. A direct borrowed lookup does not itself charge a copy.

Iterator consumption already charges an entry visit. Its fixed scalar locals do not add copy events; explicit formation of a retained output element follows the existing map-to-vector copy rule. Moves from owned insert/remove/into_iter results, argument passing, arithmetic operands and fixed whole-record moves are excluded. This finite semantic convention does not count register moves or all CPU instructions.
