# First-gate protocol preparation requirements

This is a preparation checklist, not a freeze, approval request, launch or
execution receipt. Sources checked: the experiment-protocol skill, the current
accounting amendment, its two first-gate resource authorizations, the reviewed
controller/runtime artifact manifest and the publisher trust readback receipt.

1. Derive a new gate-only protocol from this preserved full-cohort draft and bind
   the existing `gate-p739.json` plan. Retain all 60 prescribed targets, candidate,
   rho and rho A/A arms, one warmup and five measured rounds per target/arm, the
   original measured-index seed policy and interleaved order. The gate denominator
   is 1,080 planned arm executions: 180 warmup and 900 measured; 300 measured
   candidate/reference pairs. Keep the parent 1,260-target objective explicitly
   linked. Gate termination cannot silently reduce either planned denominator.
2. Scope sample-size, analysis input manifests, expected denominator and output
   descriptions to this gate. Preserve the same exact cost mapping, common cold
   interval, five online phases, per-target five-replicate A/A calibration rule,
   resource sidecars, failure/null rules and independently reviewed source-linked
   replay contract. A missing or invalid partner never becomes a qualified ratio.
   This scope adjustment does not authorize changing scientific controls or seeds.
3. Bind the actual immutable image digest, versioned downloaded-and-verified
   controller/runtime artifacts and completed package-only controller update
   receipt. Bind the accepted request, exact instrument hash and prepared plan,
   runtime memory limit of 8 GiB and observed admission/owner reconciliation.
   Approved publication/update actions need no additional approval; unfinished
   execution evidence must not be replaced by an authorization record.
4. Carry the first-gate cumulative limit of 14,400 additive worker-execution
   seconds and absolute UTC deadline 2026-10-30T03:32:22Z into the actual admission
   and stop mechanism, including controls, warmups, attempts, recovery and fresh
   validation. Enforce the remaining allowance, not a fresh allowance per worker
   or epoch. Retain the 3,600-second per-execution and 25,000,000-coefficient caps.
   Do not change the legacy Diem deadline. Later-stage budgets remain unresolved.
5. Keep recovery computation clocks invalid; require the existing fresh L2
   measurement, explicit attempts/resumes history, memory observations and A/A
   evidence for qualified clock exports. Preserve observed failures and all
   missing planned rows if the budget or deadline prevents completion.
6. Resolve the current null preflight-runtime fields honestly before frozen
   validation: the canonical frozen protocol requires an estimated total runtime,
   while the skill asks for measured call costs. An allowed maximum budget is not
   a measured runtime estimate. Record actual evidence or an explicit justified
   protocol treatment; do not invent a calibration measurement. This is a
   protocol-field requirement, not an inferred new user-approval flow.
7. Once the factual bindings and admission requirements are resolved, run the
   native validator, freeze the gate protocol with its canonical body hash and
   immutable source provenance, and commit it before affected measurements. Keep
   this amendment and all prior drafts intact. Bind canonical exports to that
   frozen gate identity and retain the raw/native outputs and resource history.

No experiment, deployment or additional approval has been performed by preparing
this checklist. Software review and deterministic analyzer replay remain distinct
from empirical instrument, clock and cost-ratio qualification.
