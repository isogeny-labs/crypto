# Explicit unknown-runtime characterization gate — software validation

This change preserves the default frozen-protocol requirement for a runtime estimate. A narrowly defined opt-in accepts unknown runtime only for the exact existing p186379 target0 gate. It does not convert a budget into an estimate or authorize execution.

Extension: `extensions.unknown_runtime_characterization_gate`, schema `pencil-bounded-unknown-runtime-gate/v1`. Required fields are runtime_estimate_status="unknown", resource_caps_are_not_runtime_estimates=true, remaining_cohort_blocked_until=["complete_gate","all_15_measured_independent_nonwall_replays","independent_review","separate_prospective_cohort_admission"], and absolute path/SHA256 bindings resource_authorization, execution_request, operational_review, prepared_spec. These bindings must equal the protocol's existing corresponding bindings; upper_gate.admission_conditions must equal the barrier array. Existing known-data terminal-state binding must also use a resolvable absolute path.

The helper verifies exact upper-gate scope, sample and arm geometry, fixed instrument and methods, finite36 model and decision statistic, unqualified clocks, single-replacement semantics, known b1 failure/records and amendment, resource-only authorization, positive finite execution/cumulative bounds, parsed start/expiry, reviewed conditional guard arithmetic, and hash-bound exact request/spec. It does not treat the conditional guard as an unconditional host-failure guarantee or infer live owner reconciliation.

Fixture copies are retained protocol/request/evidence examples used only as software test inputs. Tests mutate their semantics and hashes locally, and do not launch or replay any scientific workload. Ordinary missing-estimate rejection, opt-in acceptance, caps, timed primary, cohort relabeling, shadow bindings, mapping/grid, arm roles/identity, history, resource-only authorization and synchronized evidence-body mutations are covered.

Current implementation stays in existing hash-bound protocol_lint.rs and lib.rs. No producer, analyzer, pricing, frozen protocol or old validation artifact changed. Historical known-data context is not a new measured result. Release library tests, strict all-target Clippy and formatting logs are retained here; build receipt records the final executable separately. Independent review is required before any new protocol binding/freeze.
