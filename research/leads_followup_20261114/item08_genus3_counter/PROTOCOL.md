# Item 8 PROTOCOL: genus-3 point counter for smooth plane quartics (lead J1)

Frozen 2026-11-14 before any data run. Source `jcount.rs` was compiled (no runs) before this file was written.
All claims are [pcc:unverified] assertions. Amendments, if any, go in a dated "Amendment" section at the end.

## Instrument
`jcount.rs` (rustc --edition 2021 -O, std only). Input: q (odd prime, 3 < q < 2^31) and 15 coefficients in the
order of `pic::mons_of_degree(4)` (f[0] = x^4, f[1] = x^3 y, f[2] = x^3 z, ...). Output N1,N2,N3, Newton/L-polynomial
coefficients, #J = P(1), factorisation, Weil-interval check. Smoothness is checked first with the same certificate as
`pic::smoothness_certificate` (rank of (F_X,F_Y,F_Z)_7 = 36). Counting: per x in F_{q^k} (up to Frobenius orbits)
deg gcd(F(x,y,1), y^Q - y); y^Q mod g via y^q and Frobenius matrix steps; z = 0 points from the binary quartic.

## Cells (exact)
V1 brute-force validation: q in {5, 7, 11, 13} (30 random smooth quartics each, seeds 1), plus q in {17, 19} with 8 curves each
   if time allows. q = 1 mod 4 (5, 13, 17) and 3 mod 4 (7, 11, 19) both present. Random quartic = 15 uniform coefficients,
   rejected if not smooth. Compare N1,N2,N3 from `jcount count` path with `brute_k` (evaluates F at every point of P^2(F_{q^k}),
   shares only the field arithmetic Ext with the counter) and check Newton integrality (N_k give integral L-polynomial).
V2 GHS validation: instances of `quartic_n4v2_20261020/results/instances.jsonl` for q = 223 and q = 499 (all 5 seeds each if
   time allows, at least seed 1), plus additional GHS instances generated by `Inst::search` (same builder, unmodified,
   `ghsgen.rs` includes ghs.rs by #[path]) at smaller q = 7 mod 12 primes (q in {103, 127, 139, 151} or whichever the
   builder accepts) so that at least three distinct q are covered. Expected relation: #J = `order` (= #E0(F_{q^3}); v2 homcheck
   tests `#J * x == 0` with inst.order). Check: counter's #J == order exactly.
V3 independent check on generic curves: for generic cofactor-<=8 quartics found in step 4 the adapter checks
   `mul_scalar(x, #J) == zero` on random Pic^0 classes with the library arithmetic of pic.
T timing: one random smooth quartic per q, 1 thread, q in {31, 61, 101, 151, 211, 307, 401} for N1,N2,N3 and q in
   {1009, 2003} for N1,N2 only; 2-thread repetition at the largest q measured for N3. "Feasible" = one N3 at most 20 min
   wall on 2 threads on this host (cost of a search for cofactor <= 8 needs about 7 to 15 counts, so the adapter step uses a
   lower q).

## Predictions (frozen)
P1. N1..N3 agree with brute force on every curve of V1 (0 mismatches), and Newton integrality never fails.
P2. #J == order for every GHS instance checked (0 mismatches), and Weil interval check true.
P3. Counter cost per Frobenius-orbit representative of x for k = 3 is constant in q within a factor 1.5 (q >= 100),
    between 5 and 40 microseconds; hence N3 time ~ q^3 / 3 * (that constant), N1+N2 negligible against N3 for q >= 100.
    Predicted N3 single-thread time: q = 211 in 30 to 150 s; q = 401 in 4 to 20 min. Predicted largest feasible q on 2 threads
    (<= 20 min) is between 400 and 700.
P4 (step 4). The D family of the adapter recovers the planted log (verified through `Pic` equality x*P == Q) on 3/3 random
    cofactor-<=8 quartics at each of the two q tried; D cost in M-eq scales about q^1.0 as in the GHS record (README), within
    a factor 2 of the GHS D unit of the nearest q. Q = 3 mod 4 required (hidden restriction of v2).
Falsifiers: any mismatch in V1 or V2 falsifies correctness of the counter (stop and debug, amendment); P3 constant off by
more than 1.5x across q falsifies the q^3 cost model; any failed D recovery on a generic Jacobian falsifies "generic
Jacobians with ell || #J run unchanged" and is reported, not hidden.

## Instance rule for step 4
q prime, q = 3 mod 4, random smooth quartic with N1 >= 4, J = #J from the counter, accept when J = cof * ell with cof in 1..8,
ell prime and ell > 8 (smallest cof first). Planted instance: P = cof * (class of random Pic^0 element) of order ell, Q = x P with x
uniform in [1, ell-1]. Seeds in the instance files.
