# Exact rationality/support bundle and reuse boundary
Use C76's proven label t=X+A+sqrt(B)/X after stripping every X root (rational torsion). C82b returns the same exact sum of83Frobenius powers in the quotient, including nilpotents; its multiplication-image polynomial is identical. For split degree<=5 H, image coefficients e1,e2,e4 encode the anti-rational root count with multiplicity. On generic nonsplit H they remain necessary conditions only, not a standalone exact support test. This component does not compute new complete original root sets.

The binary prefix D has a separable linearized subspace polynomial L_D. For monic H of degree1..5, H divides L_D^8 iff every root of H lies in D: every such root has multiplicity<=5<=8; the converse follows from polynomial divisibility over an algebraic closure. Computing L_D modH then three quotient squarings therefore gives exact source support with repeats and zero retained. This oracle bounds degree explicitly and must not be reused unchanged for higher multiplicities.

Field coefficient-Frobenius maps depend only on field/basis, so one map is paid per complete batch. Each new H must rebuild all quotient-power columns. The support scalars are also paid once per complete batch. Reference and shared bundles both return every support decision plus every label/image polynomial for all36cases, so matching contracts can be compared. Standalone support returns fewer outputs; its timing is a separate cost diagnostic, never a matching algorithm ratio.

The main-target rationality theorem is C74; the32exposed relaxed/fresh norms use that scope. Four point fixtures belong to other targets and include valid ghost branches. Their anti-root labels are classified and checked, never promoted to an unconditional rejection rule for original polynomial roots. New independent main pruning means support==true and rationality_reject==true on a main-scope input. If no such case exists, faster label computation has no demonstrated pruning benefit over support.

Small point enumeration and repeated-root factor division supply independent label/support oracles. The actual panel is an exposed calibration family reused by an explicit rule, not a new hard holdout. Field size and batching cannot certify hardness. No universal solver/novelty/speed claim follows from this integration.
