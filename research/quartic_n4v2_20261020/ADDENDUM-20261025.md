1. **CPU time.** The pilot showed each `nice -n 10` process receiving 5-12% of a core (load average
   120-330), so wall seconds mostly measure the scheduler share, and IC and rho jobs run under

   (`verify_star`, `verify_d`) are timed separately (`s.controls_wall`, `s.controls_cpu`) and no
   longer fall into the matrix phase of the new arms. B0's matrix-phase wall still contains its own
   checks (N4's code); the size of that is reported.

## B0 at k = 22: blocker restated

PROTOCOL.md gives memory as the reason B0 is not run at k = 22. A second, harder reason: N4's
`ic::pack()` packs coordinates in 21 bits (needs `q < 2^21`; q = 4194271 is above) and N4's
`ic::la()` overflows for `ell > 2^63` (k = 22 has `ell ~ 2^64`). B0 at k = 21 is valid
(q = 2097091 < 2^21, `ell < 2^62`).
