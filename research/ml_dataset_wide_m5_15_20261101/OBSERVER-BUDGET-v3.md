# Higher-arity native observer loan correction

The stopped v2 run's first replay failure was cell 16 (n47, m13, untwisted). The native event observer acknowledged 27 native callbacks, then left callback 28 pending. Its observer loan was `available.work / 4 = 2,463,122`; it had reserved 2,408,448, leaving 54,674. Each bound-capture callback must first reserve `CALLBACK_WORK = 81,920` plus metered JSON serialization. Thus the next callback cannot fit the loan, independently of the 64 MiB trace-byte cap. The terminal only records generic native `observer` and `persistence_failure`, so replay cannot distinguish this budget exhaustion from an actual capture/I/O failure; the adapter now fails closed for that stop.

The source uses a fixed root work ceiling of `min(work_limit * 1024, 16,777,216)`. At the frozen work limit 50,000, the algebra pool is 12,582,912 and the post-setup native-plus-observer allowance in the saved m13 record was 9,852,488. The original quarter split gave each native event observer 2,463,122; the higher-arity half split gives it 4,926,244 while leaving 4,926,244 for native F4. The independently admitted group-checking pool remains 4,194,304, and the terminal has a separate 262,144 reserve inside algebra. The m4 loan stays at one quarter for historical replay.

The input constructor has exactly `2m−1` polynomials. Native F4 emits Begin and Initial, then at most one Basis callback for each initial insertion. The m15 initial prefix therefore needs at most 31 native callbacks, or 32 if a Terminal callback follows; later batches can emit more, subject to the fixed 4,096 event ceiling and remaining work. The half loan is not a universal proof that every possible m15 F4 trajectory can persist; the fail-safe guard remains necessary. The frozen-seed n47/n61 m15 both-twist boundary test checks the actual intended matrix, including a terminal with no pending event and no native observer stop.

This is a repartition of an existing bounded work pool, not an increase of total requested work, trace bytes, memory, or per-cell time. Any replacement run uses a new source-bound binary and a dated v3 protocol/plan at a new path. The v2 raw run and its invalid cell remain unchanged.
