1. ADX/MULX kernels (src/ecc/mont_vt.rs)

  • mont_mul4_adx: inline-asm 4-limb Montgomery product (CIOS). Each row adds the low halves of the mulx products on the adcx (CF) chain and the high halves on the adox (OF) chain. After the reduction the register holding t₀ is exactly zero and becomes the next row’s top word, so the one-word shift is a register rotation, not moves. Uses all 13 allocatable GPRs; p and n0 are read from one per-context array.
  • Mont::mul_mulx: CIOS on the _mulx_u64 / _addcarry_u64 intrinsics for every width, compiled with #[target_feature(enable = "adx,bmi2")].
  • Both run only after a one-time is_x86_feature_detected!("adx") + "bmi2" check; without ADX nothing changes.
  • ProdAdxKernel (production on ADX CPUs, chosen once per scalar multiplication): asm product + tuned dedicated squaring at 4 limbs, mulx CIOS (products and squares) at 6–9 limbs, the tuned kernel at 2–3 and 5 limbs.

At 6–9 limbs the compiler’s code from the mulx/addcarry intrinsics beats the u128 CIOS by 5–10% per scalar multiplication even through a non-inlined target_feature call. Arms adx (asm squares too) and adx_wnaf gave nothing beyond adx_sqr / tuned_wnaf.

2. Half-GCD (src/gcd/)

One half-GCD driver (hgcd.rs, von zur Gathen–Gerhard §11.1 / Thull–Yap) over a PolyRing trait, instantiated for:

  • poly: F[x] over any field (PolyField trait; Fp64 for p < 2^63), Karatsuba products;
  • gf2: bit-packed GF(2)[x] with PCLMULQDQ carry-less products (portable fallback);
  • int: integers — binary GCD and a one-divide-per-step unsigned inverse on words; for BigUint, Lehmer (Knuth Algorithm L on the top 62 bits) and a recursive half-GCD (Schönhage/Möller control structure) that applies only validated, progress-making unimodular matrices and otherwise takes one exact division step, so the gcd is exact whatever the truncation does.

All entry points return canonical results — monic polynomial gcd, the classical minimal-degree Bézout cofactors, integer cofactors reduced to the classical range — so every algorithm and threshold gives bit-identical output. Unit tests force the recursion at every size and compare with classical Euclid (F_p for seven primes from 2 to ~2^63; GF(2) to 6000 bits; integers from 1 to 40 000 bits including a Fibonacci worst case).

Bugs found and fixed while measuring

  • Equal-degree polynomial inputs started the remainder sequence with a swap instead of classical Euclid’s first division: valid but non-canonical cofactors. Found by the unit test; fixed in prepare.
  • The integer recursion could loop forever when the truncated top part of b was already below the recursion target (identity matrix accepted as “progress”). Now a matrix is applied only if it shortens b.
  • The benchmark’s “never” threshold (usize::MAX) wrapped to −1 when cast to isize, so the first crossover run’s “Euclid” arms for F_p and GF(2) actually ran half-GCD; production thresholds never hit the cast. The first hgcd_raw.jsonl is kept but its F_p/GF(2) Euclid arms are invalid; the integer arms of that run are valid. Crossovers above come from the rerun on the fixed binary.

3. Routing the library through crate::gcd

Owner’s scope choice: every non-frozen GCD / extended-GCD / inverse site. An inventory found 372 definitions in 247 files (plus name variants such as mod_inv, invmod, inverse_mod). Six agents, each owning disjoint files, replaced bodies with calls into crate::gcd while keeping every signature and observable behaviour (monic vs raw results, zero and non-unit handling, panics, call-count hooks such as jv_bitops::hook_inv). Per their reports about 260 definitions were routed; the lead then reverted four files and, after CI, restored thirteen more (below), leaving roughly 220 routed definitions. Everything compiles (cargo check --lib --bins --examples --tests; the only error is a pre-existing example that includes a research/ file outside the sparse checkout).

Not routed, by rule:

  • hash-pinned or digest-bound sources (smith protocol sources, utils/mod.rs, poly_f2m.rs, cover_transfer.rs, fp_poly.rs, checker.rs, fixed_f8_order.rs, prime_split_sextic_oracle.rs, jacobian_certificate.rs, odd_extension_transfer_pilot.rs, mceliece.rs), frozen reference copies inside tests, and files declared frozen or byte-identical copies (koblitz fixture/strong instruments, r6_2_pooled_class_rho.rs, tree_split_structured.rs);
  • separate crates (isogeny_algos/, crates/*, tools/*), which cannot depend on crypto_lib;
  • every site whose arithmetic threads recorded operation counters, work gates, certificate traces or replayed accounting (Cnt, FieldOps, Nat, muls +=, gate.charge, OpCounts, Fp2 counter windows, prime_root_trace GcdStep events, vieta_coset half-GCD budgets): a different algorithm there would change recorded GAE/op counts;
  • hand-tuned fixed-width kernels whose speed is the point (ic_boundary::invmod* asm/32-bit paths behind every ecbench affine addition, fp_backend Pornin/Kaliski/binary inverses, Mont::inv_bingcd);
  • coefficient types that are not Copy (BigUint polynomial coefficients), and Fermat inverses whose modulus is not known prime.

Restored to main after CI (provenance): twelve library sources that research crates compile by #[path] include (where crate::gcd does not exist) — binary_ecc/trace_zero.rs, binary_radical_root.rs, curve_id.rs, f4_fp.rs, isogeny_walk/poly.rs, plane_quartic_pic.rs, prime_fast.rs, residual_walk.rs, semaev_prime_poly.rs, smith_prop24.rs, three_leads.rs, ecc/field.rs (found by scanning all 1940 path-including files after the software check failed on the five_leads_e2e crate) — and koblitz_strong_rho.rs, the standing rho reference, whose git blob is pinned by docs/ic/validation/reference-currency.json (the recompute check).

Reverted by the lead after review (speed or provenance): prime_fast.rs (division-free binary inverse in the FastCurve rho walks; its root-finding gcd now uses half-GCD above the crossover only), isoclass_rho/field.rs (per-step F_{2^m} inverse would allocate), hyperelliptic_word.rs (stack arrays + table inverse), jv_sieve.rs (hash-checked by sha256sum -c in live preparation scripts).

Speed effect on routed sites. Most routed sites pass small operands (degree ≤ 8 Cantor/quartic gcds, single-word integers); for them the shared module runs its classical kernels, so the effect is neutral to positive (binary GCD; one-divide unsigned inverse, the same algorithm the fastest local copies used; Lehmer for BigUint, 1.3–2.6× over num-integer’s gcd and 4.3–5.5× over a classical BigInt extended Euclid on 256–8192-bit operands). Half-GCD itself engages only at the sizes in the crossover table.
