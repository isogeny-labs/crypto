## 2026-11-05T04:22Z — ecdb /v1/sql: session reset no longer deallocates the client's type-lookup statements

### What was done (commands, files, features)

`ecdb/src/api/sql.rs` replaced `DISCARD ALL` after each request with `SESSION_RESET`: CLOSE ALL; SET SESSION AUTHORIZATION DEFAULT; RESET ALL; UNLISTEN *; pg_advisory_unlock_all(); DISCARD PLANS/TEMP/SEQUENCES; and a DO block that deallocates only SQL-level prepared statements (`pg_prepared_statements.from_sql`). This is DISCARD ALL minus the deallocation of protocol-level statements. Added `ecdb/tests/sql_session.rs`, run against a local PostgreSQL 16.15 with a pool of one connection. Before the fix it failed at a second, fresh enum column with `400 {"code":"26000","error":"prepared statement \"s3\" does not exist"}`. After the fix it passes. Swapping the reset for a no-op (mutation) makes it fail on the leaked advisory lock. `ecdb/src/db.rs` got a comment: RecyclingMethod::Fast runs no SQL, so it is not affected.

### Decisions made (and why)

Did not use `Client::clear_type_cache()`. In tokio-postgres 0.7.18 it clears only the `types` map and keeps the cached `typeinfo`/`typeinfo_enum`/`typeinfo_composite` statements, which are the ones DISCARD ALL deallocates. Calling it would cause more lookups through the dead statement, not fewer.
