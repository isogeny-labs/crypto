### Decisions made (and why)

- The new oracle is in the **generic decomposition** track per
  `AGENTS.md` §"Tracks of index calculus" (it enumerates the base and tests
  against it); it is not an algebraic/F4 result and is labelled as such.
- Equivalence is established by an exact census, not by sampling or by the
  density argument: the CZ oracle can miss a root it fails to split, so the
  test asserts equality for the anchored sweep and containment for CZ.
- No exponent claim, no vs_ρ claim.  Per relation-search pass the cost is
  still `~p·c`; only `c` moved.  No IC-leaderboard row is touched: this is a
  stage record in the boundary ledger, not a validation-gated leaderboard
  entry (no independent replay or isolation receipt in this session).
- Recorded the pre-change tree as a control instead of attributing the
  whole gap to this change: the ledger's 2026-10-05 a = −3 rows (20-bit
  18.7–37.2 s, 24-bit 272–513 s) are **stale**; HEAD~1 already runs those
  fixtures in 0.55 s and 8.3–9.6 s.  The variable-time inversions alone are
  ~1.6× (16-bit 0.0332 → 0.0213 s, 20-bit 0.5505 → 0.3315 s).
- Wall times are exploratory (shared host, load average 6–24 on 14 cores);
  `trials`/relation is the counted quantity, and the 1.0 readings at 16/20
  bits are censored below (first draw already decomposes).
