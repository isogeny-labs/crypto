### What was done
- Installed `gawk` and `linux-tools-generic` (apt) so `tools/profile.sh` runs; the host has no PMU, so perf samples `cpu-clock` only. Probe: software sampling, callgrind yes, GPU no. [pcc:unverified]
- Built fixed jobs from the round-039 holdout (`ecbench profile-input`, 160 per arm, run by `ecbench exec`; `exec` reproduces the stored counted cost, job 642 `total_gae` 10664) and profiled both arms (`round-039/profiles/k28-{sel,inc}-cpu`): `sel`'s solve has 1.365x the samples of `inc`'s; curve addition is equal, the difference is page faults (17% vs 10%) and hash inserts (12% vs 3%) on the walk table. The table was already pre-sized, so growth was ruled out.

- Replaced the `TargetWalk` `HashMap` (48-byte entries) with `TwTable` (40-byte slots, load at most 3/4, one `madvise(MADV_POPULATE_WRITE)` for tables of 256 KiB or more, doubling if undersized) in `src/cryptanalysis/ic_boundary.rs`. Unit tests: 10 passed (4 new, 6 existing `target_walk` and wwalk pipeline tests). Interleaved A/B of the `main` build (sha256 1b86126f...) against the new build (38d7d1b0...), five rounds, 160 workloads per arm: `sel` mean solve wall 3.150 to 2.329 ms (0.739), `inc` 0.984, A/A 0.9967 and 1.0005; all non-timing report fields identical on 320 jobs. ### Decisions made
- Kept the change in the walk's own table, not a global allocator: the harness trims the allocator before each solve on purpose, so a global change would move every arm's wall time.
- Did not run an `ecbench run` session or add a benchrec record: that needs the owner's checkpoint waiver or an upload token, and S3 is unavailable. The result is labelled development evidence and no leaderboard or `benchmarks/` row is added.
- Renamed a duplicated test function in `ic_framework/plugins.rs` (defined twice on `origin/main`, E0428, so `cargo test --lib` did not compile) in its own commit.

### Open threads
