### Decisions made (and why)

- Independence is a signature by a keyring key, never a boolean: the only
  thing a producer session cannot forge is a signature with a key it does
  not hold. Verdicts are signed in CI on `main`, so the producing session
  never verifies its own work.
- The ledger is tamper-evident, not tamper-proof: a rewrite is caught by the
  base-prefix check on the pull request, which is what git on `main` can
  witness. An external anchor (the S3 checkpoint push on every bypass) covers
  what a rewritten branch would hide.
- No execution-proof backend is claimed. `execution` proofs are
  `not_covered` until the owner pins a verifier digest in the keyring; the
  mock verifier exists only inside the canary fixture. The in-house STARK is
  not wired.
- The PR-body prose lint is strict from the first pull request: a strong
  word with neither a `[pcc:ID]` citation nor `[pcc:unverified]` fails. This
  is the chat-answer rule applied where CI can see it.
