### Decisions made (and why)

- **Meta-finding drove every verdict.** Relation collection is 84–89% of an
  `ic logs` run; linear algebra is 0.11–1.9%; `row_ops` are unpriced in the ranked
  `S` metric (verified from `research/ic_linalg_pipeline_20261019/` and
  `docs/ic/ECDLP_RESEARCH_TECHNIQUES.md:1151-1153`). So any lever that is not
  cost-per-relation in the decomposition oracle, and that cannot beat the
  equal-envelope control, cannot move a ranked row.
- **D1 kept as the only live direction, but narrowed.** The design fork itself
  computed the cross-target sharing fraction `f_share ≈ b·E·n/r ≈ 7.6e-4` at n=41
  and preregistered it as a null; grounding confirmed the A\* heuristic candidate is
  the exact selector feature set already shown to carry no routing signal, and that
  no n=131 decomposition path exists. Recommended cheapest form: masked 2×2
  {sharing}×{heuristic}, n=31 sharing-null cell first, gated on the equal-envelope
  control across the §5a band. Expected outcome is a recorded null.
- **D2 downgraded to low-priority near-null.** `binary_semaev.rs:36-41` shows S3 is
  a-independent (one system, not two); shared x-roots split into disjoint per-curve
  subsets, so it is two separate DLPs sharing solve cost, not extra relations for one
  target. The Koblitz twist subgroups are wildly unbalanced (82-bit vs 53-bit at
  n=83 — the twin is trivial), so the shared-cost mechanism has no payoff scenario;
  and binary field-op counting is not wired into ecbench, so measuring it needs new
  instrumentation first.
- **D3 no-go, D4 drop.** D3 attacks a ≤1.9%-of-run stage whose gain cannot register
  in `S`, with no clean `Z/r`-vs-GF(2) encoding and no host tooling. D4's two
  readings both fail: Cheon/static-DH is a different oracle domain the frontier
  forbids from displacing plain ECDLP, and cross-target precomputation is already
  what IC does and already charged (the mt-fieldops-v5 row is unranked across the
  band; wall-time reruns lose at 2^32–2^36). Flagged the sabotage trap of comparing
  amortized IC against non-batched rho (already fenced by `AGENTS.md:2196`).
- **Persisted to the repo** because the work previously lived only in the ephemeral
  session scratchpad; the owner asked to pursue persistence + the D1 preregistration
  in parallel.
