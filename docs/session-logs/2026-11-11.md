## 2026-11-11T02:10Z — `ic corpus`: reject degenerate planted sums (Claude, side session of the ic-dataset work)

### What was done (commands, files, features)

- Branch `fix/ic-corpus-nondegenerate-plants-20261110` off `origin/main` f13a3b5265, in a sparse worktree (`/Volumes/SSD990-2/crypto-worktrees/ic-corpus-nondegenerate-20261110`); disk had about 6 GB free.
- Confirmed the mechanism in `src/cryptanalysis/ic_corpus.rs::generate`: three points drawn independently, with replacement, from a base holding both `±P` above every abscissa in `V = <1, z, ..., z^(l-1)>`. So `P_j = −P_i` occurs and `R = P_k` is a factor-base point. Repeated points `P + P + Q` also occur.
- Fix: `plant_nondegenerate` redraws until the three abscissae are pairwise distinct (no `P_i = ±P_j`) and `x_R ≥ 2^l`. The cap is 100,000 redraws, and it errors if `V` carries fewer than three abscissae. The `--sat` count is still met. The S4 check and the solver confirmation in `build_entry` are unchanged.
- Every INFO file (U instances included) now has the line `planting v2 three pairwise-distinct factor-base abscissae (no P_i = +-P_j), x_R outside the subspace; degenerate draws redrawn`. Corpora without that line predate the fix. The `ic corpus` JSON report gains `planting`, `planting_redraws_total` and per-instance `planting_redraws`.
- Tests: `plants_are_never_degenerate` (2,000 plants for each of `a = 0, 1` at n = 23, l = 4, asserting no repeated abscissa, no cancelling pair, the recomputed sum equals the target, and `x_R ≥ 2^l`), and `generated_corpus_has_no_degenerate_plants` (`generate` end to end, 40 S + 2 U per curve).

### Decisions made (and why)

- Repeated equal points (`P + P + Q`) are rejected too. `2P + Q` is a valid relation, but the INFO witness records abscissae only, so `P + P` and `P − P` are indistinguishable there. A downstream filter could not verify a plant, and a repeated root is itself a visible witness feature. At l = 4 this removes about 30-50% of the old draws, so v2 planted targets are sums of three distinct factor-base abscissae only.
- Degenerate draws are redrawn rather than filtered, so `--sat N` still yields N. This consumes a different amount of the random stream, so a given seed now yields different S *and* U instances than before v2.
- The `label_certified_by` string is unchanged (downstream may match it). Versioning is the new `planting` line. ml-cryptanalysis `csd/lab/ic_dataset/systems.py::parse_info` ignores unknown keys.
