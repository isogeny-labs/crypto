### Decisions made (and why)

The ceiling is the variable count (~14 works, 18 does not), not `m` and not
the degree bound: 8, 10 and 12 all fail identically. Because the paper's
condition `deg L = 2^t ≈ p^{1/m}` forces `m·t ≈ log2 p`, the tower height is
the field size regardless of `m` — 192 tower variables at P-192 for every
arity. `m` is therefore the wrong lever.

The lever that does reduce the count is the smoothness bound: `m·n0 ≈
log2 p / log2 B`. `B = 2` (the paper's Table 5 and every run here) gives
`log2 p`; `B = 13` gives ~52 at P-192; `B = 2^20` about 10 — at the price of
equation degree `B`. No `B > 2` run exists in this repository or in the paper,
so that is the next experiment, and the only one that can move the system size.

### Decisions made (and why)

`B` is the lever that works, unlike `m`: at the same composed degree it cuts
the variable count as `log_B` predicts (20 → 6) and the measured solve from
>300 s to ~1.1 s, while the auxiliary-curve search gets cheaper (2 561 → 57
curves). The cost is U-shaped with an interior optimum near `B = 7–11`, so
`B = 2` — the paper's only tested setting — is the worst end of the range.

Keep it as a solver-cost result, not an end-to-end run: the system comes from
`pkm_smooth_tower`, not the `ic bench` harness, and `X_R` changes coefficients
only, so cols/`D`/time are target-independent (checked on three targets per
row for `B = 5, 7, 11`).
