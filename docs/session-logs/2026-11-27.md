## 2026-11-27 — Prime31 field gate xlift timeout (PR #5279)

### What was done
- Root cause: `f4_fp::solve` takes univariate roots with `roots_univariate`, an exhaustive scan over F_p. For `prime31_coset_xlift_f4` (p = 2^31 - 1, degree 21) it produced no output in 580 s locally; the CI step has a 150 s limit and had not passed since it was added (4f13072baa).
- Added an exact path for p >= 2^28: the roots of gcd(f, x^p - x), split by Cantor-Zassenhaus with deterministic shifts. The zero polynomial and even p fall back to the scan; below 2^28 the scan is unchanged, so small-field counted operations are identical.
- Verified: xlift 168/168 roots in 19 ms (release, local); field gate green in CI on 6a33043c34. New tests (split vs scan on 360 polynomials over p in {3,5,7,101,10007,65537}; a p = 2^31-1 product with a non-residue quadratic factor) pass as an extracted standalone program.

### Decisions made
- Kept the exhaustive scan below 2^28 instead of replacing it, so no recorded small-field operation count moves.

- A release build of the full lib test target is killed by the OOM killer in this container; the CI rust job runs the in-tree tests.

## 2026-11-27 — FactoredOracle port to wide fields, Gf2W::sqr (PR #5281)

### What was done
- New `src/cryptanalysis/binary_factored_wide.rs`: the factored S₄ = S₃(u,x_R,X)·S₃(u′,x_R,X) root find of `binary_radical_root::FactoredOracle`, generic over a `FactorField` trait implemented for `Gf2_128` (n ≤ 127) and `Gf2W` (n ≤ 191), odd and even n (`ArtinSchreierAny`: half-trace table for odd n, linear inverse on the trace-0 hyperplane for even n). `pair_roots` (inline inversions) and `row` (two batched inversions per row); degenerate and guarded pairs are decided by evaluation over V. b = 1 only, as in the workspace Phase 1c study.
- `Gf2W::sqr`: BMI2 `pdep` bit-spread (x86_64, runtime-detected) or per-limb carry-less squaring, then the existing reduction, instead of a full `mul`. New test `squaring_matches_the_full_product_on_every_kernel`.
- `examples/summation_rootfind_bench_1b.rs` (the workspace Phase 1b/1c harness, previously only mirrored in the workspace) and `examples/factored_wide_check.rs` (the module's tests, run through the public API).
- Verified: `cargo run --release --example factored_wide_check` → ALL PASS (Gf2W::sqr = mul(a,a) on default/no-clmul/clmul kernels at n ∈ {61,64,113,127,128,131,163,191}; Artin–Schreier exact at n ∈ {113,126,127,130,131,163}; `pair_roots` = brute force over V for Gf2_128 n = 113, 127, 126 and Gf2W n = 130, 131, 163 at l = 4, 6, 8; batched `row` = brute force at n = 127, 130, 131, 163).
- `factored_wide_check --time` (latency chains, median of 5, 4·10⁶ reps, this 4-vCPU container, L0): n = 131 default kernel mul(a,a) 56.5 ns vs sqr 52.4 ns (0.93×); no-clmul kernel 488.6 vs 206.0 ns (0.42×). n = 163: 55.0 vs 50.4 ns (0.92×); 635.9 vs 247.9 ns (0.39×).

### Decisions made
- Validation through an example binary: the lib test binary does not compile in this 15 GiB container (rustc SIGKILL in both `cargo test --release --lib` and debug `-j 2`); the release lib does. CI's rust job runs the in-tree tests.
- No benchmarks/ or leaderboard row: a component diagnostic at L0, not a validated measurement.
