# Plane-curve and genus 2–5 index calculus implementation status

Status: work in progress, `[pcc:unverified]`. This tracks the requested table across `crypto` and `cryptanalysis`. The entries describe code paths, not a claim that they achieve the complexity bounds in the cited papers or beat a matched rho run.

| Requested row | Existing Rust path | Work needed for the requested algorithm |

| Smooth plane curves, degree `d` (Diem 2006/2011) | `crypto/src/cryptanalysis/plane_quartic_pic.rs` gives a quartic `Pic^0` group law; `diem_quartic.rs` and `research/quartic-diem-sparse_20261115/src/qds_core.rs` collect quartic line relations. `plane_curve_geometry.rs` supplies bounded degree-`d` homogeneous evaluation, rational tangents, line sections with multiplicities, fully rational line-divisor differences, and a degree-8 geometric smoothness certificate. A smooth cubic example yields the explicit `2P-2O` line relation. Bounded line sections now extract rational and irreducible quadratic parameter factors with multiplicity over fields of at most 257 elements; quadratic factors on locally smooth line sections now receive a basis-independent closed-point key and projectively normalized extension-field coordinates, but still lack general Jacobian arithmetic. | Generalize the divisor/group representation beyond quartics, extend line-section factoring beyond rational scans, and verify full DLP solves on smooth public fixtures. A bounded Macaulay/Jacobian-ideal rank certificate now checks geometric smoothness through degree 8 when the characteristic does not divide the degree; a certified line-relation entry point refuses singular curves, including a quartic with only extension-field singularities. The existing target descent is specific to the quartic study, and no general degree-d Jacobian exists yet. |
| Genus 2 (GTTD) | `crypto/src/cryptanalysis/hyperelliptic_index_calculus.rs`, `order_free_hyperelliptic_ic/mod.rs`, and `cryptanalysis/suite/src/highgenus/ic.rs` offer generic hyperelliptic IC. The former has an opt-in two-large-prime graph collector and verified-scalar DLP entry point, replayed by `research/hec_two_lp_replay_20261128`. | The exact-source narrow harness passed graph algebra, including repeated places, Jacobian identities, and genus-2 toy DLP recovery; the full root suite still needs a full checkout. Graph-cycle intermediate coefficients now use exact `BigInt` and can cancel after exceeding `i64`; a final factor-base coefficient outside `i64` is still refused. Seven exact-source graph tests and a root library compile passed, while the full root unit-test suite needs a full checkout; no complete cost comparison. This row is lower priority because its exponent ties rho. |
| Genus 3 non-hyperelliptic (Diem–Thomé / Laine–Lauter) | The quartic `Pic^0` and Diem line-relation paths above, plus `crypto/src/bin/quartic_diem_sparse.rs`. | Consolidate into a reusable end-to-end solver for arbitrary eligible smooth quartics, with independent small-instance replay and a qualified cost comparison. `crypto/src/cryptanalysis/quartic_diem_solver.rs` now exposes a bounded coordinate-input API (q ≤ 131071) that checks the subgroup and verifies the returned scalar; it is still a research solver. |
| Genus 3 hyperelliptic (GTTD; Smith isogeny + Diem) | The generic hyperelliptic IC path above passes genus-3 toy recovery. `crypto/src/cryptanalysis/smith_isogeny.rs` accepts public source Mumford classes, transfers them independently to the existing Picard-class Diem solver, and verifies any scalar again on the source Jacobian. The executable `examples/smith_public_replay.rs` recovered scalar 36 on Smith Example 1 over `F_37` and checked it on the source Jacobian; the Smith construction remains toy-scale. | Run the root test when the build fits. | Genus 4/5 hyperelliptic (GTTD) | The generic hyperelliptic IC engines handle these genera on supported one-point models; `cryptanalysis/suite/src/highgenus/cantor.rs` supplies group arithmetic. The opt-in two-large-prime collector, now accepting repeated off-base places, passed genus-4/5 combined-relation identity and verified-scalar toy DLP replay over `F_11`. | Test larger public instances and qualify full costs; this is not a measured GTTD improvement. |
| Genus 4/5 non-hyperelliptic (Diem plane model of degree `g+1`) | `cryptanalysis/suite/src/highgenus/kummer.rs` handles a restricted non-hyperelliptic superelliptic family. Merged cryptanalysis PR #2024 exposes degree-five birational charts `f2(x)u³=f1(x)` for standard genus-4/5 trigonal models and maps ordinary affine chart points to canonical Kummer ideals. It factors completely rational affine lines `u=mx+b` and maps pairs into generic factor-base `ic::Relation` rows. A bounded scan collects distinct nonzero rows, separating the genus-4 horizontal and nonhorizontal pole-divisor families. Fixed toy `F_17` scans of all 289 affine lines in each genus produced rows that each summed to the Jacobian identity; tangent sections with double and triple roots preserved multiplicity. Vertical lines `x=a` now yield a separate row family; at roots of `f1`, the ramified ordinary fiber has multiplicity three, and two such fibers gave identity rows in both genera. Draft follow-up PR #2026 also maps a root of `f2` to its normalized ramified place of multiplicity three and verifies a vertical identity row against an ordinary fiber. It now corrects mixed affine/vertical line rows by subtracting the normalized places above rational roots of `f2`; fixed genus-4/5 horizontal and nonhorizontal rows summed to identity, and a nonrational `f2` factor was refused at degree-one bound. The generic IC solver replays supplied rows in the Jacobian before using them with its random-walk source/target relations. Toy genus-4 `F_17` and genus-5 `F_7` targets `[7]D1` and `[36]D1` in checked order-19 and order-577 subgroups were recovered and scalar-verified with affine, vertical, and corrected mixed plane-line rows. The genus-4 relation-lattice index 169290 is only an order candidate. `crypto/src/cryptanalysis/plane_curve_geometry.rs` computes general line sections but does not normalize singularities. | Complete local infinity transfer and implement geometric target descent and certify a full Diem collection. A smooth plane quintic has genus 6 and a smooth sextic has genus 10, so these genus-4/5 plane models are singular. The restricted Kummer chart is not general plane-model arithmetic. |
| Linear algebra modulo `n` (block Wiedemann) | `crypto/src/cryptanalysis/koblitz_sparse_la.rs` and `large_prime_graph/block_wiedemann.rs` provide native block Wiedemann paths; `cryptanalysis/suite/src/highgenus/ic.rs` has dense elimination. `plane_curve_sparse.rs` maps rational plane-line relations and reserved target-descent coefficients into `SparseRow<u64>`; its certified constructor now requires the bounded geometric smoothness check. `cado_bwc_io.rs` exports any square row system in the repository's CADO `bwc` matrix/RHS format and verifies a returned solution against every input row. The original planted-matrix replay checks export bytes, mock CADO validation, and composite-modulus refusals. `examples/plane_curve_ecdlp_system.rs` derives a full-rank 7×7 system from the 12 fully split lines of a certified smooth cubic over `F_5`, source normalization, and public target coordinates; native solve recovers log 5 and verifies it on the source curve. Its `--target X Y` path recovered and group-checked all six nonidentity rational targets on this cubic, while refusing off-curve and noncanonical coordinates. Upstream CADO-NFS `bwc` produces a binary right-nullspace vector that normalizes to the same scalar; the example validates all original rows when run with `--cado-sol`. The interfaces require an odd prime modulus below `2^63`. | Generalize beyond toy cubic systems, qualify block Wiedemann at useful sizes, and provide geometric target descent. The suite high-genus path peels singleton columns before dense elimination (cryptanalysis PR #2010). |

The next code milestone is a normalized divisor representation for general plane models and a transfer-compatible input format. Keep every target within the repositories' public benchmark and toy-instance policy.
