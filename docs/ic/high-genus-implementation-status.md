# Plane-curve and genus 2–5 index calculus implementation status

Status: work in progress, `[pcc:unverified]`. This tracks the requested table across `crypto` and `cryptanalysis`. The entries describe code paths, not a claim that they achieve the complexity bounds in the cited papers or beat a matched rho run.

| Requested row | Existing Rust path | Work needed for the requested algorithm |
|:--|:--|:--|
| Smooth plane curves, degree `d` (Diem 2006/2011) | `crypto/src/cryptanalysis/plane_quartic_pic.rs` gives a quartic `Pic^0` group law; `diem_quartic.rs` and `research/quartic-diem-sparse_20261115/src/qds_core.rs` collect quartic line relations. | Generalize the divisor/group representation beyond quartics, implement degree-`d` relation geometry and target descent, and verify full solves on smooth public fixtures. The quartic path is only degree 4. |
| Genus 2 (GTTD) | `crypto/src/cryptanalysis/hyperelliptic_index_calculus.rs`, `order_free_hyperelliptic_ic/mod.rs`, and `cryptanalysis/suite/src/highgenus/ic.rs` offer generic hyperelliptic IC. | A paper-specific GTTD double-large-prime variant and a complete cost comparison are absent. This row is lower priority because its exponent ties rho. |
| Genus 3 non-hyperelliptic (Diem–Thomé / Laine–Lauter) | The quartic `Pic^0` and Diem line-relation paths above, plus `crypto/src/bin/quartic_diem_sparse.rs`. | Consolidate into a reusable end-to-end solver for arbitrary eligible smooth quartics, including target descent, explicit subgroup validation and independent small-instance replay. The current sparse study calls itself a local development tool. |
| Genus 3 hyperelliptic (GTTD; Smith isogeny + Diem) | The generic hyperelliptic IC paths above; `crypto/src/prime_hyperelliptic/model_transfer.rs` and `cover_transfer.rs` support transfer work. | Implement the stated Smith transfer with applicability tests, explicit map and subgroup checks, then feed the image into the quartic Diem solver. Generic hyperelliptic IC alone does not supply that transfer. |
| Genus 4/5 hyperelliptic (GTTD) | The generic hyperelliptic IC engines handle these genera on supported one-point models; `cryptanalysis/suite/src/highgenus/cantor.rs` supplies group arithmetic. | Implement and test the GTTD large-prime relation strategy on these genera, with sparse linear algebra and full target recovery. |
| Genus 4/5 non-hyperelliptic (Diem plane model of degree `g+1`) | `cryptanalysis/suite/src/highgenus/kummer.rs` handles a restricted non-hyperelliptic superelliptic family. | Build smooth plane quintic/sextic model arithmetic and Diem relation/descent machinery. The superelliptic engine is not a general plane-model implementation. |
| Linear algebra modulo `n` (block Wiedemann) | `crypto/src/cryptanalysis/koblitz_sparse_la.rs` and `large_prime_graph/block_wiedemann.rs` provide native block Wiedemann paths; `cryptanalysis/suite/src/highgenus/ic.rs` has dense elimination. | Connect curve relation formats to a verified sparse solver. The suite high-genus path now peels singleton columns before dense elimination (cryptanalysis PR #2010). CADO-NFS `bwc` is not wired in. |

The next code milestone is a verified, reusable quartic DLP API, since it is the shared destination for the genus 3 non-hyperelliptic row and the Smith transfer row. Keep every target within the repositories' public benchmark and toy-instance policy.
