No subfield, no Frobenius, no CM shortcut (trace 110–112 bits, discriminant 220–224 bits). The only structure beyond a generic prime-field curve is **the cofactor torsion (h = 4 or 8) and the Edwards/Montgomery shape** (negation, translations by torsion points, 2- and 4-isogenies to the sibling forms). That is where this regimen looks for levers; it is the only thing that distinguishes these two curves from the prime-field curves the repository has already worked.

## 1. What the regimen is for

A full solve at 2^109 operations is out of reach, so **neither curve is ever "solved" here**. The regimen measures, at fixed instance, how much each structural lever moves each phase of index calculus on **scaled analogs that keep the family's shape**, and then prices the native 221/222-bit phase costs. Rule from `AGENTS.md` (success criterion): every verified measured improvement over the current baseline is a success; the gap to matched rho is reported as distance remaining, not as pass/fail.

## 3. Phase 1: instance family (scaled analogs)

Build a ladder of public, synthetic, known-answer instances that copy the targets' *shape*, one family per curve:

- **E-family:** Edwards x² + y² = 1 + d x²y² over p = 2^k − c (c smallest giving prime), d small (≤ 2^18, as in E-222), group order 4·(prime).
- **M-family:** Montgomery y² = x³ + A x² + x over p = 2^k − c, A small, group order 8·(prime).
- Rungs by prime-order bits n = 32, 40, 48, 56, 64, 72, 80 (extend while a baseline run stays within the caps below). At each rung several curves (≥ 8) and ≥ 16 planted targets each, hash-to-curve public targets, planted scalar never given to the solver.
- A **control family** with the same p-shape and the same r size but cofactor 1 (Weierstrass), so a cofactor-specific effect can be told from a prime-field effect.
- Rho reference on every instance: the repository's counted matched rho (with the §5a band: unpriced native work of every arm, rho included, at 0, 0.1, 1 GAE per operation; rank two arms only where the order holds across the band).

The registered primary metric is the operation count in `crypto.S.gae_pinned`, per phase and total, normalised by √r to give `S` (FRAMEWORK §2). Wall time is a practicality note only. Raw counters (factor-base solves, decomposition additions, linear-algebra row operations, lookups) ride beside the GAE column; read ratios from counters until the ratios for the instance are pinned in `calibration.json`.

## 4. Phase 2: the baseline (rung 0 of every lever)

Freeze one baseline per rung before any lever runs: the current prime-field IC producer (small-factor-base, Semaev-style or table-oracle decomposition, as the repository names it in `ic bench` / ecbench specs; the director pins the exact producer and commit in the task card). ## 5. Phase 3: levers (each a single declared change against Phase 2)

These are **hypotheses to test, not results**. Each gets a preregistered prediction and a falsifier before data (`controlled-experiment` skill).

| id | lever | mechanism | predicted effect | falsifier |
|---|---|---|---|---|
| H1 | Torsion-quotient factor base | work in E(F_p)/E[h]; factor base points are classes modulo the h torsion points; relations are written in the quotient, so each class absorbs h·2 (with ±) points | fewer columns by up to 2h for equal coverage; fewer decomposition trials per relation | columns or trials per relation do not drop on E/M-family against the cofactor-1 control, or the projection to the prime-order subgroup costs more than it saves |
| H2 | Edwards complete-addition decomposition | exceptional-case-free addition lowers the per-step charge in the relation search and removes case branches in the oracle | lower decomposition additions per trial on the E-family only | no per-step change against the same producer on the Weierstrass control |
| H3 | Montgomery x-only relation search | Semaev-style x-coordinate relations on the x-only Montgomery arithmetic with ± built in | factor of 2 in effective factor base at equal cost per relation | counted cost per relation equal to baseline, i.e. a relabelling |
| H4 | Isogeny hop to sibling form | transfer the instance by a verified 2- or 4-isogeny between Edwards, Montgomery and Weierstrass models of the same curve and run the cheaper producer | none expected unless the models differ in the factor-base property; this is a control | any difference at all is investigated as an accounting artefact first |
| H5 | Degree-of-regularity forecast for sweep choice | use `dreg-triage` to choose factor base, dimension and seeds; advisory only | fewer wasted sweep cells | forecast does not rank cells better than random order |

Order: H4 first (cheap control, tells whether form alone matters), then H1, H3, H2, H5. Relabelling and accounting changes do not count as improvements (AGENTS.md).

## 8. Caps and stop rules

- A rung is dropped from the ladder when baseline relation collection stops at `max_trials` for more than a quarter of its targets; the rung is reported as not established, never downscaled silently.
- A lever is stopped when two consecutive rungs show its effect inside the A/A floor.
- Any lever that moves the total without moving the structural metric it claims is treated as misattributed until explained.
- No lever is "promoted" from stage diagnostics; only complete-solve evidence on a rung counts.
- Total effort per lever per round: one task card, one run, one assessment. Replan after each round and append the session-log entry.
