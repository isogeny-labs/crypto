# Binary named-generated-subgroup transfer certificates

This file specifies the durable replay corpus produced for the repository's
ordinary-binary cubic covers. Its structural contract is
[`binary-subgroup-transfer-certificates.schema.json`](binary-subgroup-transfer-certificates.schema.json).
The corpus is producer-side evidence. Schema conformance, a passing replay,
or a `supported_on_named_generated_subgroup` status is not a signed PCC
verdict. [pcc:unverified]

## Exact claim scope

For the degree-three cover `phi : H -> E`, write `Psi = phi^*` and
`R = phi_*`. The native implementation checks the typed identity
`R(Psi(P)) = [3]P`. A record also checks that its positive integer `r`
annihilates the exact named generator `G` and that `gcd(3,r)=1`. Every point
in `<G>` is annihilated by `r`; Bezout therefore gives a left recovery map

`[3^(-1) mod r] R : Psi(<G>) -> <G>`.

Consequently, a supported record establishes injectivity of `Psi` on the
cyclic subgroup generated by that exact point. It does not require `r` to be
the exact order of `G`, and it does not assert that every order-`r` point in
the ambient curve lies in `<G>`. The structural argument is the
`ChainedTransfer.injective_with_recovery` theorem in
`research/chained_jacobian_transfers_20261110/lean/ChainTransfer.lean`; the
cover construction, norm identity, point encoding, and arithmetic checks are
separate native obligations.

The two `exact_order_evidence` fields remain independent:

- `annihilator_primality` records evidence about whether the declared `r` is
  prime.
- `generated_subgroup_cardinality` records evidence that `G` has exact order
  `r`.

Each uses `proved`, `probable`, or `unknown` and an evidence reference. A
`probable` or `unknown` exact-order status does not weaken the narrower
generated-subgroup injectivity result when the annihilation and Bezout checks
pass. It does prevent promotion to an exact order-`r` subgroup claim.
[pcc:unverified]

The optional `traits` input is advisory provenance only. Its values cannot
promote either exact-order field. A non-`unknown` exact-order entry requires
local deterministic evidence produced or replayed by this corpus generator;
the semantic checker must reject a traits-only promotion. [pcc:unverified]

For candidate annihilators below the strict Sorenson--Webster `psi_13` bound,
the current producer locally replays strong Miller--Rabin tests to the first
sixteen prime bases through 53. Below the bound
`3317044064679887385961981`, passing the first thirteen prime bases is a
primality proof; the extra bases are retained as a control. Together with the
record's checked nonidentity and `[r]G=O` obligations, this proves
`ord(G)=r` for those records. Values at or above the bound remain `unknown`
without a separately replayed primality certificate; the producer does not
apply its local probable-prime test above that cutoff. This conclusion is
only about the named generated subgroup, not the ambient curve order.
[pcc:unverified]

## Required bindings and checks

Every map record binds the complete ICV1 identity, canonical model JSON and
its SHA-256 digest, the content-addressed HC1 source UID, and the CV1 map UID.
Every named-subgroup record additionally binds the EC1 alias, curve UID,
generator coordinates, annihilator, degree inverse, pullback divisor, typed
pushforward, and `[3]G`.

A supported named-subgroup record requires all of these producer checks:

1. the named generator is a nonidentity point on the exact target curve;
2. `[r]G = O`;
3. `Psi(G)` is nonidentity and `[r]Psi(G) = 0`;
4. the typed pull-push witness equals `[3]G`;
5. the arbitrary-class norm agrees with the typed pushforward; and
6. multiplication by `3^(-1) mod r` recovers `G` from the pushforward.

Failures are retained on the affected subgroup and map records. A failed
named-subgroup tuple requires only its EC1 and curve UIDs, failed status,
claim scope, unknown exact-order fields, and one or more failure reasons. It
may omit generator, annihilator, arithmetic witnesses, and checks rather than
inventing success data. A failed obligation cannot be represented by a
supported status. A map marked supported must contain only supported subgroup
records; a failed map must carry a map-level failure or at least one failed
subgroup. A map with no linked EC1 generator is retained as
`not_applicable_no_named_subgroup`; absence of a named input is not a failed
transfer and supplies no subgroup result.

## Producer provenance

`producer.git_commit` and `producer.rustc_version` are caller-supplied
metadata. The required `producer.attestation` value is
`caller_supplied_unverified`; consumers must not treat either string as an
independent execution attestation. [pcc:unverified]

`producer.source_sha256` covers the producer and transfer sources, the binary
cover graph link generator, this schema, and the build pins used for the
replay, including the root Cargo manifest and lockfile. The generator records
the individual digest inputs in its implementation contract; the semantic
replay recomputes the aggregate rather than trusting the displayed digest.
[pcc:unverified]

## Coverage and replay boundary

For the 2026-11-18 live graph, the acceptance target is one map record for
each of 174 binary maps. Of those, 147 maps carry 150 named EC1 bindings and
27 carry no named subgroup input. The generator must recompute these counts
from the hash-pinned registry and graph; the JSON Schema cannot enforce
cross-file completeness, uniqueness, hash preimages, or count arithmetic.
A semantic replay must fail closed on a missing, duplicate, stale, or foreign
ICV1/EC1/HC1/CV1 binding.

The corpus covers only `binary_cubic_pullback_v1`, the same-field genus-three
source with one rational infinity point and map degree three. It does not
cover the odd-characteristic degree-two family, normalized target models,
extension-field odd arithmetic, arbitrary cover searches, or every
hyperelliptic representation of an elliptic curve.

## What the corpus does not establish

The corpus contains no destination relation collection, linear algebra,
target decomposition, or scalar-recovery solver. Its scope object must keep
`solver_assessment` equal to `not_provided` and `computational_advantage`
equal to `not_assessed`. It supplies no timing, complexity, scaling, memory,
or end-to-end cost result. In particular, cover existence and an injective
generated-subgroup representation do not by themselves show that an ECDLP is
easier in the Jacobian.

The current small-field norm oracle independently checks support
factorization, residue fields, Frobenius trace, and the target group law for
its fixed GF(8) fixture, but still uses production source-Jacobian addition.
It is not a catalog-wide independent source-group oracle. Exact-order
promotion, independent replay, package publication, cryptanalysis parity,
and required review gates remain separate evidence obligations.
