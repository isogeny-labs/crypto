# Ordinary binary native dataset path

The supervised ordinary-binary path retains the original curve coefficient `a`, nonzero `b`, modulus, twist, target, and factor-base identity through construction, matrix execution, signed group checking, artifact delivery, replay, and causal export. It is exposed through the existing dataset worker and capabilities contract as `binary-m3-native-v1`.

## Supported profile

The current adapter accepts `m=3`, field degrees 23–31 and 47–61, both twists, `f4` or `f5`, degree bounds 1–6, and a sign-closed factor base of four distinct signed points over two distinct x-coordinates. Admission requires the original execution context, verified worker originals, bound capture, and a positive work allowance. Eligibility does not guarantee completion: original policy/domain and resource refusals remain explicit.

The full requested dataset portfolio remains broader than this component. Larger factor bases, other decomposition sizes, other solver families, and the production campaign retain their separate implementation and execution gates.

## Retained evidence and cost accounting

Construction emits a finite-selector determinant and coordinate ANFs, checked independently against the authenticated original. A private immutable input owner retains its original cumulative budget identity across successful storage and failure paths. Native matrix and signed-group events are captured with their actual durable acknowledgement positions. The event index refers to those committed bytes and separately retains at most one pending record.

Replay validates the entire live hash chain, exact input/index endpoints, native event identity, matrix boundary consistency, signed arithmetic, witnesses, and delivery receipts. Pending events receive typed and mathematical validation even if interruption prevented publication of a terminal result. Signed arithmetic cannot precede completion of the acknowledged matrix prefix. Missing terminal evidence remains a partial result.

The result format retains v1–v4 accounting branches. Version 4 reserves the bounded counting pass before serialization and admits the exact counted size before the second encoding pass writes bytes. Charges survive later refusal. These are modeled work/memory/trace reservations and counted group-addition calls; they are not retired hardware instructions or a performance measurement.

## Early refusals and unsupported degree bounds

A valid CLI configuration outside the native degree1–6 profile remains an authenticated unsupported result. Replay verifies the original configuration, manifest, execution/capture binding and curve/domain before accepting that result; it does not require native-profile admission first. Degree7 and32 controls cover both engines and twists. Unsupported results cannot carry native completion or witness claims.

After the worker has admitted its fixed terminal-report allowance, an early setup refusal retains the cumulative work/memory/trace ledger and its first stop. It creates no replacement capture attempt. Central replay checks the original limits, setup phase, admitted terminal charges, reported counters and absence of native results. ## Causal export

The ordinary signed-prefix projector authenticates cached original inputs and the capture watermark, replays the entire bounded arithmetic prefix before callbacks, and checks the manifest/head again before output. Public features describe original public inputs, the next group action, and the pre-addition accumulator. Resulting sums, labels, target matches, capture positions, and provenance remain in restricted records. Unsupported profiles emit no public examples and retain a restricted summary with an unknown suffix.

Matrix, equation, and construction-level causal projections remain unavailable in this projector. Boundary consistency does not certify independent matrix-basis derivation or first/last fall degree.
