# Recovery after a source restarts

A persistent Spot instance can stop and restart with the same instance ID while
its original experiment process is gone. A recovery fence that only accepts
EC2-confirmed termination will correctly wait, but it needs an explicit release
path to recover that workload. This repair adds that path and opt-in Codex
session recovery. Production handoff and a combined live replacement drill
remain pending; this document does not claim completed migration.

## Source release

`OriginReleased=true` and a SHA-256 `ReleaseReceipt` allow a successor to acquire
explicitly relinquished source work. A stopped instance, expired heartbeat or
missing EC2 lookup is insufficient. A live successor cannot be displaced. The
controller retains confirmed successor termination through long capacity gaps,
including the optional Codex owner. Release never fabricates origin termination.

Before conditionally releasing source ownership, the operator must verify the
source identity, registered command identities and absence of the original
process; download and hash-check all required checkpoints; disable the source
backup producer and prevent its restart; and retain an immutable private receipt
of those checks. Keep source disks and checkpoints for rollback. Reject a changed
owner or mismatched origin rather than overwriting it.

## Optional Codex recovery

The service remains disabled until an operator-reviewed enrollment manifest
exists at `/srv/experiments/agent-migration/agent.json`. The manifest must use
schema `spot.codex-migration/v1` and provide:

- `enabled`, `authentication_transfer_authorized`,
  `resume_active_threads_authorized` and `workspace_verified`, all explicitly true.
- `origin_instance_id` and `table` for the actual deployment.
- `codex_binary_relative`, a path beneath the restored Codex home, and optional
  `snapshot_interval_seconds` (default 60) and `codex_arguments`.
- Optional `wait_for_recovery_status` paths and `wait_for_public_ip` to hold
  agent continuation until experiment recovery and a restricted endpoint are ready.

These flags record completed operator checks. They do not grant permission or
replace source quiescence, verified workspace transfer and a conditional release
of both shared-host and Codex ownership.

`codex_snapshot.py` writes checksummed generations on durable storage. SQLite's
backup API includes committed WAL data. Authentication export requires explicit
`--include-auth`; roots are private and restore verifies every file before
writing a new home. Three committed generations are retained, with the new
pointer committed before pruning. Pruning failures appear in service status.

Each online generation validates databases and files independently; it is not
an atomic snapshot across all databases, session files and running tools. The
final initial migration requires quiescence. Interrupted external tools require
application-level reconciliation; exactly-once tool replay is not claimed.

The service binds the verified durable workspace at the worker user's home and
keeps SQLite and sockets on local storage. Its systemd readiness notification
holds legacy experiment restoration until that mount and the Codex server are
ready. If an experiment was already restored before initial enrollment, save and
quiesce it before changing its home mount, then verify and resume it afterward.

It loads parent chats and continues only previously active unblocked parents.
It does not independently start children, idle or errored chats, or chats waiting
on approval/user input. The continuation first reconciles existing artifacts and
external jobs. The RPC client never answers approval requests.

Before enrollment, inventory all source servers, active tools, external jobs,
worktree pointers and referenced scratch paths. Obtain explicit credential
transfer approval, quiesce the source agent and prevent automatic restart,
finish and verify the workspace copy including deletes/renames, and commit a
final verified session generation. Keep cloud credentials, SSH private keys and
unrelated application state outside that transfer. Preserve the original state.

The conservative process probe currently counts the Codex daemon as busy;
automatic idle shutdown of an enrolled daemon is not established.

## Native Diem continuation and coordination state

An explicitly enrolled native Diem producer takes precedence over an obsolete
process image. Its enrollment pins the executable, source artifacts, checkpoint
manifest, task grid and original UTC deadline. The replacement validates each
completed receipt and continues missing instances under shared host and workload
ownership fences. Completed receipts remain on durable storage. An interrupted
unfinished instance is recomputed; this path does not preserve its in-memory
progress. Final output must match all committed receipts and its frozen hash.

Codex's startup barrier accepts a freshly reported completed or expired
experiment deadline so it can reconcile the outcome. An error or stale status
does not satisfy that barrier. Deadline expiry remains an incomplete experiment,
not successful generation.

The optional Conductor database import requires separate authorization for
private coordination content and matching client credentials. Take a final
quiesced dump, validate restoration before replacing the empty destination
database, and preserve a backup of that destination. Write the durable
`conductor-imported.json` marker only after a successful verified import.
The node service then skips bootstrap so it retains the imported projects and
client authentication. The database remains on the durable encrypted mount.

Recovery verifies NFS home mounts by filesystem identity, requeues dependent
experiment services after a successful Codex retry, and disables login-session
IPC cleanup for the workspace-owned PostgreSQL service. Codex resumes long
histories with metadata-only responses. Empty idle editor tabs without any
persisted thread or rollout are reported as omitted; missing active work fails
closed.

Snapshots also preserve Codex policy rules and generated visual artifacts.
Authentication stays private; source cloud credentials and SSH private keys
are excluded. Worker bootstrap installs Docker and jq for the migrated tools.
External research access uses the replacement's own role with the existing
namespace permission boundary.

## Validation and live replacement result

The [sanitized validation summary](validation/recovery-20261019.json) records
test outcomes. The code was hash-compared with the Linux-validated source.
Operational identities, detailed source hashes and raw receipts remain private.

- All 111 infrastructure tests passed on Linux.
- An actual credential-free session backup restored; five SQLite databases
  passed integrity checks, the packaged executable started and a saved chat
  could be read. No turns were started and no validation process remains.
- A retained experiment archive passed complete download hashing and manifest
  validation without starting its process.
- The prepared runtime passed complete download hashing under the worker role.
- The unchanged source Rust library suite passed all 4,399 tests, with 118
  ignored, in a full serial run. The initial parallel run failed one unchanged
  global-counter assertion (two calls instead of one); that failure is retained
  in the private evidence. This repair changes no Rust source.

The approved live handoff and real AWS FIS Spot interruption test passed.
The source was quiesced and fenced, the final workspace sync completed all
70,136 bounded batches without errors, and the imported coordination database
retained 18 tasks with working client authentication. Eleven saved parent chats
loaded and all three previously active parents continued. Four idle editor tabs
had no persisted thread or rollout and were explicitly reported as omitted.

FIS delivered a real Spot interruption. AWS reported
`instance-terminated-by-experiment`. Compatible capacity was unavailable for
approximately five minutes; Auto Scaling retried and launched a successor using
the pinned runtime. No services were manually started on the successor.
Bootstrap completed without errors. Shared host, Diem and Codex ownership moved
to the successor; the scheduled controller moved the stable endpoint.

The successor retained all 46 completed Diem receipts and the original deadline,
ran exactly one producer with advancing CPU counters, and restored all eleven
saved chats. All three interrupted parents produced new model or tool events;
one completed its resumed turn. Conductor authentication and research-cluster
access worked. The successor committed a new authenticated 944-file snapshot,
all file hashes verified, with zero pruning errors. Codex, Diem and node services
each had zero restarts.

The repair changes infrastructure, not research completion criteria. Diem has
52 expected records and recomputes an unfinished instance after interruption.
Recovery can wait for compatible Spot capacity. Online Codex snapshots retain
the latest committed generation; external side effects require reconciliation.
The 60-second snapshot delay begins after a snapshot finishes, so the recovery
point interval includes its duration. Original source state and backups remain
retained privately. Automatic idle shutdown of an enrolled daemon remains
unverified.

## Desktop connection follow-up

The original replacement test established worker-side restoration and advancing
agent turns. It did not establish that the desktop had reconnected. A subsequent
user report exposed a desktop connection left in `remote-codex-not-found` after
an earlier handoff attempt. A fresh SSH login now resolves the restored CLI and
reports its expected version.

The workstation also lacked the authenticated SSH proxy, so future host-key
changes could block desktop reconnection. The installer now supports
`--ssh-only`, preserving existing coding-client hooks and plugins. This mode
was installed on the workstation and exercised through real SSH. All 113
infrastructure tests passed on Linux, including the new preservation and
deployment-mismatch tests.

An idle recovered chat is not necessarily missing work: completed turns,
pending user approvals and failures predating the migration remain distinct.
The recovery service does not override those states. Desktop visibility and
client-provided tools require the desktop connection; server health alone
does not verify that connection.
